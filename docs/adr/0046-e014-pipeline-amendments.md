## Context

E014 changed the pipeline in several places. The consolidated CI/CD spine (2026-10-11) already
states each change as rule text, but the rules had no decision record. Without one, a reader
of ADR-0035, ADR-0036 or ADR-0039 would follow rules that E014 replaced: putting Gitea-only
secrets in Gitea, treating zizmor as the major-tag guard, or using `--skip-existing` on the
Gitea index. This ADR records each decision and cites the AD that states it. It does not
restate the rule text; the spine is authoritative for that.

## Decision

1. **Poetry bootstrap exception to ADR-0001** (decision 2026-10-11, A-03; CI AD-11, product
   AD-1). `.github/requirements/poetry.txt` is the one package set CI workflows install
   outside `poetry.lock`. It installs Poetry and nothing else. Not covered: the image's
   builder stage (`docker/Dockerfile`) still installs `poetry==${POETRY_VERSION}` from PyPI
   without hashes (sprint 02 closure, AR-4; tracked in the issues backlog). It is generated by pip-tools from
   `.github/requirements/poetry.in` with the command in its header (`pipx run --python 3.14
   --spec 'pip-tools==7.6.2' pip-compile --generate-hashes …`) and is never hand-edited. CI
   installs it with `pip install --require-hashes -r .github/requirements/poetry.txt`.
   Updates: Dependabot's `pip` ecosystem on `/.github/requirements` on GitHub. If a
   Dependabot PR drops the `--hash=` lines or fails `pip install --require-hashes`, the entry
   is removed and the maintainer regenerates the file when bumping Poetry; on Gitea this is
   always manual (`notes-E014-S02-001.md`). Application, dev and publish dependencies stay in
   `poetry.lock`. Publish jobs then install only the optional Poetry group `publish`
   (`poetry install --only publish --no-root`), which holds `twine` and nothing else.
2. **One release run per tag** (CI `.memlog.md` maintainer decision 2026-10-11 (2), refined by
   the option-2 decision of the same day; plan-review decision 3; A-07, A-08; CI AD-9,
   AD-13). All destinations of a release publish from one forge's run, all-GitHub or
   all-Gitea. Each destination's secrets live on that forge only; the other forge holds no
   `PUBLISH_*` secret or variable. A release run fully from Gitea may publish every destination, with the
   PyPI, TestPyPI, GHCR and Docker Hub tokens as Gitea repository-level secrets and the AD-13
   mitigations (ADR-0039, amendment 2026-10-11). AD-10's one digest per run is kept. A
   per-forge split of destinations within one release was rejected: two runs build two
   images with two digests for one version. Not mechanically enforced: the per-release
   checklist compares secret names on both forges.
3. **Configuration-gated destinations and the NFR-4 trade-off** (E014-S02-002; PRD review
   F-05; CI AD-9, AD-10, AD-11, AD-12). A destination is enabled exactly when its token
   secret and every variable it requires are non-empty. A partially configured destination
   is skipped with one warning and the run stays green; the fail-fast registry guard of
   E013-S01-005 is retired. So a release is acceptable only with **zero**
   partial-configuration warnings and each target destination reported `enabled` exactly
   once. Not mechanically enforced: a per-release checklist item in
   `docs/ci/pipeline-walkthrough.md`.
4. **Publish-job step order** (A-05; CI AD-17, AD-18). Destination configuration → AD-15
   version guard (`dev.yaml` only) → checkout and `dist` download → hash verify → CA import →
   login / publish. Presence-only evaluation of secrets (`!= ''` in job `env`, the step's
   `HAS_*` booleans) is not a credential touch; the CA import is the first step that touches
   a credential. The hash verify checks `dist` against the build job's `wheel-sha256` and
   `sdist-sha256` outputs, never a recomputation (CI AD-2, AD-17).
5. **Dependency-audit scope** (arch gate AG-3 / AR-1; CI AD-3, PRD NFR-3). Recorded by
   ADR-0042, which this ADR cites rather than restates.
6. **Frozen hook revisions** (BL-E013-020; CI AD-3, AD-5). Every remote pre-commit repo is
   pinned to a commit SHA with a `# frozen: vX.Y.Z` comment. The `precommit-revs-frozen`
   pygrep hook enforces the 40-hex SHA for block-style `rev:` lines (a flow-style mapping is
   not matched); the `# frozen:` comment is written by `autoupdate --freeze` and not checked.
7. **Major-tag pin form is a pygrep hook, not zizmor** (F-07; CI AD-5; amends ADR-0035
   Decision 6). zizmor's `ref-pin` policy accepts any ref, `@main` included. The
   `workflows-lll-major-tag` hook enforces `LiquidLogicLabs/*@vN` over every YAML file under
   `.github/`. Coverage limit: block-style `uses:` lines with the value on the same line.
8. **Credentials never on argv** (F-09; CI AD-11). The Gitea files-check sends its
   `Authorization` header on curl's stdin. The `workflows-no-auth-header-argv` hook refuses a
   literal same-line `-H`/`--header` Authorization flag; it does not see a next-line value, a
   header built in a variable, a `--config`/`-K` file, or `-u`/`--oauth2-bearer`.
9. **Gitea files-check instead of `--skip-existing`** (CI AD-11 amendment of 2026-10-09,
   F-12; amends ADR-0036 §5). twine refuses `--skip-existing` for any index other than
   PyPI and TestPyPI. The Gitea step asks Gitea's package API which files it already holds:
   200 uploads only the missing files, 404 uploads all, any other status fails the step.
10. **No bare-major image tag while the major is 0** (F-11; CI AD-8). The `{{major}}` metadata
    line carries `enable=${{ !startsWith(needs.build.outputs.image-version, '0.') }}`. The
    `workflows-major-tag-gated` hook checks that `enable=` is present, not its value.
11. **Release concurrency wording** (F-10; CI AD-14; resolves the substance of
    BL-E013-036). `group: release`, `cancel-in-progress: false`: one release runs and one
    waits; a newer tag cancels the waiting one, which is re-run only while no newer tag has
    released. A per-ref group was rejected (two releases would race on `latest`).
12. **Base-image pre-pull with a maintained retry action** (F-18; CI AD-2). `build.yaml`
    pre-pulls the Dockerfile's digest-pinned `ARG BASE_IMAGE` default anonymously with
    `nick-fields/retry` v4.0.0 (SHA-pinned; 4 attempts, a fixed 30 s wait) and builds with
    buildx `driver: docker`, so the smoke build reads the local copy. No loop was written, so
    global rule 1's escape-hatch fields do not apply. Evaluated: `nick-fields/retry` v4.0.0
    (constant `retry_wait_seconds`) and `Wandalen/wretry.action` v3.8.0 (constant
    `attempt_delay`); no `LiquidLogicLabs/*` retry action exists. A constant wait was
    accepted over a hand-written loop with 15/30/60 s backoff.
13. **ADR-0028 re-anchored** (CO-17 residue). ADR-0028's decision binds through CI AD-6 and
    the `workflows-ref-free-checkout` hook; its CI-AR references are history.
14. **Image version label from the full version** (BL-E014-075; CI AD-8). The metadata action
    sets `org.opencontainers.image.version` from its highest-priority tag, and `type=semver`
    (default 900) outranks `type=raw` (200), so the 0.3.0 dry run labelled the image `0.3`.
    The `image-version` raw tag line in `dev.yaml` and `release.yaml` carries
    `priority=1000`; the tag set itself is unchanged. The `workflows-version-label-priority`
    pygrep hook refuses that line without it (coverage limit in its comment and AD-8). A
    pytest guard was written first and removed: it parsed workflows, which AD-4 forbids.

## Consequences

- Every pipeline rule E014 introduced has a decision record, and ADR-0001, 0028, 0035, 0036
  and 0039 carry an `Amended by` pointer here.
- **Accepted cost: four rules are checklist items, not checks.** One forge per release, zero
  partial-configuration warnings, each destination enabled once, and the
  shared-publish-step rule of ADR-0047 are verified by the maintainer per release. A missed
  checklist item can publish to the wrong forge or ship a release that skipped a
  destination. The maintainer owns the checklist.
- **Accepted cost: each pygrep guard has a stated coverage limit** (items 6, 7, 8, 10). A
  violation written in a form the regex does not match passes `just check`. The limits are
  recorded in the CI spine next to each hook.
- **Accepted cost: the retry wait is constant.** Four attempts 30 s apart may be too short for
  a long ghcr.io 429 window; the answer is re-running the failed job (CI Conventions,
  "Transient registry errors").
- The bootstrap file adds a second update path for one package (Poetry). Dependabot keeps it
  current on GitHub only.

## Revisit when

- Poetry ships a hash-locked self-install, or CI stops bootstrapping Poetry with `pip`
  (item 1);
- Gitea gains environment-scoped secrets (item 2; see ADR-0039 "Revisit when");
- a forge exposes secret names or run warnings to a check that AD-4 allows (items 2, 3);
- `nick-fields/retry` or `Wandalen/wretry.action` gains backoff, or live runs show
  4 × 30 s is too short for ghcr.io 429s (item 12);
- actionlint accepts `queue: max` (item 11).
