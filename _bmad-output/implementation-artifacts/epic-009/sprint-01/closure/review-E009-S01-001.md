## Six technical dimensions

1. **Interface contracts.** The CA-import step's `with:` inputs (`certificate`,
   `certificate-name`) match the action's actual published `action.yml` (verified
   against `LiquidLogicLabs/git-action-ca-certificate-import@main` via the GitHub API
   before use). The forge-classifier step's inputs/outputs are unchanged; only its
   internal normalization gained one line.
2. **Error/edge handling.** `tests/ci/test_forge_coordinates.py` adds a table-driven
   case for the exact edge the fix addresses (mixed-case host + trailing slash must
   project to the same registry as its lowercase form) alongside the existing
   unknown-forge and https-only negative cases.
3. **Observability.** `docs/ci/gitea-runners.md` carries the required Mermaid
   trust-ordering sequence diagram (bootstrap trust → registration → forge resolution
   → action download → job start → downstream CA import → credentialed call).
4. **Security.** Distinct secret names per destination class
   (`GITEA_PACKAGE_INDEX_CA_CERTIFICATE` vs. `GITEA_FORGE_API_CA_CERTIFICATE`) prevent
   the new secrets from re-introducing the cross-destination sharing
   `test_publisher_credentials_stay_disjoint_between_destinations` guards against; both
   are gated on `secrets.<NAME> != ''` so they are inert everywhere the secret does not
   exist, by construction rather than by a forge-identity branch.
5. **Testability.** Every new assertion is backed by real, executed code parsing the
   committed YAML or running the real bash step bodies; nothing is asserted against a
   fabricated fixture standing in for live Gitea evidence. Items needing a live Gitea
   are `pytest.mark.requires_live_gitea`-marked and skip with an explicit reason rather
   than silently passing or being omitted.
6. **Existing-library check.** No new script module was introduced. A decompiled trace
   of a previously deleted `scripts/forge_coordinates.py` was found during
   investigation and deliberately **not** resurrected: `tests/ci/test_action_policy.py
   ::test_no_publication_decision_lives_in_a_python_module` permanently forbids a
   pipeline decision living in a Python module (E008 deleted it for exactly that
   reason), so the classifier logic was kept inline and duplicated byte-identically
   across both workflow files, matching the project's established convention.
