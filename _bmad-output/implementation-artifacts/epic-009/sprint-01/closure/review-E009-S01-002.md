# Self-review: E009-S01-002 "Certify Gitea Staging and Gate Migration"

## Executive summary

This story cannot reach a live-Gitea-verified `done` in this environment (no server, no
runner, no credentials) -- the same constraint E009-S01-001 recorded. What was built is
every statically-achievable piece the story names: the F20 `REQUIRED_GITEA_CASES`
registry and its ADR-0017 evidence-export/report-projection gate, the ADR-0020
fault-injection/cleanup contract, the ADR-0016 action-closure drift comparison, the
step-summary-is-an-observation predicate, and the `docs/ci/gitea-certification.md`
runbook plus a `docs/operational.md` cross-link. All of it is real, executable Python,
exercised against synthetic fixtures that are labeled as fixtures throughout -- not
markdown promises. `poetry run pytest tests/ci/ -q` passes (370 passed, 4 skipped)
with no regression to the suite inherited from Story 9.1. The items that require an
actual Gitea instance are named individually, both in the new test module (one
`@pytest.mark.requires_live_gitea` placeholder test) and in the doc's "Items explicitly
requiring live Gitea" section, and are filed as backlog issues below.

## Claims check

- "`REQUIRED_GITEA_CASES` registry independent of the markdown doc" -- verified: the
  registry is a Python `frozenset` in `tests/ci/test_certification.py`; the doc's table
  cites it rather than defining it, and `test_the_registry_is_non_empty_and_every_...`
  guards the mapping between them.
- "mechanical check that a report row exists and resolves against a retained evidence
  export for each" -- verified: `resolve_certification_report` is exercised by 15
  tests, 11 of them negative plants (missing row, extra row, duplicate, cross-tuple,
  cross-source, cross-workflow, stale digest, tampered export, incomplete export,
  unbacked record, credential-shaped value x2, invalid trust boundary, missing field).
- "fault-injection/cleanup-postcondition contract... unit tests validating the
  contract's own data structures and validation logic using synthetic fixtures" --
  verified: `assert_recovery_contract` has one clean-pass test and 9 negative plants
  covering rerun identity, preservation (empty outputs, lost artifact scope, second
  upload request), cleanup (3 resource classes), mechanism shape, and injection timing.
- "evidence-export authenticity contract... unit-test the validator against synthetic
  good/bad fixtures" -- verified: credential-shape and tuple-fingerprint-mismatch cases
  are both present and both fail as required by the task instructions.
- "Anything requiring an actual Gitea certification run... mark it
  `@pytest.mark.requires_live_gitea`... and list it explicitly in your final report" --
  verified: one placeholder test is marked, and `CASE_REQUIRES_LIVE_GITEA` plus the
  doc's status table and "Items explicitly requiring live Gitea" section enumerate
  every case/probe this environment cannot execute.
