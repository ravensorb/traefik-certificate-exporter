# Notify Apprise Destinations After an Export Pass

Depends on: `E010-S01-001`.

As an operator,
I want export completions delivered to email, chat, or a webhook,
So that I know an export ran without watching the logs — and without this project writing a
delivery mechanism.

Depends on `E010-S01-001`: this setting's values are credentials, and shipping it before
redaction would be shipping the leak.

**Acceptance Criteria:**

**Given** one or more Apprise destination URLs configured beside `settings.postexportcommand`
**When** an export pass completes on either path (`app.py` run-at-start, or the watch drain)
**Then** each destination is notified with the exported domain list, under an explicit delivery
timeout stated in ADR-0014 as the counterpart of `post_export.py`'s 30 seconds — and a delivery
failure is logged **as a delivery failure**, never propagating and never mislabelled as an export
error by the drain's per-path handler

**Given** the two emission sites have different pass scopes — `app.py` notifies once for the
union of all files, the drain once per file
**When** both are wired
**Then** the intended scope of each is stated and asserted, rather than left to diverge as the
`restartContainers` guard already has

**Given** `apprise` added as an ordinary runtime dependency at the floor ADR-0014 records
**When** dependencies are declared
**Then** `pyproject.toml` carries the constraint and the ADR carries the licence at that floor
and the `requires_python` overlap — the licence was **verified**, not inherited from the gate,
which asserted a GPLv3 history that does not exist

**Given** nothing in this codebase detects change — every certificate is rewritten every pass,
and the image ships `RUNATSTART=true`
**When** the documentation describes what a notification means
**Then** it says "an export pass completed", not "a certificate changed", so nobody discovers
after muting the channel that a container restart notifies

**Given** delivery is fire-and-forget
**When** the documentation describes it
**Then** it states that a failed notification stops nothing and points at `postexportcommand`
as the supported way to do something that must succeed

**Given** an Apprise URL contains commas legitimately (`mailto://…?to=a@x,b@y`)
**When** the destination list is configured from the environment
**Then** confuse's native indexed keys (`…_APPRISEURLS_0`, `…_APPRISEURLS_1`) are used and the
comma convention is **not** extended to this key, with the documentation stating which form
applies where

**Given** `settings.dryRun`
**When** a pass would otherwise notify
**Then** no notification is sent, consistent with dry-run suppressing file writes, container
restarts and the post-export command

**Given** the feature is implemented
**When** `README.md`, `docker/README.md` and `config_default.yaml` are updated and unit tests
cover delivery, failure isolation and labelling, dry-run suppression, and the timeout
**Then** the epic can close

**Explicitly out of scope**, and cheap to add when a requirement names one: `pre-export` and
`cert-export` consumers, per-event configurable timeouts, a checked HTTP action, and change
detection. ADR-0013's library survey stands as the record to consult first.

## Decision record

Implements ADR-0014 (`docs/adr/0014-post-export-notifications-via-apprise.md`, **Proposed**), which
supersedes ADR-0013. Where this story and ADR-0014 disagree, the ADR is wrong until
amended rather than the story being right. Two gate reviews sit in `../arch/`.
