# Run as root unless the ACME store is proven readable by the service account

## Context

Promoted from deferred finding(s):
- BL-E013-041 (High, maintainer-review) — Traefik writes acme.json 0600 and refuses to start if group/other bits are set (pkg/provider/acme/local_store_unix.go CheckFile: mode&0o077 != 0 -> 'too open, please use 600'); Traefik runs as root by default, so acme.json is root:root 0600. ADR-0030 drops the service to abc whenever settings.restartcontainers is off, so the core function (reading the ACME store) fails with only an init WARNING, whose remedy 'relax their group permissions' is impossible under Traefik's check. Maintainer decision 2026-10-10: option A — drop privileges only when every matching ACME store file exists and is readable by the service account; otherwise run as root with a WARNING naming why and how to avoid it (run Traefik as a non-root user and set PUID/PGID to its uid/gid). Amend ADR-0030. Blocks the 0.3.0 release.

### Verified facts (2026-10-10, story prep)

- Traefik `pkg/provider/acme/local_store_unix.go` `CheckFile` rejects the store when
  `mode & 0o077 != 0` ("permissions %o for %s are too open, please use 600");
  `local_store.go` writes it `0o600`. Traefik's official image runs as root, so `acme.json`
  is normally `root:root 0600`. Relaxing group bits is therefore not a usable remedy.
- `docker/root/etc/s6-overlay/s6-rc.d/init-traefik-certificate-exporter-config/run` today:
  pre-writes `false` (drop) to `/run/traefik-certificate-exporter/run-as-root`, resolves
  settings via an embedded Python heredoc (`SettingsManager.loadFromFile`) into
  `/run/traefik-certificate-exporter/resolved-settings` (line 1 restartcontainers
  `true|false`, 2 outputPath, 3 dataPath, 4 fileSpec), sets `true` only when
  restartcontainers is on, and otherwise chowns the output path, creates the tmpfs HOME, and
  probes `"${dataPath}"/${fileSpec}` with `s6-setuidgid abc sh -c '[ -r "$1" ]'` — emitting
  only a WARNING that recommends "relax their group permissions".
- `svc-traefik-certificate-exporter/run` reads the state file with
  `cat "$PRIV_STATE" 2> /dev/null`; `true` → WARNING about restartcontainers +
  `s6-setuidgid root`; anything else (including missing) → `export HOME=…/home` +
  `s6-setuidgid abc`.
- The application enumerates the store with
  `glob.glob(os.path.join(settings.dataPath, settings.fileSpec))`
  (`src/traefik_certificate_exporter/libs/certificate_exporter.py` `exportCertificates`), so
  the "matching files" set is defined by Python `glob.glob`, non-recursive, dotfiles excluded.
- `tests/test_s6_privilege_drop.py` executes only the embedded Python; every shell property is
  asserted by grepping script text (e.g. `test_init_script_writes_the_safe_default_before_consulting_the_config`
  asserts `printf 'false\n'` precedes the resolver; `test_service_script_drops_privileges_unless_the_state_file_says_root`
  asserts a missing state file reads as drop). Those assertions encode the old policy and must
  change with it.
- ADR-0030 (`docs/adr/0030-conditional-privilege-drop.md`, Status: Proposed, 2026-10-08)
  states "The safe answer is written first … never keep root" and "A missing state file reads
  as drop" — both reversed by this decision; the amendment must say so explicitly.
- Image defaults (`docker/Dockerfile` runtime `ENV`): `SETTINGS_DATAPATH=/data`,
  `SETTINGS_OUTPUTPATH=/certs`, `SETTINGS_WATCHFORCHANGES=true`, `SETTINGS_RUNATSTART=true`.
  `just image` tags `traefik-certificate-exporter:local`. `COPY docker/root /` ships the
  whole `docker/root` tree.
- **The ADR-0030 drop never shipped** (AG-28): `git show v0.2.0:docker/root/etc/s6-overlay/s6-rc.d/svc-traefik-certificate-exporter/run`
  contains only `s6-setuidgid root`; the conditional drop arrived in commit `fb75fc6`
  (post-v0.2.0, unreleased). The 0.3.0 upgrade note is therefore written relative to v0.2.0
  (always root), not relative to the unreleased drop-by-default state. The current
  `docs/operational.md` "fallback is one-directional" paragraph (~L237) and the "Traefik's ACME
  store must be readable…exporting nothing vs working" bullet (~L249–264) describe that
  never-released state and are removed/reworded by this story.
- Observed, out of scope: the env var names in `docker/docker-compose.yml`
  (`TRAEFIK_CERTIFICATE_EXPORTER_RESTART_CONTAINERS`, `…_FILESPEC`, `…_RESOLVERID`) and
  `docker/README.md` (`…_SETTINGS_RESTARTCONTAINER`, missing the final `S`) do not match the
  `settings.restartcontainers` → `TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_RESTARTCONTAINERS`
  convention in `AGENTS.md`, so those samples do not set what they claim. Not fixed here (see
  Non-goals); should be logged as its own backlog item by the executor.

### Decisions taken during story prep (not in the maintainer text; recorded so they can be challenged)

1. **Unresolvable settings → root.** The maintainer rule is "drop ONLY when proven readable".
   If the settings cannot be resolved, `datapath`/`filespec` are unknown, so readability is
   unproven → root. This reverses ADR-0030 property 1 (fail-safe = drop). The application
   will then fail its own config load and exit (exit code 2 path), so the root process is
   short-lived.
2. **Missing state file in the service script → root,** for the same reason (nothing was
   proven) and because the dropped path is not viable without init anyway (no tmpfs HOME).
   Reverses ADR-0030 property 2.
3. **The matching set comes from the application's own `glob.glob` call,** emitted by the
   embedded resolver, not re-derived by a shell glob — same "no second parser" principle
   ADR-0030 already applies to the settings themselves.
4. **The service account must also be able to list `settings.datapath`** (`r` and `x` on the
   directory): the application globs and watches that directory, so a readable file inside an
   unlistable directory still exports nothing.
5. **The decision logic moves into a sourced shell helper** so tests can execute it; the init
   script sources it. This is the minimal structural change that makes the decision testable
   without the s6 runtime.
6. **The output path must be writable by the service account after the chown** (AG-33);
   otherwise the drop would export nothing, so it falls back to root (decision-table row 6).
7. **Unprivileged mode requires `/data` mounted `:ro`** (AG-27); a `/data` writable by the
   service account lets a compromised `abc` force root on the next start. This is documented
   as a requirement and surfaced in the log, not enforced by refusing to start.

## Acceptance Criteria

- BL-E013-041 is resolved: with a default Traefik store (`root:root 0600 acme.json`) mounted
  read-only and `settings.restartcontainers` off, the container runs the exporter as root,
  exports the certificates, and logs one WARNING explaining why.
- The service drops to the `PUID`/`PGID` account (`abc`) **only** when all of these hold:
  settings resolved; `settings.restartcontainers` is false; `settings.datapath` exists and
  is listable by `abc`; at least one file matches `settings.filespec` there; every
  matching file is readable by `abc` (`s6-setuidgid` probe); and the output path is writable
  by `abc` after the ownership walk.
- Every other case runs as root: restartcontainers on, unresolved settings, missing/unlistable
  datapath, zero matching files, any unreadable match, unwritable output path, a failed or
  invalid helper result, or a missing state file at service start.
- When `settings.datapath` or any matching file is writable by or owned by `abc`, the log
  says so in one line (appended to the root WARNING, or an INFO line when dropping) and
  points to mounting `/data` `:ro`.
- Each container start emits exactly one privilege WARNING when root is retained, naming the
  reason; for the ACME-store reasons it names the files, states that Traefik enforces `0600`
  owned by its own user, and gives the remedy (run Traefik as a non-root user and set
  `PUID`/`PGID` to that uid/gid; `restartcontainers` still forces root). No WARNING when
  privileges are dropped.
- No shipped file (scripts, README.md, docker/README.md, docs/operational.md,
  docker/docker-compose.yml comments, ADR-0030's live text) tells users to relax group
  permissions on the ACME store.
- ADR-0030 carries a dated `## Amendment (2026-10-10)` section; original text is left intact;
  the amendment enumerates every superseded passage (see Interface contracts → Docs) and its
  Consequences state that unprivileged mode is only as sound as a read-only `/data` mount.
- docs/operational.md carries a 0.3.0 upgrade note written relative to v0.2.0 (which always
  ran as root), and no longer contains passages describing the unreleased drop-by-default
  state.
- docs/operational.md and docker/README.md state that `/data` mounted `:ro` is a requirement
  for unprivileged mode.
- Automated tests execute the decision logic (not only grep it) for drop / unreadable /
  missing / restartcontainers / unresolved; a real image run proves export with a root-owned
  `0600` store.

## Business acceptance criteria

### Outcome

- An operator upgrading from v0.2.0 (which always ran the exporter as root) with a stock
  Traefik (root, `acme.json` `0600`) and `restartcontainers` off sees no functional change:
  still root, still exporting; new is one WARNING saying why it runs as root, which files
  forced it, and how to get the unprivileged mode.
- An operator upgrading from v0.2.0 whose store is already readable by `PUID`/`PGID` (Traefik
  run as that uid/gid) and `restartcontainers` off now gets the unprivileged (`abc`) service
  with no privilege WARNING — and, newly, the output path chowned to `PUID`/`PGID` on first
  start.
- An operator reading `docs/operational.md` "Container privileges" can tell, from the table
  alone, which account the service will run as for their deployment, and that the decision is
  taken once at container start.
- No documentation or log line recommends an action Traefik will refuse (relaxing `acme.json`
  permissions).

Spec: none — l3io-plan run, no spec index bound

### Non-goals

- No runtime re-check of readability. If `acme.json` ownership/permissions change after start
  (e.g. Traefik first creates the file after the exporter started, or Traefik is moved to a
  different user), the decision stands until the container is restarted; this is documented,
  not automated.
- No chown/chmod of the ACME store or `settings.datapath` — the exporter only reads it, and
  Traefik requires `0600`.
- No new setting, env var or CLI flag (no `runasroot` switch; ADR-0030 option D stays rejected).
- No change to the restartcontainers root path or the docker-socket-proxy guidance.
- No fix to the mismatched env var names in `docker/docker-compose.yml` / `docker/README.md`
  samples (separate backlog item); only the comments this story's behaviour touches change.
- No change to the file-logging limitation for the dropped account.
- No change to application Python code beyond the embedded resolver heredoc in the init script.

## Technical acceptance criteria

### Interface contracts

- **Resolved-settings file** (`/run/traefik-certificate-exporter/resolved-settings`, written
  by the embedded Python resolver): lines 1–4 unchanged (restartcontainers `true|false`,
  outputPath, dataPath, fileSpec); **new** lines 5..N: one absolute path per file returned by
  `glob.glob(os.path.join(settings.dataPath, settings.fileSpec))`, each passed through
  `os.path.abspath`, in `sorted()` order (a relative `settings.datapath` is therefore
  resolved against the resolver's cwd — the init script runs it with the same cwd the service
  uses, `/`; alternatively treat a relative datapath as row 1; pick one and test it). The
  resolver writes the file atomically (temp name in the same directory + `os.replace`), and
  the helper also treats a file with fewer than 4 lines as unresolved. A path containing
  `\n` makes the resolver write nothing (→ unresolved → root).
- **Reading the resolved file** (helper): one loop,
  `while IFS= read -r line || [ -n "$line" ]; do …; done < "$resolved"`, which both counts
  lines and collects them, so a missing trailing newline neither drops the last path nor
  miscounts; no `sed -n`/`wc -l` mix.
- **Decision helper** (new, shipped in the image): `docker/root/usr/local/lib/traefik-certificate-exporter/privilege-decision.sh`
  (bash, `# shellcheck shell=bash`, no shebang execution required; sourced). Defines one
  function:
  `tce_privilege_decision <resolved-settings-file> <service-user>`
  - stdout: exactly one line, `true` (run as root) or `false` (drop).
  - stderr: when `false`, nothing, or one `INFO:` line if the store is writable/owned by the
    service user; when `true`, exactly one `WARNING: …` line (may be long; one `echo`),
    plus at most the one writable-store line.
  - Exit status 0 in every case (a non-zero exit is a defect; the caller treats it as `true`).
  - Uses `s6-setuidgid` resolved from `PATH` (so tests can stub it) and no other external
    state than its two arguments and the filesystem.
  - Must not `set -e`/`set -u` the caller's shell or change `shopt` state on return.
- **Init script** (`init-traefik-certificate-exporter-config/run`):
  - Pre-writes `true` to `PRIV_STATE` before resolving (replacing `printf 'false\n'`).
  - Sources the helper and captures its stdout into a variable
    (`decision="$(tce_privilege_decision "$RESOLVED" "$SERVICE_USER")"`), stderr passing
    through to the s6 log. Only the exact values `true`/`false` are accepted; the value is
    written to `${PRIV_STATE}.tmp` and `mv`ed onto `PRIV_STATE`. If sourcing fails, the
    function is absent, or the value is anything else, the script writes `true` (same
    temp+`mv`) and prints `WARNING: running as root (privilege decision failed)`.
  - The `abc`-viability block (output-path chown with `find … -xdev ! -type l -exec chown -h`,
    tmpfs HOME) runs only when the decision is `false` — unchanged guards. After the chown it
    probes `s6-setuidgid "$SERVICE_USER" test -w "$outputPath"`; on failure it rewrites the
    state to `true` (temp+`mv`) and prints the row-6 WARNING (decision table). This probe may
    live in the helper as a second function (`tce_output_writable <path> <user>`) so it is
    executed by the same tests.
  - The old post-drop readability probe and its "relax their group permissions" WARNING are
    removed (the helper subsumes them).
- **Service script** (`svc-traefik-certificate-exporter/run`): reads `PRIV_STATE`; `false` →
  `export HOME="${SERVICE_HOME}"` + `exec s6-setuidgid abc …`; anything else, including a
  missing/empty file → `exec s6-setuidgid root …`. Root/abc order in the script inverts (the
  `abc` branch is now the guarded one). The service script does **not** print its own
  privilege WARNING any more (init owns it — exactly one per start, and longrun restarts do
  not repeat it); if it keeps a line, it must be INFO-level wording, not a second WARNING.
- **State paths** stay `STATE_DIR=/run/traefik-certificate-exporter`,
  `PRIV_STATE="${STATE_DIR}/run-as-root"`, `SERVICE_HOME="${STATE_DIR}/home"` in both scripts;
  the helper path is referenced from one place (init).
- **Sibling conventions observed:** each `s6-rc.d/<name>/` has `type`, `run` (and `up` for
  oneshots, pointing at `run`), `dependencies.d/`; services are registered via
  `user/contents.d/<name>`. A sourced helper is not an s6 service and must **not** get an
  `s6-rc.d` directory or a `contents.d` entry. Scripts start with
  `#!/usr/bin/with-contenv bash` + `# shellcheck shell=bash` and carry `# shellcheck disable=SCxxxx  # reason`
  inline justifications; comments explain *why* (ADR references). Keep that style.
- **Docs:** `docs/operational.md` "Container privileges: when the image keeps root, and when
  it drops" table gains rows for every root reason; ADR-0030 gets an appended
  `## Amendment (2026-10-10): drop only when the ACME store is proven readable` with
  Context / Decision / Consequences sub-paragraphs, and the ADR header gains
  `- **Amended:** 2026-10-10 (BL-E013-041, E013-S02-004)`; `docs/architecture.md` ADR index
  row 0030 title updated only if the ADR title changes (prefer not changing the title).
  The amendment includes a "Superseded passages" list naming each original passage/property
  it replaces: (1) property 1 "The safe answer is written first … never keep root"
  (fail-safe now = root); (2) property 2 "A missing state file reads as drop" (now root);
  (3) property 3 / Decision text that the service script logs the root WARNING (moves to
  init, one per start); (4) the warn-only readability probe in Decision ("probes … and
  warns") — now decides; (5) the Consequences bullet remedy "relaxes the group permission"
  — withdrawn, impossible under Traefik's `0600` check; (6) the Context claim that
  `settings.restartcontainers` is the sole input / "No new setting … is the sole input"
  — the ACME store's readability and output-path writability are now inputs. Its
  Consequences state that the default stock-Traefik deployment runs as root, and that
  unprivileged mode is only as sound as a read-only `/data` mount.

### Error and edge case handling

Decision table the helper must implement (first matching row wins):

| # | Condition | Decision | WARNING reason text must include |
|---|---|---|---|
| 1 | resolved file missing, empty, < 4 lines, or line 1 not `true`/`false` | root | could not resolve settings; cannot prove the ACME store readable |
| 2 | line 1 = `true` | root | `settings.restartcontainers` is enabled (Docker socket) + socket-proxy pointer (existing text) |
| 3 | dataPath empty, not a directory, or not listable (`-r` and `-x`) by the service user | root | the data path and that `abc` cannot list it / it does not exist |
| 4 | zero matching files (no lines 5+) | root | no file matches `<fileSpec>` under `<dataPath>` yet, so readability cannot be proven; restart the container once Traefik has written it |
| 5 | any matching file not readable by the service user | root | the unreadable file list; "Traefik enforces mode 0600 owned by the user it runs as"; remedy |
| 6 | rows 1–5 pass, but after the output-path ownership walk the service user cannot write `settings.outputpath` (`s6-setuidgid <user> test -w`) | root | `cannot write` + the output path + `PUID`/`PGID` |
| 7 | otherwise | drop (`false`) | — (no WARNING) |
| — | helper missing/failed, or stdout not exactly `true`/`false` | root | `WARNING: running as root (privilege decision failed)` |

- Writable store (AG-27), orthogonal to the rows: when `settings.datapath` or any matching
  file is writable by the service user (`s6-setuidgid <user> test -w`) or owned by its uid,
  the helper adds exactly one line — appended to the root WARNING on rows 3–6, or a single
  `INFO:` line on row 7 — saying the ACME store is writable by `<user>` and that unprivileged
  mode requires mounting `/data` read-only (`:ro`).
- File names in WARNINGs are each quoted (`'name'`), so names with spaces are unambiguous.
- Rows 3–6 WARNING wording must include: run Traefik as a non-root user and set `PUID`/`PGID`
  to that user's uid/gid; `settings.restartcontainers` still forces root. It must not contain
  "relax" or "group permission".
- File names with spaces must be handled (quote every expansion; the list comes from lines,
  not word-splitting). Names are printed as-is, space-separated.
- Symlinked store files: `[ -r ]` follows the link as the service user, which matches what the
  application's `open()` will do — acceptable, no special case.
- A store that becomes unreadable after a drop decision (Traefik recreated it, permission
  change) produces the application's existing per-file `Error processing file` errors until
  the container restarts — documented in operational.md, not handled at runtime.
- A store that first appears after a root decision (row 4) keeps root until restart — benign
  for function; documented.
- `s6-setuidgid` itself failing (e.g. unknown user) counts as "not readable" → root.
- The init oneshot must not exit non-zero for any row (s6 would otherwise block the
  service); the existing script has no `set -e` and that stays true.
- Re-run safety: the state and resolved files are rewritten every boot (`rm -f "${RESOLVED}"`
  before resolving stays), so a previous boot's answer is never reused.

- One `WARNING:`-prefixed line on the container's stdout/stderr (s6 → `docker logs`) per start
  when root is retained, containing the reason from the decision table. Grep-stable anchors
  the tests assert: `WARNING: running as root`, the reason keyword (`restartcontainers`,

- When privileges are dropped, no WARNING; the init may print one non-WARNING line stating

  `writable by`, `:ro`) — appended to the WARNING, or `INFO:` when dropping.

  exporter's per-pass `correlation_id` scope (operational.md "Tracing one export pass").

### Security considerations

- Relative to the unreleased ADR-0030 drop, this story **widens** where root survives: the
  default stock-Traefik deployment runs the exporter as root, keeping the
  RT-001/RT-003/RT-004/RT-009 surface (attacker-influenceable store parsed as root,
  `settings.postexportcommand` run as root, `/certs` written as root) that ADR-0030 aimed to
  narrow. Relative to the released v0.2.0 (always root) it narrows nothing for stock Traefik
  and narrows it for stores readable by `PUID`/`PGID`. This is the maintainer's accepted
  trade-off; the ADR amendment states it in Consequences and the WARNING gives the path to
  unprivileged mode.
- **Forcing root through a writable `/data` (AG-27).** The state and resolved-settings files
  are root-only tmpfs, so an unprivileged process cannot flip them directly. But the
  recommended unprivileged route (`PUID`/`PGID` = Traefik's uid) means `abc` may own the
  store files and, if `/data` is mounted read-write, a compromised `abc` can chmod, delete or
  plant an unreadable `*.json` there and the next container start retains root (rows 3–5).
  Mitigation required by this story: (1) ADR-0030 amendment Consequences state that
  unprivileged mode is only as sound as a read-only `/data` mount; (2) docs/operational.md
  and docker/README.md state `/data:ro` as a requirement for unprivileged mode; (3) the
  helper logs the writable/owned-store line (Error and edge case handling). The container
  does not refuse to start on a writable `/data` (not in the maintainer decision).
- The probe runs as the service user via `s6-setuidgid` — never `[ -r ]` as root (root reads
  everything and would always "prove" readability).
- The helper must not chown/chmod anything; the existing output-path ownership walk keeps its
  symlink-safe form (`find … -xdev ! -type l -exec chown -h`, no `chown -R`, no `lsiown`) and
  runs only on the drop path.
- Paths from the resolved file are data: always quoted, never `eval`ed, never used as a glob.
- `/config` stays root-owned (unchanged).
- The state directory is root-owned tmpfs inside the container; flipping the missing-file
  default to root gives an unprivileged actor no lever over the state file itself (only root
  can delete it) — the lever is the store, covered above.

Spec: none — l3io-plan run, no spec index bound

### Testability approach

All tests live in `tests/test_s6_privilege_drop.py` (pytest, module-level test functions,
`snake_case` names phrased as the property, `tmp_path` fixtures, `subprocess.run(…, check=False,
capture_output=True, text=True)`, constants `INIT_SCRIPT`/`SVC_SCRIPT`/`S6_ROOT` at top —
match these; add `HELPER = PROJECT_ROOT / "docker" / "root" / "usr" / "local" / "lib" /
"traefik-certificate-exporter" / "privilege-decision.sh"`). Update the module docstring: the
decision is now executed, not only grepped.

**Executed decision tests (new, required):** run
`bash -c 'source "$HELPER"; tce_privilege_decision "$RESOLVED" abc'` with a `tmp_path` tree:
a `datapath` dir, store files, a hand-written resolved-settings file, and a stub
`s6-setuidgid` first on `PATH`. The stub must be deterministic **regardless of the test
runner's uid** (CI may run as root, where real permission bits prove nothing): it takes
`<user> <command…>` and decides from fixture-controlled denylist files (e.g.
`$TCE_TEST_UNREADABLE`, `$TCE_TEST_UNWRITABLE`, `$TCE_TEST_WRITABLE`, one path per line).
The stub also **checks the probe itself** and exits 99 (failing the test via a recorded
`$TCE_TEST_STUB_LOG`) unless: its first argument equals the service user passed to the
helper (`abc`); file probes use `-r`; directory probes use both `-r` and `-x`; output-path
probes use `-w`. Every invocation is appended to the stub log and the tests assert on it
(one probe per matched file; user always `abc`). Assert stdout and stderr for:
- readable: all matches readable, dir listable, restartcontainers false → `false`, empty stderr;
- unreadable: one of two matches denied → `true`, stderr names that file (and not the other),
  contains `PUID/PGID`, `0600`, and does not contain `relax`/`group permission`;
- missing: datapath exists, no lines 5+ → `true`, stderr `no file matches`;
- datapath absent / denied → `true`;
- restartcontainers true (with all-readable files) → `true`, stderr names `restartcontainers`;
- unresolved: resolved file missing; and a 2-line file → `true`;
- file name with a space → correctly reported and probed (one probe per file, not per word);
- `s6-setuidgid` stub exits non-zero for an unknown user → `true`;
- resolved file with no trailing newline → last path still probed; relative datapath →
  whichever behaviour the Interface contract picked;
- output path unwritable (row 6) → `true`, stderr `cannot write`;
- writable/owned store with otherwise-drop inputs → `false` plus one `INFO:` line containing
  `:ro`; with a root row → the extra line is part of the WARNING output (one WARNING total);
- **real permissions**: one case with a pass-through stub (`shift; exec "$@"`) and a store
  file `chmod 000` → `true`; marked

### Implementation notes

- Implemented directly by the story agent (no separate dev subagent): the scope is four
  scripts, one test module and three docs, and the real-image check had to run in the same
  session as the code it verifies.
- New helper `docker/root/usr/local/lib/traefik-certificate-exporter/privilege-decision.sh`
  defines `tce_privilege_decision <resolved> <user>` (rows 1–5, 7) and
  `tce_output_writable <path> <user>` (row 6). Init sources it, pre-writes `true`, accepts only
  `true`/`false` (temp + `mv`), and falls back to `WARNING: running as root (privilege
  decision failed)`. Service script: only an explicit `false` drops; no WARNING of its own.
- **Interface choice — relative `settings.datapath` (and, after review, a relative
  `settings.outputpath`):** treated as row 1 (`could not resolve settings`), checked after
  row 2 so `restartcontainers` is still named when it is on. Reason: the service runs with s6's service directory as cwd, not `/`, so a
  relative path cannot be probed as the application will resolve it.
- **Writable-store detection:** `s6-setuidgid abc test -w`, or `test -O` (owned) **only when
  the path is writable by root** — i.e. not on a read-only mount — so an `abc`-owned store
  mounted `:ro` correctly produces no `:ro` advice (verified in scenario 2 below).
- **Deviation (row 6 + writable store):** row 6 is decided by init after the chown, after
  `tce_privilege_decision` has already returned `false`; if the store is also writable by
  `abc`, the store line has already been printed as `INFO:` rather than appended to the row-6
  WARNING. The WARNING count stays exactly one. Accepted as a cosmetic deviation.
- Init's embedded resolver now writes lines 5..N from the application's own
  `glob.glob(os.path.join(dataPath, fileSpec))`, `abspath` + `sorted`, atomically
  (`mkstemp` in the same dir + `os.replace`); a newline in any line writes nothing.
