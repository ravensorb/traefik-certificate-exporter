## Findings

### R-01: The "tag pushed before main" recovery fails under squash and rebase merges
- Severity: medium
- Kind: docs-accuracy
- Location: `docs/ci/pipeline-walkthrough.md:180-183`, `docs/adr/0038-release-only-from-protected-tags-on-main.md:83-84`
- Description: The docs say "Push `main` (through a PR), then re-run the release workflow; the re-run checks out fresh and passes." That holds only if the tagged commit itself lands on `main`, which means a merge commit or a fast-forward. This repository allows squash and rebase merges (`gh api repos/ravensorb/traefik-certificate-exporter` reports `allow_squash_merge: true` and `allow_rebase_merge: true`), and S02-002 makes PRs the only route to `main`. A squash or rebase merge writes new SHAs, so the tagged commit never becomes an ancestor of `origin/main`. The re-run fails again and the tag stays stranded. Deleting it needs bypass rights, which the docs do not say. An operator who follows the documented recovery gets a second failure and no next step.
- Suggested fix: Say that the re-run passes only if the PR is merged with a merge commit (or fast-forwarded) so that the tagged commit is on `main`. Otherwise the maintainer deletes the unreleased tag (as a bypass actor or allowed user, which is allowed because nothing was published) and re-tags the merged commit with `just release`. Make the same correction in the ADR Consequences.

### R-03: Raw `{{ default_branch }}` interpolation lets a branch name inject shell into `just release` and `just act`
- Severity: low
- Kind: deletion (security regression; confidence high)
- Location: `justfile:58`, `justfile:74`
- Description: The deleted inline derivation kept the branch name in a shell variable, so it was never parsed as code. The replacement pastes the value into the recipe text inside double quotes. Git ref names may contain `$(`, `` ` `` and `"`. Reproduced in a throwaway repository: with `refs/remotes/origin/HEAD` pointing at a branch named `a$(id)`, a recipe line `default="{{ db }}"` executed `id`, while `{{ quote(db) }}` printed `a$(id)` literally. Exploiting this requires control of the remote's default-branch name, so the practical risk is low. It is still a lost property of the deleted code.
- Suggested fix: Use just's built-in `quote()`: `default={{ quote(default_branch) }}` and `--defaultbranch {{ quote(default_branch) }}`. The alternative is to `export` the variable and read `"$DEFAULT_BRANCH"`.

### R-04: The GitHub bypass instruction names an actor that cannot be selected
- Severity: low
- Kind: docs-accuracy
- Location: `docs/ci/pipeline-walkthrough.md:244`, `docs/adr/0038-release-only-from-protected-tags-on-main.md:40-41`
- Description: "Bypass list: the maintainer or the Repository admin role only." The ruleset `bypass_actors[].actor_type` values are `Integration`, `OrganizationAdmin`, `RepositoryRole`, `Team` and `DeployKey`. There is no individual-user actor. The repository is user-owned (`owner.type: User`), so the only fitting choice is the `Repository admin` role. "The maintainer" can also be misread as GitHub's `Maintain` role, which would hand bypass to maintain-role holders. Confidence is moderate: the enum comes from GitHub's REST schema and was not re-fetched live during this review.
- Suggested fix: State "Bypass list: the Repository admin role only (on this user-owned repository that is the owner); do not add Maintain or Write". The expected `bypass_actors` output is a single `RepositoryRole` entry for admin (`actor_id` 5).
