### Error and edge case handling

- **Guard, no secrets** (fork, act, `just act dev.yaml`): `PUBLISH_IMAGE` is `false`, so the guard is skipped like every other non-login step. The job succeeds having pushed nothing (AD-10).
- **Guard, partial configuration:** with a token set and its image variable empty, the run fails after the CA import and before any `docker/login-action` or push. Nothing is published, so re-running after setting the variable is safe and needs no cleanup.
- **Guard in `release.yaml`:**
  - A guard failure fails `publish-image`. The `release` job `needs` it, so the forge release is not created: a half-configured release halts loudly instead of shipping without that registry.
  - `publish-package` may already have uploaded. `--skip-existing` makes the re-run safe (AD-11).
  - The walkthrough records this.
- **Guard, Gitea registry empty:** without the guard, `docker/login-action` with an empty `registry` defaults to Docker Hub and sends the Gitea credentials there. The guard fails first.
- **Guard, all three registries enabled and all image variables empty:** the guard reports all three in one run; it does not stop at the first.
- **`Install twine` without the bypass:** the job's full-history, tagged checkout lets the plugin resolve the version. Under `release.yaml` the version is the tag; under `dev.yaml` it is a `.devN`. The value is irrelevant to the install, and the uploaded version is the dist wheel's (AD-2).
  - If either step then fails with "No tags available", stop. The checkout precondition is broken, so record it as a defect; do not restore the bypass.
  - Evidence of a passing run (act or forge) goes in the closure notes.
- **Tagless or shallow clone (BL-E013-003):** `just install` and the `poetry-lock` hook fail with poetry-dynamic-versioning's "No tags available and fallbacks disabled by strict mode". The documented recovery is `git fetch --tags --unshallow`.
- **Dockerfile `poetry config` line:** whichever way the classification comes out, the evidence is recorded. If it fails or is unverifiable, it is filed as backlog with the evidence attached.
- **Dependabot:**
  - The evidence is one of: a `pip`-ecosystem Dependabot PR or job log dated after strict landed, or a Dependabot update-job error.
  - If it shows failure, or none can be obtained, say so in the closure notes and file an item: Medium if failing, Low if unverifiable.
- **gitleaks exempt set drift:**
  - If the fresh trace's `skipping … global allowlist` set differs from the recorded set, the record must be updated in the same change (ADR-0037 §3), never silently.
  - A new exemption that covers repository-authored content is raised as a finding, not just recorded.
- **gitleaks over-scan finding:** for a finding in an ignored install or cache tree outside the inherited set:
  1. Confirm it is third-party content.
  2. If it is a stale local artefact, delete the local tree and reinstall.
  3. Otherwise add a value or whole-line allowlist under the existing `.gitleaks.toml` rule. Re-check it in both `dir` and `git` modes. Never add a `paths` entry.
- **`tests/support.py` deletion:** delete it only if `git grep` comes back empty. If a referrer exists at implementation time, close the item by correcting the module docstring and recording the referrer.
- **Spine edit:** the AD-16 heading text stays as is, so existing `#ad-16--the-justfile-is-the-local-interface` links still resolve.

### Security considerations

- **Guard inputs:**
  - Flags, image names and `vars.PUBLISH_GITEA_REGISTRY` are passed through step `env:` and expanded as shell variables. Nothing goes in `${{ }}` inside `run:` (zizmor template-injection).
  - The guard uses no secret value. The flags are booleans already computed in job `env`.
- **Guard placement:** after the CA import (AD-18) and before every login, so no registry credential reaches any step for a half-configured run.
- **Credential misdirection:** the guard closes a path where an empty `PUBLISH_GITEA_REGISTRY` makes `docker/login-action` send `PUBLISH_GITEA_TOKEN` to Docker Hub.
- **Bypass:** removing it from `Install twine` leaves exactly one bypass site, the AD-17 builder (ADR-0036). That shrinks the places where a wrong version could be silently accepted.
- **Permissions and naming:** `permissions: contents: read` with no new permission (AD-13). No secret or variable name starts with `GITEA_` or `GITHUB_` (AD-9).
- **gitleaks:**
  - No repository path exemption is added (ADR-0033 as amended by ADR-0037).
  - The inherited default exemptions are written down rather than assumed, and drift is caught by the trace diff.
  - Accepted residual risk (ADR-0037 Consequences): a credential placed in `poetry.lock` or `.gitleaks.toml` is not reported. The docs state this.
- **BL-E013-016:** directing operators to project-scoped PyPI and TestPyPI tokens, and flagging that the Docker Hub token is account-wide, shrinks the blast radius of stored credentials. ADR-0035 widened it by moving PyPI off OIDC.
- **Docs claims:** every new claim about enforcement says whether it is mechanically enforced (global rule 3). The exempt-set record is checked by the story's verification diff and on upgrade by review. It is not a standing CI check, and the docs say so.
