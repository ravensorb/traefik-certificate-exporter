# Versioning and local tooling

## Context

First story of E013 (ADR-0035). Establishes the version identity and the local interface that every later story builds on: git tags are the only version source (AD-7), every gate is one pre-commit hook list shared by `just check` and CI (AD-3), actions are pinned per zizmor policy (AD-5), and the justfile is the local interface (AD-16).

Design authority: `_bmad-output/planning-artifacts/architecture/architecture-ci-cd-pipeline-2026-10-08/ARCHITECTURE-SPINE.md` (AD-1..AD-18), `docs/adr/0035-standard-ci-cd-pipeline.md`, `docs/ci/pipeline-walkthrough.md`. Rules are cited by AD id; do not re-decide them.

## Acceptance Criteria

- `pyproject.toml` carries `version = "0.0.0"`, `poetry-dynamic-versioning` declared under `[tool.poetry.requires-plugins]`, its build backend, and exactly the AD-7 configuration (pep440, bump, metadata=false, strict, pattern `^v(?P<base>\d+\.\d+\.\d+)$`).
- `poetry build` on a commit N commits after `vX.Y.Z` produces `X.Y.(Z+1).devN`; on the tagged commit it produces `X.Y.Z`; floating tags such as `v0` are ignored.
- `scriv` is removed from the dev dependencies and the lock file is refreshed.
- `.pre-commit-config.yaml` includes ruff, mypy (scoped to `^src/`), gitleaks (tree) plus a second gitleaks hook aliased `gitleaks-history` (history, AD-3 as amended by ADR-0036), actionlint and zizmor (official hook), plus the existing hygiene hooks.
- `.github/zizmor.yml` sets `rules.unpinned-uses.config.policies` to `LiquidLogicLabs/*: ref-pin` and `*: hash-pin`, and disables no audit (AD-5 as amended by ADR-0036).
- `.github/dependabot.yml` keeps `github-actions`, `pip` and `docker` updates, drops the artifact major-version ignores, and sets a `cooldown` on each entry (ADR-0036).
- `.gitignore` ignores `.poetry/`, and `git status --porcelain` is empty after `poetry install && just check` on a clean checkout.
- The justfile provides `install`, `check`, `build`, `image`, `act [workflow]` and `release <major|minor|patch>` exactly as AD-16 and AD-15 specify; `just act` always passes `--detect-event`; `just release` creates and pushes only an annotated tag and creates no commit.
- `poetry run pre-commit run --all-files` passes except for zizmor findings confined to files E013-S01-002 deletes, and `poetry run pytest --ignore=tests/ci` passes. (`just check` itself is an AC of E013-S01-002.)
- E013-S01-001 and E013-S01-002 land as one change, on the same branch. This story is not closed before E013-S01-002.

## Business acceptance criteria

### Outcome

The maintainer has a single, tag-derived version identity and one local entry point. After this story:
- `poetry build` stamps every package with a version derived only from git tags (AD-7), with no hand-edited version in `pyproject.toml`.
- `just check` runs exactly the hook list CI will run (AD-3), including zizmor's pin policy (AD-5).
- A release is cut with `just release <major|minor|patch>`, which pushes one annotated tag and creates no commit (AD-15, AD-16).

A reviewer can confirm this by running `poetry build` on and off a tag, `just check`, and `just --list`.

Spec: none — l3io-plan run, no spec index bound

### Non-goals

- No workflow file is added or changed. The PEP 440 to SemVer `image-version` transform is **not** here; AD-7 makes the `build.yaml` version step (E013-S01-002) the only place the version is transformed.
- `tests/ci/`, the old workflows, the composite actions, `docker-bake.hcl` and the Dockerfile are not touched (E013-S01-002).
- `scripts/release_version.py`, `scripts/committed_versions.py`, `scripts/vendored_trees.py`, `vendored-trees.lock`, `docker/act-build.sh`, `src/publication_contract/` and its `pyproject.toml` entries are not deleted here (E013-S01-003). This story only stops the justfile and pre-commit config from calling them.
- No docs, README or ADR status changes (E013-S01-003).
- No tag is created or pushed. Existing tags, including the floating `v0`, `v0.1` and `v0.2` and the malformed `v0.0.10.0`, `v0.0.9.2`, `v0.1.0.0` and `v0.1.2.0`, are left alone.

**`justfile` (AD-16)**
- Keep `set shell := ["bash", "-euo", "pipefail", "-c"]` and a `#` doc comment above each recipe, which is the sibling convention.
- The recipe set is exactly `install`, `check`, `build`, `image`, `act` and `release`. Remove `lint`, `fix`, `test`, `test-local`, `release-dry-run` and `release-resume`.
- `install`: `poetry install`.
- `check`: `poetry run pre-commit run --all-files`, then `poetry run pytest`. Nothing else, so it adds no check that `build.yaml` lacks.
- `build`: `rm -rf dist`, then `poetry build`. No `check` dependency and no `twine check`: AD-16 says "clean dist/, then poetry build".
- `image`: depends on `build`. It requires exactly one `dist/*.whl` and runs `docker build -f docker/Dockerfile --load` (or `docker buildx build --load`) with context `.` and the five AD-17 build args:
  - `POETRY_VERSION=2.4.2`
  - `WHEEL_PATH=<the wheel>`
  - `WHEEL_SHA256=$(sha256sum ...)`
  - `VERSION=<the wheel's Version>`
  - `REVISION=$(git rev-parse HEAD)`

  Tag the result with a local name such as `traefik-certificate-exporter:local`. Do not use `docker buildx bake`.

  `VERSION` is the wheel's PEP 440 version, not a locally computed SemVer spelling (AD-17 as amended by ADR-0036). AD-7 makes `build.yaml` the only place the version is transformed, so this recipe must not recompute it. E013-S01-002 makes the Dockerfile's `VERSION` check compare under PEP 440 normalisation, so both spellings are accepted. Until that lands, the current exact-match check accepts the PEP 440 value.
- `act workflow="ci.yaml"`: `act --detect-event -W .github/workflows/{{ workflow }} --artifact-server-path "$(mktemp -d)"`.
  - It passes no `--secret`, `--secret-file` or `--var` arguments.
  - Its exit status is act's own exit status: no `|| true`, no wrapper. This is the replacement for the BL-E011-004 wrapper defect.
  - `--detect-event` is mandatory (AD-16 as amended by ADR-0036). It makes act use the workflow's own trigger (`pull_request` for `ci.yaml`). Without it act sends `push`, `ci.yaml` has no matching job, and act exits 0 having run nothing. It is an event selector, not a version option.
  - `just act dev.yaml` is run from `main`, or with an event file (`-e`) that sets `ref: refs/heads/main`, so the run matches `dev.yaml`'s branch filter.
- `release bump` (AD-15, AD-16), in this order, aborting on the first failure. Every step is a `just`/shell recipe line, not a script file (AD-16):
  1. Validate `bump` ∈ {`major`, `minor`, `patch`}.
  2. Require a clean tree (`git status --porcelain` empty).
  3. Require the current branch to be the default branch, resolved from `git symbolic-ref refs/remotes/origin/HEAD`, falling back to `main`.
  4. `git fetch --tags --force origin`, then require `git rev-parse HEAD` == `git rev-parse origin/<default>`. `--force` makes a tag moved on the remote replace the local copy instead of failing the fetch.
  5. Run `just check`, then re-require a clean tree, because ruff's `--fix` could have rewritten files.
  6. Find the base tag. It is the highest tag reachable from HEAD that matches `^v[0-9]+\.[0-9]+\.[0-9]+$`. That excludes `v0`, `v0.2` and `v0.1.0.0`; today it resolves to `v0.2.0`.
     - Under the recipe's `pipefail`, `grep | head -1` can abort the recipe: `head` closes the pipe early, `grep` dies of SIGPIPE, and `grep` also exits 1 when nothing matches. So use a filter that reads all its input and always exits 0, for example `base=$(git tag --merged HEAD --sort=-v:refname | awk '/^v[0-9]+\.[0-9]+\.[0-9]+$/ && !f {print; f=1}')`.
     - Then test the empty case explicitly: `[ -n "$base" ]`, or fail with the message described under edge cases.
  7. Compute the next version as `next=$(poetry run pysemver bump {{ bump }} "${base#v}")`.
  8. Refuse if `v$next` already exists locally or on the remote (`git ls-remote --tags origin "refs/tags/v$next"`).
  9. Run `git tag -a "v$next" -m "v$next"`.
  10. Run `git push origin "refs/tags/v$next"`. It pushes only the tag, never a branch, and makes no commit.

Spec: none — l3io-plan run, no spec index bound

### Error and edge case handling

- **Floating and malformed tags.** `v0`, `v0.1`, `v0.2`, `v0.0.10.0`, `v0.0.9.2`, `v0.1.0.0` and `v0.1.2.0` exist in the repo. Neither the `pattern` (AD-7) nor the `just release` filter matches any of them. Check the AD-7 example on the current tree with `poetry build` at HEAD: N commits after `v0.2.0` gives `0.2.1.devN`.
- **`strict = true` with no matching tag reachable** (a shallow clone, or a fork without tags). `poetry build` fails rather than emitting `0.0.0`. That is intended. `build.yaml` prevents it with `fetch-depth: 0` and `fetch-tags: true` (E013-S01-002).
- **No base tag found by `just release`.** The empty match is handled by the explicit `[ -n "$base" ]` test, not by a pipeline exit status. Fail with a message naming the expected pattern. Do not default to `0.0.0`.
- **Tag already exists, remotely or locally.** Fail before tagging, so `git tag` never errors halfway.
- **Push failure after the local tag is created.** The recipe prints the exact `git push origin refs/tags/vX.Y.Z` to retry and the `git tag -d vX.Y.Z` to abandon. There is no automatic rollback, and no commit exists to roll back.
- **`HEAD` behind or ahead of `origin/<default>`.** Fail and name both SHAs (AD-15). Pushing a branch and a tag together is unsupported, by design.
- **`just check` mutating the tree** (ruff `--fix`). Caught by the clean-tree re-check in step 5.
- **Plugin installation.**
  - Poetry 2 installs `requires-plugins` into the project's plugin environment on first use, which needs network access on first `poetry install`. Document this in the recipe comment for `install`.
  - That plugin environment is the project-local `.poetry/` directory. Add `.poetry/` to `.gitignore`, with a one-line comment naming `requires-plugins`. Otherwise `just release`'s clean-tree check always fails after `poetry install`, and the gitleaks tree hook scans the installed plugin.
  - The Dockerfile's builder runs `poetry install --only main --no-root --no-directory` over this `pyproject.toml` with no `.git`, so `strict = true` would fail there. E013-S01-002 owns the fix: that step runs with `POETRY_DYNAMIC_VERSIONING_BYPASS=0.0.0` (ADR-0036). It is not changed here.
- **mypy now scoped to all of `^src/`.** Any new error surfaced in `traefik_certificate_exporter` is fixed in code or covered by the existing `[[tool.mypy.overrides]]`. Do not narrow the hook's scope.
- **Sequencing with E013-S01-002.** `tests/ci/` still exists and asserts the old pre-commit, justfile and dependabot shapes, and zizmor may report findings in the five legacy workflows. S01-001 and S01-002 land as one change on one branch, and S01-001 is not closed before S01-002. `just check` passing is S01-002's AC, confirmed once S01-002 has removed `tests/ci/` and the legacy workflows.
  - Within S01-001 alone, verify with `poetry run pre-commit run --all-files` (record any zizmor findings that point only at files S01-002 deletes) and `poetry run pytest --ignore=tests/ci`.
  - `tests/test_release_version.py` still imports `scripts/release_version.py`. It must keep passing until S01-003 deletes both.

### Observability requirements

- `just release` echoes these values before tagging:
  - base tag
  - bump type
  - computed `vX.Y.Z`
  - `HEAD` SHA
  - `origin/<default>` SHA

  It echoes the pushed tag ref after pushing. Each refusal names the failed precondition and the observed values.
- `just act` leaves act's own job log on stdout and its exit status unmodified.
- No structured logging or correlation ID applies, since these are local developer commands. The tag SHA is the identifier that later correlates the release run.

### Security considerations

- `just act` passes no secret or variable arguments, so every destination stays disabled locally (AD-9, AD-16).
- `just release` uses the developer's own git credentials for one tag push. It writes no token to disk and pushes no branch.
- zizmor's `unpinned-uses` policy is the supply-chain gate (AD-5):
  - `LiquidLogicLabs/*` may use a major tag;
  - everything else must be a full commit SHA.

  It replaces the hand-rolled SHA-pin tests in `tests/ci/`.
- The gitleaks hooks keep scanning every path, including vendored trees (ADR-0033, carried forward): `gitleaks` reads the tree and `gitleaks-history` reads every commit (AD-3 as amended by ADR-0036).
- `.github/zizmor.yml` must not disable any zizmor audit. It only configures `unpinned-uses` policies. Accepted findings are suppressed per line, never per audit (ADR-0036).

### Testability approach

This story uses no new test code (AD-4). `tests/` keeps product tests only. Verification is by command:
1. `poetry check --lock` passes.
2. Version on and off a tag, checked in a scratch clone:
   - `poetry build` at HEAD produces `dist/traefik_certificate_exporter-0.2.1.devN-*.whl`, where N = `git rev-list --count v0.2.0..HEAD`.
   - After a local-only `git tag v0.2.1` (never pushed), it produces `0.2.1`.
   - With only `git tag v9` added, it still produces `0.2.1.devN`.
3. `poetry run pre-commit run --all-files` runs ruff, mypy, gitleaks, gitleaks-history, actionlint, zizmor and the hygiene hooks. It passes except for zizmor findings confined to files E013-S01-002 deletes; record each such finding with its file.
   - The hook list is confirmed with `pre-commit run --all-files --verbose`.
   - Prove the history hook reads history: in a scratch clone, commit a live-format test token, remove it in a second commit, and see `pre-commit run gitleaks-history --all-files` fail while `gitleaks` (tree) passes. Discard the clone.
   - Prove the zizmor policy bites: add a scratch-branch `uses: actions/checkout@v7` and see it rejected. Then use `LiquidLogicLabs/git-action-docker-test@v2` and see it accepted. Revert both.
4. `poetry run pytest --ignore=tests/ci` passes.
5. `just --list` shows exactly the six recipes, and `just --show act` contains `--detect-event`.
6. `just release patch` is exercised in a throwaway clone whose `origin` is a local bare repo. The run is accepted when all of the following hold:
   - it creates `v0.2.1`;
   - `git log` shows no new commit;
   - the bare repo has the tag and no branch update;
   - a re-run refuses because the tag exists;
   - a run with a dirty tree refuses;
   - a run with HEAD ahead of origin refuses.
7. On a clean checkout, `poetry install && just check` (on the combined S01-001+S01-002 tree) leaves `git status --porcelain` empty.
8. `just check` is confirmed green on the combined S01-001+S01-002 tree, as part of closing E013-S01-002.

### Existing-library check

- Version derivation: `poetry-dynamic-versioning` 1.10.0, which wraps `dunamai`. Do not script it, and pass no version flags on any command line (AD-7).

- Pin policy: zizmor's `unpinned-uses` audit (AD-5), replacing the regex tests (closes the reasoning behind BL-E012-001).
- Pin currency: Dependabot `github-actions` (BL-E012-002).
- Hooks: official repos only (`pre-commit-hooks`, `ruff-pre-commit`, `gitleaks`, `actionlint`, `mirrors-mypy`, `zizmor-pre-commit`).
- The only shell logic is `just release`'s precondition checks and its tag/push, which AD-16 requires to live in the justfile.
