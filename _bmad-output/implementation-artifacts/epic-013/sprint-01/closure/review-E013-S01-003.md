## Findings

### M-1 — MEDIUM — kind: claim — "Re-run the failed jobs … safe by design" omits the superseded-run case, which moves mutable tags backwards

- **Location:** `docs/operational.md` § CI recovery runbook, first entry. Also
  `docs/ci/ref-free-checkout-walkthrough.md` dated update: "AD-14's … concurrency is the sole
  protection against a superseded dev run moving `dev`".
- **Description:** a re-run re-points **every** tag that run writes (spine Conventions):
  - `dev` and `sha-*` for `dev.yaml`;
  - `latest`, `X` and `X.Y` for `release.yaml`.

  AD-14's concurrency only cancels or queues runs that are *in progress*. Two cases are therefore
  unprotected:
  - **dev:** an operator re-runs the failed or cancelled jobs of an older dev run after a newer one
    finished. `dev` moves back to the older commit.
  - **release:** an operator re-runs v1.2.4's failed `publish-image` after v1.2.5 shipped. `latest`,
    `1` and `1.2` move back to 1.2.4.

  The runbook tells the operator to do exactly this, unconditionally, and calls it "safe by design".
  The BL-E012-009 note describes the protection without this limit. Global rule 3: prose must not
  overstate coverage.
- **Suggested fix:**
  - Add a condition to the runbook entry: re-run failed jobs only on the **latest** run of that
    workflow. If a newer `dev.yaml` run, or a newer release, has completed, do not re-run the older
    one. Push again or cut a new release instead.
  - Add one sentence to the BL-E012-009 note stating that a manual re-run of a superseded run is
    not covered.

### M-2 — MEDIUM — kind: deletion (confidence: high) — The warning that publish variables are an unreviewed publication-authority surface was dropped

- **Location:** `docs/operational.md`. The removed "`DOCKERHUB_ORG`" subsection said: "Changing this
  variable is a publication-authority change, and it is not a code review … anyone who can set
  repository variables redirects every stable image push…".
- **Description:** the new pipeline has more of these variables, and they steer credentialed calls:
  - `PUBLISH_GITEA_PYPI_URL` is the `twine --repository-url` that receives `PUBLISH_GITEA_TOKEN`;
  - `PUBLISH_GITEA_REGISTRY` is the `docker/login-action` registry for the same token;
  - `PUBLISH_*_IMAGE` sets the push targets.

  Anyone who can edit repository or organisation variables can send a live token to a host they
  control, with no diff and no CODEOWNERS review. CODEOWNERS covers files only. The equivalent warning
  was deleted, and nothing in `operational.md`, `pipeline-walkthrough.md` or `gitea-runners.md`
  replaces it. The story's Security considerations did not ask for it to be kept, but the contract it
  carried applies more strongly to the new design.
- **Suggested fix:** add a short paragraph to "Publishing" or "If a publication credential is
  compromised". It should say:
  - `PUBLISH_*` **variables** are part of the publication authority, especially the URL, registry and
    image values;
  - who can set them is a forge-permission decision outside CODEOWNERS;
  - a change to one should be treated like a workflow edit and checked on the next run.

### M-3 — MEDIUM — kind: claim — ADR-0033's amendment says the no-path rule is enforced by the gitleaks hooks

- **Location:** `docs/adr/0033-secret-scanning-exempts-no-path.md`, `## Amendment (2026-10-09) — ADR-0035`.
  It reads: "The rule that secret scanning exempts no path is carried forward, enforced by the
  `gitleaks` and `gitleaks-history` pre-commit hooks and by CODEOWNERS review of `.gitleaks.toml`."
- **Description:**
  - The hooks scan with whatever config they are given. A `paths` allowlist added to `.gitleaks.toml`
    is honoured silently, so the hooks do not enforce "exempts no path".
  - `.gitleaks.toml` itself, rewritten by this story, says "ENFORCED BY: CODEOWNERS review of this
    file only. No mechanical check refuses a `paths` key any more". The story AC also requires that
    to be said plainly. The two records contradict each other.
  - The amendment lists only the probe and the untracked-file-gate parts as superseded. The ADR body
    still names `test_the_secret_scanner_exempts_no_path_from_content_scanning` as the enforcement in
    "So the rule is enforced in two places". The amendment does not say that test is gone, so a reader
    of the ADR sees a live mechanical guard that no longer exists.
- **Suggested fix:** reword the amendment to match `.gitleaks.toml`. The hooks scan the tree and the
  history. The no-`paths` rule and allowlist narrowness are held by CODEOWNERS review only. The test
  that refused `paths`, and the CI probe, were both retired.

### L-1 — LOW — kind: claim — CONTRIBUTING says "a green `just check` is a green PR"

- **Location:** `CONTRIBUTING.md`, "Before opening a pull request". The same idea appears in
  `AGENTS.md` ("CI's `build.yaml` runs exactly the same thing").
- **Description:** `build.yaml` runs pre-commit and `pytest`, which is the same gate as `just check`.
  It then also builds the wheel and sdist, builds and smoke-tests the image, and runs on Python 3.14.
  A packaging or Dockerfile break passes `just check` and fails `build / build`. The inference is
  false.
- **Suggested fix:** "`just check` runs the same gates as the PR check. The PR check also builds the
  distributions and the image; run `just image` to cover that locally."

### L-6 — LOW — kind: deletion (confidence: medium) — Credential blast-radius guidance was dropped

- **Location:** `docs/operational.md`, the removed blast-radius table under "If a publication
  credential is compromised".
- **Description:** the old table said that `DOCKERHUB_TOKEN` is **account-scoped**: it reaches every
  repository the account can write, not only this one. The rewrite keeps the rotation steps and drops
  that guidance. Under ADR-0035, PyPI moves from OIDC (no stored credential) to a stored
  `PUBLISH_PYPI_TOKEN`, so more can leak than before. No doc now says to scope `PUBLISH_PYPI_TOKEN` to
  the project, or that a Docker Hub token is account-wide.
- **Suggested fix:** add two lines:
  - create `PUBLISH_PYPI_TOKEN` and `PUBLISH_TESTPYPI_TOKEN` as project-scoped tokens;
  - `PUBLISH_DOCKERHUB_TOKEN` is account-scoped, so a leak reaches every repository that account can
    push to.
