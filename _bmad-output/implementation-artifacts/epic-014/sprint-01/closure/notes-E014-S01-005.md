## What changed

- `docker/root/etc/s6-overlay/s6-rc.d/init-traefik-certificate-exporter-config/run`: new
  `RUN_MODE="${STATE_DIR}/watch-for-changes"` constant; the stale copy is removed with
  `resolved-settings`; the heredoc gets `TCE_RUN_MODE_OUT` (optional) and writes `true`/`false`
  from `settings.watchForChanges` atomically (`mkstemp` + `os.replace`, prefix `.run-mode-`),
  **before** the newline check so a bad store path cannot cost the mode. Both writes share one
  `write_atomically` helper. One per-line `# shellcheck disable=SC1091` with a reason on the
  sourced helper.
- `svc-traefik-certificate-exporter/run`: reads the mode file only (no settings env var), echoes
  `Starting application (watch mode)` / `(run-once mode)`, unresolved → watch plus
  `WARNING: run mode unresolved; defaulting to watch mode`, then always execs through the
  unchanged privilege branch.
- `svc-traefik-certificate-exporter/finish` (new, 100755): `set -uo pipefail` (no `-e`); watch or
  missing/invalid mode → exit 0; run-once → `exit_code_for "$1" "$2"` (256 + signal → 128+n;
  anything not 0-255 → 1), echo `run-once pass finished with exit code <n>; stopping container`,
  write `/run/s6-linux-init-container-results/exitcode` (WARNING and still halt if unwritable),
  `exec /run/s6/basedir/bin/halt` (absent → WARNING, exit 125).
- `src/traefik_certificate_exporter/app.py`: `_run` logs one WARNING
  `neither runatstart nor watchforchanges is set; nothing to do` and returns (before the
  exporter and `DockerManager` are built — S01-006 wraps what follows).
- `.pre-commit-config.yaml`: `s6-no-raw-settings-env` (pygrep, `repo: local`,
  `entry: 'TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_'`, `files: ^docker/root/`) and
  `shellcheck-py` `rev: a6564f5d57444e123433a5c9af733e3975c77229  # frozen: v0.11.0.1-1`
  (frozen with `pre-commit autoupdate --freeze --repo https://github.com/shellcheck-py/shellcheck-py`),
  `files: ^docker/root/`, `types: [file]`, `types_or: [shell, executable]`.
- Tests: `tests/test_s6_run_mode.py` (new, 33 cases), `tests/test_app.py::test_nothing_to_do_logs_one_warning`,
  `tests/test_container_run_once.py` (new, opt-in `integration`). The `integration` marker was
  already registered by E014-S01-001; no `pyproject.toml` change.
- Docs: `docker/README.md` (smoke path corrected; new "Run once" section), `docs/operational.md`
  ("Run-once container" runbook), `docs/adr/0044-container-run-once-contract.md` (new),

## Deviations from the story text (decided here)

1. **AC 1 "`1` reads true" is not true of the application.** confuse's `get(bool)` rejects the
   YAML int `1` (`ConfigTypeError: settings.watchforchanges: must be a bool, not int`), so the
   exporter itself refuses `WATCHFORCHANGES=1` (0.2.x too: the shell let it through, then the
   app failed). Settings parsing is out of scope. The resolver reaches the application's answer
   — no mode — and the service falls back to watch. Tests: truthy cases are `yes`, `True`, `on`,
   config-file `true`; `test_resolver_writes_no_mode_for_a_value_the_application_rejects` pins
   the `1` behaviour. Verification row 1's node ids are unchanged.
2. **The unresolved-mode WARNING goes to stderr**, not stdout: the unchanged regression test
   `test_service_script_runs_as_root_unless_the_state_file_says_false` (AC 9: unchanged) runs
   with no mode file and asserts `"WARNING" not in result.stdout`. `docker logs` shows both
   streams. The observability AC said "s6's stdout"; the AD-12 text below does not name a stream.
3. **Row 5 recorded as `test "$(grep -c …)" = 0`.** `grep -c` prints `0` but exits 1 on no match;
   the expected-value form is what was recorded with `add-test-run` (real exit 0). Raw output: `0`.
4. **Probe rows 8, 9, 11** end with `rm`, so the shell line exits 0; the hook's own exit (1) is
   printed by the `echo "exit=$?"` and pasted below. They were recorded with a description of
   that, not as a synthetic hook exit.
5. **shellcheck hook needs `types: [file]`.** Upstream declares `types: [shell]`; pre-commit
   requires all `types` AND one `types_or`, so without the reset the `with-contenv` executables
   were excluded: the first plant run printed `shellcheck....(no files to check)Skipped`. After
   the reset the hook reported SC1091 on the init script (suppressed per line), proving it reads
   the executables.
6. **`finish` computes via `exit_code_for "$1" "$2"`** after `set -- "${1:-x}" "${2:-}"`, so the
   Verification row 11 plant (`sed 's/"\$1"/$1/'`) produces SC2086 and `-u` cannot trip on a
   missing argument.

## Code review and fix iteration (1)

Review: `closure/review-E014-S01-005.md` — critical 0, high 1, medium 2, low 3.

- **F1 (High) — config-file `watchforchanges: false` does not select run-once in the image.**
  `docker/Dockerfile:128` sets the env default `…_WATCHFORCHANGES=true`, which outranks the
  file. Resolution: the claim was corrected, not the Dockerfile. Removing the ENV default
  would switch every mounted config that omits the key to the packaged default (`false`,
  i.e. run-once) — a behaviour change needing a maintainer decision, outside this story's
  files. `docker/README.md`, `docs/operational.md` and ADR-0044 now say the env var is the
  container's run-once switch; filed **BL-E014-017** (Medium). **The 0.3.0 release-note bullet
  "honours `watchforchanges: false` from any source: config file, env, …" must be reworded by
  E014-S02-005** (see below).
- **F2 (Medium) — unresolved mode falls back to watch, so a broken config crash-loops.** This is
  the story's own specified edge semantics ("Init resolver fails … service uses watch mode …
  finish respawns"). Documented in ADR-0044 Consequences and the runbook (the loop is the
  exporter failing on a broken config, reported on every start). No code change.
- **F3 (Medium) — opted-in integration test skipped (exit 0) with no socket/image.** Fixed:
  once `TCE_DOCKER_INTEGRATION=1`, a missing socket or image now FAILS. Proof:
  `TCE_DOCKER_INTEGRATION=1 TCE_IMAGE=tce-no-such-image:none poetry run pytest -q tests/test_container_run_once.py`
  → `2 failed`. (`tests/test_container_pkcs12.py` from S01-002 keeps the skip pattern; not
  touched here.)
- **F5 (Low) — status 256 without a signal, or >255, would wrap to exit 0.** Fixed in
  `exit_code_for`; `test_finish_never_reports_a_malformed_status_as_success` (4 cases).
- **F4, F6 (Low)** deferred: BL-E014-018, BL-E014-019.
