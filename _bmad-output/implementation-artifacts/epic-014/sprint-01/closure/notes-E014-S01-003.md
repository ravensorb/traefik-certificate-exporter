# E014-S01-003 notes: CA-agnostic, null-safe ACME store parsing with per-resolver isolation

## What changed

- `src/traefik_certificate_exporter/libs/certificate_exporter.py`
  - New module helpers: `_ci_get`, `_is_resolver_node`, `_is_unwrapped_store`,
    `_iter_resolver_nodes`, `_certificate_entries`, `_entry_fields`, `_read_store`,
    `_leaf_not_after`, `_log_resolver`, `_format_expiry`, and the `_Candidate` record.
  - `exportCertificatesForFile -> list[str]`, never `None`. Three phases: read the store
    (file-level `OSError`/`ValueError`/`MemoryError` give `[]` + one ERROR); collect
    candidates per resolver, each inside its own `try` (one ERROR per failed resolver,
    then `N of M resolvers failed in <file>`); choose one owner per artifact target, then
    export each owner through E014-S01-002's `__exportDomain` (change signal unchanged).
  - `__exportCertificate(data, resolverName, keys)` is replaced by
    `__certificateCandidates(data, resolverName)`; the `keys` parameter is gone and the key
    case is chosen per entry. Deviation from the story's interface text, which named the
    method `__exportCertificate`: the export moved to the file level so that the owner rule
    below can see every resolver before anything is written. Private; no caller outside
    the class.
  - `__artifactDirectory(name, resolverName)` is the single place the output directory is
    derived (used by `__exportDomain` and by the owner rule). E014-S01-006's
    `_artifact_paths` (ADR-0040) should absorb or call it.
  - `b64decode(..., validate=True)` for the key and the full chain.
  - `_iter_resolver_nodes` logs its "skipping non-resolver key" WARNING itself; otherwise
    the helpers are pure and settings-free.
- `tests/fixtures/acme_fixtures.py`: `acme_v3_fixture`, `acme_null_certificates_resolver`,
  `acme_null_account`, `acme_v17_single_store`, `acme_legacy_v1_under_account`,
  `acme_mixed_case`, `real_chain_expiring_in(days)` (all on S01-002's real-chain builder).
- `tests/libs/test_certificate_exporter.py`: 19 new tests (Verification rows 1-8, plus
  `test_v17_single_store_and_legacy_v1_under_account_export`,
  `test_domain_held_by_two_resolvers_is_exported_once_and_stays_quiet`,
  `test_the_entry_that_expires_last_owns_shared_files`). Existing v1/v2-lower/v2-upper
  tests unchanged and green.
- `docs/adr/0043-export-commit-and-reporting-contract.md`: decision 6 (per resolver and per
  file, strict base64, one owner per set of files, no size limit), Consequences, evidence.
- `README.md`: one "Supported stores" line.

## BL-E014-012 decision (two resolvers, same domain, resolver not in the path)

Decided: one owner per artifact target within a store file. The entry whose leaf expires
last owns the files; ties go to store order (Traefik's Go encoder sorts map keys, so it is
stable); every other entry is skipped with a WARNING naming both entries and their expiry.
First version used plain store order; code review R-01 showed a stale resolver left in the
store after a migration would then keep serving its old certificate, and R-02 showed the
same collision inside one resolver for `*.example.test` + `example.test`. Both are covered
by the expiry rule. Cross-file collisions (one store file per resolver) are not covered:
deferred as BL-E014-013. BL-E014-012 resolved (fixed, within-file).
