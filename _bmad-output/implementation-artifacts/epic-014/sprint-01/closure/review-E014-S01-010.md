## Verified (no finding)

- **Guard at both call sites.** `app._run` and `AcmeCertificateFileHandler.__processPath`
  call the hook and notifications only when the changed list is non-empty, pass that list,
  and leave the restart call and the `try/finally` as they were. Signatures of
  `run_post_export_command` and `send_export_notifications` are unchanged.
- **Tests fail on the old code for the right reason.** With the old code, the no-change
  tests (`test_run_at_start_with_no_changed_domain_…`, `test_drain_with_no_changed_domain_…`,
  `test_restart_recovery_pass_…`) see a hook call with `[]`, so `hookCalls == []` /
  `assert_not_called()` fails. `test_quiet_pass_logs_no_change_info_once` fails because the
  line did not exist. The four `post_export` tests fail because the old lines embed the full
  command, or for the unparsable case shlex's message. `test_postexportcommand_is_redacted_in_debug_dumps`
  fails because the key was not declared. The one-changed-domain and dry-run tests are
  regression guards, as the story says. The module sweep passes: 110 passed.
- **OSError text in "failed to start".** CPython's `subprocess._execute_child` raises the
  child's exec error with `filename` set to `orig_executable` (`argv[0]`), or to `cwd` for
  a chdir failure (`cwd` is not passed here). So `str(e)` can contain only `argv[0]`, which is
  already logged. No argument leaks through it.
- **Existing-library check.** `argv[0]` comes from the existing `shlex.split`, and redaction
  uses the existing `SECRET_CONFIG_KEYS` / `_redact_secrets` path. No redaction code was
  hand-written.
- **Deletion check.** The removed `{e}` (the shlex parse message), the full command in the
  hook lines, and the old `send_export_notifications` docstring were all removed on purpose,
  as the ACs require. `domainsProcessed or []` is kept as `… or []`. No contract was dropped
  without being replaced. Confidence: high.
- **Correlation.** The quiet-pass line runs inside the pass's correlation context on both
  paths (the `set_correlation_id` token in `_run`, and the drain thread's rebinding).
- **Docs.** ADR-0045 decisions 13 and 14, the Amends line, and Consequences; the ADR-0014
  status marker and §7 note; `docs/operational.md`; `README.md`; and the `docker/README.md`
  bullet all state the new contract and agree with the code.

### F1: MEDIUM: `just check` fails: an unsorted import and an unformatted test line (kind: claim)

- **Location:** `src/traefik_certificate_exporter/app.py:12-17`;
  `tests/libs/test_post_export.py:171-173`
- **Claim contradicted:** AC "ADR and docs … `just check` passes", and Verification row 9
  (`just check` exits 0).
- **Description:** `NO_CHANGE_MESSAGE` was added between `AcmeCertificateExporter` and
  `AcmeCertificateFileHandler`. The isort ordering ruff uses puts constants first, so
  `poetry run ruff check src tests` reports `I001 Import block is un-sorted` at `app.py:3`.
  `poetry run ruff format --check` also reports that `tests/libs/test_post_export.py` would be
  reformatted: the `m.startswith("Post-export command curl failed to start") for m in …` line
  in `test_start_failure_log_names_only_the_program` is over the line length. Both
  `ruff-check` (run with `--fix`) and `ruff-format` are pre-commit hooks, so `just check`
  modifies these files and exits non-zero. CI's `build.yaml` fails the same way.
- **Suggested fix:** run `poetry run ruff check --fix src tests` and
  `poetry run ruff format src tests`. Then re-run `just check` and record its output in the
  notes file.

### F3: LOW: on the watch path, the quiet-pass line can contradict the drain it is in, and does not name its file (kind: observability)

- **Location:** `src/traefik_certificate_exporter/libs/certificate_exporter.py`
  (`__processPath`, the `else: self.__logger.info(NO_CHANGE_MESSAGE)` branch)
- **Description:** The AC says "one INFO line per pass with no change". On the watch path the
  line is logged once per store file processed in a drain, so the effective unit is the file.
  ADR-0045 decision 13 and `docs/operational.md` state this explicitly, and it matches the
  per-file scope the hook, the notifications and the restart already have there, so the
  per-file count is an accepted interpretation and not a defect. The problem appears in a
  drain over two store files where one changed and one did not. The log then shows the hook
  running for the first file and `No certificate changed; no hook or notification` for the
  second, under the same correlation id. The message does not say which file it refers to,
  so an operator reading the log sees "no certificate changed" in a pass where one did.
- **Suggested fix:** on the watch path, name the store file in the line. For example, log
  `NO_CHANGE_MESSAGE` with ` (<sanitized path>)` appended, using the existing
  `_sanitize_for_log`. Keep the exact text on the start-up pass. Alternatively, move the line
  to the end of the drain and log it once only when no file in the drain changed. If the
  wording changes, update ADR-0045 decision 13 and `docs/operational.md` to match.

### F4: LOW: the quiet-pass line is untested on the watch path (kind: testability)

- **Location:** `tests/libs/test_certificate_exporter_watch.py::test_drain_with_no_changed_domain_runs_no_hook_or_notification`
- **Description:** `test_quiet_pass_logs_no_change_info_once` drives only `app._run`. The
  watch-path `else:` branch that logs the line has no assertion. Deleting it, or changing
  the level, leaves every test green, even though ADR-0045 and `docs/operational.md`
  document the line for the watch path as well.
- **Suggested fix:** in the drain no-change test, or in a sibling test, capture the handler's
  logger and assert exactly one INFO record equal to `NO_CHANGE_MESSAGE`. Also assert there
  is none in the one-changed-domain drain test.

### F5: LOW: `argv[0]` is logged without sanitizing control characters (kind: security)

- **Location:** `src/traefik_certificate_exporter/libs/post_export.py` (the `program`
  interpolation in the exited, completed, timed-out and failed-to-start lines)
- **Description:** `program` is interpolated raw. A quoted `argv[0]` containing a newline or
  ANSI escapes (shlex keeps them inside quotes) can forge or split log lines. The source is
  operator configuration, not an external input, so the exposure is small. The project
  already has `_sanitize_for_log` for paths, and the hook lines are now the only place the
  command reaches the logs.
- **Suggested fix:** log `_sanitize_for_log(program)`, or `repr`-quote it, in the four lines.
  Optional, since the input is trusted configuration.
