## Spine/ADR amendments for S02-003

No ADR is added or changed by this story. Exact text for E014-S02-003 to verify against the
consolidated spines, routing only deltas:

**Product spine AD-3 (logging configuration surface).** "`TRAEFIK_CERTIFICATE_EXPORTER_LOGGING_LEVEL`
joins the pre-settings `LOGGING_*` family (`LOGGING_CONSOLEONLY`, `LOGGING_CONSOLEJSON`,
`LOGGING_CFGFILE`), read with `os.getenv` in `app.py` because logging is configured before
settings load. Precedence: `-ll/--log-level` > `TRAEFIK_CERTIFICATE_EXPORTER_LOGGING_LEVEL` >
`INFO`. The value is case-insensitive, one pair of surrounding quotes is stripped, and an empty
value counts as unset. An invalid value gives one WARNING (variable, sanitized value, allowed set)
and INFO, and never exits. One INFO line at start-up names the effective level and its source
(`cli`, `env`, `default`). There is no config-file `logging.level` key."

**Product spine AD-6 (naming: config, CLI, env), Conventions row "Naming (config, CLI, env)".**
"`src/traefik_certificate_exporter/config_default.yaml` is the single key registry. Every
setting the loader reads is declared there, unset ones as `null`. Three checks enforce the
naming convention mechanically:

- `tests/libs/test_cli_args.py::test_every_settings_dest_is_a_key_in_config_default`: every
  `settings.*` argparse `dest` is a leaf or list path in the registry.
- `tests/libs/test_settings.py::test_every_config_default_key_is_read_by_the_loader`: the
  registry equals the set of keys `SettingsManager.loadFromFile` reads.
- `tests/test_settings_surface.py::test_documented_env_names_map_to_settings`: every
  `TRAEFIK_CERTIFICATE_EXPORTER_*` name in the documentation scope maps, through confuse's
  `EnvSource` rule (strip prefix, lowercase, split on `_`, drop a trailing integer index that
  addresses a list), to a registry leaf or list, or is a complete env-name string literal in
  `src/**/*.py`.

Placeholder rule: a match ending in `_` is a placeholder prefix. It is valid when, stripped of
the trailing `_`, it is a strict `_`-boundary prefix of a valid name or names a list setting."

(The legacy-name policy and the marker rule are E014-S01-009's, not this text.)

**CI spine AD-4 clarification (A-02).** "`tests/test_settings_surface.py` and the dest/registry
checks test the product's own documented surface (settings keys, env names, CLI flags, operator
docs) against the product source. They are product tests and belong in `tests/`. Tests that
police workflows, action pins or the supply chain are not product tests and stay out of
`tests/`."

### Scan contract (for E014-S01-005, E014-S01-008, E014-S01-009, E014-S02-003, E014-S02-005)

All of the following live in `tests/test_settings_surface.py` at module level. Reuse them and do
not restate them:

- **Extraction regex.** `ENV_NAME_PATTERN = TRAEFIK_CERTIFICATE_EXPORTER_[A-Z0-9_]+(?:\.[A-Z0-9_]+)*`.
  The dotted tail captures a historic `…_SETTINGS.RESTARTCONTAINER` whole. A name containing
  `.` is never valid.
- **Scope.** `_scan_pathspecs()` returns the git pathspecs `*.md`, `*.yml`, `*.yaml`,
  `*.sample`, `*Dockerfile` plus `:(exclude)_bmad-output/**`, `:(exclude)docs/adr/**` and
  `:(exclude).github/**` (the long form, because git 2.53 rejects `:!_…`).
  - `_scan_files(root)` resolves them with `git ls-files --cached --others --exclude-standard`,
    so untracked, unstaged files are in scope.
  - It then drops paths matched by the top-level `exclude:` regex of `.pre-commit-config.yaml`,
    read at test time by `_vendored_exclude_pattern(root)`.
  - A history test passes the same `_scan_pathspecs()` to `git log`. There is no second list.
- **Mapping.** `_env_name_to_key_path(name)` restates confuse's rule in about 5 lines
  (unchecked against `confuse.EnvSource` until E014-S01-009 adds that cross-check).
- **Valid sets.**
  - `_config_key_paths()` gives the registry leaves with their defaults.
  - `_valid_env_names_from_source()` gives the complete quoted env-name literals in `src/**/*.py`.
    Today that is `LOGGING_CONSOLEONLY`, `LOGGING_CONSOLEJSON`, `LOGGING_CFGFILE`,
    `LOGGING_LEVEL`, `EXPORTED_DOMAINS` and `CORRELATION_ID`.
  - `_is_valid_env_name(name, leaves, source_names)` applies the full-name and placeholder rules.
  - `_unmapped_env_names(root)` returns `path:line: NAME` for every failure.
- **Placeholder prefixes** end in `_`. They are valid when they strictly `_`-prefix a valid name
  or name a list setting. This covers `…_SETTINGS_<KEY>`, `…_SETTINGS_{KEY}`,
  `…_SETTINGS_APPRISEURLS_<n>`, and a pygrep `entry: 'TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_'`.

## 0.3.0 release notes (for E014-S02-005 `docs/upgrading.md`)

- `--restart-container` now enables restarts. It previously set an unread key, so restarts were
  off even with the flag.
- The sample `docker-compose.yml` and `docker/README.md` environment variable names are
  corrected. If you copied them, rename to `TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_<KEY>`. The
  compose sample drops the obsolete `version:` key and no longer quotes values (Compose passed
  the quotes through). `…_CONFIGFILE` / `…_CONFIG_FILE` never did anything and are removed; the
  container's config file is `/config/config.yaml`.
- New `TRAEFIK_CERTIFICATE_EXPORTER_LOGGING_LEVEL` sets the log level when `-ll` is not given. It
  is the container's verbosity switch. An invalid value falls back to INFO with one WARNING. One
  INFO line at start-up names the effective level and its source (`cli`, `env` or `default`).
- `config.sample.yml` and the image's seed config state the logging defaults correctly (the image
  sets `CONSOLEONLY=true`).
