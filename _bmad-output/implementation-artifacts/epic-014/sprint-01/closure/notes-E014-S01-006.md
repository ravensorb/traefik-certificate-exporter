## Decisions taken during implementation

1. **Index shape.** The per-file entry is keyed `(resolverName, name) → tuple[Path, ...]`, not
   `name → set[Path]` as ADR-0040 §4 and the story's interface text say. The resolver in the
   key is what lets a resolver that fails as a whole keep exactly its own previous paths
   (RV-1). The lookup is still by name across all entries. Routed below; backlog BL-E014-020.
2. **Store-file key** is `os.path.abspath(sourceFile)`, so the start-up glob and watchdog's
   event path for the same file share one entry.
3. **Updated existing tests.** `test_none_domains_is_treated_as_empty_list_without_raising`
   became `test_a_lookup_that_knows_no_domain_restarts_nothing` (the parameter it tested no
   longer exists). The two app reachability tests now expect the restart evaluation that runs
   on every pass (factory called twice; two ERROR lines for an unreachable Engine, each naming
   the endpoint).
4. **Fire-time floor (review M1).** The trailing restart checks the floor under the lock
   before recording; a pass that claimed the slot after arming wins. Added
   `test_deferred_restart_skipped_when_slot_reserved_since_arming`; the correlation and
   cancel-race tests now advance the clock to the fire time, as a real timer would.
5. **Full suite twice.** `just check` ran once before review and again after the M1 fix (the
   first post-fix run exited 1 because `ruff format` reformatted the new test; the rerun
   exited 0). The second run is the Verification row 14 the story requires at the end, so it
   was not skipped under the one-full-suite rule.

## Arch-gate carry-ins

- **AG-13 (BL-E014-008), met by single-assignment publication.** `__recordArtifacts` builds a
  new outer mapping and a new entry under a writer lock and publishes it with one assignment;
  published mappings are never mutated. `artifactMtime` takes one reference and iterates it.
  Test `tests/libs/test_certificate_exporter.py::test_artifact_index_rebuild_during_lookup_is_safe`
  rebuilds two entries (one new store file, one replaced) from inside the reader's first
  `os.stat` call; an in-place update would raise "dictionary changed size during iteration".
- **RV-1 (BL-E014-010), met by carry-over.** A certificate whose rebuild fails
  (`__exportDomain` returns `paths is None`, or raises) keeps its previous
  `(resolver, name)` paths; a resolver whose candidate listing raises keeps every previous
  path recorded under that resolver. A file-level failure keeps the whole previous entry.
  Test `test_failed_rebuild_keeps_previous_artifact_paths` (corrupt key for one domain plus a
  raising resolver; all three domains keep their previous mtimes).

## Spine/ADR amendments for S02-003

Verified against the 2026-10-11 consolidated product spine. AD-10 already states the rule,
slack, `StartedAt` handling, floor, coalesced timer, fire-time re-check, cancel, dry run and
no persistence. Deltas only:

**Product spine AD-10, Rule — replacement text** (replace from "Candidates are containers
labeled" to "the next pass recovers by the same rule."):

> On every pass — the start-up pass and every drain, including passes in which no domain
> changed — candidates are the running containers on the connected daemon labeled
> `com.github.ravensorb.traefik-certificate-exporter.domain-restart` (comma-separated
> domains) whose label names at least one domain with an exported artifact on disk. A
> candidate is restarted iff the newest mtime of its labeled domains' exported artifacts
> (read from the paths the export pass recorded, ADR-0040) exceeds its `State.StartedAt`
> (UTC, `dateutil` `isoparse`) by more than `RESTART_MTIME_SLACK_SECONDS` = 2; missing,
> empty, unparsable or zero `StartedAt` means no restart. Unchanged artifacts are not
> rewritten, so the files' mtimes and the container's start time are the only restart state.
> A per-container `RESTART_COOLDOWN_SECONDS` = 300 floor applies; a restart the floor denies
> arms one coalesced daemon timer, which at fire time re-checks, against a fresh client, that
> the container exists, its label still names a requesting domain, the rule still holds and
> no other restart has claimed the window. Failures log ERROR without re-arming; a lost
> deferral, a failed restart and a crash between write and restart are recovered on the next
> pass by the same rule.
