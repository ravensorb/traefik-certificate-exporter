Reviewer role: bmad-code-review. Inputs: the story, `/tmp/tce-s007.diff`, `notes-E014-S01-007.md`, ADR-0042, plus targeted greps of `poetry.lock`, `.github/workflows/{build,dev,release}.yaml`, `justfile` and the CI spine `.memlog.md`.

## Findings

### F1 — MEDIUM — kind: claim — environment-marker-gated lock entries are never audited, but the hook, walkthrough and ADR say "every poetry.lock group"

- **Location:** `.pre-commit-config.yaml` pip-audit comment ("Audits the venv, whose scope is every poetry.lock group"), hook name `pip-audit (every poetry.lock group, ADR-0042)`; `docs/ci/pipeline-walkthrough.md` pip-audit row ("a known advisory in any `poetry.lock` group"); `docs/developer.md:46` ("the pip-audit hook sees the whole lock"); ADR-0042 Decision §1 ("The audited venv is therefore exactly the lock"); the AD-3/NFR-3 amendment text in the notes.
- **Description:** `poetry sync --all-groups` installs every group, but only the packages whose PEP 508 markers match the interpreter and platform in use. pip-audit audits that venv, so a lock entry gated by a marker is never audited. In the relocked `poetry.lock`:
  - `pywin32` is in the **main** group with `sys_platform == "win32"` (pulled in by `docker`). It ships to Windows users of the PyPI package and is audited nowhere.
  - `tzdata` (`platform_system == "Windows"`), `colorama` and `pyreadline3` are in the same position.
  - `exceptiongroup` (`python_version == "3.10"`) and the `tomli` entries gated on `< 3.11` belong to the declared lower end of the supported range. Neither the local 3.11 venv nor CI's 3.14 venv installs them.
  - `backports-tarfile` and `importlib-metadata` (`< 3.12`) are audited locally on 3.11 but not in CI on 3.14. ADR-0042 calls CI "the authoritative gate", so the authoritative gate covers less than the local one.

  So the scope is "the lock as resolved for one interpreter on linux/amd64", not "every lock group". That is a hand-kept, implicit scope, which global rule 4 forbids. Prose that overstates coverage breaks global rule 3. The bite and scope probes (rows 3 and 13) all plant unmarked packages, so they cannot reveal this.
- **Suggested fix:** At minimum, state the limit wherever the scope is claimed. That means the hook comment, the walkthrough row, the `docs/developer.md` cell, ADR-0042 "Not covered, stated", and the AD-3/NFR-3 amendment text in the notes. The NFR-3 wording "no package in any `poetry.lock` group … carries a known advisory" overstates the gate as written. Name the uncovered marker classes (other platforms, other Python minors) and open a `BL-` key. Add the marker case to ADR-0042's revisit trigger: auditing the lock text, or a pylock that pip-audit `--locked` reads, removes it. As an option, have CI also audit at the 3.10 range end. E014-S02-005 already owns a 3.10 run, so this could be routed there rather than added here.

### F2 — LOW — kind: claim — ADR-0042 still quotes the pip-audit entries without `--aliases on`

- **Location:** `docs/adr/0042-dependency-audit-scope-is-the-whole-lock.md` Decision §1 ("The `pip-audit` hook's `entry` is unchanged (`poetry run pip-audit --skip-editable --progress-spinner off`)") and §2 (the `pip-audit-bootstrap` entry), against `.pre-commit-config.yaml` (both entries now end in `--aliases on`).
- **Description:** The deviation itself is sound and is accepted. pip-audit 2.10.1 prints only the PYSEC primary ID unless aliases are turned on, so without the flag Verification rows 3 and 14 could never show GHSA-2xpw-w6gg-jr37. The flag adds a column and changes neither scope nor exit status. However, the ADR's Decision section now quotes an entry that does not match the configuration, and states that the entry is "unchanged".
- **Suggested fix:** Add one line to the ADR's Decision (or a dated note) saying both entries carry `--aliases on`, and why. Alternatively, route that line to E014-S02-003 in the notes' amendments section.

### F3 — LOW — kind: claim — the AD-3 `pip-audit` replacement is not ADR-0042's wording verbatim

- **Location:** `notes-E014-S01-007.md`, "CI spine AD-3, `pip-audit` bullet". The claim is AC 10: "The `pip-audit` scope sentence is ADR-0042's CI AD-3 replacement wording, verbatim".
- **Description:** The notes insert a parenthetical, `` (`repo: local`, `language: system`, `poetry run pip-audit … --aliases on`) ``, between "`pip-audit`" and "audits the venv…". They also append two sentences, on offline failure and on `--ignore-vuln`. The meaning is preserved, but S02-003 is told to apply the ADR wording verbatim, and a diff check against the ADR will not match.
- **Suggested fix:** Keep ADR-0042's sentence unchanged as the first sentence of the bullet. Put the hook details, offline failure and `--ignore-vuln` policy in separate following sentences. Once F1 is fixed, add the marker limit too.

### F4 — LOW — security — new dev-group tools are installed in the token-bearing publish jobs until S02-001

- **Location:** `pyproject.toml` `[tool.poetry.group.dev.dependencies]` (`pip-audit ^2.10.1`, `deptry ^0.25.1`), together with `.github/workflows/dev.yaml:78` and `.github/workflows/release.yaml:124` (`poetry install --only dev --no-root`, run beside `TWINE_PASSWORD`/publish secrets).
- **Description:** The publish jobs install the whole dev group just to get twine. Adding pip-audit and deptry to that group adds their transitive closure to the packages present in jobs that hold live PyPI/Gitea credentials. pip-audit's closure includes CacheControl, cyclonedx-python-lib, pip-api, pip-requirements-parser and others; deptry is a native binary. The packages are locked and audited, so the risk is small. Still, it widens the credentialed install set, which ADR-0042's Consequences say S02-001's `publish` group exists to keep minimal.
- **Suggested fix:** None needed in this story, provided E014-S02-001 (twine moved into an optional `publish` group installed with `--only publish`) ships in the same release. Record that dependency in the notes for S02-001, so this interim widening is not released alone.

### F5 — LOW — testability — "offline it FAILS, never skips" is asserted in three places but never evidenced

- **Location:** the `.pre-commit-config.yaml` pip-audit comment, the `docs/ci/pipeline-walkthrough.md` pip-audit row, and the AD-3 amendment text; `notes-E014-S01-007.md` has no offline run.
- **Description:** The story's Error-handling section makes offline failure a stated behaviour, and the comment says a skip would be a false green. No Verification row and no note exercises it. pip-audit's PyPI service goes through a CacheControl HTTP cache, so the claim also depends on how a warm cache behaves. Global rule 3 asks for the check alongside the claim, or an explicit statement of what is not covered.
- **Suggested fix:** Run one offline probe and record it in the notes. For example, `HTTPS_PROXY=http://127.0.0.1:9 HTTP_PROXY=http://127.0.0.1:9 poetry run pre-commit run pip-audit --all-files; echo "exit=$?"` should give `exit=1` with a connection error, also with a warm cache. Alternatively, reword the three places as "expected to fail offline (not probed)".

## Judgement of the recorded deviations

- **`--aliases on` on both pip-audit entries:** accepted. It is needed for the required GHSA evidence and changes neither scope nor exit status. The only gap is the ADR text drift (F2).
- **`docs/developer.md:46` edited outside Files in scope:** accepted. Leaving it would have left a doc saying `just install` runs `poetry install`, which this story made false. The new cell carries the over-broad "whole lock" wording (F1).
- **Probe tooling substitutions:** accepted. These were seeding the probe clones with `.poetry/`, using `uvx --from pip-tools==7.5.3 --with 'pip<25.3'` in place of `pipx`, and running row 14 in a fresh clone. They change only how the probe inputs are produced, not what the hooks are tested against. The failed first row-3 attempt is correctly excluded from the evidence.

## Checks with nothing to report

- **Reused-before-written:** no hand-rolled logic. Vulnerability auditing uses pip-audit, the declared-vs-imported check uses deptry, and locking uses Poetry. The one-line `bash -c` loop in `pip-audit-bootstrap` is sanctioned by ADR-0042 and handles argument passing correctly (`$0` = `--`, `for f` iterates the file names).
- **Deletions:** removing `requests`, `docker-pycreds` and `expandvars` loses no behaviour. deptry's pre-change DEP002 output and `just check` (428 passed) support this, and no file under `src/`, `tests/` or `docker/` imports them. Moving `pyyaml` from dev to main does not break the `--only dev` publish jobs, which run only twine. Nothing qualifies as `kind: deletion`.
- **AC 1/2/5/6/7/8/9 and the memlog lines:** consistent with the diff and the recorded evidence. Both `- (decision)` lines are present in the CI spine's `.memlog.md`. AC 7's "digest recorded in the commit message" cannot be checked before the commit.
