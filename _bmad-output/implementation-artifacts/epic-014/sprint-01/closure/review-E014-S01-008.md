### F-2 — LOW — kind: testability
- **Location:** `tests/test_settings_surface.py::test_every_long_option_is_in_readme` (line 639-656); `README.md` usage block.
- **Description:** The guard checks that each long option string occurs as a substring anywhere in `README.md`, not inside the usage block, and nothing compares the block with `--help`. The block can drift (a help-text or metavar change, or a flag removed from the block but still mentioned in prose, e.g. the strict-parse paragraph's `--data-path`) while the test stays green; the AC's "regenerated from `--help`" is a one-time action with no mechanical check (global rule 3/4). Note also that the block reflects Python 3.11's argparse layout; on 3.13+ (the image runs 3.14) argparse renders `-c, --config-file PATH`, so the copy differs from what container users see.
- **Suggested fix:** Scope the check to the fenced block under `## Usage` (extract it, then check membership there), or assert the block equals `globalArgParser.format_help()` under a pinned `COLUMNS` and a pinned Python-version rendering (skip the exact comparison on other interpreters, keep the membership check everywhere).
