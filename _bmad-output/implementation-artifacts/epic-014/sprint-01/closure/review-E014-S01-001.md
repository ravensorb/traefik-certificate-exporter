# Code review: E014-S01-001 (Docker SDK 7.2 and a restart path that really works)

- Reviewed: `/tmp/e014s01001/review.diff` against the story's ACs 1-11, its six technical-AC dimensions, and product spine AD-10. The mtime trigger and defer-not-drop cooldown belong to E014-S01-002 and E014-S01-006, so they are out of scope here.
- Result: critical 0, high 0, medium 1, low 4.
- Confirmed against the installed SDK (`docker` 7.2.0):
  - `ContainerCollection.list(..., sparse=False, ignore_removed=False)` re-raises `NotFound` when a listed container is removed during the per-container `get`.
  - `APIClient.__init__` with `version=None` calls `_retrieve_server_version()` during construction.

## Checks that found nothing

- **Existing-library check.** The client comes only from the SDK's own switch, `docker.from_env(use_context=False)`. No `base_url` logic is built by hand. The opt-in test uses `pytest.mark.integration` plus `skipif`, and the marker is registered in `pyproject.toml`. `_endpoint()` copies the env-or-default rule, but only to build log text, never to choose a target. That is acceptable, though see F-05.
- **AC 2.** `src/` has one construction site and no `requests` import. Errors are classified as `(DockerException, OSError)`.
- **Deletion check.** Two things were replaced: `import docker` became submodule imports, and `docker.from_env()` became `_create_client()`. The `docker` name is still bound, the generic `except Exception` path with its traceback is kept, and the mocked tests were re-pointed rather than removed (AC 9). No contract was dropped.
- **Security.** The CLI context is ignored and the integration test pins its busybox image by digest. No new credentials appear, and logging `DOCKER_HOST` is acceptable under the story.

## Findings

### F-01: MEDIUM, kind: correctness/edge, `src/traefik_certificate_exporter/libs/docker.py:156`

- **Problem.** The story handles a "Container vanishes between `list` and `restart`" by logging INFO and continuing the loop (lines 177-182). It misses the same race one step earlier, inside `client.containers.list(...)`.
  - With the default `sparse=False`, docker-py lists the containers and then calls `get(id)` on each one. With the default `ignore_removed=False`, it re-raises `NotFound` when a container disappears between those two calls.
  - That `NotFound` is a `DockerException`, so the outer handler at line 195 catches it.
  - Result: the pass is aborted and nothing is restarted, not even the healthy labeled containers. The pass logs ERROR `Failed restarting containers: Docker Engine at … is not reachable: 404 … No such container`. That is the wrong diagnosis, and the renewal is lost until the next pass.
  - On a host where containers churn (CI runners, compose recreations), this happens in real use.
- **Fix.**
  - Use the SDK's own switch: `client.containers.list(filters={"label": DOCKER_LABEL}, ignore_removed=True)`.
  - Add a mocked test where `list` is called with `ignore_removed=True`, or an assertion on the call kwargs. Update `test_restarts_container_whose_label_matches_a_processed_domain`, which asserts `list.assert_called_once_with(filters=...)`, to match.

### F-02: LOW, kind: observability, `src/traefik_certificate_exporter/libs/docker.py:93-98, 195-199`

- **Problem.** Every `DockerException` gets the same text: "Docker Engine at X **is not reachable**". That includes `APIError` responses from an Engine that *is* reachable, such as a 403 from the docker-socket-proxy that `docs/operational.md` recommends, a 500, or the 404 in F-01.
  - In `check()`, a `client.version()` failure that follows a successful `ping()` is also reported as "not reachable".
  - The module comment itself lists "an Engine-side refusal" as an expected error, so the message misdiagnoses a case the code expects to see.
  - AC 8 requires only "endpoint and error text", which the message provides. The problem is that the wording sends the operator to the socket when the actual cause is authorisation or the API.
- **Fix.** Use neutral wording for the `DockerException` and `OSError` branch, e.g. `Docker Engine request to {endpoint} failed: {e}`. Alternatively, branch on `docker.errors.APIError` (reachable, refused) versus the rest (unreachable). Keep a single ERROR line and no traceback.

### F-03: LOW, kind: claim, `tests/libs/test_docker.py:379-380`

- **Claim (AC 3).** "builds `docker.DockerClient(base_url=…missing.sock)`, **calls `.ping()`**, and asserts … it raises `docker.errors.DockerException`".
- **Problem.** On 7.2, `DockerClient(...)` with `version=None` auto-negotiates and raises during construction, so `.ping()` is never reached. The test is still a valid regression guard, because the scheme error would surface at construction too. But the ping path that the AC names is not what the test exercises.
- **Fix.** Construct with `version="1.44"` (offline, no negotiation), then assert that `client.ping()` raises `DockerException` without the scheme error. Alternatively, reword the test comment and the AC 3 evidence so they say construction is what raises.

### F-04: LOW, kind: test-coverage, `tests/test_app.py:332-360`

- **Problem.** AC 7 limits the start-up check to "When `settings.restartcontainers` is true". Both new app tests set it to true. No test shows that `_create_client` and `check()` are *not* called when restarts are off. If the `if settings.restartContainers:` guard were removed, deployments without a Docker socket would get a spurious start-up ERROR, and the suite would stay green.
- **Fix.** Add `test_startup_reachability_check_is_skipped_when_restarts_are_off`. It reuses `_run_once_with_restarts` with `restartContainers=False`, or a parameter for it, and asserts `factory.assert_not_called()` and no ERROR records.

### F-05: LOW, kind: robustness/test, `tests/libs/test_docker_engine.py:80` (and `_endpoint` at `libs/docker.py:75`)

- **Problem (test runtime).** In the busybox container, `sleep 300` runs as PID 1 and ignores SIGTERM. `c.restart()` therefore waits the full 10 s default stop timeout before it sends SIGKILL. This makes the required release-evidence test (AC 10) needlessly slow, and slower again on a loaded host.
- **Problem (`_endpoint`).** `_endpoint()` copies docker-py's env-or-default rule by hand. If `_create_client()` ever changes its target, for example through a `base_url` setting, the log line will name the wrong endpoint, and nothing would catch that.
- **Fix.**
  - In the test, pass `init=True` (tini forwards signals) or `stop_signal="SIGKILL"` to `containers.run`.
  - For `_endpoint()`, a unit test that pairs a set `DOCKER_HOST` with `_endpoint()` and with the real client's resolved target would pin the two together. This is optional.
