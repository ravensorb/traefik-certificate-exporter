## F1. MEDIUM, kind: claim / guard-reach
**Location:** `src/traefik_certificate_exporter/config_default.yaml:1`, `tests/libs/test_cli_args.py:178`

**Problem:** The new header comment claims "every setting the loader reads is declared here". Both new guards take that file as the stand-in for "what the loader reads":
- the dest check proves `dest ∈ config_default.yaml`;
- the env check proves `name → path ∈ config_default.yaml`.

Neither proves `path ∈ the keys settings.py actually reads`. Those keys are a hand-written list at `settings.py:354-375`, which is the set M1 diverged from. Only one direction is enforced at runtime:
- **Enforced:** a non-Optional key that the loader reads but the registry lacks raises `NotFoundError`.
- **Not enforced:** a key that is in the registry but that the loader no longer reads (or reads under another spelling) is silent. Both guards then stay green while the CLI flag or documented env var sets a key nothing reads. That is exactly the M1 failure mode.

For `confuse.Optional` keys (`traefikresolverid`, `pkcs12passphrase`, `postexportcommand`, `appriseurls`), even the first direction is silent: a missing declaration yields `None`.

Global rule 3 (write the check with the rule) and rule 4 (prove the reach) both apply.

**Suggested fix:** Add one test that derives the loader's read set and asserts it equals the registry's leaves. Either:
- build `Settings` from a `config_default.yaml`-shaped tree where every leaf has a sentinel value, and assert every sentinel reaches a `Settings` attribute; or
- record the `self._config["settings"][...]` accesses through a spy `confuse` view.

Alternatively, weaken the comment so it states only what is checked.

## F2. LOW, kind: guard-reach
**Location:** `tests/libs/test_cli_args.py:192`

**Problem:** The dest check accepts any existing dotted path, including a mapping. A future `dest="settings.domains"` would pass even though it names a dict, not a setting. The env-name check in `tests/test_settings_surface.py` deliberately rejects non-leaves (`..._SETTINGS_DOMAINS` is invalid), so the two guards disagree on what a valid target is. The story's error-handling AC states "only leaves and lists are valid targets".

**Suggested fix:** After the walk, also require `not isinstance(node, dict)`. Reusing `_config_key_paths()` would give both guards one definition.

## F3. LOW, kind: guard-reach
**Location:** `tests/test_settings_surface.py:165`

**Problem:** The placeholder branch does not apply the full-name branch's rule that an index only addresses a list.
- `TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_DATAPATH_<n>` is accepted, because the stem equals a valid name.
- The concrete `..._SETTINGS_DATAPATH_0` is rejected, which `test_env_name_mapping_rules` asserts.

A doc that told operators to use indexed keys for a scalar setting would pass the scan.

**Suggested fix:** When the stem itself maps to a leaf and the source text continues with an index placeholder, require the leaf to be a list. A simpler option is to accept a stem that equals a leaf name only when that leaf's default is a list, or when the stem is a strict `_`-boundary prefix.
