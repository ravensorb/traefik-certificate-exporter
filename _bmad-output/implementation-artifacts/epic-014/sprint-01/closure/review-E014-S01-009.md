## Medium

### M1: Mixed-case env names that confuse honours are reported as "Unknown setting"
- **kind:** correctness (false positive)
- **location:** `src/traefik_certificate_exporter/libs/legacy_settings.py:211` (`_is_valid_env_name`), `:259-267` (`find_legacy_settings`)
- **description:** `settings.py:308` calls `set_env(prefix=..., sep="_")`. confuse's `EnvSource` defaults to `lower=True`, so it lowercases the tail and applies `TRAEFIK_CERTIFICATE_EXPORTER_settings_DataPath`. Detection compares against the upper-case set only, so it reports a working setting as wrong. Verified:
  `EnvSource` -> `{'settings': {'datapath': '/x'}}`;
  `find_legacy_settings` -> `Finding(kind='unknown', name='TRAEFIK_CERTIFICATE_EXPORTER_settings_DataPath', suggestion=None)`.
  The operator is told the name "matches no setting", but the setting is in effect. difflib is case-sensitive, so no suggestion is given either.
- **fix:** Normalise before matching: `canonical = ENV_PREFIX + name[len(ENV_PREFIX):].upper()`. Use it for `_is_valid_env_name`, `_legacy_entry` and `_nearest_env_name`, and keep the original name in the message. Add a test that a mixed-case valid name gives no finding. Extend the A-11 cross-check with one mixed-case name so the test pins confuse's `lower=True`.

### M2: Output-only names `..._EXPORTED_DOMAINS` and `..._CORRELATION_ID` are accepted silently and offered as suggestions
- **kind:** correctness (misleading advice; spec-conformant, so route a spec delta)
- **location:** `src/traefik_certificate_exporter/libs/legacy_settings.py:40-49` (`SOURCE_ENV_NAMES`), `:237-245` (`_nearest_env_name`)
- **description:** These two names are set by the exporter for the post-export hook's process (`post_export.py:65-68`). The exporter never reads them. Because they are in `valid_env_names()`:
  - an operator who sets them gets no warning, although nothing changes;
  - they are offered as "did you mean" targets.

  Verified: `..._DOMAINS` -> `did you mean TRAEFIK_CERTIFICATE_EXPORTER_EXPORTED_DOMAINS?`, `..._EXPORT_DOMAINS` -> `..._EXPORTED_DOMAINS`, `..._CORRELATIONID` -> `..._CORRELATION_ID`. That sends an operator from one dead name to another, which is the failure this story exists to prevent. The interface-contract AC lists these names as valid, so the code follows the AC. The defect is in the AC.
- **fix:** Split `SOURCE_ENV_NAMES` into read names (the `LOGGING_*` names) and hook-output names (`EXPORTED_DOMAINS_ENV`, `CORRELATION_ID_ENV`). Keep both valid for the documentation scan. Remove hook-output names from the suggestion options, and give an operator who sets one a WARNING ("set by the exporter for the post-export command; has no effect"). Route the AC/AD-6 delta through the notes file for S02-003.

### M3: The replacement column of the legacy table is never checked; the marker rule's "every other name is still checked" is false for `legacy_settings.py`
- **kind:** claim / scope (global rules 3 and 4)
- **location:** `tests/test_settings_surface.py:139-146` (marked `.py` skipped by the literal scan), `:217-232` (`_unmapped_env_names` iterates `_scan_files()` only, and `*.py` is not in `_SCAN_INCLUDE`), `:21-24` (module docstring); `src/traefik_certificate_exporter/libs/legacy_settings.py:75-157`
- **description:** Quoted claims:
  - the story's C-01 says "Marked files still have every non-legacy name checked";
  - the test-module docstring says "every other name in it is still checked".

  `legacy_settings.py` is a marked file, but nothing scans its non-legacy names. The `.py` file is outside the doc scan scope, and the literal scan skips it. No test asserts that `LegacyName.replacement` values are valid. `test_each_legacy_env_name_warns_once_with_replacement` builds its expected string from `entry.replacement` itself, so it is tautological on content. A typo such as `..._SETTINGS_RESOLVERINPATHNAM` in the replacement column would make every legacy WARNING tell operators to switch to another dead name, and `just check` would stay green. All current replacements are valid (checked by hand against `config_default.yaml`).
- **fix:** Add `test_legacy_replacements_are_valid`:
  - every env-row `replacement`, run through `ENV_NAME_PATTERN`, must pass `_is_valid_env_name` (the placeholder rule covers `..._APPRISEURLS_<n>`);
  - every config-row replacement must be a leaf path of `config_default.yaml`.

  Plant a typo'd replacement as the probe. Alternatively, run marked `src` files through the `_unmapped_env_names` per-line check. Then correct the docstring so it states exactly what is checked.

## Low

### L1: Detection warnings do not run under a start-up correlation_id
- **kind:** claim
- **location:** `src/traefik_certificate_exporter/app.py:162` (call to `loadFromFile`), `:188-189` (first `set_correlation_id`)
- **description:** Quoted claim (Observability): "All of these run under the start-up `correlation_id`, before the first pass." `loadFromFile` runs before any id is bound. The only start-up id is created later, and only inside `if settings.runAtStart`. The WARNINGs therefore carry the unset sentinel. They are emitted before the first pass, so only the first half of the claim holds.
- **fix:** Either amend the AC and the AD-6 routing text to "before the first pass, outside any pass id", or bind one start-up id around the settings load in `_run`. Do not leave the AC as written.

### L2: A sparse list index is reported as valid, but confuse does not build a list from it
- **kind:** spec-gap (the code follows the AC)
- **location:** `src/traefik_certificate_exporter/libs/legacy_settings.py:211-219`; AC "Indexed valid name (`…_SETTINGS_APPRISEURLS_3`): valid after dropping the index"
- **description:** Verified: with only `..._SETTINGS_APPRISEURLS_3` set, `EnvSource` yields `{'settings': {'appriseurls': {'3': 'y'}}}`, a dict and not a list. confuse converts index keys to a list only when they are contiguous from 0. The operator gets no warning, but the setting does not take the shape the loader expects.
- **fix:** Route to the spec. Optionally, in `find_legacy_settings`, warn when the indices for one list name are not `0..n-1`. The check is names-only, so no value is needed.

### L3: The history-scan header parser keeps the previous file's `skip` state on a header it cannot parse
- **kind:** correctness (guard scope, global rule 4)
- **location:** `tests/test_settings_surface.py:296-306` (`_history_names`, `_DIFF_HEADER`)
- **description:** `core.quotePath=false` only stops octal-escaping of high bytes. Git still C-quotes paths that contain `"`, `\` or control characters, producing `diff --git "a/..." "b/..."`. `_DIFF_HEADER` does not match that header, so the `skip` flag from the previous file carries over. There are two outcomes:
  - after a vendored file, a documentation file's names are silently dropped (false green);
  - otherwise, a vendored file's names are counted.

  A path containing ` b/` is also attributed to the wrong file, because the `a/.*` is greedy. Both cases need unusual filenames, which is why this is low.
- **fix:** Treat any line starting with `diff --git ` that the regex does not match as a hard failure (`pytest.fail` naming the header). Alternatively, parse quoted headers by attributing from the `+++ b/<path>` line or by un-quoting. Add a probe commit with a quoted path.

### L4: The test-side legacy matcher re-implements the runtime matcher
- **kind:** simplification / drift risk
- **location:** `tests/test_settings_surface.py:153-163` (`_is_legacy_env_name`) vs `src/traefik_certificate_exporter/libs/legacy_settings.py:222-232` (`_matches`, `_legacy_entry`)
- **description:** The coverage test, the marker rule and the stale-marker rule decide what counts as "legacy" with a second copy of the exact-or-`*`-prefix rule. If the runtime rule changes (for example, to M1's case-normalisation, or to a different wildcard), the gate's rule and the runtime rule diverge without notice. The gate exists to prove that the runtime will warn on every documented name.
- **fix:** `return legacy_settings._legacy_entry("env", name) is not None`, so there is a single matcher.
