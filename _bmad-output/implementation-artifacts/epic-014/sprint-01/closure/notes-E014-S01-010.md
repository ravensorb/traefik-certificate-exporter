# E014-S01-010 — Hook and notifications only for changed domains; postexportcommand redaction

Extends **ADR-0045** (`docs/adr/0045-restart-policy-only-on-change-defer-not-drop.md`,
reserved and written by E014-S01-006) with decisions 13 and 14, and marks ADR-0014 §7
"Amended by ADR-0045". No new ADR reserved (S01-002/S01-003 precedent, as the story states).

## What was built

- `app.py` (`_run_passes`, run-at-start block): `domainsChanged = exporter.exportCertificates() or []`;
  hook and notifications only `if domainsChanged`, with that list; otherwise one INFO
  `No certificate changed; no hook or notification`. The restart call and S01-006's
  `try/finally: dockerManager.cancel()` are unchanged.
- `libs/certificate_exporter.py` (`AcmeCertificateFileHandler.__processPath`): the same guard
  and line. `NO_CHANGE_MESSAGE` constant defined beside `WATCH_DEBOUNCE_SECONDS`, imported by
  `app.py`, so both call sites log the same text.
- `libs/post_export.py`: every log line names only `argv[0]` (`Post-export command <prog>
  exited <n>: <stderr>`, `… completed successfully`, `… timed out …`, `… failed to start: <e>`);
  the parse failure logs `Post-export command could not be parsed; check its quoting` and
  neither the command nor `shlex`'s message. Signature unchanged; docstring states the
  changed-only contract.
- `libs/notify.py`: `send_export_notifications` docstring rewritten to the new contract,
  citing ADR-0045. Signature and body unchanged (the "no certificates were written" body
  branch is now unreachable from the call sites; left in place, the story scoped notify.py
  to the docstring).
- `libs/settings.py`: `("settings", "postexportcommand")` added to `SECRET_CONFIG_KEYS` with a
  rationale comment. No new redaction code; `_redact_secrets`, `_secret_leaf_names` and
  confuse's `dump(redact=True)` derive from the registry, and the existing registry-derived
  guard `test_every_declared_secret_key_is_redacted_in_every_sink` now also covers the key.
- Tests: the 13 named in the ACs, plus the S01-006 watch test file's quiet-line assertion
  (review F4).
- Docs: ADR-0045 (header "Amends: ADR-0014 §7", decisions 13-14, consequences, tests);
  ADR-0014 (second "Amended by" header line + a note under §7); `docs/operational.md` (new
  "When the post-export hook and notifications run: only on change" subsection under
  Monitoring, and "The hook command is a secret in the logs" under the trust boundary);
  `README.md` (`--post-export-command` help lines, Post-Export Hook section, Export
  notifications section).

## Decisions taken during implementation

1. **Quiet-pass line scope on the watch path.** The hook and notifications run once per store
   file in a drain (existing scope, ADR-0014), so the quiet line is logged once per store file
   whose export changed nothing. For a single `acme.json` (the normal deployment) that is once
   per pass. Stated in ADR-0045 decision 13 and `docs/operational.md`. Review F3 (Low) notes the
   line does not name the file → BL-E014-024.
2. **Out-of-list files changed.**
   - `libs/cli_args.py`: the `--post-export-command` help now states "only on change" and the
     program-name-only logging; the README usage block is a copy of that help (S01-006's
     precedent). Only the post-export lines of the README block were replaced; the rest of the
     block is already wrapped at mixed widths and was not regenerated.
   - `docker/README.md`: its bullet "A notification means 'an export pass completed', not 'a
     certificate changed'" stated the contract this story reverses; rewritten to "only on
     change". Leaving it would have shipped a contradicting operator doc.
   - `tests/test_app.py::test_sigterm_during_the_run_at_start_sweep_exits_cleanly` (existing):
     it parked the start-up sweep inside a `sleep 20` hook over an EMPTY data directory. Under
     the new policy an empty store changes nothing and runs no hook, so the sweep finished
     before SIGTERM. The test now plants one certificate (`acme_v2_lowercase_fixture()`), so the
     first pass into an empty output directory changes a domain and the hook runs. Assertions
     unchanged.
3. **Restart-recovery test** reuses S01-006's `FakeClient`/`FakeContainer`, `_env`, `_store`,
   `_domain_files`, `_set_mtime` from `tests/libs/test_docker.py` and the `real_chain()`-backed
   `acme_v2_certificate` fixture, driving the real `app._run` → real `AcmeCertificateExporter`
   → real `DockerManager` (client factory replaced by a `FakeClient` subclass with `ping` /
   `version`, which the start-up reachability check calls).

## Spine/ADR amendments for S02-003

Verified against the 2026-10-11 consolidated product spine, which states this story's target
(AD-9 hook/notification policy, AD-3 secret registry); route only where the merged text
differs from the below.

**Product spine AD-9 — the hook/notification clause (replacement text):**

> The post-export hook and the Apprise notifications act only on the domains whose exported
> artifacts changed in the pass (ADR-0043): at both call sites (`app._run`'s start-up pass,
> `AcmeCertificateFileHandler.__processPath` per store file) they run only when that list is
> non-empty and receive exactly it, so `TRAEFIK_CERTIFICATE_EXPORTER_EXPORTED_DOMAINS` and the
> notification body name only changed domains. When nothing changed, neither runs, and one INFO
> line `No certificate changed; no hook or notification` is logged. This holds for every pass,
> including the run-at-start pass, a run-once container, and a pass that only recovers a lost
> restart (AD-10). In a dry run the list is the domains that would change; both keep their
> dry-run skip lines and run nothing. ADR-0045 decision 13 (amends ADR-0014 §7).

**Product spine AD-3 — the secret registry clause (replacement text):**

> `SECRET_CONFIG_KEYS` declares `settings.pkcs12passphrase`, `settings.appriseurls` and
> `settings.postexportcommand`; every dump sink derives its redaction from it, value-aware
> (an unset secret renders `null`). Post-export hook log lines name only the program
> (`argv[0]`), never its arguments or the command string, and a parse failure names neither the
> command nor the parser message (ADR-0045 decision 14).

**ADR-0014 status block — keep both "Amended by" markers** (S02-003 must not collapse them):

> - **Amended by:** ADR-0043 ("exported domain list" means the domains at least one of whose artifacts changed on disk in the pass)
> - **Amended by:** ADR-0045 (§7: the post-export hook and notifications run only for the domains whose artifacts changed in the pass; when nothing changed, neither runs — a notification now means "a certificate changed")

**Product spine `.memlog.md` — append at merge:**

> - (decision) 2026-10-11 E014-S01-010: post-export hook and notifications run only for
>   changed domains, never on a pass that changed nothing; `postexportcommand` is a declared
>   secret and hook log lines name only `argv[0]` (ADR-0045 §13-14, amends ADR-0014 §7).

## 0.3.0 release notes (for E014-S02-005)

- The post-export hook and Apprise notifications run only when at least one domain changed,
  and list only the changed domains. In 0.2.x they ran after every pass, including every
  exporter start.
- `postexportcommand` is treated as a secret: it is redacted in DEBUG dumps, and hook log lines
  name only the program, not its arguments.
