# Code review: E014-S01-006 (restart only on change; defer, don't drop)

Reviewer role: bmad-code-review. Scope: this story's hunks only (see the task's file list).
Standards: ADR-0040 Decision §1-6, ADR-0041 Decision §1-2, the story's technical ACs and the
AG-13 / RV-1 carry-ins.

Summary: critical 0, high 0, medium 2, low 4.

The core design holds up. The lock is never held across a Docker round trip. The pending
entry is popped under the lock and the work runs outside it. The `remaining + 1` interval
is correct. The index is published by single assignment and writers are serialised (AG-13).
Failed certificates and failed resolvers carry their previous paths over (RV-1).
`python-dateutil` is used for exactly the one `isoparse` call that the dimension-6 answer
justifies, and `threading.Timer` is reused as justified. No other path join of base,
resolver and domain was found (ADR-0040 §2). The tests are not vacuous:
- case 2 asserts `timers == []`, so a deferral cannot hide a restart;
- the AG-13 test publishes a new store file mid-iteration, so in-place mutation would raise;
- the RV-1 test compares mtimes before and after, so a dropped entry gives `None`;
- the global `time.time` patch in the `clock` fixture is coherent, because `FakeContainer.restart` and `_always_newer` read the same clock.

## MEDIUM

### M1 (kind: claim). A trailing restart ignores the rate floor, so a container can restart twice within seconds

- **Location:** `src/traefik_certificate_exporter/libs/docker.py:449-460` (`_deferredRestart`, locked section)
- **Claims contradicted:**
  - Story AC "Rate floor kept": "No container is restarted more than once per `RESTART_COOLDOWN_SECONDS`."
  - ADR-0045 §7: "No container is restarted more than once per 300 s."
- **Problem:** Under the lock, the fire-time path checks only `__generation`. Then it overwrites `__lastRestart[cid] = time.time()` without checking whether another restart claimed the slot since the timer was armed. The timer fires at window end + 1 s. Suppose an immediate pass reserves the slot in `[windowEnd, fire time]`. Its `container.restart()` is still in flight (stop takes up to 10 s, and `StartedAt` only moves at start), so the fire-time `_needsRestart` still sees the old `StartedAt` and the deferred path restarts the container again.
- **Evidence:** A throwaway probe confirmed it (run, then deleted; nothing left in the tree). After a deferral, the probe advanced the clock past the window, called `_reserveRestart("c1", now)` (an in-flight immediate restart), advanced 0.5 s and fired the timer. The deferred path called `restart()` regardless.
- **Fix:** In the locked section, before recording, read `previousAt = self.__lastRestart.get(containerId)`. If `previousAt is not None and time.time() - previousAt < RESTART_COOLDOWN_SECONDS`, log INFO `Skipping deferred restart of container <id>: restarted within the window` and return.
  - This is safe. If that other restart fails, `_releaseRestart` restores the slot and the next pass recovers it by the same rule.
  - Add `test_deferred_restart_skipped_when_slot_reserved_since_arming`: arm, advance past the window, `_reserveRestart`, fire, then assert no restart.

## LOW

### L1 (kind: claim). The proxy allowlist misses endpoints the client always calls

- **Location:** `docs/operational.md:89-93` (the runbook step 3 allowlist line edited by this story)
- **Problem:** The doc says to allowlist only `GET /containers/json`, `GET /containers/{id}/json` and `POST /containers/{id}/restart`. That list is incomplete:
  - With docker-py 7.2.0 (installed), `docker.from_env()` leaves `version=None`, so `APIClient.__init__` calls `_retrieve_server_version()` (`docker/api/client.py:203-207`), which is `GET /version`, on every `_create_client()`.
  - `check()` also calls `GET /_ping`.
  - A proxy that allows exactly the three documented endpoints breaks client construction, so every restart fails with the start-up ERROR.
- **Fix:** Add `GET /_ping` and `GET /version` to the list. Note that Tecnativa's `PING`/`VERSION` sections are on by default.

### L2 (kind: claim). Interface and ADR-0040 drift is not recorded

- **Location:** `src/traefik_certificate_exporter/libs/certificate_exporter.py:495-497`, `:722-746`; `src/traefik_certificate_exporter/libs/docker.py:93-99`, `:116-118`
- **Problem:** The implementation departs from the written contracts in three places:
  - **Index shape:** the index is `sourceFile → {(resolverName, name) → tuple[Path]}`, where ADR-0040 §4 and the story's interface contract say `{name → set[Path]}`.
  - **Failed builds:** ADR-0040 §4 says domains "failing to build are not recorded". The code carries their previous paths over (RV-1).
  - **Pending state:** the story's contract names `__pending: dict[str, threading.Timer]` plus `__pendingDomains`. The code uses one `dict[str, _Pending]`.
  - All three are reasonable (RV-1 needs the resolver in the key). But only ADR-0045 §3 mentions the RV-1 carry-over, and ADR-0040 §4 still states the opposite with no "Amended by" marker.
- **Fix:**
  - Add an "Amended by ADR-0045 (RV-1)" marker to ADR-0040 §4 and route it through the S02-003 notes section.
  - List all three deviations in the notes file.

### L3 (kind: deletion, confidence: medium). The architecture sequence diagram still shows the removed domain-list contract

- **Location:** `docs/architecture.md:77-79`
- **Problem:** The diagram still shows `Handler->>Docker: restartLabeledContainers(domains)` / "match container label against domains". That contract was removed by this story. The diagram no longer matches the code, which evaluates `restartLabeledContainers(exporter.artifactMtime)` on every pass, by mtime against `StartedAt`.
- **Fix:** Change the call to `restartLabeledContainers(artifactMtime)` and the note to "restart if newest artifact mtime > StartedAt + 2 s (ADR-0045)". Alternatively, route it to S02-003 in the notes file.

### L4 (kind: claim). The runbook says a failed restart is "never retried in-process", then says the next ACME write recovers it

- **Location:** `docs/operational.md` runbook step 7 (diff line "a failed restart (logged at ERROR; never retried in-process)")
- **Problem:** The same paragraph says the next pass recovers it, and names "the next ACME write" as one such pass. That pass is in-process: the same process's next drain restarts the container by the rule, subject to the floor. An operator could read "never retried in-process" as "restart the exporter to recover".
- **Fix:** Reword to "not re-armed; the next pass (a later ACME write in this process, or the next start-up pass) restarts it".

## Checks with no finding

- **Lock discipline / cancel-vs-fire:**
  - pop under the lock;
  - Docker work outside it;
  - `cancel()` clears the dict and bumps the generation, and the generation is re-checked before recording;
  - `timer.cancel()` runs outside the lock.
  - A `cancel()` that lands after the generation check but before `container.restart()` still restarts. That is a sub-millisecond window on a daemon thread at exit, and the result is benign.
- **Remaining math:** `remaining = previousAt + 300 - now`, with `Timer(remaining + 1)`. The test asserts `270 + 1`, and the dry-run log asserts `291s`.
- **Every-pass evaluation:**
  - app runs it after exporting, the hook and notifications;
  - watch runs it once per file per drain;
  - an unchanged pass makes only a list/inspect round trip;
  - dry run logs `[DRYRUN] would restart` on every pass for a container that already satisfies the rule, as the AC specifies.
- **`try/finally` in `_run`:** it covers the both-false branch, the run-at-start exception path and the watch interrupt path, and all four are parametrized in `test_run_cancels_pending_restarts_on_every_exit_path`.
- **ADR-0041:** `tests/libs/test_docker_engine.py` was updated to the `artifactMtime` signature with a `StartedAt + 3` stub. No test passes a domain list any more.
- **Reused-before-written:** no hand-rolled timestamp parsing, scheduler or hashing.
- **Deletion check:** the removed `domains is None` handling is re-expressed as `test_a_lookup_that_knows_no_domain_restarts_nothing`. Label parsing now strips whitespace, a behaviour-compatible widening.
