# E014-S01-008 — CLI/output hygiene: notes and evidence

## What changed

- `src/traefik_certificate_exporter/libs/settings.py`: `_URL_SCHEME` (RFC 3986 scheme regex),
  `_redact_url_like(item)` and `_redact_secret_value(value)` beside `_is_empty_secret`; the
  `_redact_secrets` dict branch now routes a present declared-secret value through
  `_redact_secret_value`, which redacts a list per element (`<scheme>://***REDACTED***`, or
  `***REDACTED***` without a scheme or for a non-string; empty elements and empty lists pass
  through). `_dump_settings` logs `json.dumps(safe, indent=2, default=str)`.
- `src/traefik_certificate_exporter/libs/cli_args.py`: `metavar=` on every value-taking action
  (`PATH`, `GLOB`, `RESOLVER`, `PASSPHRASE`, `COMMAND`, `LEVEL`, `DOMAIN`), as the story's table
  specifies; `-c` help says "the configuration file to load"; `-ll` help lists the choices via
  `%(choices)s`. `parse_args_strict()` uses `parse_known_args()` and calls
  `globalArgParser.error()` on ANY leftover token, with `_unrecognized_arguments_message` adding
  a `Did you mean '<flag>'?` line per `-`-token (matched on the part before `=`) through
  `suggest.nearest_name`, and always `Try '--help' for full usage.`. There is no `difflib` in
  `cli_args.py`.
- `src/traefik_certificate_exporter/libs/legacy_settings.py` (outside Files in scope, one-line
  change): `from .suggest import nearest_name` became `from . import suggest` /
  `suggest.nearest_name(...)`. Without it, the AC's shared-helper test ("`suggest.nearest_name`
  is patched once") cannot reach the env path, because a `from`-import binds the function at
  import time. No behaviour change.
- `README.md`: usage block regenerated from `COLUMNS=220 traefik-certificate-exporter --help`.
  The strict-parse paragraph now mentions the suggestion, the `--help` pointer, and that stray
  positionals also exit 2.
- Tests: 2 tests and 2 helpers appended to `tests/libs/test_settings.py`, plus the existing
  `test_a_secret_nested_in_a_list_of_objects_is_redacted` assertion updated from the old
  scalar collapse to the per-element form (it now also asserts that `PLANTED` is absent).
  6 tests appended to `tests/libs/test_cli_args.py`, including
  `test_stray_positional_argument_still_exits_two` (BL-E014-002), and
  `test_every_long_option_is_in_readme` in `tests/test_settings_surface.py`.

## Spine/ADR amendments for S02-003

- **Product spine AD-3: none — checked AD-3 and ADR-0025.** AD-3's Rule already says "a
  declared-secret list is redacted per element, keeping only the `<scheme>://` and the
  count", which matches this story's code. Pre-existing and not introduced here: the same
  sentence says redaction of every sink derives "via `confuse`'s `redact`". The settings dump
  and the argparse-namespace sink actually use `settings._redact_secrets`, which derives from
  the same `SECRET_CONFIG_KEYS` registry, not from confuse. S02-003 may want to reword it.
  Suggested replacement for that clause: "and redaction of every sink derives from that
  registry: the config dump via `confuse`'s `redact`, the settings dump and the raw argparse
  namespace via `settings._redact_secrets`;".
- **ADR-0025: needs a change.** Its Decision paragraph says `parse_args_strict()` calls
  `globalArgParser.parse_args()`. The function now calls `parse_known_args()` and then
  `globalArgParser.error()`. Replacement for the sentence beginning "A new function
  `parse_args_strict() -> argparse.Namespace` is added…":

  > A new function `parse_args_strict() -> argparse.Namespace` is added to `cli_args.py`. It
  > calls `globalArgParser.parse_known_args()` and, if any token is left over, dash or not,
  > calls `globalArgParser.error()`, which exits 2 with the usage line and
  > `unrecognized arguments: <tokens>`. For each leftover `-`-token with a close match among the
  > registered option strings, a `Did you mean '<flag>'?` line is added, computed by
  > `libs/suggest.nearest_name`, the helper the env-name suggestions also use. The message
  > always ends with `Try '--help' for full usage.` (E014-S01-008).

  Replacement for the Consequences "Negative / trade-offs accepted" bullet:

  > `parse_known_args()` runs twice in the `main()` path, once at import and once in
  > `parse_args_strict()`. The cost is negligible (a short argv), and accepting it avoids a
  > single-parse mechanism that would complicate the import-time/strict-time split.
