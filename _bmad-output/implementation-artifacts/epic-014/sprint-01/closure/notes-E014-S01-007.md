## Decisions taken during implementation

1. **`--aliases on` added to both pip-audit entries** (deviation from the AC 3 entry text).
   pip-audit 2.10.1 prints its primary `PYSEC-*` ID only; without aliases the output never
   names `GHSA-2xpw-w6gg-jr37`, which Verification rows 3 and 14 require. The flag only adds a
   column; it changes neither scope nor exit status. Recorded in the hook comment.
2. **`docs/developer.md:46`** (not in Files in scope): its recipe table said `just install` runs
   `poetry install`, which this story made false. That one cell now says
   `poetry sync --all-groups`. Nothing else in the file changed.
3. **Probe clones are seeded with the repo's `.poetry/` plugin env** (`cp -r .poetry`). Without
   it, `poetry add` in a fresh clone fails resolving the `poetry-dynamic-versioning` plugin
   against the user environment (`docker-apps-cfgmgr` pins `ruamel.yaml ^0.18.14`), which is the
   execution-notes failure. The first row-3 attempt failed this way (exit 1 from `poetry install`,
   not from the hook); that attempt is not evidence and is not counted.
4. **Row 14 uses `uvx --from 'pip-tools==7.5.3' --with 'pip<25.3'`** instead of
   `pipx run --spec 'pip-tools==7.5.3'`: `pipx` is not installed on this host, and pip-tools 7.5.3
   on the newest pip fails with `ImportError: cannot import name 'stdlib_pkgs'`. The tool only
   generates the hashed probe file, so this does not change what is tested. Row 14 ran in a
   fresh clone (synced with `poetry sync --all-groups`) rather than row 13's clone, because the
   first attempt's cleanup had already removed it; the bootstrap hook does not read the lock
   groups, so this is equivalent.
5. **Lock-scope probe package:** `P=jinja2==3.1.4`, not in `poetry.lock` (`poetry show jinja2`
   → "Package jinja2 not found"); OSV advisories GHSA-q2x7-8rv6-6q7h (PYSEC-2026-1475),
   GHSA-gmj6-6f8f-6699, GHSA-cpwx-vrp4-4pq7.
6. **`poetry update` moved the dev-group `poetry` to 2.5.1** (inside `^2.4.2`). CI and the
   Dockerfile still install Poetry 2.4.2 from their own pins; S02-001 owns that bootstrap.
7. `oauthlib` relocked 3.3.1 → 4.0.0 (transitive via apprise/requests-oauthlib); 3.3.1 carried
   GHSA-xpv3-w29h-x7cv. The notify tests pass on it.

## Review

`review-E014-S01-007.md`: critical 0, high 0, medium 1, low 4. One fix iteration:

- F1 (medium, marker-gated lock entries unaudited while text claimed "every group"): the limit
  is now stated in the hook comment, the walkthrough row and `docs/developer.md`, and routed to
  NFR-3, AD-3 and ADR-0042 below. Backlog BL-E014-023 (Medium) holds the gap itself (candidate
  owners: E014-S02-005's 3.10 run, or ADR-0042's pylock revisit).
- F2 (low): ADR-0042 `--aliases on` note routed below (ADRs are not edited from a code story).
- F3 (low): the AD-3 replacement now starts with ADR-0042's sentence verbatim.
- F4 (low): recorded for S02-001 below.
- F5 (low): offline probe run; it found the claim was imprecise, and the wording was corrected:
  - warm cache, proxy to a closed port:
    `HTTPS_PROXY=http://127.0.0.1:9 … poetry run pre-commit run pip-audit --all-files` →
    `Passed`, exit 0 (pip's HTTP cache answered; PyPI sends `cache-control: max-age=900`);
  - cold cache, same proxy:
    `poetry run pip-audit --skip-editable --progress-spinner off --cache-dir "$(mktemp -d)"` →
    `requests.exceptions.ProxyError … Unable to connect to proxy`, exit 1.
  So offline it fails, except within 15 minutes of an online run, when the result is that run's
  data. Not a stale-data false green beyond 15 minutes; CI starts cold.
