### Implementation decisions and assumptions

- **Nearest-name matching ignores the shared prefix.** `difflib` compares the part after
  `TRAEFIK_CERTIFICATE_EXPORTER_`. Over full names, the 29 common characters made every name
  "close": `…_FOO` was suggested `…_CORRELATION_ID`.
- **Mixed case** (review M1). confuse matches the prefix case-sensitively and lowercases the
  rest, so `…_settings_DataPath` sets `settings.datapath`. Detection therefore compares
  confuse-mapped names upper-cased. The `os.getenv` names stay exact-match, because `getenv`
  is case-sensitive: `…_logging_level` is reported as unknown, with `did you mean …_LOGGING_LEVEL?`.
- **Hook-output names** (review M2). `…_EXPORTED_DOMAINS` and `…_CORRELATION_ID` stay valid, as
  the AC says (no warning), but they are never offered as a suggestion (`HOOK_OUTPUT_ENV_NAMES`).
- **The history scan excludes commit messages** (`--format=`): they are not operator
  documentation. Verification row 1, as written, includes messages and vendored paths, so its
  scope is wider than the test's. Its output below contains no name outside the table either.
- **Detection runs inside `loadFromFile`.** The architect rejected arch-gate AG-4, which asked
  to move it.
- **Process deviation.** The development was done directly by this story agent rather than by
  a separately spawned dev subagent, because I was dispatched as the dedicated agent for the
  story. The review was a separate subagent, bracketed with dispatch open/close.
  `just check` ran twice: once before review, and once after the fix iteration, because the
  gate is the definition of done and the code changed after the first run.
- **How expected-fail probe runs are recorded.** This follows E014-S01-004's convention: a
  probe is recorded as a pass when it fails as expected. Probes 7a, 7b, 8, 9a and 9c were first
  recorded with the raw pytest exit code (1, the expected failure). The verdict (0 = failed as
  expected) was then appended under the same label, so the derived `tests_passing` reflects
  probe verdicts. Both entries remain in `test_runs`.

## Spine/ADR amendments for S02-003

**Product spine AD-6.** Verify that the 2026-10-11 consolidated text says the following, and
route only the deltas:

> At start-up, after logging is configured and the config file is located, the exporter
> checks setting names once.
>
> - Each `TRAEFIK_CERTIFICATE_EXPORTER_*` environment name and each raw config-file key path
>   (read with `yaml.safe_load`) that matches a row of `LEGACY_SETTING_NAMES`
>   (`libs/legacy_settings.py`, the single legacy → replacement table) gives one WARNING. The
>   WARNING names the old name, where it was found and the replacement, and says the old name
>   is ignored.
> - An environment name that maps to no setting gives one WARNING with the nearest valid name
>   (`suggest.nearest_name`, `difflib`, cutoff 0.6, compared after the common prefix). With no
>   close match, it points to README `## Usage`.
> - Names are matched as confuse sees them: everything after the prefix is case-insensitive.
>   Names read with `os.getenv` (`LOGGING_*`) are exact.
> - Values are never logged.
> - Legacy names are not aliases: they stay without effect.
> - The check is advisory: a failure in it is logged once and start-up continues.
>
> Coverage is enforced in `tests/test_settings_surface.py`:
>
> - `test_legacy_map_covers_documented_names` scans `git log -p HEAD` over the documentation
>   pathspecs, minus the pre-commit vendored `exclude:`. Every name ever documented must be
>   valid, a placeholder prefix, or a table row. The test fails on a shallow clone.
> - Files that list legacy names by design carry the marker
>   `tce-settings-scan: legacy-names-listed`, and a marked file must quote at least one legacy
>   name.
>
> The policy (warn, ignore, no aliases) has no ADR, by explicit decision (C-16b): it is local
> to settings loading, reversible, and changes no stored data or interface. Revisit if aliases
> are ever wanted, because an alias is a compatibility contract.

**Deltas from implementation, for S02-003 to route:**

1. **Timing wording** (review L1, BL-E014-014). The WARNINGs are emitted before the first pass
   but outside any pass correlation id. The settings load precedes the only start-up id, which
   exists only under `runatstart`. Amend "under the start-up correlation_id" to "before the
   first pass, outside any pass id", unless BL-E014-014 is fixed by binding a start-up id
   around the settings load.
2. **Hook-output names** (review M2). `…_EXPORTED_DOMAINS` and `…_CORRELATION_ID` are set by
   the exporter for the post-export command. They are valid names, but they are never offered
   as suggestions. Setting them on the exporter is not warned about (the AC as written).
   Decide whether AD-6 should warn: "set by the exporter for the post-export command; has no
   effect here".
3. **Sparse list indices** (review L2, BL-E014-015). Indices that are not contiguous from 0 are
   accepted silently, although confuse then yields a mapping, not a list.

**Contract for writers** (E014-S01-005, E014-S02-003, E014-S02-005):

- Placeholders end in `_` (`TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_<KEY>`), which is
  E014-S01-004's rule. A grep pattern that is a bare prefix (pygrep
  `entry: 'TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_'`) passes as a placeholder, in the tree and
  in the history.
- A file that lists legacy names must carry the marker `tce-settings-scan: legacy-names-listed`
  in a comment (`<!-- … -->` in Markdown, `#` in YAML and Python), and must quote at least one
  `LEGACY_SETTING_NAMES` name. Otherwise `test_stale_marker_fails` fails. `docs/upgrading.md`
  must carry it.
- In a marked documentation file, every non-legacy name must still be valid or a placeholder.
- A replacement written into `LEGACY_SETTING_NAMES` must be a valid name, enforced by
  `test_legacy_replacements_are_valid`.
- Any name ever committed in scope that is neither valid nor a placeholder needs a
  `LEGACY_SETTING_NAMES` row. History is immutable, so the remedy is a row, never a scope
  exclusion.
- A new env name the source reads with `os.getenv` must be a module constant included in
  `legacy_settings.SOURCE_ENV_NAMES`, enforced by
  `test_runtime_valid_env_names_equal_source_scan`.
- E014-S01-008 must call `suggest.nearest_name` for its `Did you mean` line.

**Scan contract extension.** The marker token `tce-settings-scan: legacy-names-listed` permits
`LEGACY_SETTING_NAMES` names in that file only, and a marked file must contain at least one.
The src literal scan skips marked `.py` files. History hunks are attributed by their
`diff --git` header and filtered with the same `_vendored_exclude_pattern()`.

## 0.3.0 release notes (for E014-S02-005 `docs/upgrading.md`)

- The exporter warns at start-up about legacy or misspelled setting names (environment and
  config file), names the replacement, and ignores the old name. Values are never logged.
- Unknown `TRAEFIK_CERTIFICATE_EXPORTER_*` environment variables get one WARNING with the
  nearest valid name.
