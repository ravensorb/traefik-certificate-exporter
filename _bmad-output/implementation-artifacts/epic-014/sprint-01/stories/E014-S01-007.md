**Found while elaborating:**

- `src/traefik_certificate_exporter/libs/logging_utils.py:16` does `import yaml`, but `pyyaml` is declared only in the **dev** group (`pyproject.toml:37`). At runtime it arrives only transitively, through `confuse`. That is the NFR-3 failure class: an undeclared direct import.
- An untracked `uv.lock` at the repo root (`git status`) contradicts ADR-0001 (Poetry is the single dependency source) and is not ignored.

**There is no gate** that catches a vulnerable lock (research §8 "Gap"), or a declared-but-unused or imported-but-undeclared dependency. Under global rule 3, each rule ships with its check. Under global rule 1 and CI AD-4 ("policy is enforced only by standard tools' configuration … `tests/` holds product tests only"), both checks are maintained tools run as pre-commit hooks: `pip-audit` for advisories, `deptry` for declared-vs-imported. Neither is a hand-written test.

**`requests` and E014-S01-001.** S01-001 catches transport errors as `docker.errors.DockerException` and `OSError` (`requests.RequestException` subclasses `IOError`) and does not import `requests`. So removing `requests` here leaves no undeclared import. If an `import requests` ever reappears in `src/`, `deptry` reports it as DEP003 (transitive-only) and the hook fails (F-10).

Upstream branch `3.24` still pins s6-overlay 3.2.1.0. E014-S01-005's `finish`/`halt` semantics were probed on 3.2.1.0, so they must be re-verified on the new digest.

**Sequencing.** This story lands **after** E014-S01-001, which moves `docker` to `^7.2`, and after S01-005, whose s6 behaviour the base bump must preserve.

3. **pip-audit gate.** `pip-audit` is added to the dev group, with a `repo: local` pre-commit hook:
   - `id: pip-audit`
   - `language: system`
   - `entry: poetry run pip-audit --skip-editable --progress-spinner off`
   - `pass_filenames: false`
   - `files: ^(pyproject\.toml|poetry\.lock)$`

   `just check` and CI's `build.yaml`, both of which run `pre-commit run --all-files`, therefore always run it. It passes on the relocked environment. The comment above it states the scope (every lock group, ADR-0042), the offline failure, and the `--ignore-vuln` policy.

   **Scope (ADR-0042).**
   - The `install` recipe in `justfile` and the "Install Poetry and the project" step in `.github/workflows/build.yaml` run `poetry sync --all-groups` instead of `poetry install`, so the audited venv is exactly `poetry.lock`, every group included. No group is named.

     - `id: pip-audit-bootstrap`
     - `language: system`
     - `entry: bash -c 'rc=0; for f; do poetry run pip-audit --require-hashes --disable-pip --progress-spinner off -r "$f" || rc=1; done; exit "$rc"' --`
     - `pass_filenames: true`
     - `files: ^\.github/requirements/[^/]+\.txt$`

     Its file set is the glob, never a named file. The directory is empty until E014-S02-001, so pre-commit skips the hook until then. Its comment cites ADR-0042 and the same offline and `--ignore-vuln` policy.

### Error and edge case handling

- **pip-audit offline (no network):** the hook fails. That is acceptable, and it is stated in the hook comment and the walkthrough. Under `pre-commit run` on a normal commit, a commit that touches neither `pyproject.toml` nor `poetry.lock` does not run it; `just check` (`--all-files`) always does.
- **A new advisory without a fix:** the hook fails. The only accepted remedy besides upgrading is `--ignore-vuln <ID>` added to the hook `entry`, with a comment naming the ID, the reason and a backlog `BL-` key. No tool polices the comment; review does, and that limit is stated in the hook comment.
- **deptry cannot map a distribution to an import name:** it reports the dependency as unused (DEP002). The fix is a `package_module_name_map` entry with a comment, never a rule ignore.
- **A conditional or optional import** (inside `try/except ImportError`): deptry still counts it. If one is ever needed, it goes through `per_rule_ignores` with a reason and a `BL-` key.
- **watchdog 6 behaviour change** surfacing in the watch tests: fix the call site and record the change. Pinning back to 2.x is not acceptable.

Spec: none — l3io-plan run, no spec index bound

### Observability requirements

N/A — dependency and gate changes add no runtime logging. pip-audit's output (package, version, advisory ID, fix version) and deptry's (rule code, package, file and line) are the gates' diagnostics and appear in CI logs.

### Security considerations

- The point of the story: remove known-vulnerable transitive versions (urllib3 HIGH ×6) and add a standing gate so they cannot return unnoticed.
- pip-audit queries PyPI/OSV over HTTPS. No credentials are involved. deptry runs offline over the local tree.
- Removing unused dependencies shrinks the install's attack surface, and deptry keeps it from growing back silently.
- The base-image digest bump picks up Alpine package security updates. The digest pin itself (AD-2) stays.

Spec: none — l3io-plan run, no spec index bound
