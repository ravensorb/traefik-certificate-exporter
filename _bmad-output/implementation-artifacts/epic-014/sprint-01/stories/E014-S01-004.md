**Log level cannot be changed in the container.**

- `-ll` is CLI-only (`cli_args.py:123-130`, default `"INFO"`).
- `app.py:85-92` reads only `globalArgs.logginglevel`, and logging is set up before settings load.
- The s6 service hard-codes `traefik-certificate-exporter -c /config/config.yaml` (`svc-traefik-certificate-exporter/run:26,31`).
- Even so, `docs/operational.md:39` and `docker/README.md:115` tell container operators to use `-ll DEBUG`.

**BL-E011-032.** `config.sample.yml:17-21` says both logging switches "are opt-in and default to off". The image ships `TRAEFIK_CERTIFICATE_EXPORTER_LOGGING_CONSOLEONLY=true` (`docker/Dockerfile:124`).

**Decision taken here (research §5 "Recommended").** Add `TRAEFIK_CERTIFICATE_EXPORTER_LOGGING_LEVEL`. It is read with `os.getenv` in `app.py` as the fallback when `-ll` is not given, and `-ll`'s argparse default becomes `None`.

- This matches the existing `LOGGING_CONSOLEONLY` / `LOGGING_CONSOLEJSON` / `LOGGING_CFGFILE` family, which is also read before settings load.
- A config-file `logging.level` key is **not** added, because the file is read after logging is configured.
- **Assumption, recorded:** an invalid env value falls back to INFO with one WARNING naming the variable and the allowed values. It does not exit. Logging verbosity is not a correctness setting, and exiting would put a watch-mode container into an s6 respawn loop.

## Business acceptance criteria

### Outcome

- An operator who passes `--restart-container`, or copies any environment variable from `docker/README.md` or `docker/docker-compose.yml`, gets the documented behaviour. Copying a sample no longer turns a setting silently off.
- A container operator can raise verbosity with `-e TRAEFIK_CERTIFICATE_EXPORTER_LOGGING_LEVEL=DEBUG`.
- A future documentation or CLI change that names a setting nothing reads fails `just check`.
- An operator still using an old or misspelled name (for example `TRAEFIK_CERTIFICATE_EXPORTER_RESTART_CONTAINERS` from the old compose sample) sees a start-up WARNING telling them the exact name to use instead, rather than a setting that is silently off.

### Non-goals

- No `--restart-containers` alias and no flag renames. The flag name stays; only its `dest` is fixed.
- No config-file `logging.level` key. Logging is configured before the file is read.
- No support for the dead names as deprecated aliases. They never worked, so no one depends on them. Detection only warns; a legacy name still has no effect.
- No nearest-name suggestion for unknown config-file keys that are not in the legacy table. The maintainer asked for suggestions on unknown env vars; config files get the legacy-table check only. Recorded as an assumption; revisit if operators report silent config-key typos.
- Does not change metavars, typo suggestions or the settings dump format (E014-S01-008).
- Does not change how s6 reads `watchforchanges` (E014-S01-005).
- Does not change precedence (CLI > env > file > default).

## Technical acceptance criteria

### Interface contracts

- `cli_args.py`:
  - `--restart-container`: `dest="settings.restartcontainers"`.
  - `-ll/--log-level`: `default=None`, with `choices` unchanged. The help text states the env fallback and the effective default INFO.
- `app.py`: new private `_resolve_log_level(cli_value: str | None) -> str`. It returns an upper-case level name, reads `os.getenv("TRAEFIK_CERTIFICATE_EXPORTER_LOGGING_LEVEL")`, and emits the invalid-value WARNING after logging is set up. `main()` uses its result for `setup_logging(default_level=...)` and `logger.setLevel(...)`.
- `config_default.yaml`: three keys declared `null`. There is no shape change for the other keys.
- `libs/legacy_settings.py` (new):
  - `LegacyName`, a frozen dataclass: `source: Literal["env", "config"]`, `name: str` (a trailing `*` means prefix match), `replacement: str | None`, `hint: str` (the fix in words, used when `replacement` is `None`).
  - `LEGACY_SETTING_NAMES: tuple[LegacyName, ...]`, the single table. The module carries the `tce-settings-scan: legacy-names-listed` marker comment.
  - `valid_env_names() -> frozenset[str]`: derived from `config_default.yaml` leaves and lists via the confuse rule, plus the `src` env-name literals (`LOGGING_*`, `EXPORTED_DOMAINS`, `CORRELATION_ID`). ### Error and edge case handling

- **Invalid `LOGGING_LEVEL`** (e.g. `verbose`): INFO plus one WARNING naming the variable, the value (sanitized) and the allowed set.
- **Empty `LOGGING_LEVEL`:** treated as unset, with no warning.
- **Quoted value** (`"DEBUG"`, which Compose passes through when quoted): strip one pair of surrounding quotes before validating, because the documented samples historically quoted values.
- **An env name with an integer index** (`APPRISEURLS_0`): the trailing index is dropped before the path check.
- **An env name that is a prefix of a dict path** (`SETTINGS_DOMAINS`): it is not a leaf, so it fails the check. Only leaves and lists are valid targets.
- **Legacy and new name both set** (`…_RESTART_CONTAINERS` and `…_SETTINGS_RESTARTCONTAINERS`): one WARNING for the legacy name, which is ignored; the new name takes effect as usual.
- **Prefix legacy entry** (`…_NOTIFY_*`): several matching vars (`…_NOTIFY_0`, `…_NOTIFY_1`) give one WARNING per variable name, each pointing to `…_SETTINGS_APPRISEURLS_<n>`.
- **Indexed valid name** (`…_SETTINGS_APPRISEURLS_3`): valid after dropping the index; no warning.
- **Unknown name with no close match** (`…_FOO`): one WARNING saying it matches no setting, with the README pointer, and no suggestion.
- **Config file absent or unreadable:** config detection is skipped; the existing config-load error handling is unchanged.
- **Same name in env and config** (not possible today; names differ per source): each source is reported separately.
- Detection never raises: a failure inside it is logged once at WARNING and start-up continues, because it is advisory.

### Security considerations
