**M1.** `src/traefik_certificate_exporter/libs/cli_args.py:73` sets `dest="settings.restartcontainer"`, but the settings loader reads `settings.restartcontainers` (`settings.py:363`).

- `--restart-container` (documented in `README.md:22,42` and `docs/operational.md:63`) therefore sets a key nothing reads. The review probe showed `restartContainers=False` even with the flag set.

**M2 / BL-E013-042.** Env names that nothing reads (research §5 table "Documented names that map to nothing"):

- Compose list-form values are quoted (`- FOO="/data"`). Compose passes the quotes through, and the raw `os.getenv` readers do not strip them (research §5 compose probe).
- `docker/docker-compose.yml:1` uses the obsolete `version:` key.

**Log level cannot be changed in the container.**

- `-ll` is CLI-only (`cli_args.py:123-130`, default `"INFO"`).
- `app.py:85-92` reads only `globalArgs.logginglevel`, and logging is set up before settings load.
- The s6 service hard-codes `traefik-certificate-exporter -c /config/config.yaml` (`svc-traefik-certificate-exporter/run:26,31`).
- Even so, `docs/operational.md:39` and `docker/README.md:115` tell container operators to use `-ll DEBUG`.

**BL-E011-032.** `config.sample.yml:17-21` says both logging switches "are opt-in and default to off". The image ships `TRAEFIK_CERTIFICATE_EXPORTER_LOGGING_CONSOLEONLY=true` (`docker/Dockerfile:124`).

**Decision taken here (research §5 "Recommended").** Add `TRAEFIK_CERTIFICATE_EXPORTER_LOGGING_LEVEL`. It is read with `os.getenv` in `app.py` as the fallback when `-ll` is not given, and `-ll`'s argparse default becomes `None`.

- This matches the existing `LOGGING_CONSOLEONLY` / `LOGGING_CONSOLEJSON` / `LOGGING_CFGFILE` family, which is also read before settings load.
- A config-file `logging.level` key is **not** added, because the file is read after logging is configured.
- **Assumption, recorded:** an invalid env value falls back to INFO with one WARNING naming the variable and the allowed values. It does not exit. Logging verbosity is not a correctness setting, and exiting would put a watch-mode container into an s6 respawn loop.

## Business acceptance criteria

### Outcome

- An operator who passes `--restart-container`, or copies any environment variable from `docker/README.md` or `docker/docker-compose.yml`, gets the documented behaviour. Copying a sample no longer turns a setting silently off.
- A container operator can raise verbosity with `-e TRAEFIK_CERTIFICATE_EXPORTER_LOGGING_LEVEL=DEBUG`.
- A future documentation or CLI change that names a setting nothing reads fails `just check`.

E014-S02-005 generates `docs/upgrading.md` from this list. Every bullet is a user-visible change.

- "`--restart-container` now enables restarts. It previously set an unread key, so restarts were off even with the flag."
- "The sample `docker-compose.yml` and `docker/README.md` environment variable names are corrected. - "`config.sample.yml` and the image's seed config state the logging defaults correctly (the image sets `CONSOLEONLY=true`)."

### Non-goals

- No `--restart-containers` alias and no flag renames. The flag name stays; only its `dest` is fixed.
- No config-file `logging.level` key. Logging is configured before the file is read.
- No detection of, or warning about, legacy or unknown setting names at runtime, and no legacy-name table (E014-S01-009). The dead names are corrected in the docs here; they never worked, so no aliases are added.
- Does not change metavars, typo suggestions or the settings dump format (E014-S01-008).
- Does not change how s6 reads `watchforchanges` (E014-S01-005).
- Does not change precedence (CLI > env > file > default).

### Error and edge case handling

- **Invalid `LOGGING_LEVEL`** (e.g. `verbose`): INFO plus one WARNING naming the variable, the value (sanitized) and the allowed set.
- **Empty `LOGGING_LEVEL`:** treated as unset, with no warning.
- **Quoted value** (`"DEBUG"`, which Compose passes through when quoted): strip one pair of surrounding quotes before validating, because the documented samples historically quoted values.
- **An env name with an integer index** (`APPRISEURLS_0`): the trailing index is dropped before the path check.
- **An env name that is a prefix of a dict path** (`SETTINGS_DOMAINS`): it is not a leaf, so it fails the check. Only leaves and lists are valid targets.
