# Docker SDK 7.2 and a restart path that really works

## Context

**Review finding:** B1 (BLOCKER) in `_bmad-output/implementation-artifacts/review-all-epics-2026-10-10/review-product.md`. Related: FR-8 row of the PRD capability trace, and NFR-5 ("blind to B1").
**Research:** `_bmad-output/planning-artifacts/research/research-2026-10-10-release-0.3.0.md` §1 "Docker SDK for Python (B1)".

**Problem.** FR-8 (restart labeled containers after an export) cannot work in any shipped artifact.

- `pyproject.toml:17` declares `docker = "^6.0.0"`, and the lock resolves `docker` 6.1.3 alongside `requests` 2.32.3.
- That pair fails on the first Engine call with `DockerException: Error while fetching server API version: Not supported URL scheme http+docker`. Research §1 local probe reproduced this both against the real `/var/run/docker.sock` and against a missing socket.
- The fix shipped in docker-py **7.1.0** (PR docker/docker-py#3257, "Fix for requests 2.32"). The latest release is **7.2.0** (2026-07-09). Research §1 probe: 7.1.0 and 7.2.0 both `ping()` → `True`.
- The failure is invisible:
  - `src/traefik_certificate_exporter/libs/docker.py:121-122` catches it and logs "Failed restarting containers";
  - every test in `tests/libs/test_docker.py` patches `docker.from_env` (`:44`, `:57`, and onwards), so `just check` is green.
- `restartcontainers` is one of the inputs that keeps the container process **root** under ADR-0030 as amended 2026-10-10 (root is also kept whenever the ACME store is not provably readable, the stock-Traefik default). Today a deployment that keeps root for restarts pays that privilege cost for a feature that does not work.

**7.2.0 behaviour change to neutralise.** Research §1:

- `docker.from_env()` now honours the active Docker CLI context when `DOCKER_HOST` is unset (new kwarg `use_context`, default `True`; `docker/client.py@7.2.0`).
- A PyPI install on a workstation with a non-default context would silently start restarting containers on a *different* daemon.
- This story keeps today's target by calling `from_env(use_context=False)`. `DOCKER_HOST` is still honoured, as now. The restart ADR written in E014-S01-006 records this choice.

**Ordering.** E014-S01-007 (dependency refresh) lands after this story, so only the `docker` constraint moves here. Removing `docker-pycreds` and the direct `requests` is S01-007's work.

**Stale text this story creates.** E014-S02-003 updates these from this story's notes file (AC 11); this story does not edit them:

No ADR is changed. The client target is preserved, not changed. The `use_context=False` choice is recorded **now**, in this story's notes file and as a `- (decision)` line appended to the product spine's `.memlog.md` at merge; E014-S01-006's restart ADR then records it formally (A-15).

**What reaches the restart path.** E014-S01-006 changes the call to `restartLabeledContainers(exporter.artifactMtime)` on every pass, including passes with no change; a labeled container is restarted when its domains' newest exported file is more than 2 s newer than its start (FR-15, product AD-10). This story does not change what the caller passes; it only makes the call reach the Engine.

## Acceptance Criteria

1. `pyproject.toml` declares `docker = "^7.2"`. `poetry.lock` resolves docker ≥ 7.2.0, produced by `poetry lock` after the constraint change, and `poetry check --lock` passes.
2. `DockerManager` builds its client through one private factory, `_create_client()`, which calls `docker.from_env(use_context=False)`. No other call site constructs a Docker client.
3. A new **unmocked** test builds `docker.DockerClient(base_url=f"unix://{tmp_path}/missing.sock")`, calls `.ping()`, and asserts both of these:
   - it raises `docker.errors.DockerException`;
   - `"Not supported URL scheme"` does not appear in `str(exc)`.

   The test FAILS on the current lock (6.1.3) and passes on 7.2.
4. A new **unmocked** test runs `DockerManager(...).restartLabeledContainers(["a.example.test"])` with `restartContainers=True` and `DOCKER_HOST=unix://<tmp>/missing.sock` (monkeypatched env).
   - It asserts that exactly one ERROR record is emitted, that the record names the unreachable endpoint, and that it does not contain "Not supported URL scheme".
   - It asserts that no exception propagates.
   - It FAILS on the current code, because the ERROR text is the scheme error.
5. A new **unmocked** test proves the CLI context is ignored:
   - it writes a `~/.docker/config.json` with `"currentContext": "elsewhere"`, plus a matching context meta pointing at `unix://<tmp>/elsewhere.sock`, under a monkeypatched `HOME`, with `DOCKER_HOST` unset;
   - it asserts that the client from `_create_client()` does not target `elsewhere.sock`.

   On the current lock the test FAILS, because `from_env(use_context=...)` raises `TypeError` there. That failure says nothing about context-targeting, so the dev **also** records a run on 7.2 with `_create_client()` temporarily returning `docker.from_env()` (default `use_context=True`), showing the test fails because the client targets `elsewhere.sock`. Both outputs go in the notes file.
6. An **opt-in integration test** runs against a real daemon. It runs only when `TCE_DOCKER_INTEGRATION=1` **and** the socket exists; otherwise it is skipped with a stated reason. It:
   - starts a throwaway `busybox:1.37@sha256:<digest>` container (pinned by digest; the digest is resolved at dev time with `docker buildx imagetools inspect busybox:1.37` and recorded in the notes file) labeled `com.github.ravensorb.traefik-certificate-exporter.domain-restart=it.example.test`, running `sleep 300`;
   - calls `restartLabeledContainers(["it.example.test"])`;
   - asserts that the container's `State.StartedAt` changed;
   - force-removes the container in a `finally`.

   It is marked `@pytest.mark.integration`, and the marker is registered in `pyproject.toml` `[tool.pytest.ini_options] markers`.
7. When `settings.restartcontainers` is true, `app._run` performs one start-up reachability check (`DockerManager.check()` → `client.ping()`).
   - On success it logs INFO `Docker Engine reachable (API <version>)`.
   - On failure it logs ERROR, naming the endpoint and the error, and the exporter **continues**: exporting still has value even when restarts cannot happen.
8. Engine failures inside `restartLabeledContainers` are logged as one ERROR line naming the endpoint and the error text. The expected operational failures are caught as `docker.errors.DockerException` and `OSError`. `requests.RequestException` subclasses `IOError` (= `OSError`), so transport errors are covered **without importing `requests`**: no module in `src/` imports `requests`, because E014-S01-007 removes it from the declared dependencies and its `deptry` hook fails on an undeclared or transitive-only import. These are logged without a traceback. Any other exception keeps `logger.exception`.

## Business acceptance criteria

### Outcome

- An operator who sets `restartcontainers: true` and mounts the Docker socket gets the labeled containers restarted after an export. They can confirm this in the container's `StartedAt`, and in the INFO `Restarting container: <id>` line.
- An operator whose socket is missing or unreachable sees one ERROR at start-up that names the endpoint, instead of a misleading scheme error buried in a traceback on every pass.

#### 0.3.0 release notes

E014-S02-005 generates `docs/upgrading.md` from this list. Every bullet is a user-visible change.

- "Container restarts (`restartcontainers`) now work. 0.2.x shipped a Docker SDK that could not talk to the Engine API, so no restart ever happened. A 0.2.x deployment with labeled containers and `restartcontainers: true` (or `--restart-container`), where restarts were a silent no-op, **starts restarting labeled containers after the upgrade**, whenever their certificates change (see the restart-policy note of E014-S01-006)."
- "The Docker client ignores the Docker CLI context (`docker context use …`). `DOCKER_HOST` or the default socket `unix:///var/run/docker.sock` is used, as before. This matters for PyPI installs on workstations with a non-default context."
- "Docker Engine API 1.24 or newer is required (docker-py 7.x floor)."
- "When `restartcontainers` is on, the exporter checks the Docker Engine once at start-up: INFO `Docker Engine reachable (API <version>)` on success, one ERROR naming the endpoint on failure. Exporting continues either way."
- "An unreachable Engine is reported as one ERROR line naming the endpoint, instead of the misleading `Not supported URL scheme http+docker` traceback."

## Technical acceptance criteria

### Interface contracts

- `DockerManager._create_client(self) -> docker.DockerClient`: returns `docker.from_env(use_context=False)`. It is the single construction point.
- `DockerManager.check(self) -> bool`: pings once and logs the result as described in AC 7. It never raises.
- `DockerManager.restartLabeledContainers(self, domains: list[str] | None) -> None`: the signature and the label contract (`DOCKER_LABEL`, comma-separated domains) are unchanged.
- `pyproject.toml`:
  - `[tool.poetry.dependencies] docker = "^7.2"`;
  - `[tool.pytest.ini_options]` gains `markers = ["integration: needs a real external service; opt-in via environment"]`.
- Sibling conventions:
  - `libs/docker.py` holds module-level constants plus one class. Keep the new methods on `DockerManager`, using the existing `camelCase` method style (`restartLabeledContainers`, `_reserveRestart`).
  - Tests for `libs/x.py` live in `tests/libs/test_x.py`. The integration test goes in `tests/libs/test_docker_engine.py`, a sibling named for the seam it exercises.

Spec: none — l3io-plan run, no spec index bound

### Error and edge case handling

- **Socket absent or permission denied:** one ERROR per pass and at start-up, then the export continues; the restart is skipped for that pass. This is the "missing socket" test.
- **`DOCKER_HOST` set to an unreachable TCP endpoint:** the same handling. docker-py's default timeout (60 s) applies; it is not shortened in this story.
- **Container vanishes between `list` and `restart`:** docker-py 7 raises `docker.errors.NotFound` consistently (research §1, 7.0.0 notes). Log it at INFO ("container gone"), keep the per-container loop going, and release the reservation.
- **Engine API older than 1.24:** unreachable by design in 7.1+ (research §1 Risks). This surfaces as the same ERROR. Docs state the floor.
- **Dry run:** unchanged. No client call beyond `list`.

Spec: none — l3io-plan run, no spec index bound

### Observability requirements

- The restart path's log lines carry the existing per-pass `correlation_id`. No new mechanism is needed: the calls happen inside the pass's context, as today.
- Start-up check: one INFO on success, including the API version from `client.version()["ApiVersion"]` or the negotiated version; one ERROR on failure.
- The ERROR text names the endpoint (`DOCKER_HOST` or `unix:///var/run/docker.sock`) and the exception message. There is no traceback for expected Docker errors.

Spec: none — l3io-plan run, no spec index bound

### Security considerations

- The Docker socket is host-root-equivalent. Ignoring the CLI context (`use_context=False`) means a `~/.docker` directory planted in the service's `HOME` cannot redirect restarts to another daemon.
- `restartcontainers` is one of the inputs that keeps root (ADR-0030 as amended 2026-10-10). This story makes that privilege buy a working feature; it does not widen it.
- The integration test's image is pinned by digest (`busybox:1.37@sha256:…`), so its behaviour cannot change under a moved tag.
- No credentials are introduced. `DOCKER_HOST` values are not secrets, and logging them is acceptable.
