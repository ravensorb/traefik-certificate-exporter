## Acceptance Criteria

- The deferred finding BL-E011-033 is resolved: Redacting a list collapses it to a scalar, destroying its count/scheme signal
  - A declared-secret list value is redacted per element. Each non-empty element becomes `<scheme>://***REDACTED***`, where the scheme matches `^[A-Za-z][A-Za-z0-9+.-]*(?=://)`. An element without a scheme becomes `***REDACTED***`. Empty elements and empty lists are passed through.
  - Test: `["tgram://123:abc/456", "mailto://u:pw@host", "weird"]` → `["tgram://***REDACTED***", "mailto://***REDACTED***", "***REDACTED***"]`, and none of `123:abc`, `pw` or `weird` appears anywhere in the output. It FAILS on the current code.
- The deferred finding BL-E011-034 is resolved: Unrecognised-flag failure names no near-match and never points at --help
  - `parse_args_strict()` parses with `parse_known_args()`. If any leftover token starts with `-`, it calls `globalArgParser.error(...)` with:
    - `unrecognized arguments: <tokens>`;
    - for each `-`-token with a close match among the registered option strings, from `suggest.nearest_name(token, options)` (E014-S01-009's shared helper; `difflib.get_close_matches(..., n=1, cutoff=0.6)` underneath, never called directly here), a line `Did you mean '<match>'?`;
    - always, `Try '--help' for full usage.`
  - Leftover non-option tokens without a dash are reported in the same message.
  - The exit code stays 2.
  - Test: `--dtaa-path /x` → stderr contains `Did you mean '--data-path'?` and `--help`, with exit 2. It FAILS on the current code.
  - Test: `--zzzzzz` → no "Did you mean", but the `--help` pointer is present.
  - Test (shared helper, C-04): `suggest.nearest_name` is patched once to return a sentinel. Both a flag typo (`parse_args_strict`) and an unknown env name (E014-S01-009's `find_legacy_settings`) then show that sentinel, which proves both paths use the one helper.
- The deferred finding BL-E011-035 is resolved: Usage block, now shown on every typo, leaks internal config paths as metavars
  - Every value-taking action gets an explicit `metavar`:

    | Flag | metavar |
    |---|---|
    | `-c` | `PATH` |
    | `-d` | `PATH` |
    | `-fs` | `GLOB` |
    | `-o` | `PATH` |
    | `--traefik-resolver-id` | `RESOLVER` |
    | `--pkcs12-passphrase` | `PASSPHRASE` |
    | `--post-export-command` | `COMMAND` |
    | `-ll` | `LEVEL` (choices listed in the help text) |
    | `-id` | `DOMAIN` |

  - Derived test: for every action in `globalArgParser._actions` with `nargs != 0` (`option_strings` non-empty, excluding `help`), `metavar` is set and contains no `.`. `format_help()` contains no `SETTINGS.`.
  - The `-c` help text says "configuration file to load".
- The deferred finding BL-E011-036 is resolved: Active-settings dump is one unwrapped 400-character JSON line
  - `_dump_settings` logs `json.dumps(safe, indent=2, default=str)` of the already-redacted object.
  - Test: the captured DEBUG record spans more than one line, and parsing it back with `json.loads` equals the redacted dict.

## Business acceptance criteria

### Outcome

- An operator reading DEBUG output sees `appriseUrls` as a list of the same length, each entry showing its scheme (`tgram://***REDACTED***`). They can tell how many notification targets are configured, and of what kind, without any credential appearing.
- A user who mistypes a flag (`--dtaa-path`) is told the closest real flag and pointed at `--help`.
- `--help` and the usage line show readable placeholders (`PATH`, `DOMAIN`) instead of `SETTINGS.DOMAINS.INCLUDE`.
- The active-settings DEBUG dump is multi-line and legible, matching the adjacent config dump.

#### 0.3.0 release notes

E014-S02-005 generates `docs/upgrading.md` from this list. Every bullet is a user-visible change.

- "Clearer CLI errors: an unrecognised flag gets a `Did you mean …?` suggestion and a `--help` pointer. The exit code is still 2."
- "Readable `--help` placeholders (`PATH`, `DOMAIN`, `LEVEL`) instead of internal config paths. The `-c` help text now says it is the configuration file to load."
- "Redacted Apprise URLs in DEBUG output keep their count and scheme (`tgram://***REDACTED***`)."
- "The DEBUG active-settings dump is now multi-line, indented JSON. Log scrapers that parsed the old single-line dump must be updated."

### Non-goals

- Does not route argparse's usage or error output through the structured logger (UX-009: raw stderr, no level, timestamp or `correlation_id`). That stays deferred.
- Does not change which keys are secret (`SECRET_CONFIG_KEYS`). Only the list rendering changes.
- Does not change confuse's own `dump(redact=True)` rendering (`appriseurls: REDACTED`), which is library behaviour.
- Does not change settings precedence, flag names or dests (E014-S01-004 owns the `--restart-container` dest).
- Does not stop `postexportcommand` from being logged verbatim (review m4). E014-S01-010 owns that: it adds the key to `SECRET_CONFIG_KEYS` and makes the hook log lines name only the program.

## Technical acceptance criteria

### Interface contracts

- `_redact_secrets(value)` keeps its signature and its recursive dict/list/scalar dispatch. A declared-secret key whose value is a non-empty `list` maps to the per-element form. A `str` secret value remains `***REDACTED***`.
- New private helper `_redact_url_like(item) -> object` in `settings.py`, beside `_is_empty_secret`.
- `parse_args_strict() -> argparse.Namespace`: same signature, and still exits 2 through `globalArgParser.error`. Import-time `globalArgs` stays the lenient `parse_known_args` (ADR-0025).
- `cli_args.py`: `metavar=` is added on value-taking actions only. `dest`, `type`, `default` and `choices` are unchanged, apart from what E014-S01-004 already changed.
- `_dump_settings()` keeps its signature. Only the serialisation changes.
- Sibling conventions:
  - Tests for `libs/settings.py` live in `tests/libs/test_settings.py` and those for `libs/cli_args.py` in `tests/libs/test_cli_args.py`, each named `test_<behaviour_in_words>`.
  - `cli_args.py` imports `nearest_name` from `libs/suggest.py` (E014-S01-009). It does not import `difflib`.
  - The README check joins E014-S01-004's `tests/test_settings_surface.py`, using its `PROJECT_ROOT` idiom.

Spec: none — l3io-plan run, no spec index bound

### Error and edge case handling

- **A list element that is not a string** (dict or number): `***REDACTED***`, never raises.
- **Empty string elements:** passed through, consistent with `_is_empty_secret`.
- **Typo of a flag that takes a value** (`--dtaa-path /x`): both tokens are listed as unrecognized, and the suggestion is computed only for the `-`-token.
- **Abbreviated valid flags** (`--data /x`): still accepted by argparse's `allow_abbrev`, unchanged.
- **`-h`/`--help`:** still exits 0 (existing test `test_strict_parse_still_prints_help_and_exits_zero`).
- **`json.dumps` on a non-serialisable value:** `default=str`, never raises.

### Security considerations

- Per-element redaction must never emit any part of a URL after the scheme: no userinfo, host, path, token or query. The test asserts the absence of every secret substring.
- Revealing the scheme (`tgram`, `mailto`) is accepted. It names a service type, not a credential, as UX-002 requested.
- `_dump_settings` serialises the post-`_redact_secrets` object only. A test asserts that the raw passphrase is absent from the dump at DEBUG.
- `--pkcs12-passphrase`'s metavar `PASSPHRASE` is a placeholder. The argparse namespace redaction (`settings.py:317-319`) is unchanged.

### Existing-library check

- `difflib.get_close_matches` (stdlib) does near-match suggestion, reached only through E014-S01-009's `suggest.nearest_name`, so there is one call site. argparse's `suggest_on_error` would be the native option, but it needs Python 3.14, and `pyproject.toml` allows `>=3.10`. Revisit when the floor reaches 3.14.
- `argparse`'s `error()` and `metavar` are the library's own mechanisms. There is no CLI-library swap (`click`/`typer`).
- `json.dumps(indent=2)` (stdlib) does the pretty-printing. `jsonpickle` stays only for flattening the `Settings` object.
- `re` with the RFC 3986 scheme grammar handles scheme capture. `urllib.parse.urlsplit` was considered and rejected, because Apprise URLs carry tokens in the netloc with `:` (`tgram://123:abc/…`), which `urlsplit` treats as a port and can raise `ValueError` on. A one-line anchored regex for the scheme is all that is needed.
