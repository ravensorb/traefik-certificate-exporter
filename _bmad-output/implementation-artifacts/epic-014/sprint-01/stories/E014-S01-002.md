# PKCS12 export: passphrase, intermediates, chain parsing, build before replace

## Context

**Review findings:** `review-product.md`, findings B2 (BLOCKER) and M4 (MAJOR, the "build the PFX before any rename" half). Also the FR-2 row: "Broken with passphrase".
**Research:** `research-2026-10-10-release-0.3.0.md` §2 "cryptography and PKCS#12 (B2)", covering "The exact bug", "Two adjacent defects found while reading" and "Recommended fix". Also §3 "Per-resolver isolation (M4)" for the build-first recommendation.

**B2: a passphrase breaks every PFX**

- `src/traefik_certificate_exporter/libs/certificate_exporter.py:625` calls `serialization.load_pem_private_key(key_data, password=passphrase)`.
- The ACME key is unencrypted PEM (`b64decode(...)` at `:420`), so any non-`None` `pkcs12passphrase` raises `TypeError: Password was given but private key is not encrypted`. Research §2 probe, cryptography 50.0.2.
- The exception lands in the per-certificate `except` (`:522-523`). By then the PEMs (`:463-480` flat, `:492-505` default) have already been replaced. `names.append(name)` (`:515`) is skipped, so restart, hook and notification are all skipped for a domain whose files changed.
- No test sets a passphrase on the export path (`tests/libs/test_certificate_exporter.py:45,335`).

**Two adjacent defects (research §2, not in the review; probe-verified)**

1. **The PFX carries no intermediates.** `export_to_pkcs12` receives only the leaf slice and passes `cas=None` (`:483-488`, `:508-513`, `:668`). Windows/IIS and Java consumers must then fetch the intermediates themselves.
2. **A single-certificate `fullchain` is sliced wrongly.** `fullchain.find("-----BEGIN CERTIFICATE-----", 1)` returns `-1` (`:422-424`). The result is `cert = fullchain[0:-1]`, which drops the final newline, and `chain = "\n"`.

**M4, the part this story owns**

- A domain's artifacts are committed one file at a time, and the PFX is built *last*. Any PFX failure therefore leaves a partial rotation that is never reported.
- This story builds every artifact in memory first, then writes, then reports.
- E014-S01-003 owns the per-resolver and per-file half of M4. **Sequencing:** land this story before S01-003. Both edit `AcmeCertificateExporter.__exportCertificate`.

**Tests are blind today.** The shared fixtures (`tests/fixtures/acme_fixtures.py:8-16`) carry placeholder PEM text. Probe from the review's NFR-5 row: an LE v2 fixture → 4 PEM files, domain list `[]`. Only `test_a_real_export_writes_every_artifact_atomically` uses real material, through a file-local `_real_material` helper at `tests/libs/test_certificate_exporter.py:291-324`. That helper is self-signed, and its fullchain is the leaf twice.

**The per-domain "changed" signal (maintainer decision 2026-10-11, "restart only on change").** This story produces the signal that decides the post-export hook and notifications. It also provides the guarantee that the restart trigger relies on. E014-S01-006 restarts a labeled container when the newest mtime among its labeled domains' exported artifacts is later than the container's `State.StartedAt`, with a 2 s slack. That rule holds only because unchanged artifacts are never rewritten. This story already builds every artifact in memory before the first write:

- Before replacing a file, the exporter compares the built bytes with the file already on disk. The files on disk **are** the state: there is no fingerprint store, and the comparison gives the same answer after an exporter restart.
- An artifact whose content is unchanged is **not rewritten**. A domain none of whose artifacts changed is **not reported**.
- The PFX cannot be compared byte for byte: PKCS12 encryption draws a fresh random salt and IV on every build, so two builds of the same input differ. The PFX is therefore compared by content (AC 5).
- E014-S01-003 passes the signal through per resolver. E014-S01-010 owns the policy that consumes it: the post-export hook and notifications run only for changed domains. The restart decision is E014-S01-006's mtime-vs-`StartedAt` rule, which depends on this story leaving an unchanged artifact's mtime untouched.
- Today `libs/docker.py:18-23` records that name-based change detection was tried and reverted, because a drain pass reports every domain whether or not it changed. BL-E012-008 asks for a per-domain signal from the export path; this is that signal.

## Acceptance Criteria

1. **The passphrase works.** An ACME v2 fixture with a real key and a CA-signed leaf plus one intermediate is exported with `pkcs12Passphrase="s3cret"`. Then:
   - `pkcs12.load_key_and_certificates(pfx_bytes, b"s3cret")` returns a key, the leaf, and `len(cas) == 1`;
   - the domain **is** in the list `exportCertificatesForFile` returns.

   The test FAILS on the current code (TypeError → domain not reported).
2. **Intermediates are included.** Without a passphrase, the same fixture yields a PFX whose `additional_certs` equal the intermediates, in input order. The test FAILS on the current code (`cas=None`).
3. **Chain parsing uses the library.**
   - The fullchain is parsed with `cryptography.x509.load_pem_x509_certificates`.
   - `cert.pem` (or `<name>.crt`'s leaf use) is `certs[0].public_bytes(Encoding.PEM)`.
   - `chain.pem` / `<name>.chain.pem` is the concatenated `public_bytes(Encoding.PEM)` of `certs[1:]`; for a single-cert fullchain it is empty.
   - `fullchain.pem` is the decoded store bytes, unchanged.
   - A single-certificate fullchain test asserts `cert.pem` equals the input PEM byte for byte (Traefik writes Go `pem.Encode` output, 64-column, `\n`). It FAILS on the current code.
4. **Build before replace.** For each domain, the exporter does all decoding, parsing and PKCS12 serialisation before the first `_atomic_write*` call for that domain.
   - A fixture whose certificate does not parse, or whose key is not a PEM private key, leaves every pre-existing file in that domain's directory byte-identical.
   - That domain is not reported.
   - The other domains in the same resolver are exported.
   - The test FAILS on the current code, because 4 PEM files are rewritten.
5. **The change signal and the reporting contract (maintainer decision 2026-10-11).**
   - After the build and before any write, each artifact is checked against the file already on disk:
     - **PEM artifacts** (key, cert, chain, fullchain; flat `.key/.crt/.chain.pem/.fullchain.pem`): changed if the file is absent, unreadable, or its bytes differ from the built bytes.
     - **PFX:** changed if the file is absent or cannot be loaded with the configured passphrase (`None` when unset), or if its encryption state differs (a passphrase is set if and only if `load_key_and_certificates(existing, None)` fails), or if its content differs: the private key (PKCS8 DER, unencrypted), the leaf DER, or the ordered list of additional-certificate DERs.
   - Only changed artifacts are written. Unchanged artifacts are not rewritten, so their inode and mtime stay the same.
   - A domain is reported if and only if at least one of its artifacts changed and was replaced in this pass.
   - If a write fails after one or more changed artifacts were replaced (disk full, EIO), the domain **is** reported, and one ERROR names the domain and the artifacts that were and were not written. Because the files are the state, the next pass sees the remaining differences and writes them.
   - Tests, each FAILING on the current code where noted:
     - Two consecutive exports of the same store: the first reports the domain; the second reports nothing and rewrites no file (inode and mtime unchanged). FAILS today, because every pass rewrites and reports.
     - A fresh `AcmeCertificateExporter` over an output directory written by an earlier instance reports nothing (the state survives an exporter restart).
     - One byte of one domain's certificate changed in the store: only that domain is reported, and only its changed artifacts are rewritten.
     - A deleted output file is rewritten and its domain is reported.
     - A changed passphrase rewrites the PFX (and only the PFX) and reports the domain. An unencrypted→encrypted switch is detected the same way.
     - Two builds of the same PFX with a passphrase differ byte for byte, which proves why the PFX is compared by content. This is recorded as evidence that the design premise holds on the locked `cryptography`.
     - An `OSError` injected on the third write: the domain is reported, with the ERROR described above.
6. **An empty passphrase means none.** `pkcs12Passphrase` of `None` or `""` yields an unencrypted PFX, loadable with `password=None`. A non-empty `str`/`bytes` value yields `BestAvailableEncryption`.
7. **Dry run** performs steps 1–4 and the AC 5 comparison in memory, writes nothing, and reports the domain when the build succeeded **and** at least one artifact would change. Build errors now surface in dry run too.
8. **The shared fixtures carry real material.**

Its name and shape are fixed, because E014-S01-003 and E014-S01-006 build on it: `real_chain() -> RealChain`, where `RealChain` is a `NamedTuple` with `key_pem: bytes`, `leaf_pem: bytes`, `intermediate_pem: bytes` and `fullchain_pem: bytes` (leaf then intermediate).

   - Tests that relied on placeholder PEM still pass, or are updated with a stated reason.
9. ADR-NNNN is written as described in Context, with "Amended by" markers on ADR-0014, 0023 and 0024. `just check` passes.
10. **Spine/ADR routing (maintainer decision 7).** The dev writes `_bmad-output/implementation-artifacts/epic-014/sprint-01/closure/notes-E014-S01-002.md` with a section `## Spine/ADR amendments for S02-003`. It gives the exact replacement text for:

## Business acceptance criteria

### Outcome

- An operator who sets `pkcs12passphrase` gets an encrypted `.pfx` for every domain, with AES-256/SHA-256 via `BestAvailableEncryption`. Restart, hook and notification fire for those domains.
- A Windows/IIS or Java consumer can import the `.pfx` without fetching intermediates separately.
- A domain whose key or certificate is malformed keeps its previous files intact. Consumers never see a rotated PEM next to a stale PFX.
- A pass over an unchanged store rewrites nothing and reports nothing, so nothing downstream (restart, hook, notification) is triggered by it.

#### 0.3.0 release notes

E014-S02-005 generates `docs/upgrading.md` from this list. Every bullet is a user-visible change.

- "`pkcs12passphrase` works. In 0.2.x, setting it made every PKCS12 export fail and suppressed the restart, hook and notification for that domain."
- "`.pfx` files now include the intermediate certificates."
- "`cert.pem`/`chain.pem` are correct for single-certificate chains (`chain.pem` is empty when the store holds no intermediates; `cert.pem` keeps its final newline)."
- "An unexportable domain no longer has its PEM files rotated."
- "PKCS12 uses AES-256/SHA-256 when encrypted. The consumer floor is Windows 10 1709+/Server 2019+, OpenSSL 3 or current macOS; Windows Server 2016 and older cannot import an encrypted `.pfx`."
- "An empty `pkcs12passphrase` (`\"\"`) means no passphrase: the `.pfx` is unencrypted."
- "Unchanged certificates are no longer rewritten on every pass. A file is replaced only when its content changed, so file modification times are stable."
- "The domain list given to the post-export hook (`TRAEFIK_CERTIFICATE_EXPORTER_EXPORTED_DOMAINS`) and to notifications is now the set of domains whose exported files **changed** in that pass, not every domain in the store."
- "The first pass after upgrading from 0.2.x rewrites every `.pfx`, because it now carries the intermediates. That pass therefore counts as a change for every domain: labeled containers are restarted once, and the hook and notifications fire once."

### Non-goals

- No `pkcs12legacy` (3DES/SHA1) option for Windows Server 2016 and older. Research §2 marks it YAGNI until requested.
- Does not change the flat-mode `<name>.crt` content, which today holds the full chain (`:470`). Changing it would break consumers.
- Does not make the five-file set transactionally atomic. Per-file atomicity plus build-first is the contract.
- Does not change resolver-level parsing, null handling or version detection (E014-S01-003).
- Does not change the PKCS12 friendly-name fallback ("LetsEncrypt Certificate").
- Does not add certificate/key match validation beyond what `serialize_key_and_certificates` enforces.
- Does not decide what consumes the change signal. Restart policy is E014-S01-006's; hook and notification policy is E014-S01-010's.
- No fingerprint or state file besides the exported files themselves. An operator who edits or deletes an output file causes a rewrite and a "changed" report on the next pass; that is intended.
- Does not compare the PFX's encryption algorithm or iteration count. A PFX with the same content and the same encryption state counts as unchanged.

## Technical acceptance criteria

### Interface contracts

- New pure function `PemToPfxConverter.build_pkcs12(key_pem: bytes, certs: list[x509.Certificate], passphrase: str | bytes | None) -> bytes`. It has no I/O and loads the key with `password=None`.
- `PemToPfxConverter.export_to_pkcs12(filename, key_data, cert_data, passphrase=None)` keeps its name for any external caller. It becomes a thin `build_pkcs12` plus `_atomic_write_bytes` wrapper, and also accepts a list of certificates or a full-chain PEM.
- New private helper `_parse_fullchain(fullchain_pem: bytes) -> list[x509.Certificate]`. It wraps `x509.load_pem_x509_certificates` and raises `ValueError` on zero certificates.
- New private helpers `_file_differs(path: Path, data: bytes) -> bool` (absent or unreadable counts as different) and `_pfx_differs(path: Path, key, certs: list[x509.Certificate], passphrase: str | bytes | None) -> bool` (the AC 5 content comparison; it never raises, and any load failure counts as different).
- `AcmeCertificateExporter.__exportCertificate(...) -> list[str]`: the return list carries the AC 5 semantics. It is the **changed** domains, and it is the only change signal E014-S01-003 and E014-S01-006 consume.
- The artifact names and modes are unchanged:
  - `_SECRET_FILE_MODE` (0600) for the key and the `.pfx`;
  - umask-derived for the others;
  - flat names `<name>.key/.crt/.chain.pem/.fullchain.pem/.pfx`;
  - default names `privkey.pem/cert.pem/chain.pem/fullchain.pem/cert.pfx`.
- Sibling conventions: module-level private helpers in `certificate_exporter.py` are `_snake_case` functions next to `_atomic_write*`. Test fixtures are plain builder functions in `tests/fixtures/acme_fixtures.py`, not pytest fixtures; keep that style and add a module-level cache.

Spec: none — l3io-plan run, no spec index bound

### Error and edge case handling

- **The key is encrypted or not a private key:** `TypeError`/`ValueError` from `load_pem_private_key` → one ERROR for that domain, nothing written, not reported.
- **Zero certificates in the fullchain, or unparseable PEM:** `ValueError` → the same handling.
- **The key does not match the leaf:** whatever `serialize_key_and_certificates` raises → the same handling.
- **A write fails mid-set:** AC 5. The remaining writes for that domain are not attempted, and the domain is reported with an ERROR.
- **Passphrase is `""`:** treated as none (AC 6). Today `BestAvailableEncryption(b"")` would raise `ValueError`.
- **Non-ASCII passphrase:** encoded UTF-8, as today.
- **Wildcard names:** the existing `*.`-strip and path-component checks run before any build. Order: validate the name, then build, then compare, then write.
- **Existing file unreadable** (permissions): counts as changed; the write is attempted and fails or succeeds under the existing error handling.
- **Existing PFX encrypted with a different passphrase:** the load fails, so the PFX counts as changed and is rewritten with the configured passphrase.
- **Flat and default layouts:** the comparison applies to whichever names the layout writes.

Spec: none — l3io-plan run, no spec index bound

### Observability requirements

- **Per-domain build failure:** one ERROR naming the domain (`_sanitize_for_log`) and the failure class: "key", "certificate chain" or "pkcs12". It never includes key bytes or the passphrase.
- **Partial write:** one ERROR naming the domain plus the written and unwritten artifact names.
- **Success:** the existing INFO `Extracted certificate for: <name> (<sans>)` when the domain changed. A DEBUG line gives the intermediates count and the names of the changed artifacts.
- **Unchanged domain:** one DEBUG line `Certificate for <name> unchanged; nothing written`. There is no INFO line, so a quiet pass stays quiet.
- All lines run inside the pass's existing `correlation_id` context. No new mechanism is needed.

Spec: none — l3io-plan run, no spec index bound

### Security considerations

- The passphrase is never logged. The existing `SECRET_CONFIG_KEYS` redaction is unchanged. The DEBUG introspection (`:681-697`) keeps loading with the passphrase but logs only subject, issuer and dates.
- An empty passphrase must not produce a PFX that *looks* encrypted. AC 6 makes an unset passphrase and `""` identical.
- The `.pfx` stays 0600 regardless of encryption. A key-bearing file is never umask-derived.
- Build-first removes a state in which a consumer reads a new key next to an old PFX. A mismatched pair is an availability fault, not a confidentiality fault, and it is closed.
