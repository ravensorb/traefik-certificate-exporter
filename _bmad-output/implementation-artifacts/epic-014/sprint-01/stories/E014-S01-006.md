**Problem.**

- `src/traefik_certificate_exporter/libs/docker.py:28` sets `RESTART_COOLDOWN_SECONDS = 300`.
- `_reserveRestart` (`:47-69`) denies a restart inside the window, and `restartLabeledContainers` then **drops** it with an INFO log (`:101-108`).
- A second rotation for the same container inside 5 minutes leaves that container serving the stale certificate until some unrelated later ACME write, which may be weeks away. Examples: two resolvers renewing minutes apart, or a reissue after a revocation.
- `docs/operational.md:78-96` documents "moves on" as intended.
- No ADR records the cooldown (the review's grep of `docs/adr` for BL-E011-016 found none). BL-E012-004 notes that the story which introduced it never stated the window or where it is configured.
- **Every pass restarts every labeled container whose domain is in the store** (BL-E012-008). A drain pass reports every domain it exported, changed or not (`docker.py:18-23`), and the image runs a pass at every start (`RUNATSTART=true`). With restarts working again after E014-S01-001, every exporter start and every ACME write would restart every labeled container, rate-limited only by the cooldown.

**Maintainer decision 2026-10-11: restart only on change.**

- A labeled container is restarted only after a certificate for one of its domains changed, and only if the container has not started since that change. The exact trigger is the rule below.
- The change signal comes from E014-S01-002: before replacing a file, the exporter compares the built bytes with the file already on disk (the PFX by content). Unchanged artifacts are **not rewritten**, so their modification times do not move. E014-S01-003 passes the per-domain signal through per resolver. Unchanged domains are not reported.
- The policy lives here. It applies to every pass, including run-at-start. `runatstart` stays on by default, because the start-up pass produces the first export. Into an empty output directory every artifact is new, so the first deployment restarts once. A later exporter restart over an unchanged store restarts nothing.
- The post-export hook and notifications get the same "only on change" policy in E014-S01-010, which depends on this story and amends ADR-0014 §7.

**Restart trigger: exported-file mtime vs container start (architecture re-review MAJOR, orchestrator decision 2026-10-11).** The re-review found that the files on disk are the only change state. A restart driven only by "S01-002 reported this domain changed in this pass" is therefore lost for good in two cases. In the first, the exporter crashes between writing the files and restarting the container. In the second, a pending deferred restart is cancelled at shutdown. In both cases the next pass sees unchanged files, reports nothing, and the container keeps serving a stale certificate. The restart decision therefore compares two timestamps that survive a crash, so no extra state needs to be persisted:

- **Rule.** On every pass, including passes in which no domain changed, a candidate container is restarted when `newestArtifactMtime > startedAt + RESTART_MTIME_SLACK_SECONDS`.
  - `newestArtifactMtime` is the newest `st_mtime` among the exported artifact files (the PEMs and the `.pfx`, in the configured layout) of every domain in the container's label.
  - `startedAt` is the container's `container.attrs["State"]["StartedAt"]`, parsed as UTC.
- **Candidate set (exact).** The labeled containers on the connected daemon (`containers.list(filters={"label": DOCKER_LABEL})`, running containers only) whose label names at least one domain with an exported artifact present in the output directory when the rule is evaluated. The rule is evaluated after the pass's writes have completed. "Present on disk" covers every domain exported in this pass, because S01-002's writes leave the files on disk. It also covers domains that were exported earlier and are unchanged now, so their containers are still checked. A container whose labeled domains have no artifact on disk is not a candidate. The list of changed domains does not narrow the candidate set.
- **Why one rule is enough.** Unchanged certificates are not rewritten (S01-002), so their mtimes stay older than any container that started after the last real change. The same rule covers four cases:
  - a crash between write and restart: the files are newer than `StartedAt`;
  - a deferred restart lost at shutdown, or a failed restart: same;
  - the one-time restart after upgrading from 0.2.x: every `.pfx` is rewritten with its intermediates, so it is newer than every running container;
  - the start-up pass: the first export into an empty directory is newer than the container, and an unchanged store is not.
- **Clock-skew slack.** `RESTART_MTIME_SLACK_SECONDS = 2` is defined in `libs/docker.py` and is not configurable. A file must be more than 2 s newer than the container's start before it triggers a restart.
  - In the supported setup (local daemon, output directory on a local filesystem), the mtime and `StartedAt` come from the same host clock.
  - The slack absorbs up to 2 s of drift where the output directory sits on a network filesystem whose server sets the mtime. Without it, such drift would restart a container a second time on the next pass after every rotation.
  - Accepted cost: a container that started less than 2 s before the write is not restarted.
  - Skew larger than 2 s is unsupported and documented.
- **`StartedAt` missing, empty, unparsable or the zero value** (`0001-01-01T00:00:00Z`, a container that never started): the container is treated as needing no restart, with a DEBUG log. It is not an error.
- **Output files missing.** A domain with no artifact on disk contributes nothing to `newestArtifactMtime`. A file that `os.stat` cannot read (`OSError`, for example a race with an atomic replace) counts as missing, with a DEBUG log. If a file was deleted, the next pass rewrites it (S01-002 treats a missing file as changed), so its fresh mtime triggers the restart.
- **Containers on another daemon are out of scope.** Only the daemon the exporter is connected to (E014-S01-001's `_create_client()`) is listed or restarted. A remote daemon whose clock differs from the output filesystem's clock by more than the slack is unsupported.
- **The cooldown and deferral stay.** A restart that the rule calls for but the 300 s floor denies is deferred, not dropped (ACs below). If the deferral is lost (cancelled at shutdown, or the process crashes), the next pass recovers it by the same rule, because the files are still newer than the container's `StartedAt`. With `runatstart: false`, that next pass is the next ACME write.
- **`StartedAt` parsing uses `python-dateutil`** (`dateutil.parser.isoparse`), a new runtime dependency (Existing-library check).

**The threading model is safe to extend** (research §6):

- One `DockerManager` is shared by the start-up pass (`app.py:132`) and the watch handler (`certificate_exporter.py:722-726`).
- Drains already run on daemon `threading.Timer` threads (`certificate_exporter.py:1021-1025`).
- Shutdown cancels the pending drain (`app.py:186-192`, ADR-0026).

## Business acceptance criteria

### Outcome

- A labeled container is restarted when, and only when, an exported certificate file for one of its domains is newer than the container's own start time. Unchanged certificates are never rewritten, so restarting the exporter, or an ACME write that changes nothing for that container, does not restart it.
- Every certificate change that matches a labeled container is followed by a restart of that container. **No rotation leaves a container serving a stale certificate.**
  - Within one running process, the restart follows at most one cooldown window (5 minutes) after the change.
  - A restart lost to an exporter crash between write and restart, to a failed restart, or to a deferred restart cancelled at shutdown is recovered on the next pass: the next exporter start's run-at-start pass, or the next ACME write.
  - Caveat: until that next pass runs, the container keeps the old certificate. With `runatstart: false`, the next pass is the next ACME write.
- The storm protection is unchanged: no container restarts more than once per 5 minutes, however noisy the ACME store is.
- An operator can read the window, the trigger rule, the clock slack and their rationale in `docs/operational.md` and the ADR.

### Non-goals

- The window and the clock slack are not configurable.
- No restart state is persisted. The cooldown is process-local, so a fresh process's first pass is eligible (`docker.py:36-38`). The restart decision reads only the exported files' mtimes and the container's `StartedAt`, which survive a crash. A pending deferral cancelled at exit is not saved; the next pass recovers it by the same rule.
- No fingerprint store or persistence besides the exported files. Change detection is E014-S01-002's file comparison; this story only consumes the file mtimes it leaves.
- No restart for a container whose certificate files are older than its start, even on an operator's request. A manual `docker restart` is the tool for that.
- No containers on another Docker daemon than the one the exporter is connected to, and no support for clock skew beyond 2 s between the output filesystem and the daemon.
- No retry or backoff for a failed deferred restart beyond the next pass's re-evaluation.
- No change to which containers match (the label contract).
- Does not change when the post-export hook or notifications run, and does not change `postexportcommand` logging (E014-S01-010).

## Technical acceptance criteria

### Interface contracts

- `DockerManager`:
  - **changed:** `restartLabeledContainers(artifactMtime: Callable[[str], float | None]) -> None`. The callable returns the newest artifact mtime (epoch seconds) for a domain, or `None` when none is on disk. The domain-list parameter is removed, because the changed list no longer drives restarts;
  - **unchanged:** `_reserveRestart`, `_releaseRestart`;
  - **new constant:** `RESTART_MTIME_SLACK_SECONDS = 2`, with a rationale comment;
  - **new:** `_startedAt(container) -> float | None`, which parses `attrs["State"]["StartedAt"]` with `dateutil.parser.isoparse` to UTC epoch seconds. It returns `None` for a missing, empty, unparsable or year-1 value;
  - **new:** `_needsRestart(container, artifactMtime) -> bool`, the rule, with the DEBUG logs from Observability;
  - **new private state:** `__pending: dict[str, threading.Timer]` and `__pendingDomains: dict[str, set[str]]`, both guarded by the existing `self.__lock`, plus the `artifactMtime` lookup per pending entry;
  - **new:** `_scheduleDeferredRestart(containerId: str, domains: set[str], remaining: float, correlationId: str | None, artifactMtime: Callable[[str], float | None]) -> bool` (`True` if armed, `False` if coalesced);
  - **new:** `_deferredRestart(containerId: str, correlationId: str | None) -> None`, the timer target;
  - **new:** `cancel() -> None`.
- `AcmeCertificateExporter.artifactMtime(domain: str) -> float | None` (new, public). It returns the newest `os.stat(...).st_mtime` over the artifact paths the configured layout (`flat` or per-domain directory) writes for `domain`, or `None` if none exists. An `OSError` on one file counts as missing. The paths come from the same helper the export path uses to name a domain's artifacts (extracted by E014-S01-002 or here), not from a second copy of the path logic.
- `_reserveRestart` keeps returning `(allowed, reason, previousAt)`. The caller derives `remaining` from `previousAt` and `RESTART_COOLDOWN_SECONDS`.
- `app._run`: a `try/finally: dockerManager.cancel()`. It calls `restartLabeledContainers(exporter.artifactMtime)` on every pass. The hook and notification calls are left as they are; E014-S01-010 guards them.
- `AcmeCertificateFileHandler.__processPath` (`certificate_exporter.py:1044-1060`): the same restart call. The handler already receives the shared `DockerManager`.
- `pyproject.toml`: `python-dateutil = "^2.9.0"` joins the runtime dependencies, and `poetry.lock` is refreshed.
- Sibling conventions:
  - `docker.py` documents each constant with a rationale comment above it. The rewritten block says "only on change", "files newer than the container's start" and "defer".
  - Methods use `camelCase`, with private names prefixed `_`.
  - Tests stay in `tests/libs/test_docker.py`; the call-site tests go in `tests/test_app.py` and `tests/libs/test_certificate_exporter_watch.py`; the `artifactMtime` tests go in `tests/libs/test_certificate_exporter.py`.
  - Patching follows the existing `patch("…docker.time.time")` style, and `threading.Timer` is replaced by a recording fake class, not a `MagicMock`, per research §6.

### Error and edge case handling

- **Lock discipline:** the callback never holds `self.__lock` across a Docker round trip. It pops the pending entry under the lock, then works outside it.
- **Container gone:** `NotFound` → INFO, the entry is cleared, and no exception escapes the timer thread.
- **Label removed or changed:** no restart, plus INFO.
- **Container restarted by someone else while a deferral was pending:** its fresh `StartedAt` is later than the files, so the fire-time rule check skips it with INFO.
- **`StartedAt` missing, empty, unparsable or `0001-01-01T00:00:00Z`:** the container needs no restart; DEBUG; no exception.
- **Output files missing or unreadable:** they contribute nothing to `newestArtifactMtime`, with a DEBUG log on `OSError`. A container with no artifact on disk for any labeled domain is not a candidate. A deleted file is rewritten by the next pass (S01-002), and its fresh mtime triggers the restart.
- **Clock skew:** up to 2 s of skew with the mtime clock ahead is absorbed without a repeat restart. A container that started less than 2 s before the write is not restarted (accepted, documented). Larger skew (remote daemon, network-filesystem output) is unsupported.
- **Stopped containers:** `containers.list` returns running containers only. A stopped labeled container is not restarted, and it loads the current files when it next starts.
- **Containers on another daemon:** never listed, never restarted (out of scope).
- **Engine unreachable at fire time:** ERROR (the E014-S01-001 message), and the reservation is released. The next pass recovers the restart.
- **Domains appended while pending:** the pending domain set is unioned and the timer is not re-armed.
- **Run-once mode:** `__lastRestart` is empty at start, so a deferral is unreachable within one pass unless a resolver lists the same container twice. Even then the `try/finally` cancel runs before exit. An unchanged store in run-once mode restarts only containers older than their domains' files, which happens only after a crash or a cancelled deferral.
- **A `cancel()` racing a firing timer:** the callback re-checks under the lock that its entry was still pending. If it was not, it returns without restarting. Test `tests/libs/test_docker.py::test_cancel_racing_fire_does_not_restart`.
- **A write that partly failed:** E014-S01-002 reports the domain as changed, and the files it did write are newer than the container, so the container restarts. The next pass writes the remaining differences, and their newer mtimes restart it again, subject to the rate floor.
- **Dry run:** E014-S01-002 reports domains that *would* change and writes nothing, so mtimes do not move. The restart path logs `[DRYRUN]` lines only.

### Observability requirements

- **INFO on restart:** `Restarting container <id>: exported files for <domain> (<mtime UTC>) are newer than its start (<StartedAt UTC>)`.
- **DEBUG per evaluated candidate:** `Container <id>: newest artifact <mtime UTC>, started <StartedAt UTC>; no restart needed`.
- **DEBUG on a missing or zero `StartedAt`:** `Container <id>: StartedAt missing or unparsable (<raw value>); not restarting`.
- **DEBUG on a file `OSError`:** `Cannot stat <path>: <error>; treated as missing`.
- **INFO on arm:** `Deferring restart of container <id>: cooldown active, <n>s remaining; one restart scheduled`.
- **DEBUG on coalesce:** `Restart of container <id> already scheduled`.
- **INFO on fire:** `Restarting container: <id> (deferred)`.
- **INFO** when the restart is skipped at fire time, giving the reason (`gone`, `label no longer matches`, or `already started after the certificate was written`).
- **ERROR** on failure.
- **DEBUG on shutdown:** `Cancelled <n> pending deferred restart(s); the next pass restarts them`. INFO when n > 0, so the delay is visible.
- Every deferred line carries the arming pass's `correlation_id`.

### Security considerations

- The rate floor exists against a hostile or noisy ACME store driving restarts over a host-root-equivalent socket (BL-E011-016 / RT-009).
  - Restart only on change narrows this further. A store rewrite that changes nothing for a container does not rewrite its files, so it never reaches the socket.
  - The new behaviour keeps the bound (at most one restart per container per window) and adds at most one daemon timer per labeled container. Memory is therefore bounded by the number of labeled containers, not by the number of store events.
- The restart rule also trusts the output directory's mtimes. Anyone who can write to it can already replace the certificates the containers serve, so this grants nothing new; `docs/operational.md` states that the output directory must be writable only by the exporter.
- The fire-time label and rule re-check means a container that was unlabeled during the window, or was already restarted, is never restarted on stale authority.
- No new credentials. The one new input is the container's `State.StartedAt`, read from the daemon the exporter already trusts.

### Existing-library check

- `threading.Timer` (stdlib) is already the project's scheduling primitive for drains (ADR-0026). Adding a scheduler library (APScheduler, `sched`) for one timer per container would be a new dependency with no gain.
- The Docker SDK (`containers.get`, `restart`, `errors.NotFound`, `container.attrs`) does the Engine work.
- **`State.StartedAt` parsing: `python-dateutil` 2.9.0.post0, `dateutil.parser.isoparse`.**
  - Docker emits RFC 3339 with nanoseconds and a `Z` suffix (`2026-10-11T08:15:30.123456789Z`). The stdlib's `datetime.fromisoformat` accepts neither on Python 3.10, the project floor (`pyproject.toml`: `python = ">=3.10,<3.15"`); it accepts both from 3.11.
  - `isoparse` truncates the fraction to microseconds, returns an aware UTC datetime, and parses the zero value as year 1. All three were checked against the 2.9.0.post0 wheel on 2026-10-11 (`isoparser.py:369`, `us_str = frac.group(1)[:6]`).
  - No hand-written timestamp trimming.
  - Revisit when the floor reaches 3.11, where the stdlib suffices.
- `os.stat(...).st_mtime` (stdlib) supplies the artifact mtimes.
- Change detection is E014-S01-002's file comparison (`bytes` equality and `cryptography`'s PKCS12 loader). No fingerprint or hashing code is written here.
- The ADR, not code, records the policy.
