**What E014-S01-006 leaves in place, and this story builds on.**

- Both call sites (the run-at-start pass in `app._run`, and `AcmeCertificateFileHandler.__processPath`) call `restartLabeledContainers(exporter.artifactMtime)` on every pass, inside `app._run`'s `try/finally: dockerManager.cancel()`.
- The restart ADR-NNNN ("Container restart policy: only on change, …") exists, reserved and written by S01-006.
- E014-S01-002 returns, per pass, the domains whose artifacts **changed** on disk; E014-S01-003 passes that list through per resolver.
- The hook (`run_post_export_command`) and the notifications (`send_export_notifications`) still run on every pass with that list, as they did before S01-006.

**Post-export hook and notifications (decided in E014-S01-006's elaboration, explicitly).** Both fire only for domains S01-002 reports as changed in that pass. When no domain changed in a pass, neither runs. `TRAEFIK_CERTIFICATE_EXPORTER_EXPORTED_DOMAINS` and the notification body list only the changed domains. This amends ADR-0014 §7 ("an export pass completed", not "a certificate changed"), which was written when nothing detected change. It is stated as a release note. It applies to every pass, including run-at-start and a pass that only recovers a lost restart (S01-006's crash case), in which nothing changed.

**Hook command logging (review-product m4, plan review F-11, maintainer decision 10).** The hook logging lives in `libs/post_export.py` (`:79-91`). It logs `postexportcommand` verbatim at ERROR and DEBUG (`Post-export command '<command>' exited …`), and the DEBUG settings dump shows it verbatim because it is not in `SECRET_CONFIG_KEYS` (`settings.py:34-41`). A command carrying a token (`curl -H "Authorization: …"`) leaks it. This story touches the hook call sites, so it takes the fix.

## Business acceptance criteria

### Outcome

- The post-export hook and notifications report real changes only, so an operator can keep the notification channel unmuted. An exporter restart over an unchanged store, or a pass that only recovers a lost restart, sends nothing.
- A `postexportcommand` that carries a credential never puts it in a log line or a DEBUG dump.

#### 0.3.0 release notes

E014-S02-005 generates `docs/upgrading.md` from this list. Every bullet is a user-visible change.

- "The post-export hook and Apprise notifications run only when at least one domain changed, and list only the changed domains. In 0.2.x they ran after every pass, including every exporter start."
- "`postexportcommand` is treated as a secret: it is redacted in DEBUG dumps, and hook log lines name only the program, not its arguments."

Spec: none — l3io-plan run, no spec index bound

### Non-goals

- Does not redact the hook's own stderr, which is logged on failure as the hook's diagnostic output.
- Does not change the restart trigger, deferral or cooldown (E014-S01-006).
- Does not change what counts as "changed" (E014-S01-002) or how it passes through resolvers (E014-S01-003).
- Does not change how other secret values render in the dumps (E014-S01-008 changes list rendering).
- No new hook or notification triggers (for example on restart).

## Technical acceptance criteria

### Interface contracts

- `app._run`: the run-at-start block calls the hook and notifications only when the changed list is non-empty. The restart call and the `try/finally` from E014-S01-006 are unchanged.
- `AcmeCertificateFileHandler.__processPath` (`certificate_exporter.py:1044-1060`): the same guard.
- `libs/post_export.py`: `run_post_export_command`'s signature is unchanged. The log lines use `argv[0]` only.
- `libs/notify.py`: `send_export_notifications`'s signature is unchanged; only its docstring changes.
- `libs/settings.py`: `SECRET_CONFIG_KEYS` gains `("settings", "postexportcommand")`, with a rationale comment above it like its siblings'.
- Sibling conventions: the call-site tests go in `tests/test_app.py` and `tests/libs/test_certificate_exporter_watch.py`; the redaction tests go in `tests/libs/test_post_export.py` and `tests/libs/test_settings.py`; names follow `test_<behaviour_in_words>`.

Spec: none — l3io-plan run, no spec index bound

### Error and edge case handling

- **No domain changed:** neither the hook nor the notifications run; one INFO line says so. The restart evaluation (S01-006) still runs.
- **Run-once mode over an unchanged store:** runs no hook and no notification.
- **Dry run:** E014-S01-002 reports domains that *would* change and writes nothing. The hook and notifications keep their existing dry-run skips.
- **`postexportcommand` that `shlex` cannot parse:** the ERROR says the command could not be parsed and names neither the command nor the parser's message text, which can echo a fragment of it.
- **Hook non-zero exit, timeout, failure to start:** the existing handling is unchanged apart from naming only `argv[0]`.

Spec: none — l3io-plan run, no spec index bound

### Observability requirements

- **INFO per pass with no change:** `No certificate changed; no hook or notification` (once per pass, so a quiet pass is still visible).
- Hook lines: `Post-export command <argv[0]> exited <n>: <stderr>`, `… timed out …`, `… failed to start: <error>`. They never include the arguments.
- Dry-run skip lines for the hook and notifications are unchanged.
- All lines run inside the pass's existing `correlation_id` context.

Spec: none — l3io-plan run, no spec index bound

### Security considerations

- `postexportcommand` often carries a credential (an `Authorization` header, a webhook token). Logging only `argv[0]`, and treating the key as a declared secret, closes the NFR-1 gap from review-product m4.
- Fewer hook runs means fewer executions of an operator-supplied command; the command itself is unchanged and still runs without a shell.
- No new credentials and no new inputs.

Spec: none — l3io-plan run, no spec index bound

- Hook and notification guards at both call sites (`tests/test_app.py`, `tests/libs/test_certificate_exporter_watch.py`), with patched recorders.
- The restart-recovery pass (no change, restart happens, no hook or notification), reusing S01-006's fake Docker client and the `real_chain()` fixture.
- `postexportcommand` redaction (`tests/libs/test_post_export.py`, `tests/libs/test_settings.py`).
