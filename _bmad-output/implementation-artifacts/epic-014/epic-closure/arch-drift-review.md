## Executive summary

The product half of E014 matches its decisions, and that still holds when the two sprints are read together:

- One artifact-path helper (ADR-0040).
- Build → compare → write (ADR-0043).
- The run mode resolved by the package (ADR-0044).
- Restart only on change, with defer-not-drop (ADR-0045).
- An `import-linter`-enforced layering (ADR-0048).

Both pass call paths (`app._run_passes` and `AcmeCertificateFileHandler.__processPath`) still apply the same AD-9 sequence. The epic-level drift sits in the release itself and in a claim about supply-chain coverage. Neither is visible from either sprint alone.

**Counts:** 0 BLOCKER, 2 MAJOR and 6 MINOR.

- **AD-1 (MAJOR):** the released 0.3.0 does not have the shape the CI spine and E014-S02-007 require.
  - Gitea's `0.3.0` image was built by a local `act` run on `c7394e2`, with a tag that existed only in a throwaway clone.
  - Docker Hub's `0.3.0` was built by the GitHub release run on the real tag commit `046016b`.
  - As a result, one version has two digests and two revisions.
  - GHCR and the GitHub release were not published, yet the story is closed `done`.
  - No ADR or backlog item records any of this.
- **AD-2 (MAJOR):** the `import-linter` hook added at the sprint-01 closure resolves an unpinned, unhashed transitive closure from PyPI inside the job that builds the released `dist`. ADR-0042 and the pre-commit comments still say every hook environment is pinned.

**Most important action:** record the 0.3.0 release topology as an accepted exception or treat it as a defect. Then retag Gitea's `0.3.0`, `0.3` and `latest` to the Docker Hub digest with `imagetools create` (a copy, not a rebuild), and file the unmet AC 8 (GHCR) and AC 9 (forge release) items.

Blocker: 0, Major: 2, Minor: 6

## Per-principle walkthrough

**Core**
- §1 Separation of concerns: PASS at epic level. The `import-linter` contracts (`pyproject.toml:92-121`) match spine AD-13 and ADR-0048 exactly. `app` sits above `libs`, the adapters never import `certificate_exporter`, and the run-time callback `artifactMtime` is the coverage limit those documents state.
- §2 Reuse: PASS for new findings. The pass sequence is written twice (`app.py:206-235` and `certificate_exporter.py:1631-1660`). ADR-0048 accepts this, and I checked that the two copies are behaviourally identical: hook and notify only when `domains` is non-empty, `NO_CHANGE_MESSAGE` otherwise, and restart evaluation on every pass. The five copies of `Verify dist hashes` and of Destination configuration are already in the backlog (SD-02-6).
- §3 Design by contract: AD-5.
- §4 Testability: PASS. ADR-0041 was honoured across sprints. E014-S02-005 ran `pytest -m integration` with no skips (`release-0.3.0-evidence.md:68`).
- §5 Brevity: PASS. Dead code is already in the backlog (SD-01-4).
- §6 Comments: AD-3, for the ambiguous "AR-3" citation.
- §7 Dependencies: AD-2, AD-8.
- §8 GA over preview: PASS. `import-linter==2.15`, `poetry-core==2.4.0` and `poetry-dynamic-versioning==1.10.0` are all GA. Python `>=3.10,<3.15` is supported.
- §9 Logging and correlation: PASS. One id per pass on both call paths (`app.py:204-206`, handler drain). Known gaps are in the backlog (BL-E011-017 and the E014-S01-009 L1 item).
- §10 Documentation: AD-1 (no record of the release scope), AD-4, AD-6, AD-7.

**Python overlay:** PASS. Poetry is used with a committed lock, `poetry sync --all-groups` in CI (`build.yaml:58`), `requires-python` is bounded, mypy and ruff are in the gate, and there is no `print`. The `import-linter` closure is outside the lock (AD-2).

**GitHub Actions overlay**
- Actions are SHA-pinned or, for LiquidLogicLabs, pinned to the `@vN` major under a hook. Dependabot is enabled (`.github/dependabot.yml`). Permissions are least-privilege per job. Concurrency follows AD-14.
- The new `Is this the highest release tag` step (`release.yaml:77-88`) runs after a `fetch-depth: 0` checkout, so `git tag -l` sees every tag. It passes the tag through `env:`, not by interpolation.
- Findings: AD-3, AD-4 and AD-5. The duplication finding is already in the backlog (SD-02-6).

**Docker overlay:** PASS for new findings. The base is pinned by digest and tag (`docker/Dockerfile:6`, refreshed in this epic). The build is multi-stage from the verified wheel. The release published amd64 and arm64 with attestation manifests. Already in the backlog: HEALTHCHECK, image scanning, and the unhashed Poetry install in the builder (SD-02-7 and the related BL items). AD-1 covers the digest divergence across registries.

**Shell overlay:** PASS for new findings. ShellCheck and `s6-no-raw-settings-env` gate `docker/root/`. Strict mode on `run` is already in the backlog (SD-01-7). The new `release.yaml` step runs under the workflow default `bash` (`-eo pipefail`) and quotes every expansion.
