# E014 plan review — lens 3 of 3: cross-story consistency and executability (adversarial)

- **Date:** 2026-10-11
- **Scope:** the 13 E014 stories (`epic-014/sprint-0{1,2}/stories/`), their `depends_on` (`state/planned/epic-014/**`), plan snapshot `plan-2026-10-11-v1.yaml`, and the current code/config each story names.
- **Method:** for every shared file and every contract, construct an ordering in which each story meets its own ACs and the pair still conflicts. Where a conflict depends on repository facts, the fact was checked against the tree at `2139ad8` (commands quoted under Evidence).

## Verdict

**CONDITIONAL — not executable as written.** The dependency graph is mostly well-ordered for the file overlaps it knows about. But one pair of ACs is mutually unsatisfiable (S01-004's derived env-name checks against S02-005's legacy table in `docs/upgrading.md`), and S01-004's history-derived test fails on the **current** history and is non-deterministic across clones. Because that test reads immutable git history, any later commit that places a non-valid `TRAEFIK_CERTIFICATE_EXPORTER_*` string in a scanned file makes the failure permanent. S01-005 does exactly that (its pygrep `entry:` in `.pre-commit-config.yaml`), and so does S02-005 (`…_SETTINGS_<KEY>`). This must be fixed in S01-004's scope design **before** any of S01-004, S01-005 or S02-005 is developed.

The other MAJOR findings are contract hand-offs that are not carried by the consumer story (difflib helper; amendment-notes files for S02-003), plan-level parallelism with E012 and E013, and executability/classification errors (S02-005 not marked HITL; S01-007 "simple").

Counts: **BLOCKER 1 · MAJOR 7 · MINOR 11** (19 findings).
