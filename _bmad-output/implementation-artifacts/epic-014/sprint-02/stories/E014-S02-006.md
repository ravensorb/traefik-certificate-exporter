## Acceptance Criteria

1. **LLL pin form is enforced (F-07).**
   - A `repo: local` pygrep hook, id `workflows-lll-major-tag`, fails on any `uses:` of a `LiquidLogicLabs/*` action whose ref is not exactly `v<digits>` (optionally followed by a comment).
   - The match is case-insensitive and accepts a quoted value.
   - It runs over `^\.github/.*\.ya?ml$`, so a future composite `action.yml` under `.github/` is in scope.
   - The `.github/zizmor.yml` comment now names this hook as the enforcement, replacing "NOT MECHANICALLY ENFORCED".
2. **No credential on argv (F-09).**
   - Both Gitea "files" lookups (`dev.yaml`, `release.yaml`) send the `Authorization` header on stdin: `printf 'Authorization: token %s\n' "$TWINE_PASSWORD" | curl … -H @- …`.
   - A pygrep hook, id `workflows-no-auth-header-argv`, fails on `(?i)(-H|--header)[=\s]*["']?authorization:` in workflow files, so `--header=`, `-H'…'` and lower-case `authorization:` are caught.
   - The hook's comment states its coverage limit: it sees literal header flags only, not a header assembled in a variable or passed by `--config`/`-K`. The same limit goes into the AD-5/AD-11 amendment text.
3. **Release concurrency is described truthfully (F-10).**
   - `release.yaml`'s concurrency comment says: at most one release runs and one waits; a newer tag cancels the waiting one, and that one must be re-run.
   - `docs/ci/pipeline-walkthrough.md` §"Releasing" carries an operator note saying the same thing and giving the re-run command.
   - The group and `cancel-in-progress` are unchanged.
   - BL-E013-036 is scheduled to this story before dev starts (`pm-status schedule-issue --key BL-E013-036 --story E014-S02-006`), so marking this story `done` resolves it.
4. **No `:0` image tag for 0.x (F-11).**
   - The `{{major}}` line in `release.yaml` carries `enable=${{ !startsWith(needs.build.outputs.image-version, '0.') }}`.
   - A pygrep hook, id `workflows-major-tag-gated`, fails on any `pattern={{major}}` line (not `{{major}}.{{minor}}`) that lacks `enable=`.
   - The hook's comment states its coverage limit: it checks that `enable=` is present, not what the expression says. The act metadata run (Testability) is the evidence for the expression's value.
5. **Base-image pull is retried and credential-free (F-18).**
   - Before its `docker/build-push-action` step, `build.yaml` pre-pulls the base image with a bounded retry.
   - The reference is read from `docker/Dockerfile`'s `ARG BASE_IMAGE` default at run time, never repeated in the YAML.
   - The smoke build then uses that local copy, which the evidence proves: the build log shows no registry fetch of the base image.
   - No credential and no permission is added to `build.yaml`.
   - The walkthrough documents "re-run on 429" for both `build` and `publish-image`.
6. Every row of `## Verification` passes, `just check` passes, and the act evidence is recorded in the notes file. This story closes on act evidence; the live GitHub PR run of `build / build` is recorded by E014-S02-007.

### Error and edge case handling

- **Pre-pull.**
  - The retry stops after a bounded number of attempts with increasing delay: 4 attempts at 15, 30 and 60 s, per research §7(e).
  - When all attempts fail, the step fails the job with the last `docker pull` error, so the check is red and a re-run is the documented response.
  - If the Dockerfile `ARG BASE_IMAGE` line cannot be parsed (missing, no `@sha256:`), the step fails naming the file and line pattern. It never pulls an unpinned reference.
- **Rerun safety.** None of these changes alters idempotence. Uploads still skip existing files (AD-11), and the image re-points tags (ADR-0036 §5).
- **Gitea runner.** `printf | curl -H @-` needs curl ≥ 7.55. The notes record the curl version the act image provides.

Spec: none — l3io-plan run, no spec index bound

### Security considerations

- **Token off argv (F-09).** `printf` is a bash builtin, so the token never reaches an exec'd argv. The header goes through curl's stdin only. GitHub's guidance (`github/docs` use-secrets) recommends stdin or environment, never the command line.
- **No widening.** `build.yaml` stays `contents: read` and credential-free (AD-2, AD-13). The pre-pull step runs no login.
- **Retry action.** A third-party retry action runs in the credential-free build job only, never in a publish job.
