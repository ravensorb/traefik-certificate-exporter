### Error and edge case handling

- **pm-status refuses a transition**, for example because `done` is not reachable from `blocked`. Stop, record the exit code and message, and do not hand-edit. If no sanctioned path exists, end with `BLOCKED: pm-status refuses <transition>`.
- **The lock.** If `clear-lock` reports the lock already gone, or held by a live session, record that. Do not proceed while a live foreign session holds it.
- **The issue is already resolved** (exit 0, "already resolved"). Record it and continue.
- **A ref fails verification**: the commit is missing, or the story is not done. Do not resolve with that ref. Leave the item open and record why.
- **A PR is already closed or merged when checked.** Record its state and skip its command.
- **E014-S01-001 or E014-S01-007 is not `done`** when the dependency PRs are checked. Leave those PRs open and record it; they are not part of this story's done condition beyond the recorded check.
- **E014-S01-008 is not `done` when this story starts** (the dependency was violated). Do not resolve BL-E011-033..036 or close E012-S01-004; stop with `BLOCKED: E014-S01-008 not done`.
- **Re-run safety.** Every pm-status call used here is idempotent or exits 0 on already-applied state. `gh pr close` on a closed PR exits non-zero, which is harmless; it is guarded by the state check. Re-running `append-issue` would duplicate an item, so the notes record each allocated key and a re-run skips filed items.
