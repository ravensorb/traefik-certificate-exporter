## Acceptance Criteria

1. **Pre-commit hooks are SHA-frozen (BL-E013-020).**
   - Every non-`local` repo in `.pre-commit-config.yaml` has `rev: <40-hex SHA>  # frozen: vX.Y.Z`, produced by `pre-commit autoupdate --freeze`.
   - `repo: local` hooks, including E014-S01-007's pip-audit hook, have no `rev` and are out of scope for freezing. Do not move a local hook into a remote repo to freeze it; pip-audit's version is pinned through `poetry.lock`.
   - A pygrep hook, id `precommit-revs-frozen`, fails on `^\s+rev:\s+(?![0-9a-f]{40}\b)` in `.pre-commit-config.yaml`.
   - The `mirrors-mypy` rev's major version equals the locked mypy major, or the mismatch is recorded in the notes with a reason.
2. **Hook updates have an owner (BL-E013-020).** The developer re-checks the GitHub Docs pages "Dependabot options reference" (`package-ecosystem: pre-commit`) and "Supported ecosystems and repositories" (§pre-commit), and records the quoted text, the URL and the ecosystem's GA or preview status in the notes. As read on 2026-10-11, the latter says "When a hook pins a specific commit SHA, Dependabot resolves the latest matching tag and updates the `rev` value accordingly" and "You can use a `# frozen:` comment after the `rev` value to pin a hook to a particular version or version prefix." Then one of two branches applies:
   - **Supported and GA:** `.github/dependabot.yml` gains a `pre-commit` entry (directory `/`, weekly, `cooldown.default-days: 7`).
   - **Not supported, or preview only:** no entry is added, and `docs/developer.md` documents a manual cadence: run `pre-commit autoupdate --freeze` monthly and before each release, then run `just check`. A preview-only status is recorded as the reason.

   Either way, the docs state that Gitea has no Dependabot and updates there are manual.
3. **Build hashes cross the job boundary (BL-E013-021).**
   - `build.yaml` exports `wheel-sha256` and `sdist-sha256` as `on.workflow_call.outputs`.
   - Every job that downloads `dist` runs `sha256sum -c` against `needs.build.outputs.*` at the position the step-order contract gives (after the Destination configuration step and the AD-15 guard, before the CA import and before any login, upload, build or release step): `publish-package` and `publish-image` in both workflows, and `release`.
   - `publish-image` passes `needs.build.outputs.wheel-sha256` as the `WHEEL_SHA256` build-arg.
   - A mismatch fails the job.
4. **Hash-checked Poetry, minimal publish install (BL-E013-024).**
   - Every `pip install poetry` in the workflows becomes `pip install --require-hashes -r .github/requirements/poetry.txt`.
   - The file is generated from `.github/requirements/poetry.in` (`poetry==2.4.2`) by pip-tools, with this exact regeneration command recorded in the file header and in `docs/developer.md`: `pipx run --spec 'pip-tools==7.5.3' pip-compile --generate-hashes --allow-unsafe --output-file .github/requirements/poetry.txt .github/requirements/poetry.in`. (`--allow-unsafe` because Poetry's dependency set can include `pip`/`setuptools`; drop it if the generated file is identical without it, and record which.) The file is never hand-edited.
   - **Owner of updates.** Dependabot's `pip` ecosystem on `/.github/requirements` (weekly, cooldown 7). `docs/developer.md` states the fallback: if a Dependabot PR against the file drops `--hash=` lines or fails `pip install --require-hashes`, the entry is removed and the maintainer regenerates the file with the command above when bumping Poetry. Whether the first such PR keeps hashes is observed by E014-S02-007 (maintainer checklist, AG-12), not by this story.
   - **Inside the audit scope (ADR-0042).** `.github/requirements/poetry.txt` is audited by E014-S01-007's `pip-audit-bootstrap` hook through its `files:` glob; the `publish` group is audited by `pip-audit` because `build.yaml` and `just install` keep `poetry sync --all-groups` (do not narrow them). A pygrep hook `workflows-pip-install-from-requirements` (`files: ^\.github/workflows/.*\.ya?ml$`, `entry: 'pip install(?! --require-hashes -r \.github/requirements/[^/\s]+\.txt\b)'`) fails on any workflow `pip install` that is not a hashed install from that directory, so the glob stays complete.
   - `pyproject.toml` gains an optional group `publish` holding only `twine`, at the version the dev group pins now; `twine` is removed from the dev group.
   - Publish jobs run `poetry install --only publish --no-root`.
   - `poetry check --lock` passes.
   - The notes carry the ADR text for the bootstrap-only exception to ADR-0001 / product AD-1 (Context, Spine and ADR effect).
5. Every row of `## Verification` passes, `just check` passes, and the act evidence is recorded in the notes file. This story closes on act evidence; no live forge run is required here (the live GitHub checks are recorded by E014-S02-007).
6. **Audit-scope wording routed (ADR-0042).** The `## Spine/ADR amendments for S02-003` section of the notes file carries, verbatim from ADR-0042, the CI spine AD-3 `pip-audit` replacement wording (including the `workflows-pip-install-from-requirements` guard) and the PRD NFR-3 replacement wording. ### Error and edge case handling

- **Hash mismatch.** `sha256sum -c` exits non-zero and the job fails before any `twine upload`, `docker login` or release step. A re-run downloads the same artifact, so a real mismatch fails every time and never publishes.
- **A step reads a missing output.** If a reusable-workflow output is empty (for example an old caller), `sha256sum -c` gets a malformed line and fails. Before anything else, each verify step asserts that the hash matches `^[0-9a-f]{64}$`, and names the output when it does not.
- **`--freeze` bumps versions.**
  - `pre-commit autoupdate --freeze` moves each hook to its latest tag. If a bump turns `just check` red, or changes a Stack-table tool in a way that needs a decision, that repo is held at its current version. Examples: a gitleaks default-allowlist change (ADR-0037, BL-E013-027) or new zizmor findings.
  - Hold a repo back by writing the current tag's commit SHA, from `git ls-remote <repo> refs/tags/<tag>^{}`, in the same `rev: <sha>  # frozen: <tag>` form. Record the hold in the notes.
  - Any gitleaks rev change re-diffs the inherited allowlist as ADR-0037 requires.
- **Optional Poetry group.** `poetry install --only publish --no-root` must not trigger dynamic versioning. Verify under act that the step succeeds on the full-history checkout already present (AD-7).
- **Dependabot breaks the hashed file.** If a Dependabot PR against `.github/requirements/poetry.txt` lacks hashes, `pip install --require-hashes` fails in `build`, so the PR is red and cannot merge. The response is to close it, remove the `pip` entry for that directory, and fall back to manual regeneration (AC 4).
- **Rerun safety.** None of these changes alters idempotence. Uploads still skip existing files (AD-11), and the image re-points tags (ADR-0036 §5).

### Security considerations

- **SHA-frozen hooks** stop a moved upstream tag from changing code that runs inside the job that produces the published `dist` (RT-E013-03).
- **Hash hand-off** means a `dist` artifact altered between the build job and a publish job is refused. This closes the "compare with itself" gap (RT-E013-04). The verify step runs before the CA import, so a tampered artifact is refused before any credential is touched.
- **Hashed Poetry and the minimal publish group** shrink what a credentialed job installs: no `pytest`/`pre-commit`/`mypy` tree beside a live token (AR-06).
- **No widening.** `build.yaml` stays `contents: read` and credential-free (AD-2, AD-13).
