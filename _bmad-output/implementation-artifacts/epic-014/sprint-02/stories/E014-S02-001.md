## Acceptance Criteria

1. **LLL pin form is enforced (F-07).**
   - A `repo: local` pygrep hook, id `workflows-lll-major-tag`, fails on any `uses:` of a `LiquidLogicLabs/*` action whose ref is not exactly `v<digits>` (optionally followed by a comment).
   - The match is case-insensitive and accepts a quoted value.
   - It runs over `^\.github/.*\.ya?ml$`, so a future composite `action.yml` under `.github/` is in scope.
   - The `.github/zizmor.yml` comment now names this hook as the enforcement, replacing "NOT MECHANICALLY ENFORCED".
2. **No credential on argv (F-09).**
   - Both Gitea "files" lookups (`dev.yaml`, `release.yaml`) send the `Authorization` header on stdin: `printf 'Authorization: token %s\n' "$TWINE_PASSWORD" | curl … -H @- …`.
   - A pygrep hook, id `workflows-no-auth-header-argv`, fails on `(?i)(-H|--header)[=\s]*["']?authorization:` in workflow files, so `--header=`, `-H'…'` and lower-case `authorization:` are caught.
   - The hook's comment states its coverage limit: it sees literal header flags only, not a header assembled in a variable or passed by `--config`/`-K`. The same limit goes into the AD-5/AD-11 amendment text.
3. **Release concurrency is described truthfully (F-10).**
   - `release.yaml`'s concurrency comment says: at most one release runs and one waits; a newer tag cancels the waiting one, and that one must be re-run.
   - `docs/ci/pipeline-walkthrough.md` §"Releasing" carries an operator note saying the same thing and giving the re-run command.
   - The group and `cancel-in-progress` are unchanged.
   - BL-E013-036 is scheduled to this story before dev starts (`pm-status schedule-issue`), so marking this story `done` resolves it.
4. **No `:0` image tag for 0.x (F-11).**
   - The `{{major}}` line in `release.yaml` carries `enable=${{ !startsWith(needs.build.outputs.image-version, '0.') }}`.
   - A pygrep hook, id `workflows-major-tag-gated`, fails on any `pattern={{major}}` line (not `{{major}}.{{minor}}`) that lacks `enable=`.
   - The hook's comment states its coverage limit: it checks that `enable=` is present, not what the expression says. The act metadata run (Testability) is the evidence for the expression's value.
5. **Base-image pull is retried and credential-free (F-18).**
   - Before its `docker/build-push-action` step, `build.yaml` pre-pulls the base image with a bounded retry.
   - The reference is read from `docker/Dockerfile`'s `ARG BASE_IMAGE` default at run time, never repeated in the YAML.
   - The smoke build then uses that local copy, which the evidence proves: the build log shows no registry fetch of the base image.
   - No credential and no permission is added to `build.yaml`.
   - The walkthrough documents "re-run on 429" for both `build` and `publish-image`.
6. **Pre-commit hooks are SHA-frozen (BL-E013-020).**
   - Every non-`local` repo in `.pre-commit-config.yaml` has `rev: <40-hex SHA>  # frozen: vX.Y.Z`, produced by `pre-commit autoupdate --freeze`.
   - `repo: local` hooks, including E014-S01-007's pip-audit hook, have no `rev` and are out of scope for freezing. Do not move a local hook into a remote repo to freeze it; pip-audit's version is pinned through `poetry.lock`.
   - A pygrep hook, id `precommit-revs-frozen`, fails on `^\s+rev:\s+(?![0-9a-f]{40}\b)` in `.pre-commit-config.yaml`.
   - The `mirrors-mypy` rev's major version equals the locked mypy major, or the mismatch is recorded in the notes with a reason.
7. **Hook updates have an owner (BL-E013-020).** The developer re-checks the GitHub Docs pages "Dependabot options reference" (`package-ecosystem: pre-commit`) and "Supported ecosystems and repositories" (§pre-commit), and records the quoted text, the URL and the ecosystem's GA or preview status in the notes. As read on 2026-10-11, the latter says "When a hook pins a specific commit SHA, Dependabot resolves the latest matching tag and updates the `rev` value accordingly" and "You can use a `# frozen:` comment after the `rev` value to pin a hook to a particular version or version prefix." Then one of two branches applies:
   - **Supported and GA:** `.github/dependabot.yml` gains a `pre-commit` entry (directory `/`, weekly, `cooldown.default-days: 7`).
   - **Not supported, or preview only:** no entry is added, and `docs/developer.md` documents a manual cadence: run `pre-commit autoupdate --freeze` monthly and before each release, then run `just check`. A preview-only status is recorded as the reason.

   Either way, the docs state that Gitea has no Dependabot and updates there are manual.
8. **Build hashes cross the job boundary (BL-E013-021).**
   - `build.yaml` exports `wheel-sha256` and `sdist-sha256` as `on.workflow_call.outputs`.
   - Every job that downloads `dist` runs `sha256sum -c` against `needs.build.outputs.*` at the position the step-order contract gives (after the Destination configuration step and the AD-15 guard, before the CA import and before any login, upload, build or release step): `publish-package` and `publish-image` in both workflows, and `release`.
   - `publish-image` passes `needs.build.outputs.wheel-sha256` as the `WHEEL_SHA256` build-arg.
   - A mismatch fails the job.
9. **Hash-checked Poetry, minimal publish install (BL-E013-024).**
   - Every `pip install poetry` in the workflows becomes `pip install --require-hashes -r .github/requirements/poetry.txt`.
   - The file is generated from `.github/requirements/poetry.in` (`poetry==2.4.2`) by pip-tools, with this exact regeneration command recorded in the file header and in `docs/developer.md`: `pipx run --spec 'pip-tools==7.5.3' pip-compile --generate-hashes --allow-unsafe --output-file .github/requirements/poetry.txt .github/requirements/poetry.in`. (`--allow-unsafe` because Poetry's dependency set can include `pip`/`setuptools`; drop it if the generated file is identical without it, and record which.) The file is never hand-edited.
   - **Owner of updates.** Dependabot's `pip` ecosystem on `/.github/requirements` (weekly, cooldown 7), if the first Dependabot PR against the file keeps `--hash=` lines and passes `pip install --require-hashes`. Otherwise the entry is removed and the maintainer regenerates the file with the command above when bumping Poetry (`docs/developer.md`). The outcome is recorded in the notes.
   - `pyproject.toml` gains an optional group `publish` holding only `twine`, at the version the dev group pins now; `twine` is removed from the dev group.
   - Publish jobs run `poetry install --only publish --no-root`.
   - `poetry check --lock` passes.
   - The notes carry the ADR text for the bootstrap-only exception to ADR-0001 / product AD-1 (Context, Spine and ADR effect).
10. `just check` passes. The act evidence listed under Testability approach is recorded in the notes file. This story closes on act evidence; the live GitHub PR run of `build / build` is verified in E014-S02-005.

## Technical acceptance criteria

### Interface contracts

- Each is a 64-hex lower-case string.
- They are sourced from the `version` step, which already computes the wheel hash at `build.yaml:86`; the sdist hash is added beside it.
- Callers read them only as `needs.build.outputs.wheel-sha256` and `needs.build.outputs.sdist-sha256`.
- The existing outputs `version` and `image-version` are unchanged.

Publish-job step order (AD-17/AD-18 amendment, shared with E014-S02-002): Destination configuration → AD-15 version guard (dev only) → hash verify → CA import → login / publish. This story places the hash-verify steps; E014-S02-002 places the Destination configuration step.

### Error and edge case handling

- **Hash mismatch.** `sha256sum -c` exits non-zero and the job fails before any `twine upload`, `docker login` or release step. A re-run downloads the same artifact, so a real mismatch fails every time and never publishes.
- **A step reads a missing output.** If a reusable-workflow output is empty (for example an old caller), `sha256sum -c` gets a malformed line and fails. Before anything else, each verify step asserts that the hash matches `^[0-9a-f]{64}$`, and names the output when it does not.
- **Pre-pull.**
  - The retry stops after a bounded number of attempts with increasing delay: 4 attempts at 15, 30 and 60 s, per research §7(e).
  - When all attempts fail, the step fails the job with the last `docker pull` error, so the check is red and a re-run is the documented response.
  - If the Dockerfile `ARG BASE_IMAGE` line cannot be parsed (missing, no `@sha256:`), the step fails naming the file and line pattern. It never pulls an unpinned reference.
- **`--freeze` bumps versions.**
  - `pre-commit autoupdate --freeze` moves each hook to its latest tag. If a bump turns `just check` red, or changes a Stack-table tool in a way that needs a decision, that repo is held at its current version. Examples: a gitleaks default-allowlist change (ADR-0037, BL-E013-027) or new zizmor findings.
  - Hold a repo back by writing the current tag's commit SHA, from `git ls-remote <repo> refs/tags/<tag>^{}`, in the same `rev: <sha>  # frozen: <tag>` form. Record the hold in the notes.
  - Any gitleaks rev change re-diffs the inherited allowlist as ADR-0037 requires.
- **Optional Poetry group.** `poetry install --only publish --no-root` must not trigger dynamic versioning. Verify under act that the step succeeds on the full-history checkout already present (AD-7).
- **Dependabot breaks the hashed file.** If a Dependabot PR against `.github/requirements/poetry.txt` lacks hashes, `pip install --require-hashes` fails in `build`, so the PR is red and cannot merge. The response is to close it, remove the `pip` entry for that directory, and fall back to manual regeneration (AC 9).
- **Rerun safety.** None of these changes alters idempotence. Uploads still skip existing files (AD-11), and the image re-points tags (ADR-0036 §5).
- **Gitea runner.** `printf | curl -H @-` needs curl ≥ 7.55. The notes record the curl version the act image provides.

### Security considerations

- **Token off argv (F-09).** `printf` is a bash builtin, so the token never reaches an exec'd argv. The header goes through curl's stdin only. GitHub's guidance (`github/docs` use-secrets) recommends stdin or environment, never the command line.
- **SHA-frozen hooks** stop a moved upstream tag from changing code that runs inside the job that produces the published `dist` (RT-E013-03).
- **Hash hand-off** means a `dist` artifact altered between the build job and a publish job is refused. This closes the "compare with itself" gap (RT-E013-04). The verify step runs before the CA import, so a tampered artifact is refused before any credential is touched.
- **Hashed Poetry and the minimal publish group** shrink what a credentialed job installs: no `pytest`/`pre-commit`/`mypy` tree beside a live token (AR-06).
- **No widening.** `build.yaml` stays `contents: read` and credential-free (AD-2, AD-13). The pre-pull step runs no login.
- **Retry action.** A third-party retry action runs in the credential-free build job only, never in a publish job.
