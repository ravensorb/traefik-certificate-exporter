## Deviations from the story text (decisions, each recorded once here)

1. **pip-tools 7.6.2, not 7.5.3.** `pipx run --spec 'pip-tools==7.5.3' pip-compile ...` fails
   on this host: pipx installs the newest pip (26.2.1) and pip-tools 7.5.3 then dies with
   `ImportError: cannot import name 'stdlib_pkgs' from 'pip._internal.utils.compat'`. 7.6.2
   (current) works. 7.5.3 is the version Dependabot runs on its side; it does not have to be
   the local generator. Dependabot's own regeneration is observed by E014-S02-007 (AG-12).
2. **`--python 3.14` added.** pip-compile writes no environment markers. Resolved under the
   host's Python 3.11 the file also held `backports-tarfile`, `backports-zstd`,
   `importlib-metadata` and `zipp` (needed only on older interpreters); every workflow's
   `setup-python` installs 3.14, so the file is resolved for 3.14 and the command says so.
3. **`--allow-unsafe` dropped** (AC 4 allows it): the 3.14 output with and without it was
   identical apart from the header (`diff <(grep -v '^#' nounsafe.txt) <(grep -v '^#' poetry.txt)`
   → no output). No `pip`/`setuptools` pin is in Poetry 2.4.2's closure.
4. **Header carries the full command** (review R2): pip-compile writes its own normalised
   `pip-compile ...` line by default, without the `pipx run` wrapper. The regeneration is
   therefore two lines, with pip-tools' `CUSTOM_COMPILE_COMMAND` set to the command:
   ```sh
   export CUSTOM_COMPILE_COMMAND="pipx run --python 3.14 --spec 'pip-tools==7.6.2' pip-compile --generate-hashes --output-file .github/requirements/poetry.txt .github/requirements/poetry.in"
   eval "$CUSTOM_COMPILE_COMMAND"
   ```
   It is recorded in `poetry.in`, in `poetry.txt`'s header and in `docs/developer.md`
   ("Keep pinned tools current").
5. **pipx is not installed on this host.** Every `pipx run ...` command above was executed
   as `uvx pipx run ...` (pipx 1.17.13 run by uvx); the pipx command line itself is unchanged.
   `python3.14 -m venv` fails here (no `ensurepip`, Debian's `python3.14-venv` is absent), so
   row 8's venv was made with `uv venv --seed --python 3.14`; the install inside it is the
   row's exact `pip install --require-hashes -r` command.
6. **Checkout, download and hash verify are unconditional** in `publish-image` (were gated on
   `PUBLISH_IMAGE`) and in `release` (were gated on `PUBLISH_RELEASE`). They touch no
   credential, they must precede the CA import (AD-18 order), and they make a tampered dist
   fail the run even when no destination is enabled; it also lets the no-secret act run show
   every verify step. The old `Locate wheel` step is folded into the verify step
   (`steps.verify.outputs.wheel-path`).
7. **zizmor `use-trusted-publishing` false positive.** zizmor (auditor) reports
   `poetry install --only publish --no-root` as a publish command (it matches the word
   `publish`). It is an install that uploads nothing; suppressed per ADR-0036 §4 with an
   inline `# zizmor: ignore[use-trusted-publishing] AD-11: ...` on the step's `run: |` header
   line (an ignore inside the block scalar is not recognised; tried first, still 2 findings).
8. **`poetry check --lock` prints no `All set!`** under Poetry 2.4.2 here: it prints the
   `[tool.poetry.*] is deprecated` warnings on stderr and exits 0 (rc=0 recorded). The lock
   diff only adds the `publish` group to group/marker lists; `diff` of every locked
   `name`/`version` pair before vs after `poetry lock` is empty.

## Spine/ADR amendments for S02-003
