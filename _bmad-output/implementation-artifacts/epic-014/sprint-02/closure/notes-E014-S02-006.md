## Spine/ADR amendments for S02-003

Exact text for E014-S02-003 to apply (in the "E014 pipeline amendments" ADR and the CI spine
`architecture-ci-cd-pipeline-2026-10-08/ARCHITECTURE-SPINE.md`). These are additive to the
S02-001 items in `notes-E014-S02-001.md`; none repeats them.

1. **CI AD-2 (pre-pull).** Add: "`build.yaml` pre-pulls the base image before the smoke
   build: a `Resolve base image` step reads the digest-pinned `ARG BASE_IMAGE` default from
   `docker/Dockerfile` (never repeated in YAML) and fails, naming the file and the
   `^ARG BASE_IMAGE=<image>@sha256:<64 hex>$` pattern, if there is no single pinned default; a
   `Pre-pull base image` step pulls it anonymously with `nick-fields/retry` (4 attempts, 30 s
   apart; the last `docker pull` error fails the job). `setup-buildx-action` uses
   `driver: docker`, so the smoke build reads that local copy and does not fetch the base
   image from ghcr.io. The job stays `contents: read` with no login (AD-13). `publish-image`
   has no pre-pull: its multi-arch build runs on a `docker-container` BuildKit, which does not
   read the local store; a 429 there, or four in `build`, is answered by re-running the
   failed jobs."
2. **CI AD-5 (LLL pins).** Replace "enforced by zizmor" with: "The `@vN` form for
   `LiquidLogicLabs/*` is enforced by the `workflows-lll-major-tag` pygrep hook over every
   YAML file under `.github/` (owner case-insensitive, the ref must be exactly `v<digits>`,
   optionally quoted and followed by a comment). zizmor's `ref-pin` policy accepts any ref,
   `@main` included, and is not the enforcement. Coverage limit: block-style `uses:` lines
   with the value on the same line; a flow-style mapping, a quoted `\"uses\":` key, a folded
   or next-line value, or a reference built by a called script is not matched." Also in
   ADR-0035 Decision 6 wherever it says zizmor enforces the major-tag form.
3. **CI AD-8 (tags).** Replace the tag-set sentence with: "Release images are tagged `X.Y.Z`,
   `X.Y` and `latest`, and `X` only while the major version is not 0: the metadata
   `type=semver,pattern={{major}}` line carries
   `enable=${{ !startsWith(needs.build.outputs.image-version, '0.') }}`. An existing `:0` tag
   stays frozen at its last old-pipeline image; `:1` appears automatically from 1.0.0. The
   `workflows-major-tag-gated` pygrep hook fails a bare-major `pattern=` line (a literal
   prefix such as `v{{major}}` included) that has no `enable=`; it checks presence, not the
   expression's value."
4. **CI AD-11 (credentials off argv).** Add: "A credential never appears on a process command
   line. The Gitea files-check sends its header on curl's stdin:
   `printf 'Authorization: token %s\n' \"$TWINE_PASSWORD\" | curl … -H @- …` (`printf` is a
   bash builtin; curl ≥ 7.55, the act image has 8.5.0). The `workflows-no-auth-header-argv`
   pygrep hook (every YAML file under `.github/`, case-insensitive) fails a literal
   `-H`/`--header` Authorization flag in any quoting (`-H \"…\"`, `-H'…'`, `-H $'…'`,
   `--header=…`). Coverage limit: flag and value on the same line only; a value on the next
   line after a `\\` continuation, a header assembled in a variable, one passed through
   curl's `--config`/`-K` file, and other credential flags (`-u`/`--user`,
   `--oauth2-bearer`) are not matched." Cross-reference the same limit from AD-5's hook list.
5. **CI AD-14 (release concurrency).** Replace "Releases queue; one is never cancelled
   mid-flight" with: "Concurrency group `release`, `cancel-in-progress: false`: at most one
   release runs and one waits; a running release is never cancelled. GitHub keeps one
   pending run per group, so a newer tag cancels the waiting release, which published
   nothing. It is re-run (`gh run rerun <run-id>`) only while no newer tag has released —
   a later re-run would re-point `latest` and `X.Y` backwards; otherwise it stays unreleased
   and the next patch is cut. A per-ref group is rejected (two releases would race on
   `latest`); `queue: max` is revisited when actionlint accepts it (rejected by v1.7.12)."
   Resolves spec-proposal BL-E013-036 (deviation 1).
6. **CI Conventions, "Conditionals" (plan review A-19).** Add: "Besides single-flag step
   `if:`s, one expression-driven condition is sanctioned: the docker-metadata `enable=`
   attribute on the bare-major tag line (AD-8), which derives from
   `needs.build.outputs.image-version`, not from a secret or a flag."
7. **CI Stack.** Add: "`nick-fields/retry` v4.0.0 (`ad984534de44a9489a53aefd81eb77f87c70dc60`,
   build job only, no credentials in that job); pygrep hooks `workflows-lll-major-tag`,

8. **Retry, global rule 1.** No loop was written, so no escape-hatch ADR fields are needed.
