## Findings

### F1 — MEDIUM — kind: claim (coverage overstated) — guard comment, ADR-0042 Amendment, walkthrough

Location:
- `.pre-commit-config.yaml` guard comment ("so every tool a hook here installs comes from poetry.lock").
- `docs/ci/pipeline-walkthrough.md` "What polices the pipeline" ("so every tool a `repo: local` hook runs (mypy, import-linter, pip-audit, deptry) comes from `poetry.lock`").
- `docs/adr/0042-…` Amendment, guard bullet.

Description: the guard checks only the `additional_dependencies` and `language` keys. It never examines `entry:`, so a `language: system` hook whose entry is not `poetry run …` passes the guard while running a tool outside the lock. Examples:
- `entry: uvx some-tool` or `entry: pipx run some-tool`, which fetch unpinned and unaudited code in the `build` job;
- a bare `entry: mypy`, which resolves to whatever is first on `PATH`.

This is not hypothetical. The story's own evidence (notes, deviation 2) observed `mypy` resolving to the pyenv-global shim instead of the locked one. The stated "Coverage limit" names flow-style mappings and remote manifest languages, but not this gap. Readers are therefore told the rule is complete when it is not (global rule 3). The `poetry-lock` hook (`entry: poetry check --lock`) also runs `poetry` from `PATH`, not via `poetry run`.

Suggested fix: add a third item to the coverage limit in all three places, for example: "a `language: system` hook's `entry` is not checked: it is `poetry run <tool>` by convention (AD-3) and review, not by this hook; an entry that calls `uvx`, `pipx run` or a binary on `PATH` would bypass the lock." Alternatively, drop the "so every tool … comes from poetry.lock" consequence clause.

### F2 — MEDIUM — kind: claim (coverage overstated) — `docs/adr/0042-dependency-audit-scope-is-the-whole-lock.md` "Not covered" rows 1-2; same text in CI spine AD-3 "Hook dependencies are locked" bullet

Description: pre-commit installs a `language: python` hook repo with `pip install .`. pip then builds the repo in a PEP 517 isolated build environment, and that environment fetches the build backend from the index, unpinned and unhashed.

Verified for `astral-sh/ruff-pre-commit` at `1f1e8bf3`:
- its `pyproject.toml` has `dependencies = ["ruff==0.16.5"]` and no `[build-system]`;
- `pip install --no-index --no-deps` of that tree fails with `Could not find a version that satisfies the requirement setuptools>=40.8.0`;
- the cached hook repo contains a `ruff_pre_commit.egg-info`.

`pre-commit-hooks` (setup.py/setup.cfg, no pyproject) builds the same way. zizmor-pre-commit is likely the same (its repo was not in the local cache, so this is unverified).

Row 2 says ruff and zizmor are "exact versions with no dependencies, fetched unhashed". Only shellcheck-py's build tooling is mentioned (row 3). The unpinned `setuptools` build backend fetched for the other remote Python hooks is the same class of exposure as `ruamel.yaml`, and the list does not state it. The "seeded with the virtualenv-bundled pip and setuptools" sentence is a different thing: it describes the hook venv, not the build-isolation env.

Suggested fix: in ADR-0042 rows 1-2 add "plus its build backend (`setuptools>=40.8.0`, pip's default for a project without `[build-system]`), fetched unpinned into pip's isolated build environment". Record the same correction in the CI spine AD-3 bullet as the deviation the notes' `## Spine/ADR amendments` check should have found. The story's inventory table has the same omission.

### F4 — LOW — kind: correctness (guard reach) — `.pre-commit-config.yaml` `precommit-hook-deps-locked` entry

Description: the `additional_dependencies` alternative tolerates whitespace before the colon (`\s*:`), but `language:` does not. Neither alternative accepts a quoted key. These lines are all valid block-style YAML that sets the key, and all pass the guard (tested): `language : python`, `"language": python`, `'additional_dependencies': [x]`. The comment's coverage limit says only "block-style keys", which these are, so the limit overstates reach. The sibling guard `workflows-if-no-secrets-vars` already uses the quoted-key form `["'']?if["'']?\s*:`.

Suggested fix (tested: catches all three, still passes `language: 'system'`, `language_version:` and comments, and has zero hits on the current config): `'^\s*(?:-\s+)?["'']?(?:additional_dependencies["'']?\s*:|language["'']?\s*:(?!\s*["'']?(?:system|pygrep|unsupported)["'']?\s*(?:#.*)?$))'`. Alternatively, add "unquoted keys, no space before the colon for `language`" to the coverage limit.

### F5 — LOW — kind: claim — `.pre-commit-config.yaml` pip-audit comment (AC 7)

Description: AC 7 requires the comment to name "every `language: system` hook". The new comment names the `poetry run` hooks (pip-audit, pip-audit-bootstrap, deptry, import-linter, mypy) and omits `poetry-lock` (`language: system`, `entry: poetry check --lock`). `poetry-lock` runs `poetry` from `PATH`, not through `poetry run`. The comment's own wording ("Every `poetry run` hook") is accurate, but it does not meet the AC as written.

Suggested fix: either name `poetry-lock` with its qualifier (its `poetry` is the dev-group one only when pre-commit runs under `poetry run`, as `just check` and `build.yaml` do), or record the AC deviation in the notes.

### F6 — LOW — kind: error/edge handling — `.pre-commit-config.yaml` `mypy` hook `files: ^src/`

Description: mypy now types the runtime dependencies from the lock (confuse and others; this is the point of AC 11), so a `poetry.lock` or `pyproject.toml` change alone can change mypy's result. For example, a confuse bump changes `Configuration`'s signatures, and an edited `[tool.mypy]` changes the settings. With `files: ^src/`, a commit touching only those files does not run mypy at commit time. Before this story, dependency types were `Any`, so this could not happen. CI (`--all-files`) still catches it, so the effect is a later failure, not a missed one. The sibling hooks `deptry` and `import-linter` include `pyproject.toml` (and deptry includes `poetry.lock`) in `files`.

Suggested fix: `files: ^(src/.*|pyproject\.toml|poetry\.lock)$`, `pass_filenames: false`, `entry: poetry run mypy src`. This needs AC 2 and the spine's "scoped to `^src/`" wording to change in the same change. Otherwise, accept it and note it in the hook comment.
