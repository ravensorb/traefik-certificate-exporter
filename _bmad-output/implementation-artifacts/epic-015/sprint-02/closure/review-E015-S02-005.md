## F1 — Every-mode ERROR text hard-codes the `loaddotenv` rationale for every key in the class

- **Severity:** low
- **Kind:** defect (observability)
- **Location:** `src/traefik_certificate_exporter/libs/settings.py:231` (`_EVERY_MODE_WITHHELD_MESSAGE`), used by `_logEveryModeWithheld`
- **Trigger:** a second key is put in `ROOT_TRUST_ENVIRONMENT_ONLY_EVERY_MODE`. AC 2 says this needs no code change.
- **Evidence:** the template reads "Ignoring settings.{key} from {origin}: it decides whether a .env file is read, so it is taken only from …". The probe with `dryrun` in the class logged `Ignoring settings.dryrun from configuration file '…/c.yaml': it decides whether a .env file is read, …`, which is false for `dryrun`. Enforcement is correctly derived from the map; the message is not. `test_every_mode_withholding_covers_a_planted_key` checks only the ERROR prefix and `"Using the default value"`, so the wrong rationale passes it. This is the generic-class claim of AC 2 and the ADR-0049 amendment item 1, and the message undermines it. There is no impact in 0.3.1, where `loaddotenv` is the only key in the class.
- **Suggested fix:** make the template class-generic, for example "Ignoring settings.{key} from {origin}: it is taken only from the environment ({env}) or {flag}, never from a file, in every mode. Using the {fallback} value (ADR-0049)." Alternatively, keep a per-key rationale next to the map entry, as the trust-map comments already do. Then add a line to the planted-key test asserting that the ERROR does not mention `.env`, or that it matches the generic text.

## F2 — The planted-key scope attack covers only the config-file route; the ADR claims more

- **Severity:** low
- **Kind:** defect (testability; the guard's reach is overstated in prose)
- **Location:** `tests/libs/test_settings.py:1908` (`test_every_mode_withholding_covers_a_planted_key`); `docs/adr/0049-root-mode-trust-covers-hook-output-and-store-location.md:398`
- **Trigger:** a future change hard-codes `loaddotenv` in the `.env` route instead of deriving the key from the map. Two examples: `_loadDotenv`, or the `everyMode` branch of `_loadDotenvAsRoot` (`_every_mode_key_of_env_name`).
- **Evidence:** the planted-key test plants the second key (`dryrun`) only in `config.yaml`, only under euid 1000. `test_every_mode_withholding_covers_every_file_the_loader_reads` covers every file route, including the cwd `.env` under euid 0 and 1000. But it iterates `_every_mode_keys()`, which in production holds only `loaddotenv`, so a `.env` route that names `loaddotenv` directly would pass both guards. ADR-0049 amendment item 6 says "a second key planted in the class is withheld with no code change", with no limit to the config file. Global rule 3 calls out prose that overstates its coverage. The code is correct today: the probe showed a planted `dryrun` in the cwd `.env` was removed. The story's Testability text specified only the `config.yaml` plant, so no AC is violated.
- **Suggested fix:** parametrize the planted-key test over the route (config file, user config, cwd `.env`) and euid 0/1000. The simplest way is to reuse the `plant()` helper of the every-file scope guard with `ROOT_SETTING_TRUST` monkeypatched. Alternatively, narrow the ADR sentence to "planted in the configuration file".

## F3 — `_withholdEveryModeSettings` copies the S01-001 file-source walk-and-pop instead of reusing it

- **Severity:** low
- **Kind:** reuse (in-repo)
- **Location:** `src/traefik_certificate_exporter/libs/settings.py:773-780`, compared with `settings.py:854-860` (`_withholdFileSourcedRootSettings`)
- **Trigger:** a later fix to how a key is located and popped from confuse file sources, for example a non-dict intermediate node or a new file-source kind. A fix made in one copy and not the other means the two trust classes withhold differently.
- **Evidence:** both methods run the same loop: `for source in self._config.sources: if not _is_file_source(source): continue; node = source; for segment in keyPath[:-1]: node = node.get(segment) if isinstance(node, dict) else None; if isinstance(node, dict): node.pop(keyPath[-1] …)`. The story's existing-library answer says "Withholding: the S01-001 source-removal mechanism, reused". The approach is reused, but the code is duplicated.
- **Suggested fix:** extract one helper, `_popFromFileSources(keyPath) -> list[str]`, that returns the filenames that carried the key, de-duplicated. Use it in both methods: the every-mode method logs one ERROR per returned filename, and the root method ignores the list.
