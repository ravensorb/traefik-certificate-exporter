### Deviations from the story text (recorded, not silent)

1. **Flag name in the every-mode ERROR is registered by `cli_args`.** The story asks for the
   flag to be "derived (the argparse option for the dest)". `settings` sits below `cli_args`
   in the AD-13 `libs-layers` contract, so it cannot import the parser. `cli_args` now calls
   `settings.register_command_line_options({dest: last option string})` from
   `globalArgParser._actions` at import (an allowed downward import; import-linter passes).
   Without a registration (e.g. the init resolver, which imports `settings` only) the ERROR
   says "the command line" without the flag. `cli_args.py` was "expected: no change" beyond
   the flag; this is the one addition.
2. **`Settings.loadDotenv` is built from confuse's merged value** (`.get(bool)`, like every
   other boolean), not passed from the decision. They are equal by construction because every
   file source of the key is withheld first;
   `test_loaddotenv_settings_value_equals_the_merged_config` asserts
   `settings.loadDotenv == _loadDotenvDecided == merged` for euid 0/1000 × env/CLI/default,
   with a config file saying the opposite. This is what lets an invalid value be "reported as
   confuse does for any malformed boolean" (below).
3. **Duplicate user-config source.** `confuse.Configuration(...)` already reads the user
   config, and `loadFromFile` adds it again with `_add_user_source()` (pre-existing). The
   every-mode ERROR is de-duplicated per file name, so a user-config `loaddotenv` gives one
   ERROR as AC 5 requires.
4. **Every-mode env names match by prefix.** A `.env` name whose confuse key path starts with
   an every-mode key (`..._LOADDOTENV_0`) is treated as that key, so an indexed form cannot
   slip past the removal in non-root mode.

## Invalid-value observation (story "Error and edge case handling")

Real CLI, 2026-10-14, cwd with a `.env` holding `..._FILESPEC=dotenv-marker.json`:

```
TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_LOADDOTENV=0 traefik-certificate-exporter -c absent.yaml -d data   -> exit 1
  ERROR ... Ignoring TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_LOADDOTENV: not a boolean. No .env file is read (ADR-0049).
  confuse.exceptions.ConfigTypeError: settings.loaddotenv: must be a bool, not int
TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_DRYRUN=garbage traefik-certificate-exporter ... --no-dotenv            -> exit 1
  confuse.exceptions.ConfigTypeError: settings.dryrun: must be a bool, not str
```

So an invalid `LOADDOTENV` fails closed (no `.env` read, `dotenv-marker` absent), logs the one
ERROR, and then the `Settings` build raises `ConfigTypeError` exactly as for any other
malformed boolean (traceback, exit 1). Kept unchanged for the other booleans, as the story
directs. Unit test: `test_loaddotenv_invalid_value_fails_closed[0|garbage|]`.
