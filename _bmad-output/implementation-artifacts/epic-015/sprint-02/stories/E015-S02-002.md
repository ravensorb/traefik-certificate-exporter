**Research facts this story relies on** (§7):
- GHCR accepts only a classic PAT ("GitHub Packages only supports authentication using a personal access token (classic)"), with `write:packages` to push.
- `GITHUB_TOKEN` with `permissions: packages: write` is GitHub's recommended alternative. It would widen a job's permissions (AD-13 forbids that) and hand the ambient token to a publishing step (AD-9 forbids that).
- Gitea's `GITEA_TOKEN` "cannot publish to the package registry of its repository" (docs.gitea.com, Actions comparison). An all-Gitea release still needs a PAT for GHCR.
- `docker buildx imagetools create` with one source index makes "a carbon copy". A `--dry-run` from `docker.io/…:0.3.0` to `git.ravenwolf.org/…:0.3.0` (buildx v0.38.0) produced index bytes whose sha256 is `e3be0498…f986`, the Docker Hub digest.
- `docker buildx imagetools inspect --format '{{json .Manifest.Digest}}'` prints **no trailing newline**, so piping several of them into `sort -u` yields one line whatever the digests are. E014-S02-007's row 15 had this false green; every digest comparison here adds `echo`.

## Business acceptance criteria

### Outcome

From 0.3.1 on, every release is one build, published from one GitHub run, to PyPI, Docker Hub, GHCR, the Gitea registry and index, and a GitHub release. Every registry carries the same digest for the version, and the maintainer has a one-line command proving it. Users who track `ghcr.io/…:latest`, including the production host, receive releases again. No workstation holds a publish token, `just act` cannot publish even with secrets lying around, the Gitea token in reach of CI can no longer administer the forge, and 0.3.0's split is repaired and on record.

### Error and edge case handling

- **`./.actrc` present:** the recipe exits 1 before act runs (AC 2). The user removes or renames it.
- **`~/.actrc` holds the `-P` platform mapping and other preferences:** they are ignored by design. The recipe supplies `-P` itself. A user who needs another option runs `act` directly, outside the recipe's contract.
- **Docker credentials:** act's container pulls are anonymous. A fresh `HOME` hides `~/.docker/config.json`, so a rate-limited pull is answered by re-running (as AD-2's 429 rule).
- **Retag (D6) fails midway** (for example, `0.3.0` moved and `0.3` not): re-run the same `imagetools create`. It is idempotent, and the digest check names any tag left behind.
- **Re-running the old `release` job (D7a) fails to find `dist`:** use D7b. Never re-push `v0.3.0`.
- **A GHCR push in 0.3.1 fails with 403:** check the PAT scope (`write:packages`), then re-run `publish-image` (E015-S02-004 edge cases).
- **Old Gitea token still accepted after "rotation":** stop, revoke it in the Gitea UI (Settings → Applications), re-check. Do not proceed to S02-004 until it gets 401.
- **Gitea mirror runs `release.yaml` on the 0.3.1 tag:** with no `PUBLISH_*` secret or variable there, it is silent (AD-9). The one-forge check proves the precondition.
