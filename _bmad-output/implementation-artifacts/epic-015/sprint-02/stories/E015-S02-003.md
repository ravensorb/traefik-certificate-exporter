# Pin and audit pre-commit hook dependencies used in the build job (spec proposal BL-E014-112 / AD-2)

## Context

**Maintainer decisions:** `_bmad-output/implementation-artifacts/epic-015/maintainer-decisions.md` — MD-17. The story proceeds on each recommendation until answered.

Spec proposal BL-E014-112: `_bmad-output/implementation-artifacts/epic-014/epic-closure/spec-proposals/AD-2.md`. Research: `_bmad-output/planning-artifacts/research/research-2026-10-12-release-0.3.1.md` §6.

`build.yaml`'s `build` job runs `pre-commit run --all-files` and then `poetry build` in the same job (CI spine AD-2 steps 3 and 5). Two hooks install Python packages that `poetry.lock` does not pin and `pip-audit` does not see:

- **import-linter.** `.pre-commit-config.yaml:59-67` declares a `repo: local` hook with `language: python` and `additional_dependencies: [import-linter==2.15]`. Its comment says "Pinned here, not in poetry.lock".
- **mypy.** `.pre-commit-config.yaml:268-275` uses `repo: https://github.com/pre-commit/mirrors-mypy` at `2834ec66…` (`# frozen: v2.4.0`), with `additional_dependencies: [types-PyYAML==6.0.12.20260906, types-python-dateutil==2.9.0.20260807]`. `mypy = "^2.3.1"` is already in the Poetry dev group (`pyproject.toml:36`; `poetry.lock` has `mypy 2.4.0`). The hook does not use it; it builds its own environment.

**How pre-commit builds these environments** (pre-commit.com): a `language: python` hook repository "must be installable via `pip install .`", and "the specified dependencies will be appended to the `pip install` command". Nothing is hash-checked: pip accepts `--hash` only in requirements files, and `--require-hashes` then requires a hash on every requirement (pip "Secure installs").

pre-commit has no lock or hash option. FR pre-commit/pre-commit#3679, "Add opt-in hash-locked installs for `language: python` hooks", was closed on 2026-05-10 with "there's several duplicates. you can already feed this into `additional_dependencies`". #2201 "pre-commit lockfile" was answered with `autoupdate --freeze`, which pins the hook repository, not its dependencies.

**What actually resolves today.** A fresh `PRE_COMMIT_HOME` run of the two hooks on 2026-10-12 built two `py_env-python3.11` environments. Their transitive dependencies are resolved at install time from the ranges below.

| Hook | Declared (PyPI `requires_dist` at the pinned version) | Installed 2026-10-12 |
| --- | --- | --- |
| import-linter 2.15 | `click>=6`, `grimp>=3.17`, `rich>=14.2.0`, `typing-extensions>=3.10.0.0`, `tomli>=1.2.1` (<3.11) | click 8.5.0, grimp 3.17, rich 15.0.0, markdown-it-py 4.2.0, mdurl 0.1.2, Pygments 2.21.0, typing_extensions 4.16.0 |
| mypy 2.4.0 (+ two stubs) | `typing_extensions>=4.6.0`, `mypy_extensions>=1.0.0`, `pathspec>=1.0.0`, `librt>=0.16.0`, `ast-serialize<1.0.0,>=0.11.2`, `tomli` (<3.11) | ast_serialize 0.13.0, librt 0.16.0, mypy_extensions 1.1.0, pathspec 1.1.1, typing_extensions 4.16.0, the two stubs |

None of these is audited. The `pip-audit` hook audits the Poetry venv (`poetry run pip-audit`, ADR-0042), and these hook environments are separate venvs. CI spine AD-3's last bullet ("their tool versions come from `poetry.lock` or from the hook's `additional_dependencies` (`import-linter==2.15`)") and ADR-0042's "Not covered" list (`docs/adr/0042-dependency-audit-scope-is-the-whole-lock.md:146-160`) do not state this gap (global rule 3).

**Approach** (maintainer decision; the story proceeds on the recommendation):

| Option | Effect |
| --- | --- |
| **A (recommended; the proposal's "preferred")** | Move import-linter, mypy and the two stub packages into the Poetry dev group. Run both hooks as `repo: local`, `language: system`, `poetry run …`. Add a pygrep guard so no hook can declare `additional_dependencies` and every local hook is `system`/`pygrep`. Record the four remaining remote Python hook repos in ADR-0042 "Not covered", ranked, and file one Low backlog item for `pre-commit-hooks`' range-resolved `ruamel.yaml`. |
| B | A, plus move `pre-commit-hooks`, `ruff`, `zizmor` and `shellcheck-py` into the dev group as local system hooks, so every PyPI-installed hook is locked, hashed and audited. This is a larger diff (Dependabot then updates them via `pip` on `/`, not `pre-commit`). |
| C | Only state the gap in AD-3 and ADR-0042. |

A closes both `additional_dependencies` hooks, which run arbitrary unpinned code in the dist-building job. The residual, stated honestly, is exact-version wheels (ruff, zizmor) fetched unhashed and one range (`ruamel.yaml`).

**Guard design (AD-4: pygrep is the allowed mechanism).** A `repo: local` pygrep hook `precommit-hook-deps-locked` over `^\.pre-commit-config\.yaml$`, with entry `^\s*(?:-\s+)?(?:additional_dependencies\s*:|language:(?!\s*(?:system|pygrep|unsupported)\s*(?:#.*)?$))`. `unsupported` is pre-commit ≥4.4.0's alias for `system`; the lock has pre-commit 3.8.0.

Run as a temporary hook on 2026-10-12, it flagged exactly `.pre-commit-config.yaml:64` (`language: python`), `:65` and `:275` (`additional_dependencies`). On a copy with option A applied, it passed. Planted `additional_dependencies` on a remote hook (`actionlint`) and planted `language: python` on a remote hook (`zizmor`) each failed it. A flow-style `{… additional_dependencies: [y]}` hook passed; that is the coverage limit. The guard cannot see a remote repo's own manifest language, so the four remote Python repos above are the stated exception, recorded in ADR-0042 and not enumerated in the hook.

## Acceptance Criteria

1. **The two hooks run from the lock.**
   - `pyproject.toml` `[tool.poetry.group.dev.dependencies]` declares `import-linter = "^2.15"`, `types-pyyaml = "^6.0.12.20260906"` and `types-python-dateutil = "^2.9.0.20260807"`. `mypy` stays.
   - `poetry.lock` is regenerated with `poetry lock`, which keeps existing pins.
   - `poetry check --lock` passes.
2. **Hook definitions.** In the existing `repo: local` block:
   - `import-linter`: `language: system`, `entry: env PYTHONPATH=src poetry run lint-imports --no-cache`, no `additional_dependencies`, same `files`.
   - `mypy`: `language: system`, `entry: poetry run mypy`, `args: [--config-file=pyproject.toml]`, `files: ^src/`, `types_or: [python, pyi]`, `require_serial: true`. The id stays `mypy`, so `pre-commit run mypy` is unchanged.
   - The `pre-commit/mirrors-mypy` repo entry is removed.
3. **No hook environment is built for them.** With a fresh `PRE_COMMIT_HOME`, running `mypy` and `import-linter` creates no `py_env-*` directory (two before the story).
4. **They are audited.** `poetry run pip list` shows import-linter, grimp, mypy, types-pyyaml and types-python-dateutil. The `pip-audit` hook passes over them.
5. **They still examine the code** (anti-false-green). In a throwaway clone, a planted type error under `src/` fails `mypy`, and a planted `import traefik_certificate_exporter.app` in `libs/object.py` fails `import-linter` (contract `entrypoint-on-top`). The current tree passes both. A probe on 2026-10-12, `poetry run mypy --config-file=pyproject.toml src/` in the Poetry venv, gave "Success: no issues found in 14 source files". If adding the stubs to the venv changes mypy's result, the findings are fixed in this story or the story stops and files them; `[tool.mypy]` settings are not loosened.
6. **The guard exists and covers its scope.**
   - Hook id `precommit-hook-deps-locked`, `language: pygrep`, the entry above, `files: ^\.pre-commit-config\.yaml$`, beside `precommit-revs-frozen`.
   - Its comment cites BL-E014-112 and ADR-0042 and states the coverage limit: block-style keys only; a flow-style hook mapping is not matched; remote hook repos' own manifest languages are not visible, and those are listed in ADR-0042.
   - The scope-attack plants of `## Verification` row 4 fail it.
7. **Comments and records corrected.**

## Business acceptance criteria

### Outcome

The job that builds the published wheel, sdist and smoke image no longer installs unpinned, unaudited Python packages for import-linter and mypy. Their whole dependency closure is hash-locked in `poetry.lock`, updated by Dependabot `pip`, and checked by `pip-audit` on every run. Any future hook that tries to bring its own unlocked dependencies fails `just check`. The remaining third-party hook environments are listed with exactly what they fetch, so the next reviewer knows the real coverage.

#### 0.3.1 release notes

- Internal-only (no upgrade note): mypy and import-linter run from `poetry.lock`; the new `precommit-hook-deps-locked` guard. Contributor-visible: `poetry sync --all-groups` now installs import-linter and two type-stub packages.

Spec: none — l3io-plan run, no spec index bound

### Non-goals

- Does not move ruff, zizmor, pre-commit-hooks or shellcheck-py into the lock (option B). It records them instead.
- Does not hash-verify golang hook toolchains, or audit Go modules.
- Does not change mypy strictness or import-linter contracts.
- Does not change `build.yaml`'s step order or split hooks out of the `build` job.
- Does not lock Poetry's plugin environment (BL-E013-033, ADR-0042).

## Technical acceptance criteria

### Interface contracts

- Hook ids stay `mypy` and `import-linter`, so `pre-commit run <id>`, `just check` and `build.yaml` (`pre-commit run --all-files`) are unchanged.
- `language: system` hooks require the Poetry venv: `just install` locally, and `poetry sync --all-groups` in `build.yaml`, both already true (AD-2 step 2).
- Sibling conventions in the `repo: local` block:
  - every `system` hook's entry is `poetry run <tool>`;
  - every hook has a comment citing its AD/ADR;
  - `pass_filenames` and `files` are set explicitly;
  - pygrep guards state a "Coverage limit:".
- Dependency declarations in the dev group follow the existing caret style, with the comment convention "Dependency gates run as `repo: local` pre-commit hooks; their versions are pinned here by poetry.lock" (`pyproject.toml:37-38`), extended to name mypy and import-linter.
- Dependabot: the `pre-commit` ecosystem no longer sees mypy; the `pip` ecosystem on `/` updates the dev group through `poetry.lock` (AD-5). No `dependabot.yml` change is needed.

Spec: none — l3io-plan run, no spec index bound

### Error and edge case handling

- **Venv missing or stale:** a `system` hook fails with `poetry run` "command not found". The fix is `just install`. This is the same failure mode as pip-audit and deptry today.
- **mypy finds new errors once stubs and real packages are importable:** fix them in scope if they are true positives with a one-line fix. Otherwise stop and file them; `[tool.mypy]` is never loosened to pass.
- **pip-audit reports an advisory in a newly locked package** (for example, rich or Pygments): handled by ADR-0042's policy (upgrade, or `--ignore-vuln <ID>` with reason and `BL-` key).
- **pre-commit is upgraded to ≥4.4** and `system` is reported as deprecated: the guard already allows `unsupported`. Renaming is a separate change.
- **Gitea runner / act:** `build.yaml` is unchanged, so there is no runner difference.

Spec: none — l3io-plan run, no spec index bound

### Testability approach

There is no pytest and no custom policy code (AD-4). The checks are:

- the pygrep guard, run over the real config and over planted copies in a throwaway clone that attack its scope (a remote-hook override and a language override, not only the local hook);
- a fresh-`PRE_COMMIT_HOME` run proving no hook env is built;
- planted type and import violations proving the moved hooks still examine `src/`;
- `just check`.
