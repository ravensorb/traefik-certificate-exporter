# Close the /config root-escalation: the service account must not control what runs as root

## Context

**Maintainer decisions:** `_bmad-output/implementation-artifacts/epic-015/maintainer-decisions.md` — MD-19, MD-20, MD-21, MD-22, MD-23, all accepted as recommended on 2026-10-12. The earlier MD-01..05 (take `/config` back to root, neutralise the base `lsiown` lines, refuse a non-root-owned config) are withdrawn.

**Maintainer constraint (2026-10-12), verbatim:** "for the root fix -- do NOT break lsio and the way they do things". It means:
- `/config` stays owned by `abc` (`PUID`/`PGID`), as the base image makes it;
- the base image's `lsiown` lines and init scripts are not disabled, patched or worked around;
- host operators keep editing `/config/config.yaml` as their normal `PUID` user;
- `/config`, `/app` and `/defaults` are not taken back to root, and an `abc`-owned config is not refused.

Promoted from deferred finding(s):
- BL-E014-119 (High, epic-redteam (RT-1)) — See _bmad-output/implementation-artifacts/epic-014/epic-closure/redteam-report.md. Deferred to E015 (0.3.1) per epic-closure directive: only BLOCKER/CRITICAL fixed at E014 closure; 0.3.0 released. Not ADR-accepted.

**Evidence:** `_bmad-output/implementation-artifacts/epic-014/epic-closure/redteam-report.md` §RT-1. On the released `ravensorb/traefik-certificate-exporter:0.3.0`, uid 911 replaced `/config/config.yaml` with `restartcontainers: true` and `postexportcommand: "/bin/sh -c \"id > /certs/pwned.txt\""`, and the next start ran the hook as `uid=0(root)`. Re-run during this enrichment (2026-10-12) against `traefik-certificate-exporter:local` (built 2026-10-12 05:42 from `main`), with `PUID=1000` and a generated store: after the first boot `/config` was `1000:1000 755` and `config.yaml` `0:0 644`; uid 1000 replaced `config.yaml` with the payload (`mv -f` succeeded); the next run-once start logged the `restartcontainers` root WARNING and `/certs/pwned.txt` contained `uid=0(root) gid=0(root) …`.
**Research:** `_bmad-output/planning-artifacts/research/research-2026-10-12-release-0.3.1.md` §1 "LinuxServer conventions and the root boundary". Every base-image fact below was read from the digest-pinned base image, its upstream source, or the 0.3.0 / `:local` images.

**Problem.**

- The base image is `ghcr.io/linuxserver/baseimage-alpine:3.24@sha256:d2deff7a…fea` (`docker/Dockerfile:6`, label `org.opencontainers.image.version=4bf86442-ls13`, revision `f6b732b1`). Its `init-adduser/run:53-57` runs `lsiown abc:abc /app`, `/config` and `/defaults` on every start. This is LinuxServer's convention and stays as it is. `/config` is therefore always writable by the `PUID` account, inside the container and, for a bind mount, on the host.
- LinuxServer's own images treat `/config` as the operator's configuration, even for root components. `linuxserver/docker-swag@0cc53e2`, `init-fail2ban-config/run`, copies `/config/fail2ban/action.d` and `jail.local` into `/etc/fail2ban`, and `svc-fail2ban/run` runs `fail2ban-client -x -f start` as root. LinuxServer has no mechanism that keeps the `PUID` account from configuring a root component. This project's ADR-0030 does treat the drop to `abc` as containment, and that is the gap.
- The exporter runs as root in most deployments, not only when `restartcontainers` is on. The privilege decision (`docker/root/usr/local/lib/traefik-certificate-exporter/privilege-decision.sh:79-168`) keeps root when settings are unresolved, when `restartcontainers` is true, or when `abc` cannot read the store. A stock Traefik writes `acme.json` `0600` owned by root.
- A root exporter takes every setting from whichever source wins in confuse: CLI > environment > config file > packaged default (`settings.py:313-346`). It then acts on two settings as root:
  - `postexportcommand`, through `subprocess.run` (`post_export.py:88`), with the exporter's uid;
  - `outputpath`, which root writes into (`certificate_exporter.py`, `_atomic_write`, `directory.mkdir(parents=True)` at `:1020`). In dropped mode, init also chowns everything under it to `abc` (`init-…-config/run:146-153`).
- The image sets `TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_OUTPUTPATH=/certs` and `…_DATAPATH=/data` as `ENV` (`Dockerfile:123-130`). The environment outranks the file, so in the image `config.yaml` cannot move `outputpath` today. That protection is incidental, undocumented and untested, and a PyPI install run as root has no such `ENV`.
- Root mode itself is file-controlled: `restartcontainers: true` in `config.yaml` forces it. Once root mode no longer takes a command or a write target from a file, forcing it gains an attacker only what `docker.py` does with the socket: `ping`, `version`, `containers.list(filters={"label": DOCKER_LABEL})`, `containers.get(id)` and `container.restart()` (`docker.py:157-158,300-301,365,479`). There is no create, exec or pull, and the endpoint comes only from `DOCKER_HOST`.
- Three documents claim `/config` stays root-owned, which has not shipped since 0.3.0 and is not LinuxServer's convention:
  - `docs/adr/0030-conditional-privilege-drop.md:89-91`;
  - `docs/operational.md:294-301` ("it must be root-owned");
  - `docs/operational.md:417-420`.
  `docker/README.md:90-99` says nothing about `/config` ownership or the hook.

**Options evaluated** (research §1):

| Option | Verdict |
|---|---|
| (a) Take `/config`, `/app`, `/defaults` back to root in init, neutralise the base `lsiown` lines at build, refuse a non-root-owned config | **Withdrawn** by the maintainer constraint: it breaks the LinuxServer ownership convention and host editing as `PUID`. |
| (b) Run the hook as `abc` even when the exporter is root: `subprocess.run(user=, group=, extra_groups=[])` (stdlib since Python 3.9; floor here is 3.10), `s6-setuidgid abc` (`/usr/bin/s6-setuidgid` in the image) or `setpriv` (`/bin/setpriv` in the image) | **Rejected as the fix.** Root writes keys `0600 root:root` (`_SECRET_FILE_MODE`, `certificate_exporter.py:66`), so an `abc` hook cannot read `privkey.pem` or `cert.pfx`, and it cannot reach the Docker socket. Hooks that copy keys or signal a container would break. An operator who needs a root hook still needs an opt-in, and an opt-in from `/config` would reopen RT-1. So the opt-in must come from the environment anyway, and (d) on its own closes the attack. Recorded in MD-22. |
| (c) Split the root part out: a root-only reader hands the store to an `abc` process, or one s6 service per privilege | **Rejected.** LinuxServer has no such pattern for a single application; its images run a root service directly (swag's fail2ban). It would need a new IPC path and a second service, which is far larger than (d), and the hook and Docker restarts would still need root. |
| (d) **A root process takes the settings that decide what root executes or where it writes only from the environment or the command line, never from a file** | **Adopted.** When `os.geteuid() == 0`, `postexportcommand` and `outputpath` coming from a configuration file or a `.env` file are withheld. The value falls back to the next non-file source (environment, CLI, or the packaged default), and one ERROR names the setting and the file. Every other setting stays settable from `config.yaml`. The base image, its init and `/config` ownership are untouched. A dropped (`abc`) exporter still runs a `config.yaml` hook, as `abc`. Whoever writes the container's environment (compose file, `docker run`) already controls the container, so an environment-sourced root hook is the operator's explicit choice. |
| (e) Make root-mode triggers (`restartcontainers`) environment-only too | **Rejected** (MD-21). Under (d) a file-forced root mode runs no file-sourced command and writes no file-chosen path. Its remaining reach is restarting containers that carry the restart label. Making the trigger environment-only would also make the root resolver and a dropped `abc` exporter disagree about `restartcontainers`. |

## Acceptance Criteria

1. **Every setting has a declared root-trust class, derived from the key registry.** `src/traefik_certificate_exporter/libs/settings.py` declares `ROOT_SETTING_TRUST: dict[tuple[str, ...], str]`, beside `SECRET_CONFIG_KEYS`. It maps every leaf key path of `config_default.yaml` to one of two module constants:
   - `ROOT_TRUST_ENVIRONMENT_ONLY = "environment-only-when-root"`: `("settings", "postexportcommand")` and `("settings", "outputpath")`;
   - `ROOT_TRUST_ANY_SOURCE = "any-source"`: every other leaf (`datapath`, `filespec`, `traefikresolverid`, `resolverinpathname`, `flat`, `dryrun`, `restartcontainers`, `domains.include`, `domains.exclude`, `watchforchanges`, `runatstart`, `watchinterval`, `pkcs12passphrase`, `appriseurls`), each with a one-line comment saying why it is safe from a file (MD-21).

   A test derives the leaf set from `config_default.yaml` and fails on any leaf that is missing from the map, on any key in the map that is not a leaf, and on any value that is neither constant (AC 6).
2. **A root process withholds an environment-only setting that came from a file.** `SettingsManager.loadFromFile` gains a step after every source is merged (after `set_args`, before `check_setting_names` and `_mark_present_secrets`). When `os.geteuid() == 0` (guarded with `hasattr(os, "geteuid")`), for each `ROOT_TRUST_ENVIRONMENT_ONLY` key it reads the key's `view.resolve()` pairs (confuse 2.3.0, in priority order):
   - If the winning pair's source is a file source, the value is withheld. A file source is a `confuse` source with a `filename` that is not the packaged default (`source.filename is not None and not source.default`), which covers the config file and the confuse user config.
   - The value is withheld by **removing the key from every file source** in confuse's own source list (`self._config.sources`, each a dict-backed `ConfigSource`; pop the leaf from that source's nested `settings` mapping when it is a dict), never by `view.set(...)`. `set()` would insert a new filename-less `ConfigSource` at the front, indistinguishable from the one `set_args` adds, so `sourceOf` would report "command line" for a value that came from the environment or the default. After the removal, confuse's own `resolve()` yields the next source in the unchanged precedence order (environment, command line, or the packaged default), with its real source object. For `postexportcommand` this is normally `null` (hook off); in the image `outputpath` falls back to `/certs` from `ENV`.
   - The file's path is captured for the ERROR before the key is removed. One ERROR is logged per withheld key (Observability).

   When the euid is not 0, nothing changes.
3. **`.env` files cannot smuggle an environment-only setting into a root process.** `load_dotenv` writes into `os.environ`, so a `.env` value would otherwise look like the environment. When the euid is 0, the loader snapshots the environment names before each `load_dotenv` call (the module `.env` and the cwd `.env`). Afterwards, any environment-only key's variable that the call newly added is removed and logged with the same ERROR, naming the `.env` file. The variable name is `TRAEFIK_CERTIFICATE_EXPORTER_` plus the upper-cased key path joined by `_`, derived from `ROOT_SETTING_TRUST`, never typed, and it is compared case-insensitively because confuse's `set_env` lower-cases. A variable the real environment already held is untouched (`load_dotenv` does not override). Other `.env` keys load as today.
4. **The hook's source and uid are visible at start.** `app.py`, after the `Output Path:` line (`:177`), logs one INFO line: `Post-export command: <set|not set> (source: <environment|command line|configuration file '<path>'|default>), runs as uid <euid>`. The source comes from a new `SettingsManager.sourceOf(keyPath) -> str`, which classifies the first pair of `resolve()`. Because withholding removes the file pair instead of adding an overlay (AC 2), the reported source is the real one: a root process with the hook only in `config.yaml` reports `default`, and one with the hook in both `config.yaml` and the environment reports `environment`. The command itself is never logged, because it is a declared secret (`SECRET_CONFIG_KEYS`, ADR-0045). The line follows the existing `Log level: … (source: …)` pattern (`app.py:140`).
5. **The hook is the only process the package spawns.** This keeps AC 2 the one gate on what root executes. A test walks every `*.py` file under the installed `traefik_certificate_exporter` package directory, found with `rglob` and not a list. With `ast`, it finds every call to `subprocess.*`, `os.system`, `os.popen`, `os.exec*`, `os.spawn*`, `os.posix_spawn*`, `os.fork*`, `pty.spawn` and `asyncio.create_subprocess_*`, and every `from subprocess import`. It asserts that the only site is `libs/post_export.py` `_run`. A second test plants a module with `os.system("id")` in `tmp_path` and asserts that the same scanner reports it.
6. **Scope guards** (global rule 4):
   - The classification test of AC 1 lives in `tests/test_settings_surface.py`, next to the other `config_default.yaml`-derived checks, and reuses its `CONFIG_DEFAULT` constant. A companion test runs the same helper over a copy of the default tree with an extra planted leaf and asserts that the helper reports that leaf.
   - The file-source guard in `tests/libs/test_settings.py` wraps `confuse.sources.YamlSource.__init__` and `settings.load_dotenv` to record every file the loader reads. The test places a config file, a confuse user config (through `HOME`), a cwd `.env` and a module `.env`. For each recorded non-default file, it sets `postexportcommand` in that file alone and asserts that a root load yields `None`. The notes show that it fails when the `.env` handling of AC 3 is deleted.
7. **The running image proves the boundary without changing LinuxServer's init**, in `tests/test_container_root_trust.py` (new, opt-in, marker `integration`). It runs against `${TCE_IMAGE:-traefik-certificate-exporter:local}` with `PUID=1000 PGID=1000`, named volumes for `/config` and `/certs`, run-once mode, and a store from `tests/fixtures/acme_fixtures.py` (`0644`, so a change always happens on a fresh `/certs`):
   - (i) **RT-1 replay.** After a first boot, uid 1000 replaces `/config/config.yaml` by rename with `restartcontainers: true` and `postexportcommand: "/bin/sh -c \"id > /certs/pwned.txt\""`, and the container starts again. Asserted: the root WARNING for `restartcontainers` is present (root mode was forced), `/certs/pwned.txt` does not exist, the log has the AC 2 ERROR for `settings.postexportcommand` naming `/config/config.yaml`, and the AC 4 line reads `not set … runs as uid 0`.
   - (ii) **Control: an environment hook still runs as root.** The same command, set as `TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_POSTEXPORTCOMMAND` with `TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_RESTARTCONTAINERS=true`, writes `uid=0(root)`.
   - (iii) **Dropped mode keeps the `config.yaml` hook, as `PUID`.** With `/data` mounted `:ro`, `restartcontainers` off and the hook in `config.yaml`, `/certs/pwned.txt` starts with `uid=1000` and the AC 4 line reads `runs as uid 1000`.
   - (iv) **`/config` stays LinuxServer-owned and host-editable.** After start, `stat -c '%u:%g' /config` is `1000:1000`, and as uid 1000 creating `/config/probe`, writing it, and replacing `config.yaml` by rename all succeed.
8. **LinuxServer's init is untouched.** The diff contains no change to `docker/Dockerfile` that names `init-adduser`, and none under `docker/root/etc/s6-overlay/s6-rc.d/init-adduser/` (which holds only `branding`). The resolver in `init-traefik-certificate-exporter-config/run` runs as root through the same `loadFromFile`, so AC 2-3 apply to it without any script change. No s6 script changes in this story.
9. **Docs state what ships.**
   - `docs/adr/0030-conditional-privilege-drop.md:89-91` is replaced by a dated amendment. It says LinuxServer's `init-adduser` gives `/config` to `abc` on every start (the LinuxServer convention, kept), that this was BL-E014-119, and that from 0.3.1 a root exporter takes `postexportcommand` and `outputpath` only from the environment or the command line. It points to the new ADR.

## Business acceptance criteria

### Outcome

- The account the exporter drops to (`abc`, i.e. `PUID`) keeps owning and editing `/config`, as in every LinuxServer image. It can no longer decide what the exporter runs as root, or where root writes. The RT-1 replay (rename a `config.yaml` with `restartcontainers: true` and `postexportcommand` into `/config`, then restart) still yields root mode, but the hook does not run, and the log says why.
- An operator who sets the hook in the container's environment, as `docker/README.md`'s compose example shows (`:184`), sees no change: it runs as before, as root when the exporter is root.
- An operator who set the hook in `config.yaml` and runs the exporter as root gets one ERROR at every start naming the setting, the file and the environment variable to use. Certificates keep being exported.
- In unprivileged mode a `config.yaml` hook keeps working, as `PUID`.
- ADR-0030, `docs/operational.md` and `docker/README.md` describe the ownership that actually ships and the new boundary. An image test proves both on every run of the integration suite.

#### 0.3.1 release notes

The release story generates `docs/upgrading.md` from this list. Every bullet is a user-visible change.

- "**Security (BL-E014-119): a root exporter no longer takes `postexportcommand` or `outputpath` from a file.** `/config` is owned by your `PUID`/`PGID` account, as in every LinuxServer image. In 0.3.0 that account could set `postexportcommand` in `config.yaml` and have the next start run it as root. From 0.3.1, when the exporter runs as root, these two settings are read only from `TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_POSTEXPORTCOMMAND` / `…_OUTPUTPATH` or the command line. A value from `config.yaml` or a `.env` file is ignored, with one ERROR at start."
- "**Action if you run as root with a hook in `config.yaml`:** move it to the container's `environment:` as `TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_POSTEXPORTCOMMAND`. The start-up line `Post-export command: … (source: …), runs as uid …` shows where the hook came from and which uid runs it. In unprivileged mode (`runs as uid` = your `PUID`) a `config.yaml` hook keeps working."
- "**Nothing changes in `/config` ownership.** It stays owned by `PUID`/`PGID` and editable from the host as that user. Earlier documentation that said `/config` stays root-owned was wrong and has been corrected."
- "**PyPI installs run as root:** the same rule applies. Pass `--post-export-command` / `--output-path`, or set the environment variables."

Spec: none — l3io-plan run, no spec index bound

### Non-goals

- Does not change /config ownership or LSIO init (base image `init-adduser`, `lsiown`). No change to `docker/Dockerfile`, to the base image's s6 scripts, or to `/app` and `/defaults` ownership.
- No change to the privilege decision (ADR-0030 rows): what makes the service drop or keep root is unchanged, and `restartcontainers` stays settable from `config.yaml` (MD-21).
- The hook is not run as `abc` when the exporter is root (MD-22). An environment-sourced hook runs with the exporter's uid, as today.
- No new setting or environment flag to opt back into file-sourced root hooks.
- No change to the seeded `config.yaml`'s owner (`0:0` from init), and no move of the venv out of the `abc`-owned `/app` (MD-23: separate backlog items).
- No protection against code the operator chooses to run as root: Docker mods, `/custom-cont-init.d`, a root hook whose program or script lives in `/config`, or `TRAEFIK_CERTIFICATE_EXPORTER_LOGGING_CFGFILE` pointed into `/config`. These are documented (AC 9), not enforced.
- No change to the hook's inherited environment (RT-3) or to argv secrets (RT-4).
- No fix for the file-logging "Known limitation" paragraph (`docs/operational.md:422-426`, BL-E015-001) beyond removing its "root-owned `/config`" wording (AC 9).

## Technical acceptance criteria

  - New module function `_env_name(keyPath: tuple[str, ...]) -> str`, which returns `"TRAEFIK_CERTIFICATE_EXPORTER_" + "_".join(keyPath).upper()`. It is the same rule confuse's `set_env(prefix=…, sep="_")` applies, and the loader's `set_env` call uses the same prefix literal.

- `src/traefik_certificate_exporter/app.py`: one INFO line after `:177` (AC 4), using `os.geteuid()` where available and `"n/a"` otherwise.
- No change to `post_export.py`, `notify.py`, `docker.py`, `certificate_exporter.py`, `docker/Dockerfile` or any s6 script.

  - names `tce-root-trust-it-<hex8>`;
  - `container.remove(force=True)` and volume removal in `finally`.
  Edits as uid 1000 go through `docker run --user 1000:1000 --entrypoint sh` helper containers on the same named volume, so no host `chown` is needed.

### Error and edge case handling

- **Both a file and the environment set the key:** the environment wins as today. Nothing is withheld, and no ERROR is logged.
- **Only a file sets `postexportcommand`, and the exporter is root:** the hook is off for this start, and the ERROR repeats on every start until the operator moves it. Exports, notifications and restarts proceed. Withholding is chosen over exiting (MD-20).
- **Only a file sets `outputpath`, and the exporter is root:** in the image it falls back to the `ENV` `/certs`. On a PyPI root run it falls back to the packaged default `./certs`, relative to the cwd, and the ERROR says so; `require_existing_path` (`app.py:41-48`) then applies as today.
- **The init resolver** (root, output to `/dev/null`) applies the same rule. So the resolved `outputPath` that init chowns in dropped mode never comes from a file. It agrees with a root service, and in the image a dropped service reads the same `ENV` value.
- **Dropped mode:** the exporter is `abc`, so the rule is inactive and a `config.yaml` hook runs as `abc`. That account already owns `/config`, so it gains nothing.
- **A `.env` defines the key, but the real environment already had it:** `load_dotenv` keeps the real value. Nothing is removed, and no ERROR is logged.
- **The confuse user config** (`$HOME/.config/traefik_certificate_exporter/config.yaml`) is a file source and is withheld in the same way. In root mode `HOME` is `/root`.
- **Windows (no `os.geteuid`):** the rule is inactive, and the AC 4 line says `runs as uid n/a`.
- **A future setting added to `config_default.yaml` without a class:** `tests/test_settings_surface.py` fails, naming the key (AC 6). E015-S01-002 adds `validatekeys` and must classify it (`any-source`).

### Security considerations

- **Closes BL-E014-119 / RT-1 as reproduced.** A file the `PUID` account can write can no longer name a command that root runs, or a directory that root writes into or that init chowns. The account can still force root mode (MD-21). Root mode then uses the Docker socket only to list and restart containers that carry `com.github.ravensorb.traefik-certificate-exporter.domain-restart`, through the restart rule's rate floor.
- **Settings classification** (derived from `config_default.yaml`; the test enforces completeness):
  - environment-only when root: `postexportcommand` (root executes it) and `outputpath` (root writes to it; init chowns under it);
  - any source:
    - `datapath`/`filespec` (read and JSON-parsed only; key outputs stay `0600` root-owned in root mode);
    - `traefikresolverid`, `resolverinpathname`, `flat` and `domains.*` (path components are whitelisted, and containment is checked by `_is_safe_path_component`/`_is_contained_within`);
    - `restartcontainers` (bounded Docker API, above);
    - `appriseurls`: network egress only. Apprise 1.13.1 loads no plugins unless `AppriseAsset(plugin_paths=…)` is passed, and `notify.py:55` passes none. `notify()` is called without `attach`. `ntfy://…?attach=` forwards a remote URL to the ntfy server and reads no local file. The only plugin that spawns a process, `macosx`, is disabled off Darwin;
    - `pkcs12passphrase`, `dryrun`, `watchforchanges`, `runatstart` and `watchinterval`: no privilege effect.
  - Logging configuration is already environment-only (`TRAEFIK_CERTIFICATE_EXPORTER_LOGGING_CFGFILE`, `logging_utils.py:240-260`).
- **Guards attack the scope, not only the rule** (global rule 4): the classification is derived from the key registry and a planted extra key; the file-source guard is derived from every file the loader actually opens; the spawn-site guard walks the package with `rglob` and reports a planted `os.system`; the image test replays the real attack on the built image, including the base image's init.
- **Residual risks (in the ADR):**
  - an operator's environment-sourced root hook that runs a script stored in `/config`, or a `LOGGING_CFGFILE` in `/config` (documented, not enforced);
  - Docker mods and `/custom-cont-init.d` run as root by the operator's choice;
  - the venv lives under the `abc`-owned `/app`. Renaming `/app/.venv` returned `EXDEV` on overlay2 here (RT probe and 2026-10-12 re-probe), but that depends on the storage driver (MD-23);
  - Apprise destinations from `config.yaml` can send the changed domain names to any host (egress), not secrets.
- No new secrets. The ERROR and INFO lines carry no setting values.

### Existing-library check

- **Provenance:** confuse 2.3.0's own `ConfigView.resolve()`, `ConfigSource.filename`/`.default`, `EnvSource`, and `RootView.sources` (a public list of dict-backed `ConfigSource` objects). Verified 2026-10-12 against the installed `.venv/lib/python3.11/site-packages/confuse/` (2.3.0): `RootView.resolve()` returns `((dict(s), s) for s in self.sources)`; `set()` inserts a new filename-less `ConfigSource` at index 0 and `set_args` calls `set()`, so a `set()`-based fallback is indistinguishable from the command line (validation V-02). A throwaway probe built a `Configuration` with a default source, a `YamlSource` holding `postexportcommand` and `outputpath`, and an `EnvSource` holding only `outputpath`; after popping both keys from the `YamlSource` alone, `resolve()` yielded `(None, default)` for the hook and `('/certs', EnvSource)` then the default for `outputpath`, and `.get()` returned `None` and `/certs`. So confuse keeps doing the precedence; the story only removes an inadmissible source's entry. There is no second parser and no hand-rolled precedence. confuse has no public per-key source removal; `clear()` drops every source, so it does not fit.
- **`.env`:** python-dotenv 1.2.4's `load_dotenv`, unchanged. Only an `os.environ` name snapshot surrounds it.
- **Dropping privileges for the hook** (rejected, MD-22): had it been needed, stdlib `subprocess.run(user=, group=, extra_groups=)` (Python ≥ 3.9; project floor `>=3.10`) or the image's `/usr/bin/s6-setuidgid` would have been used, never a hand-written `setuid` sequence.
- **Spawn-site scan:** stdlib `ast`. This is a test helper inside pytest, not a runner.
- **Tests:** pytest and the Docker SDK (`docker` package), already used by `tests/test_container_*.py`. There is no new dependency and no new harness.
