# Warn about pre-confuse TRAEFIK_* env names

## Context

**Maintainer decisions:** `_bmad-output/implementation-artifacts/epic-015/maintainer-decisions.md` — MD-08, MD-09, both accepted as recommended on 2026-10-12 (recorded here as D-1 and D-2).

Promoted from deferred finding(s):
- BL-E014-107 (Low, live-host-test (rwusdckrls6-2026-10-12)) — See _bmad-output/implementation-artifacts/epic-014/sprint-02/closure/live-host-test-rwusdckrls6-2026-10-12.md.

**Evidence.** Live-host test row A (`live-host-test-rwusdckrls6-2026-10-12.md:21`): production sets `TRAEFIK_RESOLVERID_INOUTPUTPATHNAME=1`, and 0.3.0 logs "No legacy warning". The output layout was still correct only because `settings.resolverinpathname` now defaults to `true` (`config_default.yaml`). Reproduced on 2026-10-12 against the current tree:
- `find_legacy_settings({"TRAEFIK_RESOLVERID_INOUTPUTPATHNAME": "1", "TRAEFIK_RESOLVERID": "r", "FLAT": "1"}, None)` returns `[]`;
- a CLI run with `TRAEFIK_RESOLVERID_INOUTPUTPATHNAME=1 TRAEFIK_CERTIFICATE_EXPORTER_DRYRUN=1` warns about the second name only.

**Research:** `_bmad-output/planning-artifacts/research/research-2026-10-12-release-0.3.1.md` §4 "Historical TRAEFIK_* environment names (E015-S01-004)". It holds the derivation commands and their output. The table below is that output.

**Why they are missed (verified against the current tree).**

- `src/traefik_certificate_exporter/libs/legacy_settings.py`:
  - `find_legacy_settings` examines only `n.startswith(ENV_PREFIX)`, where `ENV_PREFIX = "TRAEFIK_CERTIFICATE_EXPORTER_"`;
  - `_legacy_entry` matches against `_canonical(name)`, which assumes that prefix;
  - so no name outside the prefix can ever be found, even if a row were added.
- The table's derivation (E014-S01-009) and its guard, `tests/test_settings_surface.py::test_legacy_map_covers_documented_names`, examine only names matching `ENV_NAME_PATTERN = TRAEFIK_CERTIFICATE_EXPORTER_…` (`:50-52`), over the documentation pathspecs `_SCAN_INCLUDE` (`:59`).
- The pre-confuse names were not read by Python at all. **The 0.0.x image's `docker/root/app/run.sh` translated them into CLI flags** with presence tests: `if [ ! -z ${NAME+x} ]; then appParams+=" --flag"; fi`. That file is a shell script, outside both the regex and the pathspecs. The guard reported success over a set that did not contain them (global rule 4).

**Historical pre-confuse environment names (derived 2026-10-12, `git log HEAD`, full history, 234 commits, not shallow).**

- **Pre-confuse releases:** tags `v0.0.2` through `v0.0.9.2`. The first tag containing `3f14b25` is `v0.0.10.0`.

- **Misspelling:** `TRAEFIK_RESOLVERID_INOUTPUTPATHNAME` ("IN OUTPUT PATH NAME") is the name the old image read, verbatim. It is a row as spelled, and is not "corrected".
- **Semantics note (docs only):** the 0.0.x flags were presence-based (`${NAME+x}`). Setting a name to *any* value, `false`, `0` and empty included, turned the flag on. The replacement settings are booleans, so `TRAEFIK_RESOLVERID_INOUTPUTPATHNAME=false` meant "on" in 0.0.x and must become `…_RESOLVERINPATHNAME=true`.
- **Excluded by the derived rule:** `LLL_EX_INSTALL_*` and `PACKAGE_REPO_URL` also appear as `${…+x}` under `docker/`, in `docker/Dockerfile` and `docker/root/opt/l3io/common/scripts/10-install-packages.sh`. Neither file ever contained `appParams`, and they are build-time helper variables, not exporter settings. They are excluded because the scope is derived from the translator idiom, not from a hand-kept path list.

## Acceptance Criteria

1. **One table.** The eleven names above become `LegacyName("env", <name>, <replacement>, <hint>)` rows in `LEGACY_SETTING_NAMES` (`libs/legacy_settings.py`), the single legacy table. No second list exists anywhere in `src/`. The module docstring and the comment above the table are corrected:
   - these names *did* work, in the 0.0.x image (v0.0.2–v0.0.9.2), and have been silently ignored since v0.0.10.0;
   - the policy stays warn-and-ignore with no aliases (AD-6, C-16b);
   - the table is derived from `git log -p HEAD` over the documentation scope **and** the pre-confuse translator script.
2. **Detected at start-up.** `find_legacy_settings` also examines environment names outside `ENV_PREFIX`:
   - a name outside the prefix yields a `legacy` finding only if it equals an env row's `name` **exactly and case-sensitively**, because the shell expansions in `run.sh` were case-sensitive;
   - such a name never yields an `unknown` finding and is never offered to `suggest.nearest_name`. So Traefik's own `TRAEFIK_*` static-configuration variables (for example `TRAEFIK_ENTRYPOINTS_WEB_ADDRESS`), `PUID`, `TZ` and any other variable produce nothing;
   - prefixed names behave exactly as today.
3. **Warning text matches the existing legacy warnings:** `Legacy setting <NAME> in environment is ignored; use <replacement>`, or `…; <hint>` when there is no replacement (`_message`). Production's case reads exactly `Legacy setting TRAEFIK_RESOLVERID_INOUTPUTPATHNAME in environment is ignored; use TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_RESOLVERINPATHNAME`. One WARNING per variable present, and values are never logged.
4. **Coverage is derived from history, and a hand-dropped name fails (global rule 4).** A new test, `tests/test_settings_surface.py::test_legacy_map_covers_preconfuse_env_names`, works as follows:
   - **(a)** it derives the translator files with `git log --format= --name-only -G appParams HEAD`, so deleted files and any second translator are found without a path list;
   - **(b)** it extracts `\$\{([A-Za-z_][A-Za-z0-9_]*)\+x\}` from added and removed lines of `git log -p HEAD -- <those files>`;
   - **(c)** it adds every `\bTRAEFIK_(?!CERTIFICATE_EXPORTER_)[A-Z0-9_]+` in the history over `_scan_pathspecs()`, reusing `_history_names`'s hunk attribution and vendored-path exclusion (generalise it to take the pattern; do not copy it);
   - **(d)** it asserts that every derived name is an exact `env` row of `LEGACY_SETTING_NAMES`;
   - **(e)** it fails, and never skips, on a shallow clone, reusing the existing guard. CI checks out with `fetch-depth: 0` (`.github/workflows/build.yaml:45`), so `just check` and CI see the same history;
   - **non-vacuity:** at least one translator file is found, and `TRAEFIK_RESOLVERID_INOUTPUTPATHNAME` is in the derived set.
5. **Scope attack, permanent test.** `test_preconfuse_scan_finds_a_deleted_translator_script(tmp_path)` runs in a throwaway git repository, built with the existing `_git` helper. It commits `docker/root/app/run.sh` with `appParams` and `${KNOWN+x}`, and a **second** script at another path with `appParams` and `${PLANTED_NAME+x}`. A later commit deletes that second script. A `README.md` mentions `TRAEFIK_PLANTED_DOC`. The derivation must return `PLANTED_NAME` and `TRAEFIK_PLANTED_DOC`. This proves that the scope is neither one hard-coded path nor today's tree.
6. **Rule attack, permanent test.** `test_preconfuse_coverage_reports_a_dropped_row(monkeypatch)` removes the `TRAEFIK_FILESPEC` row from the table the coverage helper reads. The helper must then report `TRAEFIK_FILESPEC` as uncovered.
7. **`docs/upgrading.md`:**
   - the legacy table block is regenerated with `poetry run python -m tests.test_settings_surface`, and `test_upgrading_lists_every_legacy_name` passes;
   - the prose above it gains two sentences. First: 0.3.1 also warns about the pre-confuse names of the 0.0.x image. Second: those names were presence-based, so `NAME=false` meant on. The prose stays inside the marked file (`tce-settings-scan: legacy-names-listed`).
8. **Spine:** AD-6 already states the pre-confuse rule and its coverage test (consolidated 2026-10-12). The notes file records that the shipped behaviour matches it, or the deviation (see ADR and spine routing).

## Business acceptance criteria

### Outcome

- An operator still running a compose file from the 0.0.x era (v0.0.2–v0.0.9.2) is told at start-up, once per variable, which name to use instead, without the value being printed. On rwusdckrls6 this means one WARNING for `TRAEFIK_RESOLVERID_INOUTPUTPATHNAME`.
- Unrelated environment variables, Traefik's own `TRAEFIK_*` included, produce no new warning.
- Every environment name the project ever told operators to set is now either valid or warned about, and a test derived from git history keeps it so.

#### 0.3.1 release notes

- "Start-up now also warns about the environment variables of the 0.0.x image, which have been ignored since v0.0.10.0. They are `TRAEFIK_FILESPEC`, `TRAEFIK_RESOLVERID`, `TRAEFIK_RESOLVERID_INOUTPUTPATHNAME`, `DRYRUN`, `FLAT`, `RESTART_CONTAINERS`, `DOMAINS_INCLUDE`, `DOMAINS_EXCLUDE`, `RUN_AT_START`, `CONFIG_FILE` and `TEST_VERSION`. Each warning names the `TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_*` replacement. The names are still ignored, and behaviour is unchanged. In 0.0.x these variables switched their option on whatever their value, so `FLAT=false` meant flat: set the replacement to `true` or `false` explicitly."

Spec: none — l3io-plan run, no spec index bound

### Non-goals

- No aliases: the old names still set nothing (AD-6, C-16b). An alias would be a compatibility contract and would need an ADR.
- No warning for arbitrary unprefixed or `TRAEFIK_*` variables: only exact historical names.
- No case-insensitive or "did you mean" matching for unprefixed names.
- No change to the `run.sh`-era CLI flags. `git log -p -- libs/cli_args.py` shows that only `dest` ever changed (E014-S01-009), and the 0.0.x flags are already rejected by the strict parser.
- No committed fixture of the history. CI has full history, so the test re-derives the set on every run. See Testability approach for why a fixture was rejected.
- No change to the image's init scripts or to `settings.py`.

## Technical acceptance criteria

### Interface contracts

- `libs/legacy_settings.py`:
  - `LEGACY_SETTING_NAMES`: eleven new `env` rows, written as full literals like the existing rows, since the stale-marker check reads them. The `LegacyName` dataclass is unchanged. A name not starting with `ENV_PREFIX` means "exact, case-sensitive match against the raw environment name".
  - **new:** `_TEST_VERSION_HINT` constant (string), with `CONFIG_FILE` reusing `_NO_CONFIG_FILE_ENV`.
  - `find_legacy_settings(environ, config_tree, config_path=None) -> list[Finding]`: the signature is unchanged. The environment loop iterates `sorted(environ)`:
    - a prefixed name follows today's path unchanged (`_canonical`, legacy, then valid, then unknown);
    - an unprefixed name is looked up with a new `_preconfuse_entry(name) -> LegacyName | None` (exact match over env rows whose `name` does not start with `ENV_PREFIX`), and produces either a legacy finding or nothing;
    - findings stay environment-first.
  - `_message`, `warn_legacy_settings`, `check_setting_names`, `valid_env_names`, `Finding`: unchanged.
- `tests/test_settings_surface.py`:
  - `_history_names(root, pattern=ENV_NAME_PATTERN)` gains the pattern parameter. The default keeps today's behaviour and callers.
  - **new:** `_PRECONFUSE_TRANSLATOR_IDIOM = "appParams"`, with a comment saying it is the 0.0.x `run.sh` variable that collected CLI flags;
  - **new:** `_PRECONFUSE_PRESENCE_TEST = re.compile(r"\$\{([A-Za-z_][A-Za-z0-9_]*)\+x\}")`;
  - **new:** `_PRECONFUSE_DOC_PATTERN = re.compile(r"\bTRAEFIK_(?!CERTIFICATE_EXPORTER_)[A-Z0-9_]+")`;
  - **new:** `_preconfuse_translator_files(root) -> list[str]`;
  - **new:** `_preconfuse_env_names(root) -> set[str]`;
  - **new:** `_uncovered_preconfuse_names(root, table=LEGACY_SETTING_NAMES) -> list[str]`, which includes the shallow-clone guard, factored out of `_undocumented_history_names` into a `_require_full_history(root)` helper that both call.
- Sibling conventions:
  - helpers are module-level `_snake_case` so later tests can reuse them (the module docstring says so);
  - the git subprocess calls use the existing `-c core.quotePath=false … --no-color --no-ext-diff --format=` options;
  - throwaway repositories use `_git(...)`;

### Error and edge case handling

- **Case:** `flat=1` or `Dryrun=1` gives no finding. An exact-case match is required (shell variables are case-sensitive). Prefixed names keep confuse's case rule.
- **A new and an old name both set** (for example `TRAEFIK_RESOLVERID` and `…_SETTINGS_TRAEFIKRESOLVERID`): one warning, for the old name only. This mirrors `test_legacy_and_new_name_both_set_warns_only_for_legacy`.
- **Empty value** (`DRYRUN=`): the name is present, so it is warned about, because presence is what mattered in 0.0.x.
- **`CONFIG_FILE` set by the operator in the container:** warned about with the existing config-file hint. The init script's own `CONFIG_FILE=` is a shell local and is not exported to the exporter process. The dev confirms this in the notes by running the image with no such variable and seeing no warning (optional image row).
- **The detection failing:** unchanged. `check_setting_names` logs once and start-up continues.
- **History edge cases:**
  - a C-quoted or unattributable `diff --git` header fails the test (the existing `_DIFF_HEADER` rule, reused);
  - a shallow clone fails the test;
  - a future commit that adds an `appParams` script with a new `${NAME+x}` fails the test until a row is added. That is the intended pressure: the remedy is a row, never a scope exclusion (as E014-S01-009 put it).
- **Generic names outside the container** (a CLI user whose shell has `FLAT=1` for another tool): they get one advisory WARNING. This is accepted and recorded as maintainer decision D-1 in the notes. The message says the name is ignored, which is true.

Spec: none — l3io-plan run, no spec index bound

### Observability requirements

- One WARNING per legacy variable present, in the existing format (AC 3), emitted at settings load before the first pass and outside any pass id (AD-6).
- No new log lines, levels or fields. Nothing is logged for unprefixed variables that are not in the table.

Spec: none — l3io-plan run, no spec index bound

### Security considerations

- Values are never read or logged. `Finding` carries no value, and `_message` formats only the name and the replacement or hint. `test_preconfuse_values_are_never_logged` sets `TRAEFIK_RESOLVERID` and `DOMAINS_INCLUDE` to a secret-looking marker and asserts that the marker is absent from every captured record.
- Unprefixed names are matched against a fixed table only. Arbitrary environment names are never echoed, which would otherwise leak the names of unrelated host variables into the exporter's log.
- The history test runs `git` with fixed arguments (no shell, no user input), as the existing scan does.
