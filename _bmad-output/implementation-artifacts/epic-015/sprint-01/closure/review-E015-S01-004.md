## Findings

### F1 (LOW): `_is_legacy_env_name` runs the full detector, outside the advisory try

- **Location:** `src/traefik_certificate_exporter/libs/settings.py`, `_is_legacy_env_name`, called
  from `_loadDotenvAsRoot`.
- **Problem:** the function asks `any(f.kind == "legacy" for f in find_legacy_settings({name: ""},
  None))`.
  - For every prefixed non-legacy name a root `.env` adds, this computes `_is_valid_env_name` and
    a `suggest.nearest_name` suggestion, then discards both.
  - Unlike `check_setting_names`, the call is not inside the "advisory: never raises" guard. A
    failure in the registry or suggestion path would abort settings load in root mode, where the
    same failure elsewhere is logged and skipped.
  - The call also couples `settings.py` to the result shape of the detector instead of to a
    predicate.
- **Suggested fix:** add a public `is_legacy_env_name(name) -> bool` to `legacy_settings.py`,
  implemented as `_preconfuse_entry(name) is not None` for unprefixed names and
  `_legacy_entry("env", _canonical(name)) is not None` for prefixed ones. Call it from
  `settings.py`. It still uses the one table, with no unknown or suggestion work and no new
  failure surface.

### F2 (LOW): the new C-quoted translator-path refusal is never exercised

- **Location:** `tests/test_settings_surface.py`, `_preconfuse_translator_files`, the
  `path.startswith('"')` → `pytest.fail` branch.
- **Problem:**
  - The notes state that "A C-quoted translator path fails the test", but no test plants one.
  - The existing `test_history_scan_refuses_an_unattributable_header` covers `_history_names`
    only.
  - If the branch broke (for example after a change to the quoting config), a quoted path would
    be passed on as a `:(literal)"…"` pathspec that matches nothing. Its names would silently drop
    out, which is the false green that global rule 3 forbids.
- **Suggested fix:** add `test_preconfuse_scan_refuses_a_quoted_translator_path(tmp_path)`.
  - Use `_git` to commit a translator whose path contains a character that git C-quotes even
    with `core.quotePath=false` (a tab or a `"`).
  - Assert `pytest.raises(pytest.fail.Exception)` from `_preconfuse_translator_files(tmp_path)`.

### F3 (LOW): the guard's own source file is in its translator scope, and the stated remedy is wrong for a quotation

- **Location:** `tests/test_settings_surface.py`, docstrings of `_preconfuse_translator_files` and
  `test_legacy_map_covers_preconfuse_env_names`.
- **Problem:**
  - Once committed, this test file contains `appParams`, so `-G appParams` makes it a
    "translator". The same holds for any test or doc outside `_SCAN_EXCLUDE` that ever mentions
    the idiom.
  - A later literal `${FOO+x}` in such a file, such as a docstring example or a new
    scope-attack fixture written as a literal, derives `FOO` and turns `main` red.
  - The test docstring says "The remedy is a row, never a scope exclusion". For a quotation that
    remedy is wrong: it would add a bogus legacy row, and the exporter would warn about an
    arbitrary variable.
  - Today the file holds no literal presence test (verified by the developer in a throwaway
    clone, and consistent with `_translator_script` building the string).
- **Suggested fix:** in the test docstring, state the two cases:
  - a real translator needs a row;
  - a file that only quotes the idiom must build the presence test at run time, as
    `_translator_script` does.
  
  No code change is needed.

### F4 (LOW): `_PRECONFUSE_DOC_PATTERN` cannot tell Traefik's own variables from 0.0.x names

- **Location:** `tests/test_settings_surface.py`, `_PRECONFUSE_DOC_PATTERN` and its use through
  `_history_names`.
- **Problem:**
  - AC 4(c) prescribes the rule. Any future documentation line that shows Traefik's own
    static-configuration environment would be derived as a pre-confuse name and fail the gate.
    Examples are a compose sample with a `traefik` service that sets
    `TRAEFIK_PROVIDERS_DOCKER=true`, or prose naming `TRAEFIK_ENTRYPOINTS_WEB_ADDRESS`.
  - The documented remedy, adding a row, would make the exporter warn about a Traefik variable.
    That contradicts AC 2 and the business AC "Traefik's own `TRAEFIK_*` … produce no new
    warning".
  - Zero such names exist in history or in the working tree today (verified), so this is latent.
- **Suggested fix:** record this limit in the test docstring, as the existing "Coverage limit"
  note does for translators. Docs that show Traefik's own variables must not appear in the
  documentation scope verbatim; build them, or keep them outside the scanned pathspecs. If
  this ever happens, bound the docs rule to commits before the confuse refactor (`3f14b25`),
  since that commit is when these names stopped working. Either choice is a recorded
  decision, not a silent exclusion.

### F5 (LOW): `_git_log` duplicates the git invocation of `_history_names`

- **Location:** `tests/test_settings_surface.py`, the new `_git_log` and the inline
  `subprocess.run([... "log", "-p", "--no-color", "--no-ext-diff", "--format=", ...])` in
  `_history_names`.
- **Problem:** the story asks the git calls to use the existing fixed options. The diff does this
  by adding a second copy of the option list instead of sharing one. A later change to one copy,
  such as adding `--no-textconv` or `-c core.quotePath=false` handling, can drift from the other.
  The two scans would then attribute or quote paths differently.
- **Suggested fix:** have `_history_names` call `_git_log(root, "-p", "HEAD", "--",
  *_scan_pathspecs())`. Behaviour is identical, and the history checks then have one definition
  of the invocation.
