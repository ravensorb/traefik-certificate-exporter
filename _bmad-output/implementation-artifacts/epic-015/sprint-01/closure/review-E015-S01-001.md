## F1 — HIGH — kind: claim / security

**Location:** `src/traefik_certificate_exporter/libs/settings.py:558` (`_loadDotenvAsRoot`), with `libs/post_export.py:81` (`env = os.environ.copy()`), `docs/adr/0049-root-mode-trust-covers-hook-output-and-store-location.md:207,231` and `docs/operational.md:315`.

**Description.** In the image, a root exporter loads `/config/.env`, which `abc` can write (P1, cwd `/config`). `_loadDotenvAsRoot` removes only the three environment-only `TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_*` names. Every other variable that `.env` adds stays in the root process's `os.environ` (P2), because `load_dotenv` adds any name the real environment lacks. The root hook inherits that environment through `os.environ.copy()`.

So `abc` can write `LD_PRELOAD=/config/evil.so` (musl honours `LD_PRELOAD`) and get its code run as root by the operator's environment-sourced hook. That is exactly the configuration this story tells root-mode operators to use. The same route sets `DOCKER_HOST`. ADR-0049 and ADR-0050 rely on `DOCKER_HOST` "from the environment only" to bound root's Docker reach.

This contradicts these claims:
- Outcome: "It can no longer decide what the exporter runs as root."
- Security: "A file the `PUID` account can write can no longer name a command that root runs."
- ADR-0049 Decision 4: "`.env` files are files."

The ADR's residual-risk list and the operational "Trust boundary" bullets name `/config` scripts and `LOGGING_CFGFILE`, but not `/config/.env`. Both lists read as complete.

The issue predates this diff (0.3.0 had it), but this story adds the `.env` trust rule and claims the boundary.

**Suggested fix.** Treat a `.env` file as untrusted as a whole in root mode, not key by key: when `_is_root()` is true, do not call `load_dotenv` at all. Log one ERROR naming the file and saying "use the container's environment". This removes the hand-kept name list and closes every variable at once. Alternatively, admit only `TRAEFIK_CERTIFICATE_EXPORTER_*` `any-source` names from a root-mode `.env` and drop the rest. Either way, also:
- add a unit test that plants `LD_PRELOAD` and `DOCKER_HOST` in a cwd `.env` under euid 0;
- add an image test (or extend (ii)) that writes `/config/.env` as uid 1000 and asserts the hook's environment lacks the planted variable;
- record the rule, or the residual, in ADR-0049 as a dated amendment and in `docs/operational.md` "Trust boundary".

## F2 — MEDIUM — kind: claim / test-scope

**Location:** `pyproject.toml:127-134` (coverage-limit comment) and `tests/libs/test_post_export.py:268` (`_spawn_capable_names`); also `docs/adr/0050-spawn-site-guard-uses-ruff-banned-api.md` "Coverage limit".

**Description.** The coverage-limit comment and ADR-0050 name only *dynamic* access (`getattr`, `importlib`, `__import__`, `eval`) as what escapes TID251. Static, plain-import spellings escape it as well (P3):
- `import posix; posix.system()/posix.fork()/posix.posix_spawn()` (`os` re-exports these from `posix`);
- `from concurrent.futures.process import ProcessPoolExecutor`;
- `asyncio.subprocess.create_subprocess_exec`;
- `ctypes.CDLL(None).system`;
- `webbrowser.open`;
- the event-loop methods `loop.subprocess_exec` / `loop.subprocess_shell`.

The derived-name test takes its scope from `dir(os)` only. The spawn primitives' real source of truth is the `posix` / `nt` module, and the test leaves out `asyncio.subprocess` and `concurrent.futures.process`. So the guard proves the rule over a set that does not contain every way to reach the same primitives (global rule 4), and the prose overstates the guard's reach (global rule 3).

**Suggested fix.**
- Add these to the banned table: the modules `posix`, `nt`, `_posixsubprocess`, `asyncio.subprocess`, `concurrent.futures.process`, `ctypes` and `webbrowser`, or at least the first five.
- Derive the `os` names in `_spawn_capable_names` from `dir(posix)` (or `nt`) as well as `dir(os)`, and also require `posix.<name>`.
- State in both the comment and ADR-0050 that attribute calls on runtime objects (`loop.subprocess_exec`) are not statically resolvable.

## F3 — MEDIUM — kind: claim / test-scope

## F9 — MEDIUM — kind: correctness / guard scope

**Location:** `src/traefik_certificate_exporter/libs/settings.py:569-581` (`anySource` set, `name.upper() in anySource`); claims at `docs/operational.md:308`, `docs/upgrading.md:43`, and the ADR-0049 amendment, Decision 4 as replaced.

**Description.** The admitted set holds only the leaf name `_env_name(keyPath)`. confuse's `EnvSource` also maps indexed names to list elements: `…_SETTINGS_APPRISEURLS_0`, `…_DOMAINS_INCLUDE_0`. `config_default.yaml` and `README.md:212` document the indexed form as *the* way to set `appriseurls` from the environment.

In root mode, a `.env` that sets an `any-source` list setting in the documented form therefore has it removed (R1). Apprise notifications and domain filters configured that way silently stop on upgrade, apart from an ERROR that reads as if these were dangerous settings. That contradicts the docs and the ADR, which say a root `.env` "may set only `any-source` settings", implying those settings still load.

The admitted set is not derived from the real source of truth: the mapping from environment names to key paths that confuse's `EnvSource` applies. The tests plant only the scalar `…_SETTINGS_DRYRUN`.

**Suggested fix.** Admit a name when it maps to an `any-source` key path under `EnvSource`'s rule: the exact `_env_name`, or `_env_name` + `_<digits>` for keys whose packaged default is a list. Alternatively, run the name through confuse's own `EnvSource` and compare the resulting key path. Add a root-mode test that plants `…_APPRISEURLS_0` and asserts it loads. Alternatively, if the drop is intended, say so in the ADR amendment, the upgrading note and the ERROR text.

## F10 — MEDIUM — kind: test-scope / claim

**Location:** `tests/libs/test_post_export.py:369-372` (`_TID251_SUPPRESSION`) and `:393` ("in every spelling ruff honours"); `pyproject.toml:136-141`; the ADR-0050 amendment, "Suppressions".

## F13 — LOW — kind: observability / log integrity

**Location:** `src/traefik_certificate_exporter/libs/settings.py:626-633` (the per-file removal ERROR).

**Description.** The removed names are interpolated verbatim into a root process's ERROR.
