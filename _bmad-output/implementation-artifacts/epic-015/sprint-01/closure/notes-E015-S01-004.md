### Story-prep defect: `-G appParams` now matches planning artifacts

Since the planning commits, `git log -G appParams HEAD` lists four `_bmad-output/` files (above)
besides `run.sh`. Their history quotes placeholder presence tests:

```
$ git log -p --no-color --format= HEAD -- '_bmad-output/**' | grep -E '^[+-]' | grep -oE '\$\{[A-Za-z_][A-Za-z0-9_]*\+x\}' | sort -u
${KNOWN+x}
${NAME+x}
${PLANTED_NAME+x}
```

AC 4(a) as written ("every file `-G appParams` returns") would derive `NAME`, `KNOWN` and
`PLANTED_NAME` and keep the gate red with no remedy but a fake row. Resolution:
`_preconfuse_translator_files` runs `git log -G appParams` with the documentation scan's own
exclusion (`_scan_exclude_pathspecs()`, i.e. `_SCAN_EXCLUDE`: `_bmad-output/**`,
`docs/adr/**`, `.github/**`) and drops vendored paths with `_vendored_exclude_pattern()`. No
new list: both are the existing scan's single definitions. Every other file using the idiom is
still in scope (a test or a doc included). `tests/test_settings_surface.py` itself contains
`appParams` and so becomes a translator once committed; it holds no literal presence test (the
scope-attack script is built by `_translator_script`), verified in a throwaway clone with the
file committed: translators = `docker/root/app/run.sh`, `tests/test_settings_surface.py`; the
presence-test grep over the new test file, `legacy_settings.py` and `docs/upgrading.md`
returns nothing (exit 1).

Other implementation notes:
- Translator paths are passed back to git as `:(literal)<path>` pathspecs. A first draft used
  the global `--literal-pathspecs`, which also disables `:(exclude)` magic, so the scan found
  no translator at all; the non-vacuity assertion caught it (fail-first output below).
- A C-quoted translator path fails the test, like the existing `_DIFF_HEADER` rule.
- `_uncovered_preconfuse_names(root, table=None)` reads `legacy_settings.LEGACY_SETTING_NAMES`
  at call time (instead of a default bound at import), so the rule-attack test's monkeypatch
  attacks the table the runtime uses.
- The docs-history part reuses `_history_names(root, pattern)` (new `pattern` parameter,
  default unchanged), so hunk attribution and vendored exclusion are shared, not copied.
- `_require_full_history(root)` is factored out of `_undocumented_history_names` and called by
  both history checks.

## `.env` interaction with E015-S01-001's root-mode rule

Behaviour before this story's `settings.py` change (S01-001 as shipped): in root mode
`_loadDotenvAsRoot` removes every name a `.env` newly adds that is not an `any-source`
setting, and lists it in one ERROR advising "Set them in the container's environment
instead". A legacy name (`FLAT`, or a prefixed one like
`TRAEFIK_CERTIFICATE_EXPORTER_RESTART_CONTAINERS`) was therefore removed before
`check_setting_names` ran: no double report, but a contradiction — the operator was told to
move a name to the container's environment, where it sets nothing and draws the legacy
WARNING on the next start.

Decision (applied): a legacy name is still removed from a root `.env` (security unchanged:
root's environment and the hook's never see it), but it is not listed in the root-mode ERROR;
it is reported once by the legacy WARNING, which names the replacement. Mechanism:
`settings._is_legacy_env_name(name)` asks `find_legacy_settings({name: ""}, None)` (the one
table, no second list), `_loadDotenvAsRoot` collects such names in `self._legacyDotenv`, and
the `check_setting_names` call passes `{**os.environ, **dict.fromkeys(self._legacyDotenv, "")}`
(names only; values never read).

Cases, each tested in `tests/libs/test_settings.py`:

| Where the legacy name is | euid 0 | non-root |
|---|---|---|
| `.env` (cwd or module) | removed from `os.environ`; one legacy WARNING; not in the root `.env` ERROR (other removed names, e.g. `LD_PRELOAD`, still are) | stays in `os.environ`; one legacy WARNING; no ERROR |
| process environment | kept (never filtered); one legacy WARNING; no ERROR | one legacy WARNING |

Tests: `test_a_legacy_name_in_a_dotenv_file_is_reported_once_as_legacy[0|1000]`,
`test_root_warns_once_about_a_legacy_name_in_the_real_environment`. The settings themselves
are unchanged (`flat`, `restartContainers` stay `False`). Scope note: the story listed
`settings.py` as out of scope; the orchestrator's instruction to remove double reports and
contradictions with the S01-001 rule required these three hunks. User-visible: documented in
`docs/upgrading.md` (`### Environment names of the 0.0.x image are warned about`, last
bullet) and in ADR-0049 Decision 4.

`CONFIG_FILE` and the init script (edge case in the story): not run against the image (the
optional image row is not part of Verification). Read-only check of
`docker/root/etc/s6-overlay/s6-rc.d/init-traefik-certificate-exporter-config/run`: line 23
assigns `CONFIG_FILE=/config/config.yaml` without `export`, and line 55 passes it to the
init resolver as `TCE_CONFIG_FILE`, so neither the resolver nor the exporter inherits
`CONFIG_FILE` unless the operator set it in the container. The resolver's own
`loadFromFile` writes its log to `/dev/null` (line 55), so a container start shows each
legacy WARNING once, from the exporter. Not verified in a running image.
