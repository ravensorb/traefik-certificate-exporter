## Findings

### R1 — LOW — kind: test (false-green risk)
- **Location:** `tests/libs/test_certificate_exporter_watch.py`, `test_real_observer_detects_store_replaced_by_rename`
  (the two `not in recorder.paths` assertions).
- **Description:** The test waits on `recorder.arrived`, which is set when `acme.json` is exported. It then
  asserts right away that `other.json` and `acme.json.tmp` were never exported. `doTheWork` drains a batch in
  `sorted()` order, and both forbidden names sort after `acme.json`
  (`/data/acme.json` < `/data/acme.json.tmp` < `/data/other.json`). If a regression queued them in the same
  batch, the drain thread would record them only after it had already set `arrived`. The assertions
  therefore hold only because the drain thread, with a fast `MagicMock` exporter, finishes the batch before
  the waiting test thread resumes. They do not hold by construction. The probe caught the planted violation
  in 10 of 10 executions, so today the gap is theoretical. It is still a scheduling-dependent pass: a slower
  exporter stand-in, or a CI host under load, could let it go green. The sibling
  `test_real_observer_ignores_store_renamed_away` avoids this problem because its sentinel sorts last.
- **Suggested fix:** Before the negative assertions, wait for the drain to finish. For example, bound-wait
  until `handler.isWaiting is False` and `handler.draining is False`, or `handler.timer.join(5)`. An
  alternative is to make the sentinel a path that sorts after the forbidden names, written after the
  rename, as the renamed-away test does.

### R2 — LOW — kind: claim (log injection, AD-3)
- **Location:** `certificate_exporter.py` `__queuePath` (shutdown DEBUG `f"Shutting down; ignoring change to {path}"`)
  and `__logEvent` (`f"Certificates changed found in file: {path}"`), both reached from `on_moved` with `destPath`.
- **Description:** Story §Security says new log lines sanitize paths "so a newline or control character in a
  renamed file name cannot forge log lines (AD-3)". The two new `on_moved` lines (the DEBUG line and the
  rename-away INFO line) do use `sanitize_for_log`. A matching destination, however, goes through
  `__queuePath`, and both lines on that path log it unsanitized. One of them, the shutdown DEBUG line, was
  rewritten by this story (`event.src_path` -> `path`). For example, renaming a file onto
  `"x\n<forged line>.json"` (which matches `*.json`) produces an INFO line that forges a second log record.
  The capability is not new: a `created` event for the same name already reached `__logEvent` unsanitized.
  The notes disclose it honestly under "Notes for review". The story's security claim is still broader
  than what shipped.
- **Suggested fix:** Pass `path` through `sanitize_for_log` in `__logEvent` and in the `__queuePath` shutdown
  DEBUG line. Each is a one-token change, and it also covers `created`/`modified`. If that is judged out of
  scope, narrow the story's Security sentence and record a backlog item.

## Claims check (kind: claim) against ACs — no further finding
- AC1/AC2: `__matches` is `match_any_paths([path], included_patterns=self.patterns,
  excluded_patterns=self.ignore_patterns, case_sensitive=self.case_sensitive)`. These are the same function
  and the same inputs that dispatch uses, and nothing is hand-rolled. `src_path` is never queued. Covered by
  the rename-onto unit test, the case-insensitive unit test and the real-observer tests.
- AC3/AC5: the matching `src` is discarded under `self.lock` before `dest` is queued. Covered by
  between-names and the temp-file test.
- AC4: rename away arms nothing and logs one INFO, with the open window's correlation id or `-`. Covered by
  the two rename-away tests. An empty window left open drains to `isWaiting=False` with no export, because
  `doTheWork` checks for an empty set.
- AC6: `DirMovedEvent` is dropped by dispatch (`ignore_directories=True`). The `is_directory` guard in
  `on_moved` is defensive and unreachable via dispatch. The move-in from another directory is pinned for
  both observers.
- AC7/AC8: `NO_CHANGE_MESSAGE` path tested. The shutdown latch is preserved through `__queuePath`. The
  real-observer tests run on `inotify` and `polling`.
- AC9/AC10: the doc text is present, and the notes record the AD-11 check with no deviation.
- Thread safety: `on_moved` takes the lock twice, once for the discard and once inside `__queuePath`. A
  drain that slips into the gap either takes `dest` in its loop or finishes and lets `__queuePath` open a new
  window, so no wakeup is lost. The INFO correlation id is read under the lock and logged after it is
  released, so at worst it is the just-closed window's id, which is cosmetic. watchdog dispatches to one
  handler from one emitter thread, so `on_*` calls are serialized with one another.
- Notes honesty: the fail-first output, its deviations (rename-away and unchanged-content fail before the
  change, editor-style passes before it) and the added test are all explained. The counts are consistent:
  16 new tests (10 unit plus 3x2 real-observer), 43 total = 27 existing + 16. The 43-passed result was
  reproduced. The `just check` row was not re-run, per the brief.
