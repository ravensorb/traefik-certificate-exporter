# E015-S01-003 notes: Watch mode detects store files replaced by rename

Date: 2026-10-12. Built on the uncommitted E015-S01-001/-002 tree; nothing of theirs reverted.

## What changed

- `src/traefik_certificate_exporter/libs/certificate_exporter.py`, `AcmeCertificateFileHandler` only:
  - new `on_moved(event)`: returns on `is_directory`; DEBUG `Watchdog received moved event - <src> -> <dest>.` (both through `sanitize_for_log`); when `src_path` matches, discards it from `pendingPaths` under `self.lock` (with the residual-race comment); when `dest_path` matches, `__queuePath(dest_path)`; otherwise, if the source matched, one INFO `Store file <src> was renamed to <dest>, which does not match the watched file pattern; not exported, exported certificates left in place`, under the open window's correlation id or the unset placeholder. A move matching neither (unreachable through `dispatch`) does nothing beyond the DEBUG line.
  - new `__matches(path)`: `watchdog.utils.patterns.match_any_paths([path], included_patterns=self.patterns, excluded_patterns=self.ignore_patterns, case_sensitive=self.case_sensitive)`. No hand-written matching.
  - new `__queuePath(path)`: the previous `handleEvent` body (shutdown latch through `__arm()`), parameterised by path. `handleEvent(event)` keeps its signature and delegates after the `is_directory` check.
  - import `from watchdog.utils.patterns import match_any_paths`. No other region touched. `on_created`, `on_modified`, `doTheWork`, `cancel`, `__processPath`, `__arm`, `__rearm` unchanged.
- `tests/libs/test_certificate_exporter_watch.py`: docstring sentence on renames; 10 unit tests (real watchdog event classes through `handler.dispatch`) and 3 real-observer tests parametrized `inotify`/`polling`. Existing tests unchanged.
- `docs/architecture.md`: §2 relation label now `on_created/on_modified/on_moved(dest) -> exportCertificatesForFile`; §3 gains a paragraph above the sequence diagram stating the trigger set and the rename-away behaviour.
- `docs/operational.md`: runbook step 1 names `Watchdog received created event` / `Watchdog received moved event`, states rename-onto is detected, rename-away is logged at INFO, and the NFS/SMB (inotify, local-only) limitation.

## Spine/ADR amendments

Checked the consolidated product spine AD-11 ("Watch, trigger events, debounce and shutdown", `ARCHITECTURE-SPINE.md`) against the shipped code:

- trigger set (created/modified under a `settings.filespec` match, and a rename onto such a name) — matches `on_created`/`on_modified`/`on_moved`;
- `dest_path` re-tested by the handler with watchdog's `match_any_paths` over its own `patterns`, `ignore_patterns`, `case_sensitive` — matches `__matches`;
- matching source discarded from the pending set under the lock; matching destination queued through the created/modified path — matches (`__queuePath`);
- store renamed away logged at INFO, not exported, artifacts left in place — matches;
- rename in from another directory arrives as `created` — pinned by `test_real_observer_detects_store_moved_in_from_another_directory[inotify]`;
- directory events, `on_closed`/`on_deleted` not triggers; non-recursive — unchanged (`ignore_directories=True`, `app.py` untouched);
- residual race accepted and documented — code comment in `on_moved`;
- shutdown latch covers renames — `__queuePath` keeps the latch; `test_rename_after_cancel_arms_nothing`;
- network-filesystem limitation — documented in `docs/operational.md`.

**No deviation. No spine or ADR change applied, no ADR number reserved.**
