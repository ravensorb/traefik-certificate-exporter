# Create the Forge Release and Finalize All Aliases Last

As a release maintainer, I want development and stable aliases finalized only after immutable
publication, so convenient names never advertise incomplete or stale delivery.

Depends on: `E008-S01-001`, `E008-S01-002`.

## Acceptance Criteria

**Given** required stable publishers succeed, **when** finalization runs, **then** it creates the
active-forge Release for the exact tag and attaches wheel, sdist, `SHA256SUMS`, and
`build-manifest.json`; required failure or skip blocks the Release and every alias (CI-AR28,
CI-AR40).

**Given** the stable Release succeeds, **when** stable aliases are evaluated, **then** Git aliases
`vMAJOR.MINOR` and `vMAJOR` and image aliases `MAJOR.MINOR`, `MAJOR`, and `latest` advance only to
a newer compatible stable version. Prereleases, older versions, malformed tags, or missing
digests leave them unchanged (CI-AR29).

**Given** required development publishers succeed, **when** `dev` finalization becomes eligible,
**then** concurrency has prevented an obsolete finalizer and a just-in-time fetch proves the
candidate still equals the protected default-branch head. A stale candidate halts without moving
`dev` (CI-AR29).

**Given** any image alias moves, **when** the operation is inspected, **then** it copies the
already-published digest for each enabled registry and never invokes a build.

## Files in scope

- `.github/workflows/dev.yaml`
- `.github/workflows/release.yaml`

## Definition of Done

- This story is the sole owner of both dev and stable alias jobs.
- Explicit transitive dependencies cover all required and enabled publishers.
- Release/finalizer jobs alone receive ref/Release write permission; registry alias steps receive
  only the relevant registry credential.
- Run summaries record Release URL, final digest/platforms, JIT head result, and alias outcomes as
  workflow-native evidence (CI-AR41).
- Tests plant missing dependencies, stale dev head, backward stable versions, prereleases, absent
  digests, early aliases, widened permissions, and build commands in finalizers; all must fail.

## Test anchors

Guard, then the violation planted to prove it fires:

- Sole alias ownership: jobs moving a ref, tag, or registry alias, derived from the parsed steps,
  equal the registered finalizer set; plant an alias step in a publisher job (scope attack).
- Dependency completeness: transitive `needs` covers every required and enabled publisher; plant
  a deleted `needs` entry, then a new publisher nothing depends on (scope attack).
- Forward-only: version ordering decides, not tag spelling; plant an older version, a prerelease.
- Stale dev head: the just-in-time fetch returns another head; plant removing the recheck step.
- Absent digest: plant an empty digest output; the alias step must halt rather than move a name.
- Least privilege: per-job parsed `permissions`; plant `contents: write` on a publisher and a
  registry credential on the ref-writing job.
- No build in a finalizer: parsed finalizer steps hold no build action; plant one in an alias job.

## Out of Scope

- Custom remote-state schemas or destructive reconciliation.
- Production Gitea migration (Epic 9).
