# Create the Forge Release and Finalize All Aliases Last

As a release maintainer, I want development and stable aliases finalized only after immutable
publication, so convenient names never advertise incomplete or stale delivery.

Depends on: `E008-S01-001`, `E008-S01-002`.

## Acceptance Criteria

**Given** required stable publishers succeed, **when** finalization runs, **then** it creates the
active-forge Release for the exact tag **via `LiquidLogicLabs/git-action-release@v2`** and
attaches wheel, sdist, `SHA256SUMS`, and `build-manifest.json` through that action's `artifacts`
input; the finalizer blocks the Release and every alias on any `failure` or `cancelled`
result, and on any `skipped` destination the enabled set says should have run (CI-AR28,
CI-AR40, ADR-0011).

**Given** an optional destination is disabled by toggle, or absent by host capability, **when**
finalization evaluates results, **then** its `skipped` result does not block: the finalizer
`needs:` every publisher statically, runs under `if: ${{ !cancelled() }}`, and compares
`needs.<job>.result` against the enabled set emitted once as a plan-job output. `always()` is
forbidden -- it would also run on cancellation, advancing aliases over a half-published set.

**Test anchors, both mandatory:** a disabled optional destination must still finalize; an enabled
destination that skipped must not. Plant each.

**Given** the Release is created, **when** the run summary is written, **then** it records the
action's `html-url` and `assets` outputs so a published Release is traceable from the run
(CI-AR41).

**Given** the workflow runs on GitHub or on self-hosted Gitea, **when** the Release is created,
**then** the same step serves both: the action resolves the instance from `GITHUB_SERVER_URL`
and speaks each forge's own API, so no forge-kind branch appears in the workflow (CI-AR2,
CI-AR6). See ADR-0010; `platform:` is the documented override if detection ever misfires.

**Given** stable aliases are evaluated, **when** the workflow decides whether an alias may
advance, **then** the **Git tag set is the only ordering authority**: `vMAJOR` advances only if
the released tag is the greatest annotated `vX.Y.Z` in the repository, and `vMAJOR.MINOR` only if
it is the greatest within its minor. No registry is read to answer this (F4).

This gate is the workflow's, not the action's. `git-action-tag-floating-version` moves an alias
**unconditionally** -- it performs the move and does not compare versions -- so releasing `v1.2.4`
after `v1.3.0` exists would drag `v1` backwards unless the workflow refuses first. Prereleases are
skipped by the action's own `ignore-prerelease: true`; ordering is not.

**Test anchor:** plant a step that reads a registry tag to decide an alias -- it must fail. Plant
a re-release of an older patch with a newer stable tag present -- the alias must not move.

**Given** the stable Release succeeds, **when** stable aliases are evaluated, **then** Git aliases
`vMAJOR.MINOR` and `vMAJOR` are moved by
**`LiquidLogicLabs/git-action-tag-floating-version@v1`** (`update-minor: true`,
`ignore-prerelease: true`) and image aliases `MAJOR.MINOR`, `MAJOR`, and `latest` advance only to
a newer compatible stable version. Prereleases, older versions, malformed tags, or missing
digests leave them unchanged (CI-AR29).

**Given** required development publishers succeed, **when** `dev` finalization becomes eligible,
**then** concurrency has prevented an obsolete finalizer and a just-in-time fetch proves the
candidate still equals the protected default-branch head. A stale candidate halts without moving
`dev` (CI-AR29).

**Given** any image alias moves, **when** the operation is inspected, **then** it copies the
already-published digest for each enabled registry and never invokes a build.

## Definition of Done

- This story is the sole owner of both dev and stable alias jobs.
- Explicit transitive dependencies cover all required and enabled publishers.
- Release/finalizer jobs alone receive ref/Release write permission; registry alias steps receive
  only the relevant registry credential.
- Run summaries record Release URL, final digest/platforms, JIT head result, and alias outcomes as
  workflow-native evidence (CI-AR41).
- Tests plant missing dependencies, stale dev head, backward stable versions, prereleases, absent
  digests, early aliases, widened permissions, and build commands in finalizers; all must fail.

## Test anchors

Guard, then the violation planted to prove it fires:

- Sole alias ownership: jobs moving a ref, tag, or registry alias, derived from the parsed steps,
  equal the registered finalizer set; plant an alias step in a publisher job (scope attack).
- Dependency completeness: transitive `needs` covers every required and enabled publisher; plant
  a deleted `needs` entry, then a new publisher nothing depends on (scope attack).
- Forward-only: version ordering decides, not tag spelling; plant an older version, a prerelease.
- Stale dev head: the just-in-time fetch returns another head; plant removing the recheck step.
- Absent digest: plant an empty digest output; the alias step must halt rather than move a name.
- Least privilege: per-job parsed `permissions`; plant `contents: write` on a publisher and a
  registry credential on the ref-writing job.
- No build in a finalizer: parsed finalizer steps hold no build action; plant one in an alias job.

## Out of Scope

- Custom remote-state schemas or destructive reconciliation.
- Production Gitea migration (Epic 9).

## Prep finding P1 — registering a finalizer makes its whole file alias-moving

`test_alias_ordering_is_decided_from_git_never_from_a_registry` scopes to the **workflow file**,
not the job: once any job in `dev.yaml` or `release.yaml` uses
`LiquidLogicLabs/git-action-tag-floating-version`, no job anywhere in that file may run
`docker manifest inspect`, `buildx imagetools inspect`, `skopeo inspect|list-tags` or
`crane ls|digest|manifest`. That is deliberate — it is what stops a registry read in the plan job
from deciding ordering one job earlier — and it is also why stories 001 and 002 keep every
published-image inspection inside `.github/workflows/publish-image.yaml`, which moves no alias.

Consequence for this story: the finalizer reads `digest` and `platforms` from upstream job
outputs. It never inspects a registry to obtain them, and the image alias move is a digest
**copy** (`buildx imagetools create`), which is a write and is not matched by that guard.

The guard is correct as shipped. Do not relax its scope to the job level to make a step fit;
place the step instead.

## Implementation record

Delivered as three registered finalizer jobs, not one, because the least-privilege anchor and the
ordering gate pull in different directions from a single job.

| `(workflow, job)` | Authority | What it does |
|---|---|---|
| `release.yaml` / `finalize` | `contents: write`, **no** registry credential | evaluates the gate, re-checks the tag, creates the Release, decides alias ordering, moves `vMAJOR`/`vMAJOR.MINOR` |
| `release.yaml` / `finalize-image-aliases` | `packages: write`, **no** `contents: write` | copies the published digest onto `MAJOR.MINOR`, `MAJOR`, `latest` |
| `dev.yaml` / `finalize-dev-alias` | `packages: write` | just-in-time head re-read, then copies the digest onto `dev` |

New surface: `scripts/finalizer_gate.py` (the ADR-0011 decision table) and
`scripts/stable_tags.py --alias-plan` (the F4 ordering decision, ordered by
`git for-each-ref --sort=v:refname` — git owns version comparison, as it already owns peeling and
reachability in that module).

### Three corrections against the real actions, found by reading their `action.yml`

1. **`git-action-tag-floating-version@v1` inputs are camelCase** — `updateMinor`,
   `ignorePrerelease`. The `update-minor:` / `ignore-prerelease:` spelling this story and ADR-0006
   both carried is not an input at all; the action would have fallen back to `updateMinor: false`
   and the `vMAJOR.MINOR` alias would have silently never moved.
   `test_the_git_alias_action_runs_only_behind_the_ordering_gate` now asserts the real spelling,
   and the hyphenated pair is one of the planted violations.
2. **It takes no token input** and pushes with plain `git` from the workspace. Every governed
   checkout is `persist-credentials: false`, so `finalize` grants itself a push credential
   explicitly, on the push URL only, composed from `github.server_url` — forge-neutral, and no
   other job sees it.
3. **It is `using: node20`**, not node24 as ADR-0006 recorded. `git-action-release@v2` is node24.
   E009's pinned `act_runner` tuple needs both.

### Accepted limitation: a back-port moves no Git alias

The alias action moves the major **unconditionally** and offers no minor-only mode, so the whole
invocation is gated on the released tag being the greatest annotated `vX.Y.Z`. A back-port patch
published while a newer stable tag exists therefore moves no Git alias, even though its own
`vMAJOR.MINOR` could legitimately advance. This satisfies the AC as written (both clauses are
"only if"), and hand-rolling the minor move is forbidden outright by ADR-0006. The **image**
aliases have no such limitation — the workflow moves those one name at a time — so `MAJOR.MINOR`
does advance there while `MAJOR` and `latest` do not. Recorded in ADR-0006; revisit if the action
gains a major/minor split.

### One shipped guard amended, and paid for

`test_publisher_credentials_stay_disjoint_between_destinations` compared credentials pairwise
across every publisher, which encodes "one publisher per destination". The alias job and the image
publisher address the *same* registry and must present the same credential to it, so the pairwise
form rejected the correct arrangement while the rule its own docstring states was satisfied. The
comparison is now per destination class, and the narrowing was paid for with two new obligations,
each proven by a planted violation: a publisher must belong to exactly one destination class, and
a package publisher may not declare `packages: write`. The original planted violation — a registry
credential on the package job — still fails. Recorded in ADR-0011.

### Guards added, each proven by planting the violation it forbids

`test_only_registered_finalizers_move_an_alias` (equality with the registry, both directions) ·
`test_no_finalizer_builds_anything` · `test_ref_writing_and_registry_alias_privileges_never_meet` ·
`test_every_finalizer_waits_for_every_publisher_and_reads_every_result` ·
`test_the_git_alias_action_runs_only_behind_the_ordering_gate` ·
`test_the_release_carries_the_whole_verified_bundle_and_is_traceable` · the two mandatory ADR-0011
anchors and the ordering, absent-digest and stale-head anchors, all executed against the real
`run:` bodies.

24 violations were planted and every one fired, including the scope attacks the story names: an
alias step inside a publisher job; a registry read in the *plan* job of an alias-moving file; a new
publisher that nothing depends on; a publisher whose result the gate never reads; a Release
attaching one distribution from outside the revalidated bundle; and a summary row degraded to a
literal while the job output stayed intact.
