# Publish Immutable Stable Packages and Images from Exact Tags

As a release maintainer, I want exact deliberate tags to publish the verified stable artifacts,
so each destination receives the version identity already chosen by the repository.

Depends on: `E008-S01-001`.

## Acceptance Criteria

**Given** a release event, **when** the guard runs, **then** unknown forges, non-tags, lightweight
tags, floating tags, prereleases, and malformed tags fail before credentials. Only an annotated
exact `vX.Y.Z` tag whose peeled commit equals the event SHA and is reachable from the protected
default branch proceeds.

**Given** an accepted tag, **when** identity validation runs, **then** tag, committed Poetry
version, lock, built distribution metadata, application version, and source SHA agree before any
publisher starts (CI-AR11).

**Given** a stable publisher receives `verified-dist-v1`, **when** it authenticates, **then** it
has already revalidated `SHA256SUMS` and `build-manifest.json`, including exact source/version and
wheel input (CI-AR36).

**Given** package publication, **when** upload begins, **then** the reviewed full-commit-SHA PyPI
action receives only the verified wheel/sdist and its job-scoped OIDC/token. Planning does not
invent the SHA; implementation records its review (CI-AR24, CI-AR38).

**Given** stable image publication, **when** the image job runs, **then** it performs one Buildx
multi-platform invocation from the exact wheel, attaching the exact immutable version tags for
the required forge registry and optional Docker Hub. It emits one published digest and both
inspected platforms; no destination rebuilds (CI-AR39, CI-AR40, CI-AR41).

## Destination matrix — channel decides, and channel is the file you are in

`dev.yaml` is always the development channel and `release.yaml` always the stable one, so this
distinction costs no runtime condition (ADR-0011).

| Destination | `dev.yaml` | `release.yaml` |
|---|---|---|
| image -> active forge registry | **always** | **always** |
| image -> Docker Hub | **never** | if `PUBLISH_IMAGE_DOCKERHUB` |
| package -> forge Python index | if supported *(host capability)* | if supported *(host capability)* |
| package -> TestPyPI | if `PUBLISH_PACKAGE_TESTPYPI` | **never** |
| package -> PyPI | **never** | if `PUBLISH_PACKAGE_PYPI` |

No toggle is renamed or removed; each is channel-scoped, so `PUBLISH_IMAGE_DOCKERHUB` is inert in
`dev.yaml`. Development images never reach Docker Hub.

Two reasons a destination may be absent, recorded distinctly because conflating them hides a
regression: **disabled by toggle** (an operator chose it) and **absent by host capability**
(GitHub has no forge Python index, and no toggle can override that).

The enabled set is produced **once**, by the plan job, as a job output -- not a repository-owned
schema (CI-AR41), and reviving neither retired CI-AR22 nor CI-AR23. No publisher re-reads
`PUBLISH_*`; a guard enforces it.

## Definition of Done

- `release.yaml` owns exact stable-tag events and calls the verifier once.
- `FORGE_REGISTRY` and optional toggles obey the same fail-closed rules as development.
- GitHub/Gitea package capabilities and credentials stay explicit and job-local.
- Tests prove annotated peeling, event-SHA equality, protected-branch reachability, version
  agreement, one image invocation, required platform inspection, and finalizer blocking.
- Failures remain destination-local and never force, delete, or overwrite immutable identities
  (CI-AR37, CI-AR38).

## Test anchors

Guard, then the violation planted to prove it fires:

- Annotated peeling: a ref table of lightweight, floating, prerelease, malformed, and branch refs;
  plant dropping the annotated-object check so a lightweight tag passes.
- Event SHA and reachability: plant a peeled commit differing from the event SHA, then one
  unreachable from the protected default branch.
- Version agreement: tag, Poetry, lock, distribution metadata, application version, and SHA are
  compared as a relation, never a literal version; plant one mismatched field per run.
- One verifier call: parsed verifier `uses:` in `release.yaml` counts one; plant a second.
- One image invocation: plant a per-registry rebuild, then an index carrying one platform.
- Finalizer blocking: required publishers derived from the parsed jobs all appear in the
  finalizer's transitive `needs`; plant a new publisher absent from it (scope attack).

## Implementation notes

`.github/workflows/release.yaml` is the stable sibling of `dev.yaml` and restates nothing: it calls
`forge-coordinates`, `setup-poetry-python`, `verified-bundle`, `verify-build.yaml` and
`publish-image.yaml`, and composes `scripts/stable_tags.py` for every tag decision (F8, F9). Every
published-image read stays in `publish-image.yaml`; the channel consumes its `digest` and
`platforms` outputs, and a new guard asserts that consumption, which P1's placement guard did not
(LOW-3).

Decisions taken here that the story did not settle:

- **`DOCKERHUB_REPOSITORY` (new repository variable).** Docker Hub's namespace is unrelated to the
  forge owner, so it cannot be derived. `PUBLISH_IMAGE_DOCKERHUB` is honoured only alongside a
  lowercase `<namespace>/<repository>`; an enabled toggle without one fails the plan job, exactly as
  `FORGE_REGISTRY` fails closed rather than guessing a registry. Recorded as `BL-E008-004`, because
  the value has never been set for this repository and the destination is therefore untested
  end to end.
- **PyPI is `unsupported` off GitHub.** Trusted publishing needs an OIDC identity a Gitea runner
  does not have, so the toggle cannot conjure it — the same treatment TestPyPI already has in the
  development channel, and reported as absent-by-host-capability rather than as a failed job.
- **The event object is peeled before it is compared.** A push event reports the ref's new object
  id, and an annotated tag's ref names the tag object; this channel accepts only annotated tags, so
  an unpeeled comparison would refuse every release. `git rev-parse <object>^{commit}` is a no-op
  for a commit, so one spelling is correct wherever this runs. Found by code review (HIGH-1) and
  covered by a test that drives the guard with the tag object.
- **`scripts/stable_tags.py` gained `--expect-tag`.** "Is the ref I was handed an annotated exact
  `vX.Y.Z` whose peeled commit is this one" was three shell copies of a relation the module already
  owns — including one in front of the PyPI upload, where nothing tested it (F9, review MEDIUM-1).
  It is now one call, tested in `tests/test_stable_tags.py`.
- **The protected default branch stays pinned as `origin/main`** rather than derived from
  `github.event.repository.default_branch`, whose availability on Gitea's runner is unverified.
  Both spellings fail closed; deferred as `BL-E008-003` rather than changed unrecorded.

Guards: 30 new or widened contract tests, each proven by planting the violation it forbids — rule
and scope. Two planted violations were *missed* on the first attempt and both were defects in the
guard, not in the plant: the pre-upload re-read check was reading the comment that names the
mechanism rather than the mechanism (fixed with `_uncommented` on both halves, which also hardened
the development channel's half of the same guard), and the credential-disjointness vacuity check
had been folded across files by the widening (restored per file). Widened in place rather than
duplicated: channel checkouts, pre-upload tag re-read, and credential disjointness now derive their
scope from who calls the image publisher, so a third channel is covered without an edit.

Repo-wide: 259 tests pass (was 202 at story start). `actionlint`, `ruff-check`, `ruff-format` and
`mypy` pass on every changed file.
