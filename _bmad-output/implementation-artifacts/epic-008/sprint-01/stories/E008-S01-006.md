# Recover Partial Releases and Cut Over Atomically

As a release operator,
I want identity-based recovery and one atomic legacy cutover,
So that failed releases can be completed safely and no competing workflow can publish unverified content.

Depends on: `E008-S01-004`, `E008-S01-005`.

## Re-scope note

cutover" has already happened, and this story must **verify** those parts rather than perform
them again:

## Acceptance Criteria

**Given** a stable run is starting or being rerun for the same exact tag
**When** reconciliation inventories remote state
**Then** it checks package filenames/hashes for every package destination in the plan, image manifests/platform digests, Release tag/commit/assets, OCI aliases, and Git aliases against the retained distribution, plan, and expected identities
**And** "every package destination" includes the always-on forge package registry, which is reconciled on every run rather than only when a toggle enabled it (maintainer decision, `docs/ci/codex-assesment.md`, "Divergences resolved (2026-09-01)")
**And** it classifies each mutation as matching, missing, mismatched, or unverifiable

**Given** a remote immutable object matches
**When** its publisher stage executes
**Then** it is reused without upload, rebuild, replacement, deletion, or retagging
**And** only missing required destinations or assets are attempted

**Given** any existing immutable package, image, Release, or asset mismatches or cannot be verified
**When** reconciliation runs
**Then** the workflow fails before every remaining visibility or alias mutation
**And** it does not delete or replace the conflicting object

**Given** a stale rerun finds a newer valid alias
**When** alias reconciliation runs
**Then** immutable objects for the older release may still be verified or repaired
**And** every OCI and Git alias remains on the newer completed release

**Given** a same-tag recovery run is completing destinations a previous run left missing
**When** its concurrency is evaluated
**Then** it acquires exactly the two non-cancellable groups a first run acquires — the per-destination immutable-publication groups of `E008-S01-004` and the single-writer alias-finalization group of `E008-S01-005` — and introduces no recovery-specific group
**And** no recovery job that mutates a remote object may be cancelled by supersession, because a recovery run cancelled mid-flight produces exactly the half-published state it was started to repair

**Given** a destination has been classified as missing and is about to be written
**When** the boundary between classification and mutation is examined
**Then** the classification that authorises a mutation and the mutation it authorises run in the same non-cancellable job
**And** the pair is never split across a cancellable boundary, since a decision that survives its authorising context is a stale decision

**Given** the stable run reaches any terminal state after planning
**When** evidence is persisted
**Then** schema-valid `release-receipt-v1.json` records source/package identities, each required destination result, forge Release/assets, and OCI/Git alias results
**And** an incomplete mutation sequence is represented as incomplete rather than successful (CI-AR26)

**Given** a stable run completes or fails after artifact creation
**When** workflow artifacts are inspected
**Then** its distribution, publication plan, and receipt are retained for 30 days
**And** recovery jobs validate those retained identities before reuse

**Given** the recovery artifacts have expired or their identity cannot be established
**When** a retry is requested
**Then** the workflow rejects rebuilding as a retry
**And** instructs the operator to create a new release identity rather than replacing the expired release

**Given** `ci.yaml`, `dev.yaml`, `release.yaml`, and `verify-build.yaml` satisfy their preceding stories
**When** the cutover change is applied
**Then** legacy `build.yaml`, `build-container.yaml`, `build-package.yaml`, `test.yaml`, Release Please configuration, and every competing build/package/release/publication trigger are removed or disabled in the same change
**And** exactly the four approved workflow sources remain active (CI-AR5)

**Given** legacy build scripts are inventoried
**When** no documented external consumer remains
**Then** root `build.sh` and `docker/build.sh` are removed
**And** `docker/act-build.sh` remains only as the direct verifier wrapper from Story 7.5
**And** no local script can publish a package or image outside the release helper's exact Git push

**Given** the committed-version contract is active
**When** `pyproject.toml` is cleaned up
**Then** unused dynamic-versioning backend/plugin configuration is removed unless a documented current consumer is proven
**And** Poetry remains the sole dependency and package-version interface

**Given** GitHub repository protections are configurable
**When** release readiness is recorded
**Then** the default branch rejects rewrites and requires verification, exact stable tags are restricted and immutable, only release maintainers can perform the deliberate atomic release push, only the release publisher can update Git aliases, and only isolated publisher jobs can update OCI aliases (CI-AR34)

**Given** protected package publication is enabled
**When** environments and job permissions are reviewed
**Then** `pypi` and `testpypi` are distinct protected environments, GHCR and Release permissions are job-scoped, and Docker Hub credentials are repository-scoped
**And** unavailable repository-admin settings are explicitly recorded as an external readiness blocker rather than assumed complete

**Given** the cutover pull request is validated
**When** repository checks run
**Then** `poetry check --lock`, the complete pytest suite, pre-commit, and actionlint over all remaining workflows pass
**And** event fixtures prove PR, default-branch, exact-tag, alias-tag, malformed-tag, all-disabled, and each enabled-destination path reaches only its intended jobs

**Given** operators and contributors use the new pipeline
**When** CI/CD documentation is reviewed
**Then** it documents all variables, secrets, protected environments, schemas, action references, immutable/mutable identities, multi-architecture behavior, release and resume commands, permission/protection rules, partial-failure recovery, and the 30-day boundary (CI-AR35)

## Technical Acceptance Criteria

### Interface contracts

**Given** reconciliation is needed by several publishers
**When** it is placed
**Then** it is a `publication_contract` capability invoked through `./.github/actions/publication-contract`, not a job: each publisher reconciles its own destination immediately before mutating it, because a central up-front reconcile job would go stale before the mutation it authorises
**And** the shared piece is the classification function and its four-value result, not a workflow

**Given** reconciliation adds no job of its own
**When** its placement is checked against cancellation
**Then** it inherits the non-cancellable group of the publisher or finalizer that calls it — a second reason it is a capability and not a job, alongside the staleness reason above
**And** the `receipt` job is deliberately outside those groups and remains cancellable: it mutates nothing remote, and its `if: always() && !cancelled()` already means a cancelled run produces no receipt

**Given** the receipt is written
**When** its job is placed in `release.yaml`
**Then** a `receipt` job declares `needs` on every publisher and the finalizer with `if: always() && !cancelled()`, so a receipt exists for failed runs, which is the case that matters
**And** it holds `contents: read` only; it writes an artifact, never a Release asset or a ref
**And** it uploads `release-receipt-v1.json` with `retention-days: 30`

**Given** the retention window
**When** artifacts are uploaded
**Then** `verified-dist-v1` (already 30 days), `publication-plan-v1.json` and `release-receipt-v1.json` all carry `retention-days: 30`
**And** a recovery run downloads all three from the original run and validates each before reusing any identity from it

**Given** a retry is attempted after the artifacts have expired
**When** the recovery path runs
**Then** the run fails with a message naming the expired run and instructing the operator to cut a new release identity through `just release`
**And** it must not fall back to rebuilding: a rebuild produces a new artifact set, and treating it as the same release is exactly the substitution CI-AR26 prohibits

### Data model

**Given** `release-receipt-v1.schema.json` as packaged today
**When** the four-way reconciliation classification is recorded
**Then** the schema must be extended: `reconciliationStatus` is currently `{failed, matched, pending}` and cannot express `missing`, `mismatched` or `unverifiable`
**And** the extension adds those three values, keeps `matched`, and keeps `pending` for a mutation not yet attempted
**And** the `complete` conditional branch continues to require every `oci_aliases` and `git_aliases` entry to be `matched`, so widening the enum cannot accidentally let an incomplete release validate as complete

**Given** BL-E007-005 records that no evidence artifact carries run correlation
**When** the receipt is written
**Then** it gains a `run` object — run id, run attempt, repository, server URL — mirroring the plan's
**And** `build-manifest-v1` deliberately does not gain one: the manifest must stay byte-deterministic for identical source, and a run id would make every rebuild differ, breaking the identity comparisons this whole story rests on

**Given** the receipt must represent a run that failed before some destinations were attempted
**When** its required properties are examined
**Then** `package`, `oci`, `forge_release` and `reconciliation` are all required today; a run that never reached the image publisher must still produce a schema-valid document
**And** `package` must carry one entry per package destination rather than a single destination's facts, because the plan now always has at least the forge package registry and may also have PyPI or TestPyPI
**And** the extension must make "not attempted" representable — an empty `oci.images` array with a `pending` classification, or an explicit `attempted: false` — rather than forcing the writer to fabricate an entry

**Given** a disabled destination
**When** it appears in the receipt
**Then** it is recorded as disabled by policy, distinctly from failed and from not-attempted; conflating them makes an all-disabled run indistinguishable from a broken one
**And** the always-on forge package destination can never carry that representation: a receipt recording it as disabled must fail validation, since no configuration can produce that state and a document claiming it is describing a run that did not happen

### Error handling and edge cases

**Given** the four classification outcomes
**When** each is produced
**Then** `matching` means the remote object exists and its hash or digest equals the expected value; `missing` means it does not exist; `mismatched` means it exists with a different hash or digest; `unverifiable` means it exists but its identity could not be read
**And** only `missing` authorises a mutation; `mismatched` and `unverifiable` are both hard failures with no delete, replace, overwrite or retag
**And** `unverifiable` is deliberately not treated as `missing`: assuming absence from a failed read is how a rerun overwrites something it could not see

**Given** a stale rerun of an older tag while a newer release is complete
**When** it runs
**Then** the older release's immutable objects may still be verified and completed, and the receipt records that
**And** every OCI and Git alias is left on the newer release, and the run ends successfully rather than failing — a repair is not an error

**Given** a recovery run is superseded by a newer run for the same tag
**When** both are queued
**Then** the non-cancellable groups serialize them and neither is cancelled; the second reconciles whatever the first completed and finds most destinations `matched`
**And** cancelling the first is prohibited rather than merely slower: a run cancelled between "classified `missing`" and "mutation completed" leaves an object whose existence no receipt records, and the next reconciliation reads that object as `unverifiable` — a hard failure requiring manual intervention, produced by an optimisation that saved a few minutes

**Given** a run cancelled mid-finalization
**When** the receipt job runs
**Then** `if: always() && !cancelled()` means no receipt is produced for a cancelled run, which is a gap the operator guide must state plainly rather than leave implied
**And** the recovery path treats "no receipt" the same as "incomplete": it reconciles from remote state and the retained plan

**Given** `build.sh` and `docker/build.sh` are removed
**When** the removal is validated
**Then** nothing in the repository references them: `justfile`, `docker/README.md`, `README.md`, `docs/developer.md`, any workflow, and any remaining script must be checked and updated in the same change
**And** the surviving publish surface is exactly two things: the release helper's atomic two-ref push, and the CI publisher jobs

### Observability

**Given** the receipt is the terminal evidence artifact
**When** it is read
**Then** it answers, without opening the run log: which version and source SHA; which destinations were required, which were disabled, which succeeded, which failed and why; the Release id, URL and asset hashes; every image digest and platform set; every OCI and Git alias with expected and actual targets; and the run that produced it
**And** `status` is `complete` only when the schema's conditional branch is satisfied — an incomplete sequence can never serialize as complete

**Given** an operator must trace a promoted artifact set back to its run
**When** they follow the chain
**Then** receipt `run.run_id` -> the workflow run -> `publication-plan-v1.json` (same run object) -> `verified-dist-v1` -> `build-manifest.json` `source_sha`
**And** the manifest remains the byte-deterministic root of that chain, carrying no run-varying field

**Given** the event-path fixtures
**When** they are exercised
**Then** each fixture's expected job set is asserted, so "which jobs does a malformed tag reach" is answerable from the test suite rather than from a live push

### Security

**Given** the legacy scripts are removed
**When** the publish surface is re-examined
**Then** `build.sh`'s `poetry publish -r "$PACKAGE_REPO"` and `docker/build.sh`'s `docker push` / `docker pushrm` are the last credential-using paths outside the governed workflows, and removing them is a security outcome, not only tidying
**And** after removal no local script authenticates to a registry or index

**Given** repository protections
**When** readiness is recorded
**Then** the required settings are documented as a checklist: default branch rejects force-push and requires the verification check; exact `v*.*.*` tags are restricted to release maintainers and immutable; `vMAJOR`/`vMAJOR.MINOR` are writable only by the release publisher identity; `pypi` and `testpypi` are distinct protected environments
**And** any setting the maintainer cannot apply is recorded as an external readiness blocker with the reason, never assumed complete — an assumed protection is worse than a known-missing one

**Given** the receipt is a published artifact
**When** its contents are constrained
**Then** it must contain no credential value, no credential length, no credential-derived hash, and no signed URL that grants access
**And** endpoint hosts, namespaces, filenames, hashes and digests are all safe and expected

### Testability

**Given** the approved-workflow-set guard
**When** it is added to `tests/ci/test_workflow_contracts.py`
**Then** it asserts the on-disk workflow set is exactly `{ci.yaml, dev.yaml, release.yaml, verify-build.yaml}`, derived from the same glob `GOVERNED_DEFINITIONS` uses so a `.yml` file cannot slip past it
**And** the planted violation adds a `publish.yml` containing a `push` trigger; the guard must fail on it, and it must fail on the extension too, not only on the name

**Given** the no-local-publisher guard
**When** it is added
**Then** it asserts no tracked shell script outside `scripts/release_version.py`'s documented push contains `docker push`, `docker pushrm`, `poetry publish`, `twine upload`, or `gh release create`
**And** the planted violation restores a two-line `docker push` helper under `docker/`; the guard must fail, and its scope must be derived from a glob over tracked scripts rather than a hand-listed set of filenames

**Given** the recovery-non-cancellability guard
**When** it is added to `tests/ci/test_workflow_contracts.py`
**Then** it asserts that every job invoking `./.github/actions/publication-contract` for a reconcile or publish operation declares `cancel-in-progress: false`, with the job set derived from the parsed workflows rather than named, and that the only exemption is the `receipt` job, allowed by an explicit named entry so a second exemption cannot be added silently
**And** the planted violation adds a `reconcile-aliases` job with `concurrency: { group: recovery-${{ github.run_id }}, cancel-in-progress: true }`; the guard must fail on the `cancel-in-progress: true` rather than on the job's name, since a run-id-keyed group is what a plausible implementation reaches for and it looks like a lock while cancelling like a race
**And** a second planted violation adds the new job's name to the exemption list; the guard's exemption must be a single literal it asserts against, so the plant is visible in the diff of the test rather than of the workflow

**Given** the reconciliation classifier
**When** it is unit tested in `tests/ci/test_publication_contract.py`
**Then** every destination class is covered for all four outcomes: package file absent / hash equal / hash different / hash unreadable, exercised for the forge package registry as well as PyPI, since the classifier is one function over a destination rather than one per destination; image tag absent / digest equal / digest different / manifest unreadable; Release absent / asset hash equal / asset hash different / asset unreadable; alias absent / on candidate / on older / on newer / malformed
**And** the parametrisation is derived from the plan's `package_targets` rather than from a hand-written pair of destination names, so a fourth package destination is covered the day it is added rather than the day someone remembers the test
**And** the planted violation maps `unverifiable` to `missing`; the "exists but unreadable" cases must then authorise a mutation and the test must catch it

**Given** the receipt schema extension
**When** it is tested
**Then** a receipt with `status: complete` and any alias entry not `matched` must fail validation; a receipt with `status: incomplete` and a mix of `matched`, `missing` and `pending` must validate; and a run that never reached the image publisher must serialize validly
**And** a receipt with `status: complete` whose `package` array has no entry for the always-on forge package registry, or records that entry as disabled, must fail validation
**And** the planted violation for that rule drops the forge package entry from an otherwise complete receipt; a schema that only requires `package` to be present would accept it, so the requirement must be that every always-enabled `package_targets` entry has a corresponding receipt entry
**And** the planted violation sets `status: complete` on a document with one `missing` OCI alias; the existing conditional branch must reject it, proving the enum widening did not weaken it

**Given** the event-path fixtures
**When** they are added under `tests/ci/fixtures/workflows/`
**Then** the set covers pull request (exists), default-branch push, exact tag, alias tag, malformed tag, all-destinations-disabled, and one fixture per enabled destination
**And** each is asserted to reach only its intended jobs, including the negative direction: the malformed-tag fixture must reach `classify` and nothing else, and the all-disabled fixture must reach no job holding a credential

**Given** the whole-suite gate
**When** the cutover change is validated
**Then** `poetry check --lock`, `poetry run pytest`, `poetry run pre-commit run --files <changed>` and actionlint over all four workflows pass
**And** `pre-commit run --all-files` is not used, per the repository's recorded exclusion incident

## Open questions

1. **Delete `scripts/git-increment-version.sh` or keep the refusing stub?** It is already inert — five lines that print the supported commands and exit 2 — and it is a useful signpost for anyone with the old command in muscle memory. Deleting it satisfies "no local script can publish" more literally; keeping it satisfies the same rule in substance. This story assumes deletion, with the signpost moved into `docs/developer.md`, but it is genuinely a maintainer preference.
2. **Does `build.sh` have a documented external consumer?** The epic conditions removal on "no documented external consumer remains". No workflow, recipe or document in the repository references it, but it is a repository-root script that a downstream user may have copied into their own automation. This story assumes none and removes it; if the maintainer knows otherwise, a deprecation notice in the release notes is the alternative.
3. **How is "reaches only its intended jobs" asserted for an event fixture?** The repository has no workflow simulator, and adding one would be a hand-rolled runner of the kind the engineering rules forbid. This story assumes the assertion is made over the parsed workflow document — evaluating each job's `if:` and `needs:` against the fixture's context — rather than by executing anything. That is a real but bounded limitation: it proves the conditions, not the runner's evaluation of them. It must be stated where the tests live, so a later reader does not over-trust it.
4. **Is a cancelled run allowed to leave no receipt?** `if: always() && !cancelled()` produces none. Using bare `always()` would produce one for cancelled runs too, but a receipt written while a mutation may still be in flight can be wrong. This story chooses no receipt on cancel and documents it; the alternative is a receipt explicitly marked `cancelled`, which needs a schema value that does not exist today.
