# Publish Immutable Development Packages and Images

As a maintainer, I want protected default-branch artifacts published from the verified bundle,
so development delivery creates immutable package and image identities without rebuilding.

Depends on the completed Epic 7 foundation.

## Acceptance Criteria

**Given** a protected default-branch push, **when** `dev.yaml` starts, **then** unknown forges fail
closed; one full-history/tags checkout derives `X.Y.(Z+1).devN`; an exact stable tag on the source
suppresses dev publication; and `verify-build.yaml` is called exactly once for the event SHA.

**Given** a destination receives `verified-dist-v1`, **when** it reaches its first credentialed
step, **then** it has revalidated `SHA256SUMS` and `build-manifest.json`, matched source/version,
and, for images, matched the exact wheel hash to the declared image input (CI-AR36).

**Given** package publication is enabled or required, **when** upload begins, **then**
`pypa/gh-action-pypi-publish@<reviewed-full-commit-sha>` receives only the verified wheel/sdist;
implementation resolves, reviews, and records the actual full SHA. Package OIDC/tokens are
isolated from image jobs (CI-AR24, CI-AR38, CI-AR40).

**Given** development image publication, **when** the image job runs, **then** it consumes the
exact verified wheel and performs one Buildx invocation for `linux/amd64,linux/arm64` with the
immutable `dev-<12sha>` tags for the required forge registry and optional Docker Hub. It never
rebuilds per registry and emits digest/platform inspection as outputs and run summary (CI-AR39,
CI-AR41).

**Given** forge coordinates, **when** `FORGE_REGISTRY` is present, **then** it accepts only
same-forge `host[:port]` with no userinfo, path, query, or fragment. Optional toggles accept only
`true`, `false`, or absence; disabled destinations receive no credentials or requests.

## Definition of Done

- `dev.yaml` owns protected default-branch pushes and uses workflow concurrency to cancel/supersede
  stale candidates.
- Required forge and enabled external immutable publications consume one verified artifact set.
- The image job receives only enabled registry credentials; package credentials remain job-local.
- Tests cover forge fail-closed, full-history derivation, stable-tag suppression, coordinate
  validation, one verifier call, one Buildx invocation, two platforms, and secret isolation.
- Run evidence records run ID/URL, manifest/artifact hashes, published digest/platforms, and
  destination conclusions without adding a schema (CI-AR37, CI-AR41).

## Test anchors

Guard, then the violation planted to prove it fires:

- Forge fail-closed: unknown forge hits a non-zero fallthrough; plant deleting that branch.
- Full-history derivation: parsed checkout keeps full depth and tags; plant deleting the key while
  leaving the comment explaining it.
- Stable-tag suppression: every publisher is transitively gated on the suppression job; plant one
  that is not (scope attack).
- Coordinate validation: `FORGE_REGISTRY` rejects userinfo, path, query, fragment, foreign host;
  plant an unanchored pattern.
- One verifier call: parsed verifier `uses:` in `dev.yaml` counts one; plant a second elsewhere.
- One Buildx invocation: one build-push step carries both platforms and all tags; plant a
  per-registry second build.
- Secret isolation: per-job secret references stay disjoint; plant a registry credential in the
  package job.
