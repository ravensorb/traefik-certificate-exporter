# Closure notes — E012-S01-003 "Fix local act-build.sh checkout/mount strategy"

Resolves BL-E011-011. Implements ADR-0028 and CI-AR42–CI-AR46.
Code review: `review-E012-S01-003.md` — critical 0, high 0, medium 3, low 4.
Fix iterations: 1 (all three MEDIUM findings fixed; LOW-2 and LOW-4 also fixed).

## What shipped

- Every `ref:` / `repository:` input removed from all five workflow files (22 sites).
  `actions/checkout` is now the plainest possible call everywhere, so `act` skips it
  instead of wiping the disposable clone it was mounted into.
- `ci.yaml` collapsed to a single `verify` job calling `verify-build.yaml` with
  `channel: ci` only (CI-AR45).
- `verify-build.yaml` drops its `source-sha` input and self-discovers identity with
  `git rev-parse HEAD` as the first post-checkout step; `package-version` became
  optional, resolved per channel (`ci` must omit it, `dev`/`stable` must supply it).
- `docker/act-build.sh` no longer dispatches `package-version` / `source-sha`.
- Two mechanical CI-AR42 guards added in `tests/ci/test_workflow_contracts.py`
  (`with:` keys and post-checkout shell re-pinning), each with a plant test that
  drives the production helper rather than restating it.

## Fix-loop changes (review response)

- **MEDIUM-1** — the re-pinning guard now scans composite-action step groups
  unconditionally. They hold no checkout of their own precisely because they inherit the
  caller's working tree, so the old `if not any(_is_checkout(...)): continue` skipped the
  exact place a re-pin is most dangerous.
- **MEDIUM-2** — `_identity_overrides()` extracted; the plant test calls it and also
  asserts the negative cases (ref-free checkout, non-checkout `uses:` carrying a `ref:`).
- **MEDIUM-3** — `dev.yaml`'s `recheck-head` step name and `GITHUB_STEP_SUMMARY` line no
  longer claim default-branch-head freshness they cannot prove; they say "consistency
  check, not a freshness proof". `tests/ci/test_finalization.py`'s behavioural test was
  renamed and its docstring corrected so a green test no longer advertises a removed
  guarantee. `docs/ci/gitea-certification.md`'s citation follows the rename.
- **LOW-2** — `docs/ci/ref-free-checkout-walkthrough.md`, `docs/adr/0028`, `docs/adr/0029`
  are now tracked.
- **LOW-4** — `REPINNING_COMMAND` accepts `git`'s global options before the verb, closing
  the `git -C . checkout <sha>` / `git --git-dir=… fetch` evasion.

## Flags carried into closure

1. **CI-AR43 PR-merge-commit risk (accepted, stated explicitly as the security AC
   requires).** With no `ref:`, a `pull_request`-triggered checkout lands on GitHub's
   ephemeral merge commit rather than the PR head. For this pipeline that is the correct
   and safer target — it is what CI actually gates — and `ci.yaml` is fork-safe
   (no secrets, no publication). Nothing downstream pins the PR head SHA; `source-sha`
   is recorded as evidence, never asserted against an externally supplied value on the
   PR path.
2. **Deliberate deviation from "comment/doc-only" for `docker/act-build.sh`.** The story's
   Files-in-scope described the script change as documentation only, but the two
   `--input` flags had to go: the `ci` channel now actively rejects a non-empty
   `package-version`, so leaving them would have made every local run fail on the new
   contract.
3. **Scope of the `git rev-parse HEAD` discovery.** The story text reads "each job
   discovers it"; CI-AR44 reads "every other job's own identity output". Implemented in
   `source-integrity` and `distribution` only — the jobs that emit or consume identity —
   per ADR-0028's "each job that needs it". Other jobs neither produce nor consume a SHA.
4. **`act` acceptance evidence gap.** No `act` binary is available in this environment, so
   the story's "green `act` run per channel" acceptance check was not executed here.
   Filed as a backlog issue; the mechanism is correct per nektos/act #122 and is now
   mechanically guarded.
5. **Token actuals recorded as zero.** `pm-status.py usage` resolved a transcript from a
   different project path and excluded every record in the dispatch window, so no
   attributable token counts exist. Elapsed/man/HITL hours are real; `tokens_k` is a
   known measurement gap, not a claim of zero cost.
