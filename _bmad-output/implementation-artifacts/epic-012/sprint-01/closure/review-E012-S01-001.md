# Code review — E012-S01-001 "Harden privileged write/execution surfaces"

Scope reviewed: `closure/diff-E012-S01-001.patch` (complete change set) against the story's
functional, business and technical acceptance criteria. Verification was done against the
working tree, the installed `confuse`, the pinned LinuxServer base image
(`ghcr.io/linuxserver/baseimage-alpine:3.24@sha256:e174…d2c6`, pulled and inspected) and the
`lsiown` script that image ships.

Counts: **Critical 2, High 2, Medium 2, Low 3.**

---

## 1. The dropped-privilege path cannot start the application at all (`HOME=/root`)

**File:** `docker/root/etc/s6-overlay/s6-rc.d/svc-traefik-certificate-exporter/run:24-26`
(consequence lands in `src/traefik_certificate_exporter/libs/settings.py:278`)
**Severity:** Critical
**Kind:** bug

**Problem.** `s6-setuidgid abc` changes the uid/gid but leaves the environment alone, so the
exporter runs as `abc` with `HOME=/root`. `SettingsManager.loadFromFile` constructs
`confuse.Configuration("traefik_certificate_exporter", …)`, whose `read()` →
`_add_user_source()` → `config_dir()` ends in an unguarded
`os.makedirs(~/.config/traefik_certificate_exporter)`. In the image `~` is `/root`, mode
`drwx------ root root`, so that call raises `PermissionError` for uid 911. Nothing in
`app.py:_run` or `SettingsManager` catches it, so the service dies before it reads a single
certificate — and this is the **default** configuration the story ships
(`restartcontainers: false`). s6 then restarts the longrun in a loop.

**Evidence.**
- Base image inspected: `HOME=/root`; `ls -ld /root` → `drwx------ 2 root root`;
  `id abc` → `uid=911(abc) gid=1001(abc)`; `su -s /bin/sh abc -c 'mkdir -p /root/.config/x'`
  → `Permission denied`.
- `confuse.Configuration.config_dir()` source: `os.makedirs(appdir)` re-raises anything that
  is not `EEXIST`.
- Reproduced with the project's own interpreter:
  `HOME=/root python -c "import confuse; confuse.Configuration('traefik_certificate_exporter','traefik_certificate_exporter')"`
  → `PermissionError: [Errno 13] Permission denied: '/root/.config'`.
- The confuse app-dir override env var (`TRAEFIK_CERTIFICATE_EXPORTERDIR`) is not set
  anywhere in `docker/Dockerfile`.
- This is a regression introduced by the diff: with the previous `s6-setuidgid root` the
  `makedirs` succeeded.

**Remedy.** Give the dropped account a writable home before the exec — e.g. `export
HOME=/config` (read-only use is enough; confuse only needs the directory to exist) or set
`ENV HOME=/config` plus a root-owned, `abc`-readable `/config/.config/traefik_certificate_exporter`
created in the init oneshot, or set `TRAEFIK_CERTIFICATE_EXPORTERDIR` to a directory `abc`
can create. Whatever is chosen, add a smoke check that actually starts the built image with
`restartcontainers: false` — the story's "manual/documented verification" clearly did not
cover container start-up in the dropped configuration.

## 2. Change detection permanently suppresses restarts after a real certificate rotation

**File:** `src/traefik_certificate_exporter/libs/docker.py:48`
**Severity:** Critical
**Kind:** bug

**Problem.** The "did anything change?" test compares **domain names**, not certificate
material. `restartLabeledContainers` is called with the return of
`exportCertificatesForFile`, which is the list of every domain exported in the pass
(`certificate_exporter.py:516`, `names.append(name)` — appended unconditionally for each
certificate in the store, change or not). A renewal does not change the domain name, so on
every renewal after the first, `matched == previousDomains` is true and the branch returns
`(False, "no change in the matched domain set since the last restart")`. The cooldown is
never even reached, and `previousAt` is never refreshed.

Net effect: for a long-lived watcher process (the container default is
`WATCHFORCHANGES=true` + `RUNATSTART=true`), each labeled container is restarted **once per
exporter process lifetime** and never again, no matter how many times its certificate is
actually rotated. Downstream containers keep serving the old certificate until it expires.
That is the entire purpose of `restartcontainers`.

**Evidence.** `exportCertificatesForFile` → `__exportCertificate` returns all exported
names; nothing in the pass compares old and new certificate bytes. The new tests encode the
defect rather than catching it: `test_second_pass_with_same_domains_does_not_restart_again`
asserts exactly the suppressed-rotation case.

**Remedy.** Key the change detection on something that actually changes on rotation — e.g.
have the exporter return (or record) a per-domain certificate fingerprint/serial, or only
pass domains whose written bytes differed — and keep the 300 s cooldown as the rate limiter.
If that is out of scope, drop the change-detection half entirely and keep only the cooldown:
the cooldown alone satisfies the stated DoS mitigation (BL-E011-016) without breaking the
feature. Note that the business AC's wording ("restarted only when its own certificate
domain actually changed") is itself the source of the defect and should be corrected along
with the code.

## 3. `lsiown -R` over `/certs` is an arbitrary-chown primitive via planted symlinks

**File:** `docker/root/etc/s6-overlay/s6-rc.d/init-traefik-certificate-exporter-config/run:70-76`
**Severity:** High
**Kind:** security

**Problem.** The init oneshot runs as root and recursively chowns the operator/attacker-
writable output volume. `lsiown` (present in the pinned base image) is a shell wrapper whose
last line is:

```
/usr/bin/find "${PATH[@]}" "${MAXDEPTH[@]}" ! -xtype l \( ! -group "${GROUP}" -o ! -user "${USER}" \) -exec chown "${OPTIONS[@]}" "${USER}":"${GROUP}" {} +
```

`! -xtype l` only excludes *broken* symlinks; a symlink to an existing file passes the
filter, and `chown` without `-h` **dereferences it**. So any symlink inside `/certs`
pointing at a container path causes that path to be chowned `abc:abc` by root at every
container start. This is precisely the threat model the same diff documents in
`_atomic_write`'s new docstring ("a link planted at an export path by anyone who can write
the output directory"). After the drop, the exporter itself runs as `abc` and owns `/certs`,
so an exporter compromise (the RCE scenario this story exists to contain) converts into
ownership of e.g. `/etc/shadow`, `/etc/passwd`, or `/app/.venv/bin/*` on the next restart —
i.e. the change re-opens an escalation path to root that the privilege drop was meant to
close.

**Evidence.**
- `lsiown` v1 source fetched from `linuxserver/docker-mods` (`mod-scripts/lsiown.v1`);
  `/usr/bin/lsiown` confirmed present in the pinned base image.
- Reproduced the `find … ! -xtype l … -exec chown` pattern locally: the **target** file's
  ownership changed, the symlink's did not.
- The busybox `chown -R` fallback branch (line 74) is safe — busybox defaults to `-P` and
  verified locally to affect the link, not the target — so only the branch that actually
  runs in the image is vulnerable.

**Remedy.** Pass `-h` through (`lsiown -Rh abc:abc "${CERTS_DIR}"` — `lsiown`'s `getopts`
forwards `h` to `chown`), or replace both branches with an explicit
`find "${CERTS_DIR}" -xdev ! -type l -exec chown -h abc:abc {} +`. Also consider bounding the
traversal (`-xdev`) so a nested bind mount is not rewritten.

## 4. The dropped account cannot read Traefik's ACME store in the normal deployment

**File:** `docker/root/etc/s6-overlay/s6-rc.d/init-traefik-certificate-exporter-config/run:65-77`;
claim asserted in `docs/adr/0030-conditional-privilege-drop.md` ("`/data` is untouched … it can
stay root-owned and world-readable")
**Severity:** High
**Kind:** bug / claim

**Problem.** Traefik writes `acme.json` mode `0600` owned by the account Traefik runs as
(root in the overwhelmingly common deployment) and refuses to operate when the file is more
permissive. The ADR's premise that `/data` "can stay root-owned and world-readable" is
therefore false for the file that matters. After the drop, `abc` (uid 911) gets `EACCES` on
`Path(sourceFile).read_text()`; the exception is swallowed by the broad handler at
`certificate_exporter.py:584` and surfaces only as `Error processing file '…'` at ERROR —
the container keeps running and exports nothing. The default configuration this story makes
the norm therefore silently stops exporting for most existing users.

**Remedy.** Either document and enforce the requirement (`PUID`/`PGID` must match the owner
of `acme.json`, or the operator must relax its group permissions) prominently in
`docs/operational.md` and the ADR's Consequences, or add a start-up readability probe that
fails loudly ("`/data/acme.json` is not readable as uid …; set PUID/PGID to match or keep
`restartcontainers` enabled"). At minimum, remove the inaccurate "world-readable" claim from
the ADR.

## 5. `/certs` is hardcoded while the export path is configurable

**File:** `docker/root/etc/s6-overlay/s6-rc.d/init-traefik-certificate-exporter-config/run:13,70-76`
**Severity:** Medium
**Kind:** bug

**Problem.** `CERTS_DIR=/certs` is the image's *default* `settings.outputpath`
(`docker/Dockerfile:117`), not its value. An operator who sets
`TRAEFIK_CERTIFICATE_EXPORTER_SETTINGS_OUTPUTPATH` or `settings.outputpath` to another mount
gets no ownership fix-up, and the exporter — now running as `abc` — fails every write into a
root-owned directory. The failures land in `__exportCertificate`'s per-domain
`except` (`certificate_exporter.py:521`) as `Error processing domain: …`, so the container
reports healthy while exporting nothing.

**Remedy.** Resolve `settings.outputpath` in the same heredoc that already resolves
`settings.restartcontainers` (one extra printed line) and chown that path, falling back to
`/certs`; or refuse to drop privileges when the resolved output path is not writable by
`abc` and say so.

## 6. The init script re-implements settings precedence instead of asking the installed app

**File:** `docker/root/etc/s6-overlay/s6-rc.d/init-traefik-certificate-exporter-config/run:26-51`
**Severity:** Medium
**Kind:** reuse (reused-before-written)

**Problem.** The story's existing-library check justified writing the cooldown and reusing
`s6-setuidgid`; it says nothing about re-implementing configuration resolution. The heredoc
claims "Same precedence the application applies", but the application resolves
`restartcontainers` through `confuse` with sources the heredoc does not consult
(`settings.py:280-310`): the packaged default, `/app/.../.env` and `./.env` via `load_dotenv`,
and CLI args — and it coerces values differently. The heredoc's `TRUTHY` set is
`{1,true,yes,on}`; confuse parses the env value as YAML and then `get(bool)`, so a value such
as `y`, `2` or `enabled` is **true to the application and false to the init script**. Any
such divergence yields the worst combination: the application enables the Docker-socket
restart path while the container has dropped to `abc`, so restarts fail with a permission
error from `docker.from_env()` logged only as the generic "Failed restarting containers".

**Remedy.** Ask the installed package for the resolved value instead of re-deriving it —
e.g. `/app/.venv/bin/python -c "from traefik_certificate_exporter.libs.settings import
SettingsManager; …; print(mgr.settings.restartContainers)"` (one code path, one precedence,
and it keeps working when a new source is added). If the embedded parser must stay, make the
truthiness rule identical to confuse's and document the ignored sources in the ADR.

## 7. Cooldown/no-change skips are logged at DEBUG, contradicting the error-handling AC

**File:** `src/traefik_certificate_exporter/libs/docker.py:78`; `docs/operational.md:78-82`
**Severity:** Low
**Kind:** claim

**Problem.** The story's "Error and edge case handling" AC requires: "a container restarted
within the cooldown window is skipped and logged at INFO/WARNING rather than silently
dropped". The implementation logs both skip reasons at DEBUG, and the docs state DEBUG as
the designed level. With the image's default log level an operator diagnosing "my container
did not restart" sees nothing at all — the same symptom the ADR's own troubleshooting
section asks them to confirm.

**Remedy.** Log the cooldown skip at INFO (it is rare by construction — at most once per
container per 300 s) and leave the no-change skip at DEBUG, then align `docs/operational.md`.

## 8. `__lastRestart` is mutated from timer threads without synchronisation

**File:** `src/traefik_certificate_exporter/libs/docker.py:92`
**Severity:** Low
**Kind:** bug

**Problem.** Drains run on `threading.Timer` threads (`certificate_exporter.py:1020`), and
`app.py:161` calls `restartLabeledContainers` from the main thread for the run-at-start pass.
The read in `_shouldRestart` and the write at line 92 are a non-atomic read-modify-write: two
overlapping passes can both observe `previous is None` and both restart the same container,
which is exactly the storm the cooldown exists to prevent (bounded at 2x, so Low). Individual
dict operations are GIL-atomic, so there is no corruption risk.

**Remedy.** Guard the lookup+update with a `threading.Lock` held across `_shouldRestart` and
the recording assignment.

## 9. File logging breaks silently for the dropped account

**File:** `docker/root/etc/s6-overlay/s6-rc.d/svc-traefik-certificate-exporter/run:24-26`
**Severity:** Low
**Kind:** edge

**Problem.** `logging.yaml` declares `RotatingFileHandler` with the relative filename
`traefik-certificate-exporter.log`, resolved against `WORKDIR /config` — which this change
deliberately leaves root-owned. An operator who turns off
`TRAEFIK_CERTIFICATE_EXPORTER_LOGGING_CONSOLEONLY` (documented in `config.sample.yml`) now
gets a `PermissionError` inside `dictConfig`, caught at `logging_utils.py:250`, printing a
traceback and silently degrading to console logging. Not a crash, but the documented switch
no longer does what it says and nothing in the new docs mentions it.

**Remedy.** Point the file handler at a path the service account owns (e.g. `/certs/logs` or
a new `/logs` volume chowned alongside `/certs`), or document that file logging requires
`restartcontainers: true`.

## Deletion check

Every removed chunk was examined; no behaviour or contract was dropped that the change
neither re-established nor intended to drop.

- `svc-…/run`: `s6-setuidgid root` → guarded root branch + `abc` fall-through. The root
  behaviour is re-established exactly for the `restartcontainers: true` case. The removed
  commented-out `# env | sort` is restored. (high confidence, no issue)
- `init-…/run`: the removed `# write_info "Creating default config.yaml"` comment and the
  literal `/config/config.yaml` paths were replaced by `${CONFIG_FILE}`; `cp -u` from
  `/defaults` is preserved verbatim. (high confidence, no issue)
- `docker.py`: the old `set(domains).isdisjoint(restartDomains)` gate is preserved as the
  `matched` intersection, the dry-run log line and the per-container exception handling are
  both retained. The one behavioural *addition* that suppresses previously-performed
  restarts is finding 2, not a deletion. (high confidence)
