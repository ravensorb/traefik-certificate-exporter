# Fix local act-build.sh checkout/mount strategy

## Context

Promoted from deferred finding(s):
- BL-E011-011 (Medium, arch-drift (SD-01-2)) — The retained act evidence fails at actions/checkout rejecting the local-clone origin. Closing BL-E007-002 fully needs a wrapper clone/mount change, not a rerun. See _bmad-output/implementation-artifacts/epic-011/sprint-01/closure/arch-drift-review.md (SD-01-2) and docs/operational.md.

## Acceptance Criteria

- The deferred finding BL-E011-011 is resolved: docker/act-build.sh clone/mount strategy blocks a green local act run (BL-E007-002 residue)

## Business acceptance criteria

### Outcome

- A maintainer running `docker/act-build.sh` (e.g. via `just test-local`) against an
  unpushed, local-only commit gets a successful local `act` run instead of a destructive
  checkout that deletes the disposable clone's working tree — for every channel
  (`ci`/`dev`/`release`), with no special flag or environment variable required.
- A CI/CD reviewer or future contributor who finds a checkout step in any of the 5
  workflow files can tell, without archaeology, that it is intentionally unparameterized
  (ref-free) by design, not an oversight — and the walkthrough doc explains why, so they do
  not quietly reintroduce a `ref:` pin.
  Spec: _bmad-output/planning-artifacts/architecture/architecture-ci-cd-pipeline-2026-08-31/ARCHITECTURE-SPINE.md#ref-free-checkout-2026-10-08-adr-0028

### Non-goals

- **Scope re-classification flag (for step-estimate):** the design authority for this
  story grew substantially since it was first scoped. The original scope was "fix
  `docker/act-build.sh`'s clone/mount behavior." The final, authoritative design —
  recorded in `docs/adr/0028-ref-free-checkout-across-ci-cd.md` and
  `_bmad-output/planning-artifacts/architecture/architecture-ci-cd-pipeline-2026-08-31/ARCHITECTURE-SPINE.md`
  (CI-AR42–CI-AR46, amended CI-AR2/CI-AR33) — touches all **5** CI/CD workflow files
  (`ci.yaml`, `dev.yaml`, `release.yaml`, `verify-build.yaml`, `publish-image.yaml`), not
  just the local script. This is a materially larger surface than the `standard`
  classification on this file's frontmatter originally assumed when first written;
  step-estimate evaluated this on 2026-10-08 and moved the `classification:` field above
  to `complex` (state node and estimate/rollup re-run accordingly). This note is retained
  as the historical rationale for that reclassification, not an open flag.
- This story does not change `docker/act-build.sh`'s disposable-clone mechanism; that
  mechanism is explicitly retained as defense-in-depth (CI-AR33, no longer load-bearing but
  kept) — this story only notes that the checkout steps it drives are now ref-free, so
  act's built-in no-op checkout-skip applies naturally, without any `LOCAL_VERIFY`-style
  env-var gating (an earlier, superseded candidate design — explicitly not used here).
- This story does not change the CI-AR36 boundary-revalidation chain: `source-sha` and
  `package-version` continue to flow as plain data values into `publish-image.yaml`'s
  `expected-source-sha`/`expected-package-version` assertion inputs to the `verified-bundle`
  composite action, unchanged. Only checkout-pinning uses of those values are removed.
- This story does not close the narrow accepted drift risk named in CI-AR43: a
  PR-triggered `ci.yaml` run now checks out GitHub's standard synthetic merge-with-base
  commit rather than an explicitly pinned PR head SHA. This is a deliberately accepted
  trade-off (see ADR-0028 Consequences), not a defect this story fixes.

## Technical acceptance criteria

Files this story adds or changes, and the conventions their siblings establish:
- `.github/workflows/ci.yaml` — collapses from its prior `plan` + `verify` two-job
  structure to a single job calling `verify-build.yaml` with only `channel: ci` (CI-AR45);
  the convention already set by `dev.yaml`/`release.yaml` is that `workflow_call` consumers
  pass only the inputs they genuinely need, which this change now matches.
- `.github/workflows/dev.yaml` and `.github/workflows/release.yaml` — keep their existing
  `plan` jobs (genuine channel-specific work: dev-distance version computation,
  stable-tag validation), per CI-AR46; the convention to preserve is that `plan` continues
  to self-discover its own `source-sha` via `git rev-parse HEAD` for downstream data-flow
  use, but no job downstream of `plan` re-threads `ref:` into its own checkout.
- `.github/workflows/verify-build.yaml` — drops `source-sha` as a `workflow_call` input
  entirely; each job discovers it via `git rev-parse HEAD` as the immediate next step after
  checkout, before any other step (CI-AR44); `package-version` becomes
  `required: false`, and callers that omit it must omit the `with:` key entirely (never an
  empty string) — this is the convention this story establishes for future optional
  `workflow_call` inputs in this file.
- `.github/workflows/publish-image.yaml` — drops its own `ref: inputs.source-sha` checkout
  override (the scope gap caught by the architecture redesign's reviewer gate); its
  `source-sha`/`package-version` inputs remain required, consumed solely as assertion
  arguments to the `verified-bundle` composite action (CI-AR36), never as a checkout
  override.
- `docker/act-build.sh` — no code removal; a context-note-only change (comment/doc)
  reflecting that its checkout steps are now ref-free and therefore act's no-op
  checkout-skip applies naturally.
  Spec: _bmad-output/planning-artifacts/architecture/architecture-ci-cd-pipeline-2026-08-31/ARCHITECTURE-SPINE.md#ref-free-checkout-2026-10-08-adr-0028

### Interface contracts

- Every `actions/checkout` step across all 5 workflow files becomes the plainest possible
  `actions/checkout@v7` call (`fetch-depth`/`fetch-tags`/`persist-credentials` only); no
  step supplies `ref:` or `repository:`, and no step after a ref-free checkout re-pins
  identity by another route (no `git fetch`/`git checkout <sha>` shell step, no
  env-var-indirected `ref:` expression, no nested composite action that re-checks-out).
- `verify-build.yaml`'s `workflow_call` input contract: `source-sha` input is removed;
  `package-version` input gains `required: false`; a caller without a package version omits
  the `with: package-version:` key entirely (never passes `""`). `verify-build.yaml`'s
  `source-integrity` job emits `git rev-parse HEAD` as a job output (evidence/
  `build-manifest.json` only), never asserted against an externally supplied value.
- `source-sha`/`package-version` continue flowing as plain data (not checkout refs) into
  `publish-image.yaml`'s `expected-source-sha`/`expected-package-version` inputs to the
  `verified-bundle` composite action — this data-flow contract is unchanged by this story.
  Spec: _bmad-output/planning-artifacts/architecture/architecture-ci-cd-pipeline-2026-08-31/ARCHITECTURE-SPINE.md#ref-free-checkout-2026-10-08-adr-0028

### Error and edge case handling

- `ci.yaml`'s PR path: GitHub's default `pull_request` checkout now resolves to the
  synthetic merge-with-base commit; no job computes or asserts
  `github.event.pull_request.head.sha` (CI-AR43). This is an accepted, documented
  trade-off, not an error condition to special-case.
- A missing/omitted `package-version` in a `verify-build.yaml` call: the `distribution` job
  reads the committed `pyproject.toml` version directly and performs no cross-validation —
  this is the defined behavior for the `ci` channel's own call, not a failure path.
- A future workflow change that reintroduces a `ref:`/`repository:` key, or an indirect
  re-pinning route (shell-level `git fetch`/`git checkout <sha>`/`git reset --hard`), must
  be caught by the workflow-contract test named in CI-AR42's "Enforceable by" clause, not
  left to manual review.
  Spec: _bmad-output/planning-artifacts/architecture/architecture-ci-cd-pipeline-2026-08-31/ARCHITECTURE-SPINE.md#workflow-responsibilities

### Observability requirements

- `verify-build.yaml`'s self-discovered `source-sha` is recorded in `build-manifest.json`
  as evidence for every job, even though it is no longer asserted against an external
  value — so a build's actual commit identity remains auditable post-hoc.
- The walkthrough doc (`docs/ci/ref-free-checkout-walkthrough.md`) itself functions as an
  observability/discoverability artifact: a future contributor investigating "why is this
  checkout unparameterized" has a documented answer rather than needing to re-derive it
  from git history.
  Spec: _bmad-output/planning-artifacts/architecture/architecture-ci-cd-pipeline-2026-08-31/ARCHITECTURE-SPINE.md#ref-free-checkout-2026-10-08-adr-0028

### Security considerations

- Removing `ref:` pinning does not weaken CI-AR36 boundary revalidation or CI-AR11 stable
  agreement checks — both are explicitly unaffected per ADR-0028's Consequences and the
  walkthrough's "What this does *not* change" section; this story must not touch those
  assertion chains.
- The accepted trade-off (CI-AR43: PR runs test the synthetic merge commit, not a pinned
  head SHA) is a known, bounded security/consistency risk — it must be stated explicitly
  as an accepted risk in any PR/story closure notes, not silently absorbed.
- No new secrets handling is introduced; `publish-image.yaml`'s explicit forge-token/
  Docker-Hub-credential inputs are unchanged by this story.
  Spec: _bmad-output/planning-artifacts/architecture/architecture-ci-cd-pipeline-2026-08-31/ARCHITECTURE-SPINE.md#ref-free-checkout-2026-10-08-adr-0028

### Testability approach

- A new or extended workflow-contract test (following the existing naming/location
  convention of `tests/ci/test_workflow_contracts.py`) asserts (a) no `actions/checkout`
  step anywhere under `.github/workflows/` declares a `ref:` or `repository:` key, and
  (b) no step in a job that contains a checkout step invokes `git fetch`, `git checkout`,
  or `git reset --hard` against anything other than a path already present in the working
  tree (CI-AR42's named follow-up / "Enforceable" clause).
- Local verification via `docker/act-build.sh` (`just test-local` or equivalent) against
  an unpushed commit is the acceptance check for the original failure mode: a green run
  for each channel with no destructive-checkout error, per ADR-0028's Context section.
  Spec: _bmad-output/planning-artifacts/architecture/architecture-ci-cd-pipeline-2026-08-31/ARCHITECTURE-SPINE.md#ref-free-checkout-2026-10-08-adr-0028

### Existing-library check

- `actions/checkout@v7` (already the pinned version/mechanism in use) is retained as-is;
  no new checkout action or version is introduced — only its `with:` inputs are
  simplified.
- `git rev-parse HEAD` (already used elsewhere in this pipeline per CI-AR44) is the
  existing, correct mechanism for self-discovering build identity; no new tool is
  introduced for this.
- `nektos/act` is already the existing local-verification tool via
  `docker/act-build.sh`; its built-in no-`ref:` checkout-skip behavior (confirmed via
  `nektos/act` issue #122, cited in ADR-0028) is relied on as-is, not reimplemented.
  Spec: _bmad-output/planning-artifacts/architecture/architecture-ci-cd-pipeline-2026-08-31/ARCHITECTURE-SPINE.md#ref-free-checkout-2026-10-08-adr-0028

## Files in scope

- `.github/workflows/ci.yaml` — collapse to a single job calling `verify-build.yaml` with only `channel: ci`.
- `.github/workflows/dev.yaml` — keep its channel-specific `plan` job; stop re-threading `ref:` into downstream checkouts.
- `.github/workflows/release.yaml` — keep its channel-specific `plan` job; stop re-threading `ref:` into downstream checkouts.
- `.github/workflows/verify-build.yaml` — drop the `source-sha` `workflow_call` input and self-discover it via `git rev-parse HEAD`; make `package-version` optional.
- `.github/workflows/publish-image.yaml` — drop the `ref: inputs.source-sha` checkout override while keeping `source-sha`/`package-version` as assertion inputs only.
- `docker/act-build.sh` — comment/doc-only update noting its checkout steps are now ref-free so act's no-op checkout-skip applies naturally.
