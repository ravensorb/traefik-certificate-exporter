# CLI/output hygiene: redaction, usage text, flag errors

## Context

- BL-E011-034 (Medium, ux-review (UX-003)) — See _bmad-output/implementation-artifacts/epic-011/sprint-01/closure/ux-review.md
- BL-E011-035 (Medium, ux-review (UX-004)) — See _bmad-output/implementation-artifacts/epic-011/sprint-01/closure/ux-review.md

## Acceptance Criteria

- The deferred finding BL-E011-033 is resolved: Redacting a list collapses it to a scalar, destroying its count/scheme signal
- The deferred finding BL-E011-034 is resolved: Unrecognised-flag failure names no near-match and never points at --help
- The deferred finding BL-E011-035 is resolved: Usage block, now shown on every typo, leaks internal config paths as metavars
- The deferred finding BL-E011-036 is resolved: Active-settings dump is one unwrapped 400-character JSON line

## Business acceptance criteria

### Outcome

- An operator viewing debug output sees a redacted `appriseUrls` (or any other list-valued
  secret) as a list of the same length as before, each element showing its scheme
  (`scheme://***REDACTED***`), so they can tell at a glance how many notification targets
  are configured and of what kind, without any raw token/credential ever appearing.
- A user who typos a long flag (e.g. `--dtaa-path`) sees a suggestion naming the closest
  real flag and a pointer to `--help`, instead of a bare "unrecognized arguments" error
  with no guidance.
- A user reading `--help` output sees human-readable placeholders (`PATH`, `FILESPEC`,
  `DOMAIN [DOMAIN ...]`) for argument values, not internal dotted config-key names
  uppercased (`SETTINGS.DOMAINS.INCLUDE`).
- An operator comparing the active-settings debug dump against the adjacent active-config
  dump sees both pretty-printed in a legible, multi-line form, not one as a single ~400
  character JSON line and the other as block YAML.
  Spec: none — l3io-plan run, no spec index bound

### Non-goals

- This story does not fix UX-009 (the argparse usage block bypassing the structured
  logging contract — going to raw stderr with no level/timestamp/correlation_id even under
  JSON console logging). That is a separate, lower-severity backlog item explicitly
  deferred out of this story's scope.
- This story does not change which settings keys are treated as secrets (the declared-secret
  key list itself); it only changes how a list-valued secret is rendered once redacted.
- This story does not change the overall settings/config loading precedence (CLI/file/env)
  established by `confuse`; it only changes output formatting and error-message content.

## Technical acceptance criteria

Files this story adds or changes, and the conventions their siblings establish:
- `src/traefik_certificate_exporter/libs/settings.py` (`_redact_secrets`, `_dump_settings`)
  — the existing convention is that `_redact_secrets` is a single recursive function
  handling dict/list/scalar cases uniformly, and `_dump_settings` sits directly beside
  `_dump_config`, which already pretty-prints as block YAML; `_dump_settings` should adopt
  the same "legible multi-line debug dump" convention, not a new one.
- `src/traefik_certificate_exporter/libs/cli_args.py` (`parse_args_strict`, every
  `add_argument` call) — all 16 existing `add_argument` calls currently rely on argparse's
  default dotted-`dest`-derived metavar; the convention this story establishes (and must
  apply uniformly to all 16, not just a subset) is an explicit `metavar=` on every call.
- `README.md` — flag documentation already exists in prose form; the convention to match
  is whatever existing flag-to-doc mapping pattern the README already uses (table or list),
  extended only if a gap is found, not restructured.
- `tests/ci/test_documentation.py` — already a `tests/ci/` module asserting doc content
  against repository reality (see `_recovery_section`, `test_the_recovery_runbook_*`
  naming); the new assertion ("every long flag in `globalArgParser` appears in
  `README.md`") should follow this module's existing `test_*` naming and `PROJECT_ROOT`-
  relative-path conventions, not introduce a new fixture style.
- New/updated unit tests under `tests/` — the convention (per `tests/test_app.py` mirroring
  `app.py`) is a test module name mirroring its subject module, so new tests for
  `cli_args.py`/`settings.py` behavior belong in modules named to match those subjects.

### Interface contracts

- `_redact_secrets(value)` keeps its existing signature and recursive dict/list/scalar
  dispatch; the list-branch behavior changes from "collapse whole list to one scalar
  `***REDACTED***`" to "redact per-element," each non-empty element becoming
  `scheme://***REDACTED***` (original scheme preserved via a regex capturing up to the
  first `:`/`@`, remainder masked). An empty list still renders as `[]` unchanged via the
  existing `_is_empty_secret` path — this is a behavior change only for non-empty
  list-valued secrets, not a signature change.
- `parse_args_strict()` keeps its existing signature and exit-2-on-unrecognized-arguments
  contract; it gains a wrapped error path that, on an "unrecognized arguments: X" failure,
  computes the closest registered long-flag match via `difflib.get_close_matches` and
  appends a `Did you mean '--data-path'? Try --help for full usage.`-style line to the
  existing error output before exiting — no new return value or exception type.
- Every `add_argument(...)` call in `cli_args.py` gains an explicit `metavar=` keyword
  argument; no other `add_argument` keyword (`dest=`, `type=`, `default=`, `help=`) changes.
- `_dump_settings` keeps its existing signature; its internal serialization switches from
  `jsonpickle.dumps(safe, unpicklable=False)` (single line) to an indented form (e.g.
  `json.dumps(safe, indent=2)`), with the same redacted content as input — this is purely a
  formatting change, not a change to what is logged.
  Spec: none — l3io-plan run, no spec index bound

### Error and edge case handling

- `_redact_secrets` on a list element that is itself empty/falsy: left unchanged (not
  redacted), per the existing `_is_empty_secret` per-element check already used elsewhere
  in this function — only non-empty elements get the `scheme://***REDACTED***` treatment.
- `_redact_secrets` on a list element with no `:`/`@` delimiter (no discernible scheme):
  falls back to fully masking the element (e.g. `***REDACTED***` with no prefix) rather
  than raising, so a malformed or unexpected secret-list entry never crashes the dump path.
- `parse_args_strict`'s typo-suggestion path: when no close match is found (e.g. the typo
  is too dissimilar to any registered flag), the error output omits the "Did you mean"
  line entirely rather than suggesting an unrelated flag, but still includes the
  `--help` pointer.
- `cli_args.py` metavar additions: an argument that already has an explicit `metavar=`
  (if any exist) is left unchanged, not overwritten, to avoid clobbering an intentional
  existing choice.
  Spec: none — l3io-plan run, no spec index bound

### Observability requirements

- The redaction fix directly improves operator-facing debug observability: list
  cardinality and scheme are now visible in logs without exposing the underlying secret,
  which is itself the point of this AC (BL-E011-033).
- `_dump_settings`'s pretty-print change improves log readability for anyone inspecting
  startup debug output, matching the legibility already afforded by `_dump_config`'s
  output immediately adjacent to it in the logs.
- No new logging level, correlation ID, or structured-logging field is introduced by this
  story (that is explicitly out of scope per the UX-009 non-goal above).
  Spec: none — l3io-plan run, no spec index bound

### Security considerations

- The core security-relevant guarantee is that redaction continues to prevent any raw
  token/credential value from leaking into logs, even after changing from scalar to
  per-element redaction — a test must assert no raw secret value appears in the redacted
  output.
- The `--help`/typo-suggestion improvements and metavar changes are UX-only and introduce
  no new input-validation, authentication, or data-exposure surface.
- `_dump_settings`'s pretty-print change must apply to the already-redacted `safe` object
  (post-`_redact_secrets`), never to the raw unredacted settings object, preserving the
  existing redact-before-dump ordering.
  Spec: none — l3io-plan run, no spec index bound

### Testability approach

- A new/updated test (in a module mirroring `settings.py`, per existing `tests/`
  conventions) asserts that redacting a list-valued secret preserves element count and
  that no raw token/credential substring from the input appears anywhere in the redacted
  output.
- A new/updated test invokes the CLI with a typo'd flag (e.g. `--dtaa-path`) and asserts
  the "Did you mean" suggestion text appears in captured stderr, alongside the existing
  exit-code-2 assertion for unrecognized arguments.
- `tests/ci/test_documentation.py` gains a new `test_*`-named assertion (matching its
  existing naming convention) that every long flag defined in `globalArgParser` appears in
  `README.md`, so usage text and docs cannot silently drift apart again.
  Spec: none — l3io-plan run, no spec index bound

### Existing-library check

- `difflib.get_close_matches` (Python standard library) is the existing, correct tool for
  near-match flag suggestion; it is used in preference to argparse's own
  `suggest_on_error` because that argparse feature requires Python 3.14+, and this project
  targets Python 3.11.
- `json.dumps(..., indent=2)` (standard library) is sufficient for the pretty-print fix;
  no new templating or pretty-printing dependency is introduced, matching how `_dump_config`
  already achieves legible output without an extra library beyond what's already used for
  YAML dumping.
- `argparse` (standard library, already in use) remains the CLI-parsing library; this
  story only adds `metavar=` arguments and wraps its existing error path, it does not
  replace argparse with a third-party CLI library (e.g. `click`/`typer`).
  Spec: none — l3io-plan run, no spec index bound
