# Harden privileged write/execution surfaces

## Context

Promoted from deferred finding(s):
- BL-E011-012 (High, redteam (RT-004)) — Deferred half of RT-004: the CWD logging.yaml auto-discovery RCE path was closed this sprint, but the s6 service still runs as root and /config remains an operator-writable volume feeding postexportcommand. Dropping to the LinuxServer PUID/PGID account also reduces RT-001/RT-003/RT-009. Operator-breaking image change; needs its own ADR and story. See _bmad-output/implementation-artifacts/epic-011/sprint-01/closure/redteam-report.md.
- BL-E011-016 (Medium, redteam (RT-009)) — See _bmad-output/implementation-artifacts/epic-011/sprint-01/closure/redteam-report.md
- BL-E011-019 (Medium, redteam (RT-016)) — See _bmad-output/implementation-artifacts/epic-011/sprint-01/closure/redteam-report.md
- BL-E011-009 (Medium, code-review (E011-S01-004)) — os.replace() onto a symlinked target breaks the link, where the previous Path.open("w") wrote through it. See _bmad-output/implementation-artifacts/epic-011/sprint-01/closure/review-E011-S01-004.md section 5.

## Acceptance Criteria

- The deferred finding BL-E011-012 is resolved: Service runs as root (s6-setuidgid root) and postexportcommand is RCE-equivalent config
- The deferred finding BL-E011-016 is resolved: Container restarts driven by attacker-influenced domain strings over the Docker socket
- The deferred finding BL-E011-019 is resolved: Document that the post-export hook inherits the full environment including credentials
- The deferred finding BL-E011-009 is resolved: Atomic write replaces a symlinked certificate path with a regular file instead of writing through it

## Business acceptance criteria

### Outcome

- The container no longer runs as root unless `settings.restartcontainer` is explicitly
  enabled, so a compromise of `postexportcommand` or any other in-container process cannot
  trivially pivot to host-level privilege on the common (no-restart) configuration; when root
  is retained for the Docker-socket case, the operator sees a clear startup log line
  explaining why, and what to change to drop it.
- Operators restarting labeled containers are protected from a restart storm driven by
  attacker-influenced or noisy domain strings: a container is only restarted when its own
  certificate domain actually changed, and never more than once per cooldown window,
  without the operator having to configure anything extra.
- An operator reading `docker/act-build.sh`-adjacent docs (or the relevant `docs/` pages)
  can tell, without reading source, (a) that `postexportcommand` inherits the full process
  environment including credentials, and (b) that the atomic certificate write path
  deliberately refuses to inherit metadata through a symlink, and why that refusal is
  correct rather than a bug.
- CONFIG angle (the s6 run-script and restart-gating pieces are infrastructure/runtime
  configuration, not pure application code): an operator who sets
  `restartcontainer: true` gets root + Docker-socket access automatically, with no manual
  s6 script edit, and an operator who never enables it gets automatic privilege drop with
  no manual opt-in step.
  Spec: none — l3io-plan run, no spec index bound

### Non-goals

- This story does not remove or weaken the Docker-socket-based restart mechanism itself;
  it adds change-detection and rate-limiting around it, and documents the
  docker-socket-proxy pattern as an alternative, but does not implement or require
  migrating to a socket proxy.
- This story does not change `_inheritable_metadata`'s behavior; BL-E011-009 is resolved by
  confirming (via investigation already completed) that the existing refusal to inherit
  metadata through a symlink is deliberate and TOCTOU-safe, and adding a comment/doc note
  making that explicit — not by altering the logic.
- This story does not author the ADR number itself here; a new ADR documenting the
  conditional root/privilege-drop decision (same pattern as ADR-0023 from the prior epic)
  will be authored during this story's implementation, numbered via the project's
  `docs/adr/` sequence at that time. The number is deliberately not invented in this story
  file.
- This story does not address any redteam/backlog finding other than BL-E011-012,
  BL-E011-016, BL-E011-019, and BL-E011-009.

## Technical acceptance criteria

Files this story adds or changes, and the conventions their siblings establish:
- `docker/root/etc/s6-overlay/s6-rc.d/svc-traefik-certificate-exporter/run` and
  `docker/root/etc/s6-overlay/s6-rc.d/init-traefik-certificate-exporter-config/run` — the
  existing run scripts are plain shell invoking `s6-setuidgid abc ...`; the convention to
  preserve is that privilege-dropping stays a single `s6-setuidgid` wrapper call at the top
  of the script's exec chain, not scattered conditional logic throughout the script.
- `src/traefik_certificate_exporter/libs/docker.py` (`restartLabeledContainers`) — the only
  function in this module; the convention is a single `globalLogger`-based structured log
  call per decision point, matching the rest of the codebase's module-level singleton
  logging pattern (no new logger instance).
- `src/traefik_certificate_exporter/libs/certificate_exporter.py`
  (`_inheritable_metadata`/`_atomic_write`) — comment-only change; the convention is
  docstring-level explanation directly above the function, matching the existing
  docstring style already present on neighboring functions in this module.
- A new `docs/adr/00NN-...-privilege-drop.md` (number TBD at implementation time, see
  Non-goals) following the existing ADR template (Status/Date/Deciders/Context/
  Decision/Consequences) as established by `docs/adr/0023-*.md` and `docs/adr/0028-*.md`.
- Relevant `docs/` pages (operator-facing) documenting the docker-socket-proxy pattern and
  the `postexportcommand` environment-inheritance risk, following the existing heading/
  structure conventions of `docs/operational.md`.

### Interface contracts

- The s6 run scripts gain a conditional branch keyed on `settings.restartcontainer`
  (read via the existing settings-loading mechanism available to the init script): when
  true, the service process is launched without `s6-setuidgid abc` (stays root); when
  false or unset (the default), `s6-setuidgid abc` is used exactly as today. No new
  environment variable or CLI flag is introduced; the existing `restartcontainer` /
  `--restart-container` setting is the sole input.
- `restartLabeledContainers(domains: list[str] | None)` keeps its existing signature; the
  change-detection and rate-limiting become internal behavior (e.g. an in-memory
  per-container last-restarted-domain and last-restarted-timestamp record), not new
  parameters, so existing callers are unaffected.
  Spec: none — l3io-plan run, no spec index bound

### Error and edge case handling

- s6 run scripts: if `settings.restartcontainer` cannot be read at startup (missing/
  malformed config), the script falls back to the safe default (drop privileges), not to
  staying root, and logs a WARNING explaining the fallback.
- `restartLabeledContainers`: a container with no detectable prior domain state (first run)
  is treated as "changed" (always eligible to restart on first observation); a container
  restarted within the cooldown window is skipped and logged at INFO/WARNING rather than
  silently dropped; a Docker API error restarting one container does not abort processing
  of the remaining containers in the same `domains` batch.
- `_inheritable_metadata`: no behavior change, so no new edge cases are introduced; the
  existing refusal-on-symlink edge case is preserved and now documented.
  Spec: none — l3io-plan run, no spec index bound

### Observability requirements

- Startup: a single WARNING-level log line when the service remains root, naming the
  condition (`settings.restartcontainer: true`) and the remedy (disable it to drop
  privileges).
- `restartLabeledContainers`: a log line per skipped restart (cooldown or no-change),
  identifying the container and the reason, at a level that does not spam INFO logs during
  steady-state operation (WARNING/DEBUG as appropriate to existing logging conventions in
  this module).
  Spec: none — l3io-plan run, no spec index bound

### Security considerations

- The core security property this story delivers is minimizing the attack surface of a
  root-running container to only the configuration that actually requires root
  (Docker-socket access), with that trade-off surfaced to the operator rather than silent.
- Change-detection and rate-limiting on `restartLabeledContainers` directly mitigate an
  attacker-influenced or noisy domain string from being used to trigger repeated container
  restarts (denial-of-service via restart storm) over the Docker socket.
- The docker-socket-proxy documentation gives operators a least-privilege alternative to
  mounting the raw `docker.sock`, reducing the blast radius of a container compromise even
  when `restartcontainer: true` is required.
- `_inheritable_metadata`'s existing refusal to inherit metadata through a symlink is a
  TOCTOU-safe control; this story's comment/doc addition exists specifically to prevent a
  future contributor from "fixing" it into a vulnerability.
  Spec: none — l3io-plan run, no spec index bound

### Testability approach

- s6 run-script privilege-drop conditional: covered by a script-level test or, if the
  project's test suite does not yet exercise shell scripts, a manually documented
  verification procedure recorded in the story's implementation notes — the test suite
  under `tests/` has no existing precedent for testing shell/s6 scripts directly, so new
  coverage here may be procedural rather than `pytest`-based.
  N/A — no existing automated-test convention for s6/shell scripts in this repository;
  verification is manual/documented rather than a new pytest module.
- `restartLabeledContainers` change-detection and rate-limiting: unit tests alongside the
  existing test-module naming convention (a `tests/test_docker*.py`-style module mirroring
  the `libs/docker.py` subject, matching how `tests/test_app.py` mirrors `app.py`), using
  mocked/faked Docker client calls to isolate from a real Docker daemon.
  Spec: none — l3io-plan run, no spec index bound

### Existing-library check

- Privilege dropping: `s6-setuidgid` (already vendored via the linuxserver.io s6-overlay
  base image) is the existing, correct mechanism — no new tool is introduced; this story
  only makes its use conditional.
- Container restart rate-limiting: no existing library in this codebase's dependency set
  provides this; the `docker` Python SDK (already a dependency, used in `libs/docker.py`)
  has no built-in debounce/rate-limit primitive, so a small bespoke in-memory tracker is
  warranted here rather than pulling in a new dependency for a narrow, stateful,
  process-local need.
  Spec: none — l3io-plan run, no spec index bound

## Implementation notes

### Verification of the s6 run scripts

The scripts cannot be executed outside the image (`with-contenv`, s6 tooling and
`/app/.venv` are all image-only), so coverage is split:

- `tests/test_s6_privilege_drop.py` extracts the init script's embedded resolver and runs it
  against the real `SettingsManager`, asserting the privilege decision, the resolved
  output/data paths and filespec, and the failure behaviour of a malformed config. It also
  asserts the shell properties that make the fallback safe (safe default written first,
  stale answer removed, missing state file reads as drop, symlink-safe `chown`, `HOME`
  exported before the exec).
- `shellcheck -s bash` passes on both scripts.
- Not covered automatically: an actual container start. The dropped-privilege path depends
  on image facts (`HOME=/root` mode `0700`, `abc` = uid 911, `lsiown` semantics) that only a
  built image exercises. A published-image smoke test that starts the image with
  `restartcontainers: false` and asserts a successful export would close this and is worth
  a follow-up story.

### Divergence from the business acceptance criteria

The business AC asks that "a container is only restarted when its own certificate domain
actually changed". That was implemented and then reverted during the fix round: a drain pass
reports every domain it exported, and a renewal keeps the domain name while replacing only
the key material, so name-based change detection restarts each labeled container exactly
once per exporter process lifetime and never again — it breaks the feature it was meant to
refine. Only the per-container 300 s cooldown remains, which is what BL-E011-016 (restart
storm over the Docker socket) actually requires. Precise filtering needs a per-domain
certificate fingerprint from the export path and is recorded as `BL-E012-008`.

### Deferred

- `BL-E012-008` (Medium) — fingerprint-based restart filtering, as above.
