## Finding 1 — Low — Wrapper exits 0 on a failed `act` run; the new runbook section does not say so

**File:** `docs/operational.md:425-455` (new "What a local `docker/act-build.sh` run reports" section)
**Trigger condition:** `docker/act-build.sh:71-76` pipes `act ... | tee "$REPO_ROOT/act-build-...log"`
with no `pipefail` guarding that pipeline, so the script's exit status is `tee`'s — the very run this
story documents ("completed, failed" at `actions/checkout`) would have returned status 0. The new
section tells an operator to "read the transcript rather than assuming the environment is broken"
but never warns that the exit code is not a signal, so an operator (or any wrapper around the
wrapper) that checks `$?` reads a definitive failure as success.
**Concrete fix:** add one sentence to the new section stating that the wrapper's exit status
reflects `tee`, not `act`, and that the transcript is the only outcome signal. (Fixing the script
itself is out of this story's scope by its own ACs.)
**kind:** claim — **confidence:** high (verified by reading `docker/act-build.sh`; the pipeline has
no `set -o pipefail` at the invocation).
