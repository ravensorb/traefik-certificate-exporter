# Repo governance: pre-commit tracked-file coverage and vendored-tree integrity

## Context

Promoted from deferred finding(s):
- BL-E000-001 (Medium, post-restore audit) — pre-commit --all-files enumerates git ls-files, so any gate reports green over a set that excludes untracked work. This first appeared when the whole E007 delivery was untracked and every gate skipped it. It recurred on 2026-09-01 against a brand-new mypy gate: the gate passed a deliberately planted type error because src/publication_contract/ had not been staged. It recurred a third time on 2026-09-04 during the BL-E008-010 split: tests/ci/test_gates.py was written, run green under `pre-commit run --all-files`, and shipped with an undefined `Any` -- the file was untracked, so ruff never read it. Three times the gate looked green while checking nothing, and each time the file at fault was new. There is no mechanical guard for this -- the practical rule is to `git add` before trusting an --all-files result, and to prove any new gate with a planted violation rather than a green run. Worth considering a repo-level check that fails when tracked-vs-untracked coverage diverges.
- BL-E008-009 (Low, sprint closure — redteam M6) — docs/guidelines.md describes .agents/ and .claude/ as vendored BMad skills 'this project neither authors nor maintains'. That is a checkable claim and it is unchecked: 1,229 tracked files that any pull request can edit, excluded from every linting gate by .pre-commit-config.yaml's exclude and from the secret scanner by .gitleaks.toml's allowlist, in a repository whose agents hold write access and are instructed to read them and follow their directions exactly. Sprint closure addressed the review half by adding them to CODEOWNERS. The integrity half remains: a guard asserting the trees are byte-identical to the release they claim to vendor. Deliberately not done in closure -- it needs a source of truth for 'the installed release' that does not exist in the repo yet, and inventing one would be worse than the gap.

## Business acceptance criteria

### Outcome

- An agent or human running `pre-commit run --all-files` can trust a green result: the
  gate either covers every tracked-vs-untracked file, or fails loudly when they diverge,
  closing the three-times-recurring false-green pattern BL-E000-001 documents.
- A reviewer or auditor can check the standing claim in `.github/CODEOWNERS`'s header
  comment (per ADR-0027 — not `docs/guidelines.md`, which contains no independent
  description of these trees) that the vendored `.agents/`/`.claude/` trees match "an
  installed BMad release" against a mechanical check, rather than trusting prose
  (BL-E008-009's integrity half).

Spec: none — l3io-plan does not pass a spec index

### Non-goals

- Does not remove or relax the existing `exclude: '^(\.agents|\.claude|_bmad)/'` pattern
  in `.pre-commit-config.yaml` — linting those trees is a separate, already-decided
  policy (recorded in that file's own header comment and BL-E002-002's incident), not
  something this story revisits.
- Does not invent a new "installed BMad release" registry/manifest from nothing.
  BL-E008-009's own text says doing so "would be worse than the gap" if there is no
  existing source of truth; this story only wires a check against a source of truth if
  one already exists in `.claude/`/`.agents/` metadata (e.g. a version marker file), or
  otherwise records the still-missing source of truth explicitly rather than fabricating
  one.
- Does not add a general-purpose "untracked file" linter across the whole repository
  tree beyond what's needed to catch pre-commit's own `--all-files` coverage gap.
- Does not change CODEOWNERS further; the review half of BL-E008-009 is already closed
  (`.agents/`, `.claude/`, `.github/agents/` are already owned entries in
  `.github/CODEOWNERS`).

## Technical acceptance criteria

### Interface contracts

- Files touched/added, and conventions their siblings set:
  - A new check, most naturally a `repo: local` hook in `.pre-commit-config.yaml`
    alongside the existing `poetry-lock`/`justfile-fmt`/`workflow-policy` local hooks —
    same `language: system`, `always_run: true`, `pass_filenames: false` shape as
    `workflow-policy`'s entry.
  - Its logic (comparing `git ls-files` output against the working tree, or similar)
    belongs in `tests/ci/` as a new `test_gates.py`-style function (e.g.
    `test_tracked_and_untracked_coverage_do_not_diverge`), following the exact
    descriptive-sentence test-name convention already used in that file
    (`test_the_secret_scanner_and_pre_commit_exclude_the_same_vendored_trees`,
    `test_every_gate_runs_in_ci_or_is_recorded_as_local_only`).
  - If a vendored-tree integrity check is added, it is a new function in `test_gates.py`
    or a new sibling test module under `tests/ci/`, not a shell script — every existing
    gate-governance check in this repo is a pytest assertion over file content, and
    `workflow-policy`'s hook already runs `pytest -q tests/ci` as its entry point, so a
    new pytest function is picked up for free with no `.pre-commit-config.yaml` change.
  - `.github/CODEOWNERS` — update the header comment's "vendored skills, not maintained
    by us" framing (the paragraph beginning "Agent instructions. Tooling is told to
    'READ its entire contents and follow its directions exactly'...") to either cite the
    new check, or explicitly record that no "installed release" source of truth exists
    yet (see Non-goals). Per ADR-0027, this passage — not anything in
    `docs/guidelines.md` — is the one that actually frames `.agents/`/`.claude/` as
    vendored, unmaintained-by-this-project trees; `docs/guidelines.md` was verified to
    contain no independent description of these trees (its only mention of `.agents/`
    is an unrelated relative link, not descriptive prose), so it is not touched by this
    bullet.
- No new CLI flags, function signatures exposed to other modules, or data-model changes
  — this is a CI-governance addition, scoped the same way existing `tests/ci/` checks are
  (asserting over repo file state, not application code).
  Spec: none — l3io-plan does not pass a spec index

### Error and edge case handling

- The tracked-vs-untracked coverage check must itself not produce a false green: it must
  fail when a new file is `git add`-ed but not yet linted in the same run (replicating
  BL-E000-001's third recurrence — `tests/ci/test_gates.py` itself was untracked when
  first authored) — a planted untracked file in a throwaway branch is the natural
  regression test, matching how `test_the_secret_scanner_reads_content_rather_than_the_index`
  already proves its own gate with a planted leak rather than a clean run.
- Must not fail on legitimately-gitignored build artifacts (`__pycache__/`, `.venv/`,
  `dist/`) — the check is tracked-vs-untracked-and-not-ignored, not tracked-vs-every-file-
  on-disk; use `git status --porcelain --ignored=no` semantics (porcelain already
  excludes ignored files by default) rather than a raw directory walk.
- If no "installed BMad release" source of truth exists, the vendored-tree check must
  fail closed (loudly state the gap) rather than silently passing — matching
  BL-E008-009's instruction that an unchecked claim is worse than an absent one.

Spec: none — l3io-plan does not pass a spec index

### Observability requirements

- A coverage-divergence failure must name the specific untracked file(s) responsible, not
  just "coverage diverged" — actionable output is what turns this from a passive gate
  into the practical `git add` reminder BL-E000-001's own suggested fix describes.
  Spec: none — l3io-plan does not pass a spec index
- N/A beyond pytest's existing failure-message mechanism — this is a local/CI gate, not a
  running service; no logs, metrics or traces beyond the test's own assertion message
  apply.

### Security considerations

- The vendored-tree integrity check, if it compares against an external reference (e.g. a
  pinned BMad release tag or upstream checksum), must not fetch that reference over the
  network during `pre-commit run --all-files` — matching this repo's existing pattern of
  hermetic, offline-runnable gates (`tests/ci` runs with no network dependency today).
  If no offline reference exists, record that limitation rather than adding a network
  call.
- A coverage-divergence check that walks `git status` must not itself read or log file
  *contents* for files under `.agents`/`.claude` — path/hash comparison only, consistent
  with `.gitleaks.toml`'s explicit allowlisting of those trees from content scanning.

Spec: none — l3io-plan does not pass a spec index

### Testability approach

- Lives in `tests/ci/`, proven the same way every other gate in that package is proven:
  a planted-violation test (an untracked file that should have failed a gate) rather than
  a green run, per this repo's own stated rule ("prove any new gate with a planted
  violation rather than a green run" — BL-E000-001's own text).
- `tests/ci/conftest.py` and `tests/ci/support.py` already provide fixtures for repo-root
  discovery and workflow-file loading used by sibling tests; reuse them rather than
  re-deriving `git rev-parse --show-toplevel` logic ad hoc.

Spec: none — l3io-plan does not pass a spec index

### Existing-library check

- `git status --porcelain` (or `git ls-files` vs. `git ls-files --others --exclude-standard`
  diffed) is the existing, already-available mechanism for tracked/untracked divergence —
  no custom file-walking or hashing library is warranted for that half.
- For vendored-tree integrity, if BMad ships any manifest/version file inside
  `.agents/`/`.claude/` already, a hash comparison against it is preferable to adding a
  new dependency (e.g. `deepdiff`) — check for one before deciding none exists.

Spec: none — l3io-plan does not pass a spec index

## Files in scope

- `.pre-commit-config.yaml` — where the new `repo: local` coverage hook lands, alongside the existing `poetry-lock`/`workflow-policy` local hooks; also holds the `^(\.agents|\.claude|_bmad)/` exclude this story must not relax
- `tests/ci/test_gates.py` — the established home for gate-governance assertions; both the tracked-vs-untracked coverage check and the vendored-tree integrity check belong here (the `workflow-policy` hook already runs `pytest -q tests/ci`, so no hook wiring is needed for them)
- `tests/ci/conftest.py` — repo-root discovery fixtures; reuse instead of re-deriving `git rev-parse --show-toplevel`
- `tests/ci/support.py` — shared config/workflow loading helpers used by sibling `tests/ci` modules
- `tests/ci/test_meta.py` — asserts over the gate suite's own shape; likely to need updating when a new gate is added
- `.github/CODEOWNERS` — per ADR-0027 the one place framing `.agents/`/`.claude/` as vendored trees; its header comment is what this story amends to cite the new check or record the missing source of truth
- `.gitleaks.toml` — allowlists the vendored trees from content scanning; read to keep the new check path/hash-only and consistent with `test_the_secret_scanner_and_pre_commit_exclude_the_same_vendored_trees`
- `docs/adr/0027-vendored-tree-framing-lives-in-codeowners.md` — the decision that routes the framing claim to CODEOWNERS rather than `docs/guidelines.md`
- `.agents/`, `.claude/` — the vendored trees themselves; inspected read-only for an existing version/manifest marker that could serve as the integrity source of truth
- `docs/guidelines.md` — read-only confirmation that it carries no independent description of these trees (per ADR-0027); explicitly *not* edited

## Dev Agent Record

### Completion notes

- **Coverage gate (BL-E000-001).** `test_no_file_escapes_every_gate_by_never_having_been_added`
  in `tests/ci/test_gates.py`, over `git status --porcelain -z --untracked-files=all`,
  filtered by the `exclude:` pattern read from `.pre-commit-config.yaml` (derived, not
  restated). Porcelain omits ignored files, so `__pycache__/`, `.venv/` and `dist/` are
  out by construction. The failure names each stranded file. Proven twice: a real-repo
  planted untracked file, and `test_the_coverage_guard_catches_a_file_planted_in_a_real_repository`,
  which builds a throwaway git repo and asserts the ignored artifact, the excluded tree
  and the staged-but-uncommitted file are all *not* reported.
- **It found a live instance on first run**: seven untracked files, including
  `docs/adr/0024`–`0027`, were in the working tree and read by no gate. Applied the
  remedy the gate prescribes — `git add --intent-to-add` (index only, nothing committed).
  That made `docs/adr/0027` visible to the existing documentation gate, which then
  failed on a dead relative link inside it (`../.agents/...` resolves from `docs/adr/`,
  not `docs/`). Fixed in place by respelling the quoted citation so it is no longer
  Markdown link syntax — a defect surfaced by this change, so repaired here.
- **Vendored-tree integrity (BL-E008-009).** A source of truth *does* exist and was not
  invented: each `payload-manifest.json` under `.agents/skills/*/` and `.claude/skills/*/`
  declares a release version and a SHA-256 per file (142 entries across both trees, all
  matching). `test_the_vendored_trees_match_the_manifests_their_installer_shipped`
  verifies them; it is offline and reads no file as text.
  `_bmad/_config/files-manifest.csv` was evaluated and rejected as the reference: 1,187
  of its 1,214 rows name paths that do not resolve in this layout.
- **The gap is recorded, not papered over.** 74 of 82 skills per tree ship no manifest.
  `test_the_vendored_trees_are_byte_identical_copies_of_each_other` pins those by the two
  copies pinning each other, and
  `test_the_vendored_integrity_guard_records_what_it_cannot_verify` fails if
  `.github/CODEOWNERS` stops stating the limitation. CODEOWNERS's header (per ADR-0027,
  not `docs/guidelines.md`, which was not touched) now says which half is checked and
  which is review-only.
- **Fix round (review-E011-S01-002).** The High finding was correct: a
  `payload-manifest.json` records the shared payload copied into a skill
  (`generated_from: skills/_shared/`), not the skill's contents, so "a SHA-256 per
  file" and the skill-granular caveat overstated coverage by ~16x. Coverage is now
  counted in files by `_manifest_coverage()`: 142 of 2,364, leaving 2,222 pinned only
  by the two trees mirroring each other. CODEOWNERS states those three numbers and
  `test_the_vendored_integrity_guard_records_what_it_cannot_verify` recomputes them, so
  the prose cannot drift from the trees — including when a file is *added* inside a
  manifested skill, which the manifest-as-whitelist iteration never saw. The Medium
  finding follows from the same change: the gap now closes only when every vendored
  file is named by some manifest, so a future release shipping a manifest in every
  skill can no longer force the caveat to be deleted while most files stay unhashed.
- **Staged-file AC, on the record (Low finding, deferred to backlog).** The
  Error-and-edge-case AC's literal wording ("must fail when a new file is `git add`-ed
  but not yet linted") is not what the guard does, deliberately: `pre-commit run
  --all-files` enumerates `git ls-files`, which includes staged files, so reporting one
  would cry wolf at the moment the problem was fixed. The untracked case the AC's own
  parenthetical describes is the one implemented.
- **No new pre-commit hook.** `workflow-policy` already runs `poetry run pytest -q tests/ci`
  both locally and in CI, so the two gates are picked up for free; adding a second hook
  would duplicate the entry point and need its own CI wiring. The config change is a
  comment on that hook recording what it now carries. The `exclude:` pattern was not
  relaxed.
