# Harden local CI verification and release-evidence capture

## Context

Promoted from deferred finding(s):
- BL-E007-002 (Medium, post-restore audit (E007)) — The local verifier path has never completed successfully. The one attempt on 2026-09-01 destroyed the working tree and all local commits: ~/.actrc sets --bind so act mounts the real repository as the container workspace, and verify-build.yaml's actions/checkout deletes the workspace contents before discovering it cannot fetch the pinned ref. docker/act-build.sh now runs act inside a disposable clone with --no-hardlinks, refuses to proceed unless the clone resolves elsewhere, and is pinned by test_local_wrapper_never_runs_act_against_the_working_tree. That makes the path SAFE but still UNPROVEN -- no successful run exists. Closing this needs an actual green run whose result is retained. Note the clone verifies HEAD, not the dirty working tree, which is what CI verifies anyway.
- BL-E007-004 (Low, post-restore audit (E007)) — docker-bake.hcl defaults ATTESTATIONS to [] and verify-build.yaml neither enables type=sbom/type=provenance nor scans the built image, in an epic whose subject is reproducible build and verification. The Docker standards overlay is a stub, so this is provisional guidance rather than a hard rule. Decide explicitly -- enable attestations on the verified build, or record in ADR-0008 why they are deferred to the publication epic.

**Reconciliation note (2026-10-06, story review before commit):** this story originally also
carried BL-E007-003 and BL-E008-008. Both were found already resolved by prior work predating
this epic and were pulled back out:
- BL-E007-003 — resolved `fixed`, ref `df6e5ed`: the GitHub-side run-correlation evidence this
  finding asked for is already fully documented in `docs/operational.md`'s "What the run summary
  reports (CI-AR41)" section. The only remaining half (the pinned Gitea tuple) was rescoped out
  of Epic 9 (live-Gitea certification dropped).
- BL-E008-008 — resolved `deferred`: already fully decided and documented at E008 closure
  (commit `e064f16`). Required reviewers declined; trusted-publisher environment claim accepted
  but latent until PyPI publishing is enabled (an external settings change, not repo work).

## Business acceptance criteria

### Outcome

- An engineer can run `docker/act-build.sh` locally and get a completed (pass or fail)
  verifier run against the disposable clone, with the transcript retained on disk —
  closing BL-E007-002's "SAFE but still UNPROVEN" gap with an actual recorded result
  instead of a theoretical safety argument.
  Spec: none — l3io-plan does not pass a spec index
- The maintainer has made and recorded an explicit, reviewable decision about build
  attestations (enable them on the verified build, or defer with a stated reason) rather
  than leaving `ATTESTATIONS` defaulted to `[]` by omission (BL-E007-004).
  Spec: none — l3io-plan does not pass a spec index

### Non-goals

- Does not touch BL-E007-003 or BL-E008-008 — both were reconciled out of this story during
  review (2026-10-06): BL-E007-003's GitHub-side half is already implemented
  (`docs/operational.md`'s CI-AR41 section, commit `df6e5ed`) and its Gitea-side half was
  rescoped out of Epic 9; BL-E008-008 was already fully decided and documented at E008
  closure (commit `e064f16`), with the remaining action gated on an external, not-yet-taken
  event (enabling PyPI publishing).
- Does not add SBOM/provenance attestation to the PyPI publish path or any path other
  than the verified Bake image build.
- Does not change `~/.actrc` or any other out-of-repo local developer environment file;
  the safety fix is already in `docker/act-build.sh`, this story only proves it runs.

## Technical acceptance criteria

### Interface contracts

- Files touched/added, and the conventions their siblings already set:
  - `docker/act-build.sh` — no required signature change; only a successful invocation
    and retained log are needed. The existing `tee "$REPO_ROOT/act-build-traefik-certificate-exporter.log"`
    is already the retention mechanism — commit or otherwise archive one real log instead
    of adding a second one.
  - `docker-bake.hcl` — if attestations are enabled, change only the `ATTESTATIONS`
    variable's default or the caller that sets it (`.github/workflows/verify-build.yaml`'s
    Bake invocation); do not add a new variable, matching the existing
    `OUTPUTS`/`PLATFORMS` pattern of one list-typed variable per build knob.
  - `docs/adr/0008-exact-wheel-image-provenance.md` — if attestations are deferred
    rather than enabled, record the decision as a new "Amended at \<date\>" subsection,
    inserted (like the existing "Amended at E008 sprint closure" subsection at line 107)
    after `## Decision` and before `## Consequences` — that is the file's existing
    amendment position, not after `## Consequences` (do not open a new ADR for this —
    BL-E007-004 names ADR-0008 explicitly as the place to record it).
  - `tests/ci/` — any new assertion (e.g. that the verifier's Bake call passes a non-empty
    `ATTESTATIONS` list, or that the pypi-environment doc section exists) follows the
    existing one-module-per-topic layout (`test_certification.py`, `test_gates.py`,
    `test_action_policy.py`); do not add a new top-level test package.
- `act-build.sh`'s output is unstructured log text, not a machine-readable contract —
  no new interface is introduced by proving it runs.
  Spec: none — l3io-plan does not pass a spec index

### Error and edge case handling

- `act-build.sh` must still refuse to proceed (exit non-zero, no mutation) if the
  disposable clone resolves back to the real repository — this story proves the happy
  path runs green, it must not regress the existing `CLONE_ROOT = REPO_ROOT` guard
  covered by `test_local_wrapper_never_runs_act_against_the_working_tree`.
  Spec: none — l3io-plan does not pass a spec index
- If the local Act run fails for a reason unrelated to this story (e.g. a missing
  `-P ubuntu-24.04=...` runner image not yet pulled), the failure and its cause must be
  captured in the retained log, not silently discarded — an "unproven" run that fails
  for an environmental reason is itself useful evidence and must say why.
  Spec: none — l3io-plan does not pass a spec index
- If attestations are enabled and the Bake build fails under `type=sbom`/`type=provenance`
  (e.g. an unsupported `OUTPUTS` combination — Docker only supports multi-attestation
  output with certain exporters), the verifier must fail loudly rather than silently
  drop the attestation, since BL-E007-004's whole point is an explicit decision, not a
  best-effort one.
  Spec: none — l3io-plan does not pass a spec index

### Observability requirements

- The retained local Act log (or its summary) must record the source SHA and package
  version exactly as `act-build.sh` already echoes them, so a reviewer can tell which
  commit the "first successful run" evidence corresponds to.
  Spec: none — l3io-plan does not pass a spec index
- N/A for attestation decision itself — a documentation/ADR entry is not an observability
  surface in the logging/metrics sense.

### Security considerations

- `act-build.sh` passes no credentials into the Act container (already true, per its own
  comment on secret-free verification matching ADR-0007) — this story must not introduce
  any credential into the local-run path while proving it green.
  Spec: none — l3io-plan does not pass a spec index
- If attestations are enabled, confirm no additional registry credential or scope is
  required beyond what `docker/Dockerfile`'s existing build identity already holds —
  SBOM/provenance attestation via Buildx is computed locally and attached to the
  manifest list, it does not need a new credential.
  Spec: none — l3io-plan does not pass a spec index

### Testability approach

- A successful (or definitively-failed-with-cause) local Act run is evidence captured
  outside `pytest` — it cannot be asserted by a unit test since it requires a real Act
  binary and Docker daemon. Record it as a committed log excerpt or a note in
  `docs/operational.md` with the run's source SHA, consistent with how BL-E007-002's
  context frames closure ("needs an actual green run whose result is retained").
  Spec: none — l3io-plan does not pass a spec index
- The attestation decision (enable vs. defer) is testable: if enabled, a `tests/ci/`
  assertion over `verify-build.yaml`'s Bake invocation (mirroring the existing
  `test_certification.py` / `test_action_policy.py` pattern of asserting workflow YAML
  shape) must confirm `ATTESTATIONS` is non-empty; if deferred, a test asserting
  `docs/adr/0008-exact-wheel-image-provenance.md` contains the dated amendment section
  is sufficient and matches `test_the_python_formatter_never_rewrites_a_markdown_record`'s
  existing style of asserting against doc content.
  Spec: none — l3io-plan does not pass a spec index

### Existing-library check

- No new library is warranted. `docker/act-build.sh` already uses `git clone --local
  --no-hardlinks` + `mktemp -d` for the disposable clone (stdlib/coreutils); this story
  only needs to execute it, not rebuild it.
  Spec: none — l3io-plan does not pass a spec index
- Buildx's native `--provenance`/`--sbom` flags (surfaced here via Bake's `attest`
  attribute, already wired in `docker-bake.hcl`) are the existing facility for
  BL-E007-004 — no custom SBOM/provenance generator should be hand-rolled.
  Spec: none — l3io-plan does not pass a spec index
