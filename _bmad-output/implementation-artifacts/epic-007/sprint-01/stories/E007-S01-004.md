# Build and Prove One Promotable Artifact Set

As a release maintainer,
I want one verified wheel/sdist and one matching multi-architecture image manifest,
So that every destination receives artifacts proven to originate from the same source and
dependency lock.

Depends on: `E007-S01-002`, `E007-S01-003`.

## Acceptance Criteria

**Given** verification runs for a source SHA and planned package version
**When** package build completes
**Then** exactly one wheel and one sdist are built and hashed
**And** the wheel installs in an empty environment and the CLI reports the planned version
(CI-AR13)

**Given** package evidence is valid
**When** the image build runs
**Then** it installs the exact verified wheel and builds `linux/amd64` and `linux/arm64`
**And** the final OCI index contains both descriptors (CI-AR14, CI-AR16)

**Given** either platform image is inspected or smoke-tested
**When** its installed Python distribution is queried
**Then** version, source label, and wheel identity agree with `build-manifest.json`

**Given** any lint, test, package, hash, platform, or smoke check fails
**When** the reusable workflow completes
**Then** no artifact is marked promotable and downstream publication is impossible

## Technical Acceptance Criteria

### Build graph and artifacts

- The verifier has explicit jobs for source/version validation, Python quality/tests, package
  build/install verification, image build/test, and evidence finalization.
- Package jobs use the repository's selected Python/Poetry versions and `poetry.lock`; lock
  validation occurs before build.
- Distribution artifact `verified-dist-v1` contains exactly wheel, sdist, `SHA256SUMS`, and
  build manifest in a documented directory layout with 30-day retention (CI-AR31).
- Image construction receives the verified distribution artifact; it does not run `poetry
  build`, copy the full development virtualenv, or resolve an unpinned dependency graph.

### Multi-architecture contract

- QEMU is configured before Buildx; Buildx requests exactly `linux/amd64,linux/arm64`.
- Verification produces/inspects an OCI layout or temporary registry identity without making a
  public destination mutation.
- The recorded index digest is canonical and platform descriptors include OS, architecture,
  manifest digest, and expected config/source labels.
- Both platform images pass an entrypoint/help/version smoke test appropriate to the s6 image.

### Error handling and reproducibility

- A missing/extra distribution, mismatched checksum, non-canonical wheel filename, or wrong
  metadata version is fatal.
- A missing platform, duplicate platform, wrong OS/architecture, or digest change between
  verification phases is fatal.
- Cache restore/save may improve speed but never supplies the manifest evidence or bypasses a
  required check.
- The evidence finalizer runs only when every prerequisite is successful; partial evidence is
  clearly labeled non-promotable if retained for diagnostics.

### Observability and security

- Job summaries report source SHA, version, distribution hashes, platforms, index digest, and
  smoke-test outcomes without dumping environments or image history containing secrets.
- The build accepts no publisher tokens and performs no Docker/PyPI login.
- Docker build secrets, if ever required for dependency access, use BuildKit secret mounts and
  are excluded from layers and evidence; the initial implementation should require none.

### Test anchors

- Tests alter the wheel after hashing and require image-build refusal.
- Tests inject wrong package metadata, wrong source label, missing sdist, and extra distribution.
- OCI fixture tests cover correct two-platform index, single-platform index, wrong architecture,
  and manifest-digest mismatch.
- Workflow tests prove all publisher-capable adapters can consume only the finalized verified
  artifacts, not intermediate job directories.
- A reproducibility check rebuilds identical source in the supported environment and compares
  distribution hashes or documents/validates any remaining nondeterministic field.

## Deliverables

- Completed `verify-build.yaml` implementation.
- Exact-wheel Docker build path and platform verification.
- Promotable evidence bundle plus workflow/unit/integration tests.

## Out of Scope

- Registry login/push and package index upload (Epic 8).
