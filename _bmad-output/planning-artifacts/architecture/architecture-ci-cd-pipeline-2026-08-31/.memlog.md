- (constraint) Existing spine CI-AR2 requires one workflow graph across GitHub Actions/Gitea Actions/local act with no step branching on ACT; CI-AR33 requires local act testing via disposable clone + synthetic inputs, never rewriting developer worktree. These two together are in direct tension with the act/checkout friction that triggered this redesign (verified empirically: actions/checkout always recomputes repository URL from inputs and wipes/reinits the workspace on any mismatch with the recorded origin remote; the only no-op path is act's own built-in skip when a checkout step's with: has no ref: key at all).
- (constraint) just check (lint+pytest) gates just release, not test-local/act-build.sh; act-build.sh is a separate, non-blocking full-CI-parity recipe (covers gitleaks/actionlint/file-hygiene/source-integrity/distribution build that just check does not).
- (constraint) Current pipeline complexity inventory (2026-10-08): 5 workflow files, 3638 total lines, 23 actions/checkout call sites, release.yaml=1458 lines/9 jobs, dev.yaml=848 lines/8 jobs, verify-build.yaml=732 lines/10 jobs, publish-image.yaml=520 lines/1 job, ci.yaml=80 lines/2 jobs. Channels (ci/dev/stable) fan out across 4 entry points each re-deriving version/registry/tag logic.
- (decision) Binds: every actions/checkout step in ci.yaml, dev.yaml, release.yaml, verify-build.yaml. Rule: no checkout step anywhere in the pipeline ever supplies ref:/repository:/any identity-overriding input; every checkout uses plain default/ambient event-derived checkout (only fetch-depth/fetch-tags/persist-credentials remain). Prevents: host-conditional branching (ACT or any custom flag), destructive-checkout failures under local act for unpushed commits, N-times-duplicated ref plumbing. CI-ARnext (to be numbered CI-AR42 at distillation).
- (decision) Binds: ci.yaml's verify path (channel=ci). Rule: PR verification tests the GitHub-synthesized merge-with-base commit (default pull_request checkout target), not an explicitly pinned PR head SHA; no job computes or asserts github.event.pull_request.head.sha anywhere. Prevents: reintroducing GitHub-API-derived PR-head plumbing. Accepts as a known, bounded risk: a long-running PR verification run's jobs could in principle see the merge ref recomputed if the base branch moves mid-run (narrow, accepted trade-off, not engineered around via a single-checkout artifact).
- (decision) Binds: verify-build.yaml's input contract. Rule: source-sha is removed as a workflow_call/workflow_dispatch input entirely; each job that needs it (source-integrity, distribution) discovers it via git rev-parse HEAD post-checkout and emits it only as an output for evidence/build-manifest purposes. package-version becomes optional (required: false): dev.yaml/release.yaml supply their computed expected version for cross-validation against the built wheel; ci channel omits it and the distribution job reads the committed pyproject.toml version directly.
- (decision) Binds: ci.yaml. Rule: ci.yaml collapses to a single job -- no separate plan job -- that calls verify-build.yaml with only channel: ci. Prevents: a redundant pre-checkout/pre-validation stage now that verify-build.yaml self-discovers identity and the committed version.
- (decision) Binds: dev.yaml, release.yaml. Rule: both retain their plan jobs (genuine dev-distance version derivation and stable-tag validation are real, channel-specific work that must stay there), but no job in either file re-threads ref: to a previously-computed identity (e.g. stable-tag-guard, attest, and other downstream jobs drop ref: needs.plan.outputs.source-sha and just rely on default checkout, since github.sha is immutably fixed for the whole run on push/tag triggers -- zero drift risk).
- (decision) Amends CI-AR2 (generalizes it, does not weaken it): the existing 'no step branches on ACT' invariant is preserved and strengthened into 'no step branches on host, channel, or any other dimension for checkout identity purposes' -- this redesign achieves zero conditional checkout logic anywhere by construction, a strictly stronger guarantee than the prior ACT-specific wording.
- (decision) Binds: docker/act-build.sh. Rule: the disposable-clone wrapper is retained as cheap CI-AR33 defense-in-depth (insurance against a future regression reintroducing a ref: somewhere), but is no longer load-bearing for the original failure mode -- with zero ref: anywhere in the pipeline, every job hits act's built-in no-ref no-op checkout path automatically, for every channel, with no custom LOCAL_VERIFY-style flag needed.
- (event) Redesign converged after live empirical investigation (see session history): ruled out git-URL-rewrite/insteadOf tricks (reproduced the exact 2026-09-01 destructive-checkout incident in a /tmp sandbox), ruled out env.ACT-based branching (Gitea's own runners are act-based too, so ACT doesn't distinguish local-from-production), ruled out a custom LOCAL_VERIFY env flag (still host-conditional branching, in tension with CI-AR2's spirit), and ruled out a single-checkout+artifact-fanout design (solves duplication and PR-merge-ref drift, but user explicitly accepted the narrow drift risk in favor of maximum uniformity -- zero ref: anywhere, full stop).
- (event) Distilled: ARCHITECTURE-SPINE.md updated in place (revision ref-free-checkout, 2026-10-08) -- CI-AR2 amended, CI-AR33 clarified, CI-AR42-CI-AR46 added, verify-build.yaml input-contract sentence corrected. New ADR-0028 (docs/adr/0028-ref-free-checkout-across-ci-cd.md) drafted documenting full rationale, rejected alternatives, and accepted trade-offs.
- (event) Reviewer gate (rubric walker, web-research lens, adversarial lens) run as 3 parallel subagents. Findings triaged: (1) CRITICAL confirmed and fixed -- publish-image.yaml's own ref: inputs.source-sha checkout was missed in the original 4-file scope; CI-AR42 and ADR-0028 now correctly scope all 5 files (ci/dev/release/verify-build/publish-image), with its source-sha/package-version inputs clarified as assertion-only (not checkout pins), unchanged. (2) HIGH enforceability gap fixed -- CI-AR42's rule and the planned contract test now also forbid indirect re-pinning (manual git fetch/checkout/reset-hard after a ref-free checkout, env-indirected ref: expressions, nested re-checkout composites), not just a literal with: ref: key. (3) MEDIUM timing ambiguity fixed -- CI-AR44 now specifies git rev-parse HEAD runs as the immediate next step after checkout in every job that needs it, before any other step. (4) MEDIUM package-version optional-semantics ambiguity fixed -- CI-AR44 now specifies omission of the with: key (never an empty string) as the contract. (5) CRITICAL act-no-op-checkout claim disputed by the web-research lens was re-verified via a fresh live side-by-side reproduction in a disposable /tmp sandbox on 2026-10-08 (not just re-reading docs): ref:-bearing checkout step genuinely executes, deletes the workspace, and fails to fetch an unpushed SHA from the real remote; sibling ref:-free step in the same job set is skipped via plain docker cp in <40ms -- for both actions/checkout@v4 and @v7. Original claim stands; reviewer's dispute rejected with cited counter-evidence. verify-build.yaml's own CI-AR36 assertion-value data flow (source-sha/package-version continuing to reach publish-image.yaml and destination jobs as plain data, never as checkout refs) is now explicit in both the spine and ADR-0028, closing the HIGH concern about CI-AR15/CI-AR36 being silently weakened.
