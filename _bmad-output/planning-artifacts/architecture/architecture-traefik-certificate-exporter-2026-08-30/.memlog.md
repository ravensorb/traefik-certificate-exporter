- (decision) Maintainer 2026-10-11 (E014 plan review): a labeled container is restarted ONLY when the exported certificate artifacts for one of its domains actually changed (byte comparison against the files already on disk before replacing them; the files are the state, so it survives exporter restarts). Applies to every pass including run-at-start; runatstart stays default-on because the startup pass is what produces the first export. Resolves BL-E012-008. Implemented by E014-S01-002 (per-domain changed signal) and E014-S01-006 (restart policy).
- (event) Consolidated to a clean 0.3.0 target-state spine on 2026-10-11 (amendments folded in; sources listed in the spine changelog).
- (decision) Clarifies the 2026-10-11 restart decision (plan review, stale-cert-after-crash finding): the restart TRIGGER is file mtime vs container State.StartedAt (newest exported file of any labeled domain more than 2 s later than the container start). Byte/content comparison decides whether an artifact is rewritten and whether a domain is reported as changed to the hook/notifications. Unchanged artifacts keep their mtime, so the two rules agree; the mtime rule additionally recovers a crash between write and restart and a deferred restart lost at shutdown. Owner: E014-S01-002 (compare/rewrite) and E014-S01-006 (restart trigger).

- (decision) 2026-10-11 E014-S01-001: the Docker client is built only by `DockerManager._create_client()` as `docker.from_env(use_context=False)`. docker-py 7.2 makes `from_env()` fall back to the active Docker CLI context when `DOCKER_HOST` is unset; ignoring it keeps the 0.2.x target (`DOCKER_HOST`, else `unix:///var/run/docker.sock`) and means a `~/.docker` planted in the service HOME cannot redirect restarts over a host-root-equivalent socket. Recorded formally by the E014-S01-006 restart ADR.
